스틱맨 추출이 끝난 SFA에 원본 영상의 스미어(팔다리가 빠르게 움직일 때 생기는 톱니 가닥)를 옮긴다. **스틱맨이 먼저다.** 스미어 방향·길이·위치와 팔다리 끝 비돌출 규칙이 모두 스틱맨의 팔다리 좌표에 기대기 때문이다.

## 단계

### 0. 스틱맨 확정
이 스킬의 SKILL.md 절차로 스틱맨을 끝낸다. 몸 ID는 `4560000+slot*100+1..11`(1 머리, 2 몸통, 3/4·5/6 팔 위/아래, 7/8·9/10 다리 위/아래), 장마다 새 점 ID, 흰 머리 FS Kind1을 지킨다. 부속(레칸 가면 등)·인물 색은 이 단계에서 끝낸다.

### 1. 스미어 위치 찾기(탐지 → 사람 확인)
- `tools/smear_limb_scan.py`: RTMW 손목·발목 창에서 인물색 가닥·검은 가닥·움직임으로 후보를 낸다. `tools/smear_eval.py`로 기존 방식과 같은 기준(AP·상위 k·오탐 부위)으로 비교한다. 자세한 내용은 `docs/SMEAR-DETECTION-REDESIGN-2026-11-07.md`.
- **자동 탐지는 성공이 아니다.** 일반 손·신발 오탐이 크다. 후보를 확대 시트(스미어 영역 크기에 맞춘 원)로 사용자에게 보여 '맞다/아니다'를 받고, 결과를 라벨 파일(`smear-eval-labels/1`: frame, actor=원본 인물색, part, box, conf S/L/U, user 메모)로 만든다. 사용자 메모에 '전체'가 있으면 부위 전체 모드다.
- 라벨 밖에서 눈검토로 더 찾은 곳은 장면 설정 `extra`에 적는다.

### 2. 팔다리에 붙인 초안 사슬(`tools/smear_from_labels.py`)
```bash
python tools/smear_from_labels.py --stickman 스틱맨_스미어전.sfa --labels labels_user.private.json \
  --frames frames --template templates.private.json --scene scenes/nian41_1032-1271_smear.json \
  --out v18.sfa --report v18_report.json
```
- 방향은 스틱맨 아래팔/정강이, 길이·양쪽 폭은 원본 톱니 화소로 잰다(폭은 원본 팔다리 반두께를 뺀 '일그러진 정도').
- 팔다리 끝은 스미어 끝 밖으로 나오지 않는다. 팔다리를 줄이지 않고 스미어를 민다(전체 모드 포함).
- 굵기는 부위 굵기에 비례해 250~1000%, 밀도는 연동한다. 끝 정리(v6), 소형 12선 조건은 폭<28px·길이<40px이다.
- **재현 확인(11-08):** 이 명령은 v18(`3a28690b…`)의 스미어 객체·점·연결을 240장 모두 같게 만든다. v18에 남아 있던 빈 'smear_review' 층 정의(1220–1222)만 다르다.

- **수동 자세 교정:** 사용자가 장을 지정해 요청한 것만 `scenes/*_smear.json`의 `pose_fixes`(장, 객체, 원래 좌표 → 원본 판독 좌표)에 적는다. 배치 도구가 먼저 적용하고, 맞는 점이 하나가 아니면 멈춘다. 예: 1036·1037 파랑 아래팔 펴기(11-08). 크기만 맞출 때는 `smear_size`(장·인물·부위 → 길이·양쪽 폭 px)를 쓴다. 형식은 그대로다(예: 1036을 수정 전 1037의 71px·40/50px 지그재그와 같게).

- 사용자가 "스미어 없음"으로 판정한 항목은 장면 설정 `drop`(장·원본 인물색·부위)에 적는다. 회전은 `smear_size`의 `rotate_deg`(화면 기준, 음수=반시계)로 넣는다.

### 3. 모양 다시 그리기(`tools/sfa_axial_smear.py`)
```bash
python tools/sfa_axial_smear.py --source v18.sfa --overrides scenes/nian41_1032-1271_axial_smear.json \
  --out 결과.sfa --report 결과_report.json
```
- 휘두르기·평행이동은 GPT 표시 테이퍼(`sfa_flow_smear`)를 쓴다. 꺾임은 국소 이동 방향, 폭은 말단폭×관절위치비, 앞뒤 58:42, 밀도 v1.1이다.
- 팔 축 방향 이동(직진)은 갈래 지그재그(후보 B)로 그린다. 폭은 팔 굵기×2.1, 길이는 팔뚝×1.2, 가닥 3–6개, 바깥쪽(팔꿈치→손)으로 뻗는다.
- 사용자 판정 용어: **앞뒤** = 직진 갈래, **좌우** = 원본 측정 v18 지그재그 유지(`axial_overrides`의 부위별 키 `장:slot:부위` = `keep_v18`). 휘두르기 테이퍼는 움직임이 작으면 스미어가 사라지므로 좌우 판정에 쓰지 않는다(11-08 가1·가3·가8).
- 직진/회전 분류: 회전각 15° 이하는 직진, 40° 이상은 회전이다. 그 사이는 회전각만으로 나뉘지 않는다(1158 21° 회전, 1181 31° 직진). **원본 앞·뒤 장과 두 모양을 나란히 놓은 시트로 사용자 판정**을 받아 `axial_overrides`에 적는다.
- 직접 지정(`forced_streaks`): 움직임 추정이 안 되는 장에 직진 갈래를 지정할 수 있다. **사용자가 모양 변경을 요청했을 때만 쓴다**(11-08: 1036·1037에 임의로 썼다가 '스미어 형식도 바꾸래?' 지적을 받고 되돌림).
- 늘어짐 방향: 원본 확인 상자 안 가닥의 결을 `tools/smear_stretch_direction.py`로 잰다. 일치도 .30 이상이거나 눈으로 확인한 것만 `stretch_directions`에 `use: true`로 적는다. 팔 축과 25° 이내면 바깥쪽 부호로 둔다. 측정 방향이 있으면 회전 판정 장면도 그 방향 갈래로 그린다.
- 같은 명령 안에서 #303030 글로우 테두리(`sfa_outline_trial`, 사용자 선택)를 더한다. 바깥 폭은 몸통 굵기의 30%(`--outline-edge`, 11-08 사용자: 10%는 앱에서 안 보임)다. **레이어 번호는 아래→위 순서로 다시 매긴다**(`sfa_layer_order`, 테두리0·몸1·스미어2). 앱은 레이어를 번호순으로 그린다.

### 4. 검사(`tools/smear_checks.py`) — 실패하면 전달하지 않는다
```bash
python tools/smear_checks.py 결과.sfa --reference 스틱맨_스미어전.sfa --frame-base 1032
```
- 팔다리 끝 비돌출, 몸 불변(스미어·테두리 층 밖), 레이어 번호=적은 순서, 층 이름 하나, ID마다 (층, 종류) 하나, 장 안 점 ID 중복 없음, 흰 머리 Kind1 개수를 본다.
- 현재 결과(`030bf1a9…`)는 모두 통과한다(스미어 101, 위반 0, Kind1 467). 옛 기준판 `e6556a67…`은 레이어 번호 결함으로 실패한다(예상한 결과).

**처음부터 재현(11-08):** Drive 입력 3종 + 영상에서 만든 프레임으로 2→3→4단계를 실행하면 검사를 통과한다(스미어 101, 위반 0). 현재 결과 `030bf1a9…`와는 1220–1222의 빈 스미어 층 정의 유무만 다르고, 객체·점·연결은 240장 모두 같다.

### 5. 확인 영상과 사용자 판정
```bash
python tools/sfa_overlay_video.py --sfa 결과.sfa --video video.mp4 --first-frame 1032 --crop-y 63 \
  --audio-start 43 --overlay 겹침.mp4 --solo SFA만.mp4
```
- 앱처럼 레이어 번호순으로 그린다. 서버 미리보기이므로 앱 확인을 대신하지 않는다. 사용자가 앱에서 열어 확인한다.
- 결과는 숫자보다 영상·확대 시트로 먼저 보여 준다. 문제가 여러 장에 보이면 장별 수치로 공통 원인부터 찾는다.

## 지킬 것(사용자 결정)
- 스미어 폭은 물체 두께가 아니라 일그러진 정도다. 원본 좌우 비대칭을 다시 섞는 일은 테이퍼를 깨지 않는 범위에서 사용자 확인 후에만 한다.
- 빌더를 다시 짤 때 이전에 승인된 처리(끝 정리, 1147 자세 교정, 비돌출, 굵기 비례)를 목록으로 대조해 빠짐없이 넣는다.
- 승인된 뼈대를 자동 교정으로 일괄 바꾸지 않는다. 자세 오류는 장을 지정해 사람 판정 뒤 고친다(예: 1035–1037 파랑 아래팔 대기).
- 내지르기를 빗살로 그리는 방식(v5)은 사용자가 지웠다. 직진은 갈래형이다.
- 원본 프레임·라벨·좌표·결과 SFA·영상은 Drive에만 둔다. 저장소에는 코드·장면 설정(판정·방향 단위벡터)·문서만 둔다.

## 3b. 깊이 칸 레이어 — **최종 전달물은 이 판만**(사용자 11-08). 3단계 결과(한 칸)는 중간 산출물이다(`tools/sfa_depth_layers.py`, 11-08 시험)
```bash
python tools/sfa_depth_layers.py --sfa 결과.sfa --frames frames --scene scenes/nian41_1032-1271_smear.json \
  --out 결과_깊이칸.sfa --report 깊이칸_report.json
python tools/smear_checks.py 결과_깊이칸.sfa --frame-base 1032 --same-shapes-as 결과.sfa --depth-report 깊이칸_report.json
```
스미어가 원본에서 앞에 있는 다른 인물 부위를 덮지 않게 한다. 인물과 상관없는 깊이 칸마다 '테두리→몸→스미어'를 두고, 장마다 원본 색으로 앞뒤를 재서 부위를 칸에 배정한다. 사람 편집은 고려하지 않는다. 설계·측정·결과·한계는 `docs/DEPTH-LAYERS-2026-11-08.md`. 앞뒤 측정은 근사라서 위 칸으로 올린 장의 시트를 사용자 판정에 낸다. 파편(debris)도 같은 칸 체계에 넣을 예정이다(미구현).
