# 사람 모션 추출·재현 기술과 인계

2026-11-04 현재. **START-HERE.md → references/CURRENT-STATE.md → references/DECISIONS-AND-LIMITS.md부터 읽는다.** 과거 스킬 원문은 references/HISTORICAL-SKILL-THROUGH-2026-11-04.md이며 그 안의 ‘최신’이 이 문서를 덮지 않는다.

## 시작과 필요한 자료

1. 루트 AGENTS.md 전체 → HANDOFF.md → docs/HANDOFF-PROMPT.md 순서로 읽는다. claude/new-session-gknz4t만 사용하고 main은 읽거나 쓰지 않는다. 신규자는 docs/NEW-COLLABORATOR-ONBOARDING-2026-11-04.md와 references/SESSION-LEDGER.md를 읽는다.
2. 실제 자료는 이 스킬의 **private-data/**에 있다. Git 제외/Drive 보존. data/artifact_manifest.json의13종 자산/Drive ID/바이트/SHA와 data/archive_inventory.json의 중첩 파일 색인을 확인한다. 유효 캐시는 재다운로드/재피팅하지 않는다.
3. 자료가 없으면 연결된 Drive에서 manifest 파일만 내려받아 `python .claude/skills/stickman-extraction/scripts/restore_data.py --import-path /내려받은폴더`로 복원한다. 파일명이 바뀌어도 내용 지문으로 맞춘다. 이 도구는 네트워크/인증 읽기/코드 실행/학습을 하지 않는다. 토큰/키를 출력하지 않는다.
4. 최신 재현은 private-data/latest/replay.zip. `python tools/stickman_replay.py 해당묶음 --destination /비공개/새폴더`. 기존 폴더를 덮지 않는다. 코드/입력 지문이 다르면 검사를 끄지 말고 지정 버전/자료를 복구한다.

## 현재 유지할 규칙

- 사람만 담당하고 사물/이펙트/배경/파편/스미어 그림은 변환기로 보낸다. 스미어인 신체의 의미적 팔/다리는 복구 대상이다.
- **스틱맨 다음 단계 = 스미어(11-08 정립):** 스틱맨을 확정한 뒤 `references/SMEAR-PIPELINE.md`의 순서(탐지→사용자 확인 라벨→`smear_from_labels`→`sfa_axial_smear`→`smear_checks`→`sfa_overlay_video`)로 스미어를 옮긴다. 스미어는 스틱맨 팔다리 좌표를 기준으로 하므로 순서를 바꾸지 않는다. 상태는 반쯤 완성(보류)이다.
- 2D·직선 몸통·기본11객체/AC/Flags 편집망. 장마다 새 점 ID, 장간 같은 대상 객체 ID, 인물마다 Flags3 하나, 틀 밖 좌표 허용, 앱 (24,24). 고정 뼈대는 투영 길이·비율·관절 좌표 고정이 아니다.
- 원본 그림 하나=키 하나, 원본2/3컷 정지도 부드럽게 보간. 실제 컷과 실험 분할1032/1272를 혼동하지 않는다.
- 흰 머리 FS Kind1 원 전체. A안(몸통/팔 유지·머리 최소 이동), 내부 투명11번 연결 유지. 과거10초 앱 정상 확인을 새1분판에 확대하지 않는다.
- **손가락/발가락/발길이 부속0.** 가까운 단순 연속 면은 유지한다. 과거 상세 외곽/3·5손가락/발바닥 막대 시험은 미채택 이력이다.
- 거리/표시척도와 지역 극근경 폭을 구분한다. 가짜 화면 밖 머리/고정50px fallback으로 채우지 않는다. 표시 게인은 실측 거리로 세지 않는다.
- 선택 joined_chains=True는 한 팔다리 두 마디를 한 경계/채움으로 잇고 공유 마디 폭/접선을 맞춘다. 기존96M과 새97M의 객체형식이 장간 충돌하지 않게 한다. 선택 표시층 포함 전체를11객체라고 부르지 않는다.
- 접촉은 실제 확인한 만남만. 근접 회피를 붙이지 않는다. 숨은 점/보완 방향은 추론으로 기록한다. 고점수/색 지지/구조0은 신체 의미의 정답이 아니다.
- 미리보기 영상은 현재 생략하고 SFA+필요 정지 근거로 전달한다. 원본 크기 판독/구조 검사를 생략하는 뜻은 아니다.

## 새로운 장면을 처리하는 순서

1. 원본/관측/그림키/코드 지문과 보정 전 출력부터 저장한다. tools/stickman_clip.py --projection --image-keys, docs/STICKMAN-EXTRACTION-V1.md를 따른다. 선택 공통v2는 docs/GPT-STICKMAN-GENERIC-V2-2026-11-03.md. GPU/새 학습은 별도 사용자 허락이 필요하다.
2. 고정 프로필·공통 함수·장면 scenes/*.json을 분리한다. 장 번호 예외를 공통 코드에 넣지 않는다. 같은 증상이 여러 장이면 원관측→유효 축/뺀 점→허브/팔다리 출력→저장 XML을 먼저 측정한다.
3. stickman_quality.py의 전체 구조/머리/흰 채움/접촉 검사와 움직임/겹침 후보를 본다. 선택 면/부속/앞뒤 기록까지 검사한다. 후보는 합격선/자동 삭제 지시가 아니다. 컷·실제 교차·빠른 차기를 평활해 지우지 않는다.
4. 전신 미검출/부분 관측/전경 가림/실제 퇴장을 원본 크기로 구별한다. 구도/가시성/지역 관측/추론 끝점을 장면 자료에 명시한다. 같은 컷 양끝 없는 가림은 억지 연결하지 않는다. 양팔 일괄 삭제나 색만으로 부위 확정 금지.
5. 보존한 보정 전 입력으로 최소 재생성한다. 이미 보정한 SFA를 다시 넣어 feather 등을 중복 적용하지 않는다. 실제 XML의 변경 범위/불변 장을 대조한다. 기본망/머리/면/앞뒤/접촉/장간 ID형식까지 검사한다.
6. 파일·코드 / CPU / 원본 눈 판독 / 추론 / 실제 앱·사용자 확인을 나눠 기록한다. 그림을 먼저 보여 주고 눈 판정은 사용자에게 받는다. 확인한 수정 가능 오류는 실제 수정/검증까지 수행하며 목록만 저장하고 끝내지 않는다.
7. 커밋 전 루트 python -m unittest discover -s tests 전체 성공·exit0을 따로 확인한다. 시험 결과를 파이프 뒤 && 커밋과 잇지 않는다. 지정 브랜치 최신 변경 보존 후 저장/푸시하고 HANDOFF/로그에 이유·검증·SHA를 남긴다.

## 재현·일반화·학습의 경계

data/generalization_cases.json은9+7+8=24개 **같은 영상의 중첩 개발 사례 항목**이다. held_out=false, training_ready=false. 수정 전 관측/수동 보정/추론/실패/사용자 판정/미승인을 함께 보존했으며 자동 정답으로 학습시키지 않는다. 일반화는 보정하지 않은 새 영상에 공통 처리만 적용한 첫 결과를 고정해 별도로 검증한다.

최신 재현은8cad3d7 코드와11고정입력/229지문으로 중간 뼈대부터 최종 XML이 같음을 검증했다. 새 원본에서 새 눈 판정을 자동 생성한 성공이 아니다. 스킬만 떼어 읽거나 입력 없이 동일 출력·임의 영상 완성을 약속하지 않는다. Claude 계정에 설치/활성화됐다고 주장하지 않는다.

Kaggle/변환기 인계는 references/PROJECT-OVERVIEW.md와 신규자 안내를 따른다. 마지막 상태는11-04 12:13 KST version2 RUNNING, 현재 완료/결과 미확인. Claude가 상태/출력만 확인하며 무단 재실행/3회차는 하지 않는다.
