# 2D 스틱맨 추출 기술 v1

이 스킬은 저장소 루트에서 실행한다. Claude Code는 `.claude/skills/`에서 발견할 수 있고, 다른 환경의 Claude/GPT는 이 파일을 직접 읽는다. 외부 계정에 스킬이 설치됐다고 말하지 않는다.

## 시작

1. `AGENTS.md`, `HANDOFF.md`를 읽고 지정 브랜치 `claude/new-session-gknz4t`와 작업 트리를 확인한다. main은 읽거나 쓰지 않는다.
2. `docs/STICKMAN-EXTRACTION-V1.md`를 읽는다. 현행 수정 보고 `docs/GPT-STICKMAN-REVIEW-FINDINGS-FIX-2026-11-03.md`를 먼저 확인한다. 이전 기준판·최종 검토·재현 해시는 `docs/GPT-STICKMAN-FINAL-REVIEW-2026-11-03.md`와 `data/stickman_motion/extraction_v1_2026-11-03.json`에 있다.
3. 원본·관측·승인된 보정 전 SFA가 캐시에 있는지 먼저 확인하고, 없을 때만 Drive에서 복구한다. 해시를 대조한다. 원본/전체 관절/가중치/앱 녹화를 저장소에 넣지 않는다.

## 고정할 것과 바꿀 것

- 고정: `profiles/stickman_2d_v1.json`의11객체·직선 몸통·머리 A안·흰 머리·내부 투명 연결. 장마다 새 점 ID, 장간 객체 ID 유지, 인물마다 Flags3 하나, (24,24), 2D. 틀 밖 좌표 허용, 투영 신체 길이는 변해도 된다.
- 장면 데이터: 컷·비율/굵기 기준·추가 키·`scenes/*.json`의 `tracks`·`partials`·`contacts`. 새 장면을 맞추려고 생성 코드에 장 번호/인물 예외를 넣지 않는다.
- 자동: 관측 선택·키 보간·투영 길이·머리 접촉·조건부 틀 밖 사슬 보정·명시한 장면 설정 적용·저장 검사.
- 원본 판독 필요: 이펙트 가림의 다리/팔 보완, 같은 다리 중복 검출, 부분 인물, 실제 접촉/회피. 낮은 점수만으로 숨기지 말고, 높은 점수도 정답으로 믿지 않는다. 이 스킬은 이펙트를 자동 인식하는 모델이 아니다.

## 작업 순서

1. **추출/입력 보존:** 새 영상은 가이드의 `stickman_clip.py --projection --image-keys` 경로로 보정 전 투영 SFA·보고·출력 좌표를 비공개 저장한다. 현재 기준판을 단순 재현할 때는 새로 피팅하지 말고 해시 고정 입력을 `stickman_finalize.py`에 준다. 이미 장면 보정한 결과를 입력으로 다시 주면 feather가 중복 적용될 수 있다.
2. **후보 수색:** `stickman_quality.py`로 전체 파일 구조·머리·흰 채움·접촉을 검사한다. `review_candidates`는 움직임 순위, `overlap_candidates`는 양쪽 사슬의 근접 후보다. 합격선이나 자동 수정 명령으로 해석하지 않는다. 후보 앞뒤 최소2장과 같은 그림이 이어지는 범위를 함께 본다. 컷을 잇거나 진짜 빠른 차기를 평활해 없애지 않는다.
3. **공통 원인 확인:** 같은 증상이 여러 장이면 장별 원관측 → 유효 축 가중치/뺀 점 → 출력 좌표를 먼저 비교한다. 원본 크기에서 판독한다. 개별 장 문제로 나열하고 끝내지 않는다.
4. **장면 보완:** 이펙트가 가린 팔다리는 보이는 방향·전후 관측을 근거로 `tracks`에 보완한다. 전신 검출 누락은 `partials`, 원본에서 확인한 만남만 `contacts`에 둔다. 근접 회피/미확정을 억지로 붙이지 않는다. 가려진 끝점은 추론이며 접촉 정답으로 재사용하지 않는다. 증거·불확실성을 `evidence`에 남긴다.
5. **최소 재생성:** 동결 입력 + 장면 JSON → `stickman_finalize.py`. 입력 해시를 지정하고 다른 파일로 저장한다. 새 추출본은 이미 틀 밖 사슬 보정이 들어 있다. 구버전 캐시 재현에만 원본 해시가 같은 `--hidden-observations`를 쓴다.
6. **회귀 검사:** 보정 전후 실제 XML에서 바뀐 장/인물/점을 비교하고 의도 밖 변경을 확인한다. 구조 오류는 고친 뒤 전달한다. 전체 영상/전 장 시트로 수색하고 후보·접촉·컷·이펙트·부분 인물은 원본 크기로 재검토한다. 서버 렌더와 앱 편집 검증을 구분한다.
7. **전달/저장:** 영상·시트·SFA를 Drive에 먼저 전달한다. 눈 판정/방향이 필요한 경우 쟁점 그림으로 사용자에게 묻는다. 이미 받은 사용자 판정과 재현 성공을 구분한다. 커밋 전 루트에서 전체 `python -m unittest discover -s tests`의 종료코드0·OK를 따로 확인한다. 지정 브랜치 최신을 fetch하여 변경을 보존하고 커밋·푸시한다. HANDOFF와 GPT 전담 로그에 근거·시험·SHA를 남긴다.

## 완료 기준과 금지

- 구조 검사0건은 포즈 정답/전 장 합격을 뜻하지 않는다. 숫자 후보0건도 모든 튐 부재를 증명하지 않는다. 관측 잔차와 미확정 가림은 보고서에 남긴다.
- 현재 승인 기준판은 1032–1271 최신 파일이다. 첫 추출부터 임의 영상까지 무수정 자동 완성됐다고 확대하지 않는다.
- GPU·학습·Kaggle 3회차는 별도 사용자 허락 전 실행하지 않는다. 기존 판정 JSON과 애니메이터별 학습 범위는 고치지 않는다.
- 실제 공통 결함 수정은 장면 수용과 구분한다. 뼈대 구조가 바뀔 때만 프로필 버전과 회귀를 갱신하며, 장면 좌표 수정으로 버전을 올리지 않는다.

- 사용자 정정: 이 스킬 작성은 Claude 복귀 준비이며 현재 GPT 전담을 끝내는 지시가 아니다. 검토에서 확인한 수정 가능한 오류는 기록만 하고 종료하지 말고 실제 수정·검증·비교 결과까지 만든다. 겹친 인물 하나가 누락되면 남은 인물의 좌표 혼입도 함께 점검한다. 컷 초반 누락 전신을 보완할 때는 필요한12점을 명시해 다른 컷 좌표를 물려받지 않게 한다.

- 가까운 다리의 선택 연속 면 시험은 `docs/GPT-STICKMAN-LIMB-SURFACE-TRIAL-2026-11-03.md`를 따른다. 기본 뼈대 위에 면 표시층이 추가되므로 최종 전체를11객체라고 부르지 않는다. `stickman_quality.py --surface 설정.json`으로 검사한다. 선 굵기 설정만으로 이음이 생기면 근경 부분의 면 표시를 검토하되 현재 시험 범위/앱 검증 상태를 유지한다.
