## 복붙용 프롬프트

첨부한 파이썬 파일 3개는 '영상 → 스틱파이터(.sfa) 벡터 애니메이션 변환'을 위한 딥러닝 학습 코드다. 학습을 돌리기 전에 허점을 찾고 싶다. 칭찬이나 일반론은 빼고, **실제로 결과를 망치거나 학습 시간을 낭비시킬 문제**를 찾아라.

### 배경
- 스틱파이터는 휴대폰 애니메이션 앱이다. .sfa 파일 = zip 안 XML. 장(Frame)마다 오브젝트(AO): 직선(TypeId 1, 두 점), 원(2, 지름 양 끝 두 점), 2차 베지어(3, 시작·제어·끝). 속성: 색(ARGB), 굵기 배율(ThicknessScale), 글로우(반경·두께·색·세기), 레이어·그리는 순서. 채우기(FR)는 여러 오브젝트 구간을 이어 만든 닫힌 경로(짝홀). 크기 배율(ObjectScale)은 화면에 영향 없음(앱 실험으로 확인).
- 목표: 영상(앱 내보내기 영상 → 나중엔 일반 애니)을 보고, 사람이 만든 것처럼 적은 수의 오브젝트로 된 SFA를 만든다.
- 방식: AI는 '이해'(픽셀마다 지도 28채널)를 맡고, 지도 → SFA 오브젝트 조립은 따로 짠 코드(끝점·모서리에 점을 찍고 점 사이에 직선/곡선 하나)가 한다.

### 자료(vec_data.py)
- 사용자가 모은 SFA 352개(시험용 37개는 뺌). 각 장을 우리 렌더러로 그림 → H.264(CRF 23–35, 24fps)로 인코딩 → 풀기 → 640 폭. 해상도 단계 1920·1280·854·640(인코딩 폭), 선 굵기 배율 0.75–1.5 무작위, 파일마다 이어진 24장, 2번 반복.
- 정답(파일 기하에서 직접, 그리는 순서대로 번호판을 칠해 화면에 보이는 부분만): 선 가운데(1px), 선 끝 가우스(σ1.5), 관절(다른 선과 이어진 끝), 방향(cos2θ, sin2θ), 칠한 면, 속성 16채널(선 굵기 log, 선 RGBA, 글로우 반경·두께 log·세기·RGB, 면 RGBA, 그리는 순서/전체), 종류(직선·원·곡선), 배경색. AO ID도 저장(이번엔 안 씀).

### 학습(vec_train.py)
- 입력: 앞·지금·뒤 3장(9채널) 512×256 자르기, 좌우 뒤집기. U-Net(ImageNet ResNet34 인코더, 첫 층 9채널로 늘림 + 원래 크기 특징 갈래). 출력 28채널.
- 손실: 가운데(정답을 3px로 넓혀 BCE pos_weight 5 + Dice), 선 끝·관절 가중 MSE, 방향 L1(가운데 근처), 면 BCE, 속성 L1(선 속성·글로우는 가운데선 픽셀, 면 RGBA는 면 픽셀, 순서는 무언가 있는 픽셀), 종류 CE(가운데선 픽셀), 배경색 L1.
- 커리큘럼: 1920(시간 20%) → 1280(25%) → 854(25%) → 640(30%), 단계마다 새 해상도 70% + 앞 단계 30%. AdamW 1e-3, 전체 시간에 걸친 코사인, fp16. 200걸음마다 고정된 검증(파일 5%)으로 저장, 마지막 단계 최저 검증 = best.pt.
- 실행: PC방 RTX 5060 8GB 3.2시간(또는 Kaggle T4×2 4시간). 15분마다 Drive로 중간 저장, 다음 실행 때 이어서(pc_vec_run.py).
- 확인된 것: GTX 1050 Ti에서 설치·자료 만들기·한 걸음 학습·검증이 돌았다(손실 항목 모두 유한값).

### 검토해 줄 것(항목마다 근거·심각도 높음/중간/낮음·고칠 방법)
1. **정답 오류**: 정답 지도가 실제 화면과 어긋날 수 있는 곳(렌더러 vs 정답 번호판의 굵기·순서·채우기 짝홀·투명 선·글로우만 있는 선, 좌표 변환, 640 축소 때 1px 가운데선).
2. **학습 설계**: 손실 가중치 균형(한 항목이 다른 항목을 덮는지), 1px 가운데선을 3px로 넓힌 영향, 선 끝 가우스 크기, 속성 L1을 sigmoid로 0–1 회귀하는 것의 문제(예: 색은 분류가 나은지), 자르기 512×256과 가장자리.
3. **자료 다양성·누수**: 같은 파일의 반복본이 학습·검증에 나뉘지 않는지, 시험용 제외가 확실한지, 렌더러만으로 만든 영상이 앱 영상과 다를 때의 위험(도메인 차이)과 줄일 방법.
4. **시간 대비 효과**: 3.2시간·RTX 5060에서 이 모델 크기·입력 크기·배치가 적당한지, 커리큘럼 비율, 더 나은 학습률 일정.
5. **나중 단계에 막힐 설계**: 이 출력 28채널로 SFA 오브젝트를 조립할 때 모자란 정보(예: 같은 선 구분, 채우기 윤곽 구성, 겹친 선 앞뒤).
6. **코드 버그**: 실행 중 멈추거나 조용히 틀린 값을 만드는 줄(번호와 함께).

출력 형식: 표 하나(번호 | 분류 | 심각도 | 문제 | 근거(파일:줄 또는 설명) | 고칠 방법), 그 아래 '학습 전에 꼭 고칠 것' 3개 이내.
