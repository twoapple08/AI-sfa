## 3. 3-2 회차 마감 — 동의(1을 기본, 2를 초기값) → [수정]
- **작업자**: 마감 = 작업자 시작 + 회차 분 − 3분(출력 정리)을 절대 시각(`--deadline`)으로 넘긴다. 예전의 '시작 전 한 번 계산한 남은 분 − 20분'을 대체한다.
- **학습기**: 걸음마다 `지금 + 예상 마지막 평가 + 최근 걸음 × 2 > 마감`이면 학습을 멈춘다(`stop=deadline`). 중간 검증·중간 생성 평가도 시작 전에 같은 검사를 하고, 모자라면 건너뛰고 기록한다.
- **예상 마지막 평가** = 1.25 × (교사 강제 검증 + 종류별 검증 + 생성 + 저장 2회) + 60초
  - 검증: 실측 초/토큰 × 실제 검증 토큰(시험 `--val-n` 최대 400장의 묶음 토큰 + 종류별 검증 목록 토큰). 965장이 아니다(네 지적).
  - 생성: 장마다 `a_폭 + b × 길이 상한`. a_폭 = 그 폭 실측 중 가장 짧은 장(그림 읽기·준비), b = 32토큰 이상 생성의 (초 − a_폭)/토큰 중앙값(디코더는 그림 특징 칸이 폭과 상관없이 45×80이라 폭 공통). 실측 없는 폭은 아는 폭에서 화소 비례로 올린다. 모든 장이 상한까지 간다고 보는 보수적 값이다.
  - 생성 목록(`final_plan`): 시험·위치 생성 채점 + 판정(그때 단계 폭 × 마지막 방향 수, 공식이면 상한 없음 2,048·추세면 장마다 네 방향 정답 최대 × 2 + 128) + 고해상도에서 끝나면 360 2방향.
  - 실측이 없거나 토큰당 비용을 가를 수 없으면(짧은 생성만) `--final-reserve-min`(기본 20분)을 쓴다.
  - 속도 실측(검증 초/토큰, 폭별 생성 표본 64개, 저장 초)은 저장본에 남아 다음 회차 예상에 쓰인다.
- 평가 목록을 줄여 시간을 맞추지 않는다. 마지막 평가는 항상 전부 한다. 저장본은 생성 전에 저장한다. 마감을 넘기면 넘긴 초(`deadline_over_sec`)를 기록한다.
- 마지막 기록에 `final_est_sec`(예상)과 `final_sec`(실제)을 함께 남긴다. GPU에서 예상 모형을 맞추는 측정이다.
- 네 정정 수용
  - 첫 180분 회차 = 진행 0.3이 아니다. 이제 진행은 학습 진행 기준이라 준비·평가를 뺀 학습 분 ÷ 계획 분이다.
  - `--gen-minutes 20`은 20분 정각 예약이 아니다. 20분이 지난 뒤 처음 오는 검증 분기에서 생성 평가가 붙는다.

## 4. 3-3 연장 정책 — 동의 → [수정]
명시한 정책은 다음과 같다.
1. 연장은 `--plan-minutes`를 지금보다 크게 줘서 한다. 계획을 안 주고 이어 가면 계획 끝을 넘을 때만 이번 실행 분만큼 늘린다(PC 여러 번 돌리기용, 예전 그대로).
2. 해상도 단계는 되돌아가지 않는다(예전 그대로).
3. **길이 분위는 단계마다 도달한 최댓값 아래로 내려가지 않는다**(`cur_max`). 360을 전체 길이까지 배운 뒤 연장하면 360·100%로 이어 간다. 새 해상도 단계로 넘어갈 때의 20–25% 시작과는 다르다(그 단계는 도달값이 없다).
4. 학습률은 늘어난 계획의 코사인 위치에서 이어 간다(GPT 2차 결정 그대로). 계수가 계획 끝 0.05에서 600/780이면 0.169, 600/1200이면 0.525로 오른다. 연장은 두 번째 공식 기회 전용이라 이 재가열을 받아들인다. 반대하면 연장 구간을 낮은 고정 학습률로 바꿀 수 있다.
