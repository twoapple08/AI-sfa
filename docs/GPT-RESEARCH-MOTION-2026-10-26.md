## 2. Claude 대조
- 일치: 모션3가 장 사이 일관성이 가장 좋다(서버 깜빡임 계산과 같은 방향).
- 차이: Claude는 "화풍은 모션4(SDXL+LoRA)가 낫다"고 했지만 GPT는 모션4의 나카무라다움을 1점으로 봤다(흐린 발광, 셀 면 경계 없음). GPT 기준(각진 끝·흰 심·층진 셀 명암·벡터화)이 우리 목적(SFA 면)에 더 맞으므로 **GPT 판정을 따른다**. 즉 지금 LoRA 결과는 '나카무라 화풍이 붙었다'로 세지 않는다(미확인 → LoRA 끔/켬 비교로 확인).

## 3. 조사 요약 (GPT, 출처는 원 답변. 직접 실행 검증 아님)
- **영상 모델 화풍 LoRA**: Wan2.1 T2V-1.3B에 이미지+캡션 LoRA(Musubi Tuner: 잠재·문장 캐시, batch 1, gradient checkpointing, block swap). 이미지 학습 권장 12GB+·RAM 64GB 권장(32GB+스왑 가능성) → T4 한 장 조건부 가능. 학습한 T2V LoRA를 VACE-1.3B와 같이 쓰는 경로를 먼저 시험(VACE 개발자 답변 2025-05, 호환은 실제 로더로 확인 필요). VACE 제어부 LoRA(DiffSynth)·클립 학습·Wan2.2 A14B는 T4에서 실험적/비추천. T4×2는 자동으로 30GB가 아님. T4는 BF16 네이티브 아님 → FP16·SDPA 확인.
  - 첫 시험 제안: 1.3B, 이미지만, 384–512, batch 1, rank 16–32. 거의 같은 프레임 줄이고 점화·팽창·분열·소멸 고르게, 검증은 장면 단위 분리.
- **깜빡임 줄이기**: 초기 노이즈·설정 고정(기본), 광류로 이전 결과 휘어 섞기(분열·새 파편엔 잔상 위험), 사건별 키프레임 덧칠 + EbSynth류 짧은 전파, AnimateDiff-SDXL/HotshotXL(조건부), TokenFlow·FLATTEN·Rerender(24GB, T4 어려움), Go-with-the-Flow(연구 참고).
  - 적용 순서 제안: 배경 분리·고정 합성(= 시험 5) → 회색 대신 고정 팔레트 색면 블로킹(= 시험 5 C) → 키프레임 확정 후 짧게 전파 → 점·블룸 제거, 색면 경계 정리 후 벡터화.
- **도는 카메라**: Wan2.1-Fun-1.3B-Control-Camera(조건부), CameraReference3D 궤도 노드, Wan2.2 Fun Camera(24GB), Uni3C(50GB), Blender 궤도 렌더 → VACE 제어 영상. 첫 시험은 30–60도 원호 권장.
- **24fps 주의**: 16fps 결과를 24fps로 재생하면 1.5배 빨라진다.

## 4. 조정 결정 (Claude)
- **Blender 궤도 렌더는 채택하지 않는다** — 사용자 '3D는 하지 마라'(2026-10-23). 대신 2D 시차 블로킹(`tools/fx_blocking.py --orbit`, 3층 빌딩 시차 + 가까운 층 가림)을 VACE 제어 영상으로 쓴다. GPT가 말한 '앞뒤 가림으로 공전이 읽힘'은 가까운 빌딩 층이 맡는다. Fun-Control-Camera·Uni3C도 3D 카메라 조건이라 보류.
- 24fps: 우리 VACE 입력은 블로킹 장 수 그대로(24fps 블로킹) 넣고 같은 장 수를 받으므로 속도 변화 없음(시험 3 num 15장→15장 확인). 모델 기본 16fps 학습 영향(움직임 느낌)은 남는 불확실성.
- 다음 순서: (1) 블로킹에 각진 끝·비대칭 찢어짐 추가 (2) LoRA 끔/켬 비교 (3) 도는 카메라 블로킹으로 VACE+참조 (4) Wan2.1-1.3B 이미지 화풍 LoRA 학습 노트북(Musubi Tuner).
