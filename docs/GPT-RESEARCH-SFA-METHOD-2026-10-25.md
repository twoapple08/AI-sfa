### 바로 해 볼 절차 [제안]

1. 기존 생성 인물에서 눈·선글라스·머리 끝·어깨의 동일 확대 영역을 고정한다. 새 원본 수집 없이 현재 선화 지도와 563 AO 판을 비교 기준으로 보존한다. AutoTrace centerline과 현재 줄기 추적을 같은 해상도에서 비교한다. 예시 명령은 `autotrace lineart.pbm -centerline -output-format svg -output-file centerline.svg`; 입력 극성과 실제 설치 버전의 옵션은 먼저 확인한다.
2. 줄기 그래프에서 **열린 끝, 닫힌 고리, 진짜 분기, 단순 교차**를 구분한다. 접선·폭·선화 확률로 한 획의 계속 방향을 판단한다. 모든 교차를 연결하지 않는다. 가지 길이만으로 눈썹·불꽃 끝을 지우지 않는다. 짧고 약하며 형태 손실이 작은 가지만 삭제 후보로 삼는다.
3. 한 획을 호 길이에 따라 표본화하고, 모서리·뾰족한 끝·분기·가려짐 경계를 고정한다. 후보 구간 `[i,j]`마다 끝점 고정 2차 베지어를 맞추고 재매개변수화한다. `Q(t)=(1-t)^2 P0+2t(1-t) P1+t^2 P2`. 픽셀과 동일한 t의 차이만 보지 말고 **원본↔곡선 양방향 거리**, 접선, 자기 교차를 검사한다.
4. 허용 오차를 통과한 구간만 간선으로 하는 DAG에서 `D[j]=min_i(D[i]+1)`로 분할한다. **이 후보점·오차 판정 안에서만** 곡선 개수 최소다. 연속 공간의 전역 최적해라는 뜻은 아니다. 눈·가시에는 더 엄격한 오차, 선 아래 가려지는 채색 경계에는 느슨한 오차를 쓴다. 접선 연속 비용을 넣으면 이전 구간 방향을 상태에 포함하거나 후처리 공동 최적화가 필요하다.
5. 현재 굵기 변화는 원본 밝기만으로 추정하지 않는다. 선 마스크의 거리 변환으로 `폭≈2×경계까지 거리`를 초기화하고, 교차점에서 부풀어 오른 값은 제외해 인근 획의 폭으로 보완한다. 최종 굵기는 실제 렌더 비교로 보정한다. SFA가 AO별 일정 폭이면 **폭 변화 때문에 필요한 분할만** 추가한다. 끝이 빠지는 붓선은 꼭 필요한 곳에서만 적은 곡선의 닫힌 면으로 둔다.
6. 작은 고리는 닫힘·방향·넓이를 제약해 공동 맞춤한다. 원·타원은 눈동자 등의 **모양 추정 보조**로만 사용하고 출력은 TypeId 3으로 한다. 연기·폭발을 원으로 대체하지 않는다. 비유리 2차 베지어는 원호를 정확히 표현하지 못한다. ‘4개면 정확한 원’은 틀리다. 예를 들어 사분원 양 끝 접선 교점을 조절점으로 잡으면 중간 반지름은 약 1.06066배다 [계산]. 4개부터 오차를 측정해 필요할 때 늘리며 개수를 고정하지 않는다.
7. 끝점 좌표와 접선 연속을 먼저 보장하고, AC는 기존 형식 규칙대로 내보낸다. **AC 추가가 AP 저장 개수를 자동으로 줄인다고 가정하지 않는다.** 닫힘·연결·실제 편집 동작은 구별해서 확인한다.

**현 코드에서 확인한 주의점:** `tools/effect_vectorize.py::bez_fit`은 현 길이 매개변수 최소제곱, `fit`은 최대 오차점 재귀 분할이다. `depth > 12` 또는 `len(P) < 6`에서도 오차와 무관하게 수락한다. 따라서 기존 `tol`은 모든 곡선에서 보장되는 최대 오차가 아니다. ‘DP로 바꾸면 해결’ 전에 이 수락 조건과 닫힌 고리 처리부터 대조할 가치가 있다. 이번에는 코드를 고치지 않았다.

## 2. 층 쌓기: LIVE를 그대로 쓰기보다 SFA 제약을 넣은 영역별 최적화

### 근거와 차이

- **[문헌 확인]** [LIVE 논문](https://arxiv.org/abs/2206.04655)과 [공식 구현](https://github.com/Picsart-AI-Research/LIVE-Layerwise-Image-Vectorization)은 닫힌 베지어 경로를 점진적으로 추가하고 공동 최적화한다. 하지만 **밝기 순서·포함 관계·의미 부위·최적 층 수 자동 선택을 모두 보장하는 방법은 아니다.** 공식 예제도 `experiment_5x1`처럼 경로 추가 일정을 설정한다. 여기서 path 한 개는 SFA AO 한 개와 같은 단위가 아니다.
- **[문헌 확인]** [SGLIVE 논문](https://arxiv.org/abs/2408.15741), [공식 코드](https://github.com/Rhacoal/SGLIVE)는 분할의 도움을 받아 방사형 그라데이션 채우기를 최적화한다. 영역 초기화는 유용하지만 SFA에서 SVG의 그라데이션 채우기를 그대로 지원한다고 확인된 바 없다. **단색 RGBA 층으로 바꿀 별도 설계**가 필요하다.
- **[문헌 확인]** [선형 그라데이션 층 분해 공식 코드](https://github.com/Zhengjun-Du/ImageVectorViaLayerDecomposition)는 색 층 분해와 편집을 다룬다. 색을 층으로 표현하는 근거이지 사용자식 중첩 덩어리 구조나 SFA 변환의 완성품은 아니다.
- **[문헌 확인]** [VTracer 공식 README](https://github.com/visioncortex/vtracer)는 `stacked`/`cutout`을 구분한다. 현재 문서에는 spline 단순화 옵션도 있다. **stacked는 색 영역의 겹침 구조이며 밝기 순 덩어리·반투명 층과 동일하지 않다.** 외부 도구 중 빠른 비교 대상으로 좋지만, 출력의 3차→2차 변환까지 포함해 평가해야 한다. 옵션은 사용할 릴리스를 고정하고 그 버전에서 확인한다.
- **[문헌 확인]** [DiffVG Path 구현](https://github.com/BachiLi/diffvg/blob/master/pydiffvg/shape.py)은 2차 경로와 짝홀 채우기를 처리한다. 따라서 3차로 최적화한 뒤 변환하기보다, 처음부터 **2차 경로·단색 RGBA만 허용하는 연구용 최적화기**를 구성할 근거가 있다. DiffVG 결과와 앱의 AA·선 끝·합성색이 정확히 같다는 보장은 별도다.

### 바로 해 볼 절차 [제안]

1. **폭발/연기/배경/가림 물체 분리부터 고정한다.** c0426에서 현 색 규칙 마스크, 기존 SAM 계열 마스크, 둘을 검토한 마스크를 나란히 비교한다. SAM은 물체 경계 보조이지 발광체의 정확한 알파 복원기가 아니다. 테두리 없는 효과에 선화 추출기를 강제하지 않는다.
2. 각 효과를 색 계열로 나눈다. 붉은 외층·주황 중층·노랑/흰 심처럼 연결된 색 덩어리를 만든다. 연기 암부는 따로 둔다. **장면 전체 밝기 순 하나로 정렬하지 않는다.** 같은 밝기의 파랑·주황, 불꽃 안 검은 연기를 하나로 합치면 색/구조가 사라진다.
3. 색 계열 안에서 넓은 아래층 `M0`와 안쪽 층 `Mk+1 ⊆ Mk`를 초기화한다. 분위수 6층은 비교 시작값일 뿐 최종 규칙이 아니다. 먼저 거친 큰 형태를 맞추고, 원본과의 잔차가 의미 있는 덩어리로 남는 곳에만 다음 층을 추가한다. 좁은 상층이 덮는 아래층 내부의 복잡한 구멍·경계는 생략 가능하다.
4. **중요한 예외:** 불투명 상층 아래는 숨겨도 되지만 반투명 상층 아래는 계속 보인다. 단순히 ‘위가 덮으니 아무렇게나’가 아니다. `Cout=α Cf+(1-α) Cbelow`로 모든 층을 함께 렌더해 색을 맞춘다. 합성은 교환법칙이 성립하지 않으므로 순서도 저장한다. 얇은 파편·뾰족한 끝을 블러로 둥글게 만들지 않는다.
5. 초기 윤곽을 §1의 긴 2차 곡선으로 맞춘 뒤 DiffVG에서 조절점·층 RGB·알파를 공동 최적화한다. 목적은 `시각 재구성 오차 + λq×곡선 수 + λl×층 수 + 자기교차/포함관계 위반 비용`. 개수는 이산적이므로 연속 최적화만으로 줄지 않는다. 곡선 합치기·층 추가/제거를 번갈아 시험해야 한다. λ를 바꾼 품질/복잡도 후보를 보여 주고, 임의 최대 개수로 자르지 않는다.
6. 먼저 소형 미리보기에서 색·덩어리를 맞추고 원래 출력 크기에서 가시 윤곽·끝을 다시 검증한다. 저해상도에서만 맞은 결과를 합격시키지 않는다. 검정·밝은 회색·유색 배경에 올려 비교해 알파 해가 검정 바탕에만 맞았는지 확인한다.
7. 1장에서는 알파·가려진 색이 **유일하게 복원되지 않는다**. 정답 레이어를 복구했다고 부르지 말고, 사용자 규칙을 만족하는 편집 가능한 재구성이라고 부른다. 여러 프레임의 배경 변화·가림 정보가 있으면 모호성을 줄이는 데 쓴다.

**현 코드 확인:** `stack_layers_sfa.py`는 따뜻한 색/고명도 문턱과 면적 필터로 폭발을 정하고, 영역 안 L 분위수로 층을 만든다. `blob()`의 GaussianBlur+opening과 작은 구멍 제거는 중요한 가시·틈을 없앨 수 있다. `fill_layer(... argb(...))` 호출에 층별 알파 추정이 없으므로 **이 코드가 이미 반투명 층 분해까지 해결했다고 보면 안 된다.** 덩어리 중첩의 좋은 출발점이다.

CPU 4코어 서버에서는 AutoTrace·마스크/곡선 맞춤·VTracer 비교를 먼저 할 수 있다 [제안]. LIVE/DiffVG 전체 최적화 시간은 측정 전이다. 오래된 LIVE 의존성을 현 Python 환경에 무리하게 섞지 말고 분리 환경을 사용한다. GPU 최적화는 Kaggle에서 1장만 시험한 뒤 확장한다. T4 두 장이 자동으로 한 장의 큰 VRAM이 되는 것은 아니다.

### 우리 자료로 학습할 때의 실제 순서 [제안]

1. 781개 래스터 클립/1,032장 자료는 **벡터 정답쌍이 아니다**. 먼저 원본/생성 키 그림을 SFA로 바꾸고 시각 검수해 `프롬프트, raster, SFA 구조` 쌍을 만든다. 나쁜 벡터화를 대량 복제해 가르치면 현재 오류를 그대로 학습한다. 기존 트랙은 대응·시간 관찰 자료로 쓸 수 있지만 생성 시 원본 트랙을 선택해 붙이지 않는다.
2. SVG 전체 XML 대신 `Layer(role, order) → Stroke(Q-chain,width,color) / Fill(contours,RGBA) → Key(time,geometry) → Birth/Death/Split/Merge/Hold`의 SFA 중간 표현을 정의한다. 선과 면을 구분하고 2차 명령만 허용한다. 실제 파일 ID는 결정적 writer가 부여한다. 위상 변화 명령은 학습용 의미이며 기존 앱에 새 명령이 있다고 가정하지 않는다.
3. 기존 SVG/Lottie 후보는 동일한 간단한 효과 프롬프트와 생성 이펙트 그림에서 비교한다. 비공개 원본을 온라인 데모로 보내지 않는다. 성공한 출력을 2차·단색 알파 층으로 제한해 SFA화한 뒤 **변환 전후 품질**을 둘 다 본다. SVG 렌더가 좋고 SFA만 나쁘다면 생성 모델의 실패와 구분한다.
4. OmniSVG 미세조정은 공식 학습 포맷의 PNG/SVG/문장 쌍부터 준비한다. 4B 전체 학습부터 하지 말고 짧은 경로 표본의 LoRA/부분 학습 가능성·실제 메모리부터 측정한다. 공개 코드 존재가 현재 T4 자원에서 성공한다는 보장은 아니다. Illustrious용 LoCon 가중치는 다른 구조의 벡터 모델에 바로 이식되지 않는다.
5. 작은 SFA 전용 모델은 정지 구조 생성부터, 다음으로 같은 구조의 시간 계수와 위상 사건을 학습한다. 문장/태그 조건으로 **새 조절점·색·시간 변화**를 출력해야 한다. 사전 항목 번호를 내고 원본을 로드하는 설계는 사용자 요구를 충족하지 않는다.

작은 전용 모델의 고품질 생성은 아직 **우리의 연구 가설**이다. DeepSVG·OmniSVG·OmniLottie는 구조화된 벡터 학습의 실제 선례지만 ‘소량 나카무라 자료 → 폰에서 완성도 높은 SFA’의 증거는 아니다.

## 4. 움직임: (24,24) 전 장 직접 그리기에서 떨림·용량 줄이기

### 근거와 적용 한계

- **[문헌 확인]** [ToonCrafter 공식 구현](https://github.com/Doubiiu/ToonCrafter)은 두 그림 사이 래스터 보간을 제공한다. 공식 기본 설정은 512×320, 최대 16프레임, 약 24GB급 메모리를 보고한다. README는 커뮤니티의 약 10GB 구현과 12GB fp16 모델도 안내한다. 현재 T4에서의 성공은 미검증이며 폰 실행 후보로 보지 않는다.
- **[문헌 확인]** [AnimateDiff 공식 코드](https://github.com/guoyww/AnimateDiff)는 이미지 모델과 시간 모듈을 결합하며 SDXL 경로도 별도로 둔다. 같은 기반 계열의 호환이 중요하다. **Illustrious LoCon + 아무 SD1.5 motion module**의 결합이 된다고 가정하지 않는다. 정지 화풍 LoRA가 나카무라식 시간 구조까지 배웠다는 근거는 없다.
- **[문헌 확인]** [DeepSVG](https://github.com/alexandre01/deepsvg)의 잠재 보간은 가능한 구조 변화의 참고이고, [OmniLottie](https://github.com/OpenVGLab/OmniLottie)는 시간 정보를 명령으로 표현하는 최신 비교 대상이다. 둘 다 SFA의 동일 ID/점 대응을 저절로 만들어 주지는 않는다.
- **[문헌 확인]** [Layered Neural Atlases](https://layered-neural-atlases.github.io/), [논문](https://arxiv.org/abs/2109.11418)은 2D의 공통 외형·프레임별 대응·알파를 공동 최적화해 편집을 일관되게 전파한다. SFA 변환기는 아니며 영상별 최적화가 필요하다. 폭발의 급격한 분열까지 하나의 공통 atlas로 잘 표현된다는 근거는 없다. **층 색/형태를 영상 전체에서 공유한다는 발상**만 참고한다 [제안].
- **[문헌 확인]** [RAFT 공식 구현](https://github.com/princeton-vl/RAFT)은 영상의 optical flow를 추정한다. 이를 곡선/마스크의 다음 장 초기값으로 사용하는 것은 우리 적용 제안이다. 애니의 섬광·가림·새 파편에서는 flow가 틀릴 수 있으므로 그대로 정답으로 쓰지 않는다.

### 바로 해 볼 절차 [제안]

1. 새 효과 한 개를 발생→급팽창→정점→흩어짐→소멸로 계획하고, **24개 표시 칸/초**의 노출표를 만든다. 원본에서 배운 타이밍 통계는 쓰되, 원본 프레임/트랙을 그대로 배치하지 않는다. 투스는 같은 그림을 두 칸, 쓰리스는 세 칸 기록한다. 24fps라고 서로 다른 새 그림 24개를 강제로 만들지는 않는다. 카메라 이동과 효과 자체 변형도 분리한다.
2. 제작 경로는 **영상/보간 모델 → 24fps 시간표에 맞춘 래스터 장들 → 시간 일관 벡터화**가 가능하다. 모델이 생성한 16프레임이 자동으로 24fps 1초가 되는 것은 아니다. 장 수·길이·반복 노출을 명시한다. 무조건 중간 장을 늘리는 방식은 임팩트의 끊어짐을 지울 수 있다.
3. 독립 변환을 비교 기준선으로 보존하고, 개선판은 이전 장 곡선·마스크를 flow로 워프해 다음 장 초기값으로 쓴다. 같은 효과의 색 계열·층 역할·명도 문턱은 짧은 구간에서 공동 추정한다. 프레임마다 k-means/분위수를 새로 고르면 색 군집의 번호와 층 경계가 흔들릴 수 있다. 닫힌 경로의 시작점·방향·구멍도 정규화한다.
4. 재구성 오차에 `유효 영역에서의 워프된 이전 렌더/현재 렌더 차이`와 `대응 곡선·색·알파 변화 비용`을 더해 짧은 시간창에서 공동 맞춘다. 단순 좌표 차이를 작게 만들면 움직임 자체를 억제하므로 **flow 보정 후 잔차**를 규제한다. 앞뒤 flow 불일치·가림·섬광에서는 비용을 약하게 하거나 끈다. 의도한 색 변화까지 평평하게 만들지 않는다.
5. **분열·새 파편·합체·구멍 출현에서 객체/곡선 개수는 바뀌어도 된다.** 동일 AO ID·동일 점 개수는 앱 출력의 필수 조건이 아니다. 안정 구간에서만 대응을 유지하고 위상 사건에서는 재분할·재초기화한다. 고정 구조를 맞추려고 모든 프레임에 잔곡선을 삽입하지 않는다. 내부 모핑으로 중간 형태를 만들더라도 모든 결과 장을 기록하고 앱 트위닝은 사용하지 않는다.
6. 용량은 장당 곡선/층 수, 보이는 윤곽만의 저장, 같은 표시 그림의 벡터화 결과 캐시, 불필요한 좌표 자릿수 감소 후보로 줄인다. **캐시 재사용은 계산 절약이지 SFA 저장량 감소 보장이 아니다.** 반복 장도 실제 XML/ZIP 크기와 앱 동작을 측정한다. 검증된 파일 규칙 밖의 delta codec·참조 프레임 기능을 새로 있다고 가정하지 않는다. 좌표 정밀도 감소는 닫힘·연결·최소 굵기를 보존해야 한다.
7. 브리핑의 1장 0.06MB·1,117 AO를 단순히 24배 하면 약 1.44MB/초·26,808 AO 기록/초다 [계산]. 실제 애니메이션 ZIP 압축·반복·프레임별 복잡도에 따라 달라지므로 예상 용량 확정치가 아니다. 1초/24장 시험에서 SFA bytes, 전체 AO/AP/FR, 최대 장당 AO, 앱 로딩·재생을 직접 측정한다.
8. 정상 속도 영상과 임팩트/분열 확대를 먼저 본다. flow 보정 후 경계/색 오차를 **입력 영상 자체의 변화와 비교**해 변환기가 새로 만든 떨림을 측정한다. 정지 노출 칸에는 완전히 동일한 결과를 재사용한다. 화면 흔들림·번쩍임은 의도된 움직임이므로 단순 프레임 차이 최소를 합격 기준으로 삼지 않는다.

갱신된 Claude §7-1(3)의 **트위닝이 아니라 장 사이 떨림·용량이 병목**이라는 정정에 동의한다. 이전 버전의 앱 트위닝 중심 가설은 이 보고서의 추천에서 제외했다. ToonCrafter/AnimateDiff는 시간 자료의 선생님·비교 후보이고, 최종 폰에서 실행할 작은 시간 모델을 대신 완성해 주지는 않는다.

### 탑재 절차 [제안]

1. 먼저 기존에 알려진 폰 사양·메모리 정보를 재사용한다. 저장소에서 확정되지 않은 기종/SoC는 추측하지 않는다. 새 설치·페어링 반복부터 요구하지 않는다. 실제 탑재 단계에서 꼭 필요한 미확인 항목만 확인한다.
2. 서버/PC에서 같은 모델의 기준 출력을 만들고, **LoCon을 원래 Illustrious에 병합한 사본**이 기준 엔진 출력과 비슷한지 확인한다. 이 사본만 변환·양자화한다. 원본 가중치는 보존한다. 병합은 런타임 adapter 호환 위험을 줄이는 수단이지 화풍 손실이 없다는 보장은 아니다.
3. 동일 엔진의 비양자화→8bit→4bit 후보를 비교하고 프롬프트·seed·샘플러를 고정한다. 엔진이 바뀌면 seed 번호가 같아도 픽셀까지 같을 것으로 기대하지 않는다. 가중치 파일 크기 외에 텍스트 인코더·VAE·작업 버퍼·최대 RAM·실패/열 상태를 기록한다. 낮은 정밀도에서 색/가시 손실이 나타나면 한 단계 높은 정밀도로 되돌린다.
4. 폰에서 래스터 한 장이 가능하면 CPU/네이티브의 마스크·곡선 맞춤도 측정한다. **SDXL만 돌아간다고 전체 SFA 파이프라인 탑재가 끝난 것은 아니다.** SAM/DINO/lineart 대형 모델까지 매번 함께 올리지 않도록 효과 마스크/층을 같이 예측하거나 작은 분해기로 증류한다.
5. SDXL 자원 검사가 실패하면 공개 소형 그림 모델을 동일 검증셋에서 비교하거나 SFA 직접 모델로 이동한다. SDXL LoRA를 다른 기반 모델에 그대로 꽂지 않는다. 선생님 생성물/검수 자료로 다시 학습하거나 증류해야 한다. 몇 장으로 충분한지는 아직 모른다.
6. 직접 벡터 모델의 크기는 **예를 들어 100–300M를 탐색 시작점**으로 둘 수 있다. 적정 크기·품질이 확인된 권장 사양은 아니다. 200M 파라미터를 4bit로 저장한 순수 가중치는 약 100MB [계산]이나 토큰/활성값/캐시/인코더가 추가된다. 긴 벡터 토큰열의 KV cache도 측정한다. 런타임 변환기의 연산 지원까지 확인한다.
7. 최종 합격은 비행기 모드 등 네트워크 없는 조건에서 **글/태그 → 새 그림/곡선 → 시간 변화 → SFA 저장 → 앱 열기·재생** 전체 성공이다. 서버 학습은 가능하지만 최종 사용자 입력의 생성 계산을 서버에 의존하게 만들지 않는다.

## 6. LoRA 색 빠짐: 자료 비율 가설을 유지하되 마스크·배경·검증 누수를 먼저 분리

### 확인한 문제와 근거

1. **색 원인은 아직 확정되지 않았다.** ‘40% 저채도 → 회색화’는 그럴듯한 가설이고 컬러/임팩트 분리는 타당한 실험이다 [기존 보고/제안]. 하지만 기반 모델, adapter 강도, 캡션의 의미, 검정 영역, 샘플 생성 설정을 통제하지 않은 상태에서 단일 원인으로 단정하면 안 된다.
2. **[저장소 확인]** `tools/lora_split.py`는 효과 마스크 안이 아니라 **원본 그림 전체 HSV S 평균**으로 muted/vivid를 나눈다. 검정 바탕의 화려한 작은 섬광이나 회색 배경의 주황 폭발이 저채도로 분류될 수 있다. `_np`도 원본의 분류를 따른다. 새 판에는 효과 영역의 색상/채도·화면 점유율을 따로 집계할 필요가 있다 [제안].
3. **[저장소 확인]** `tools/lora_captions.py`는 인물 영역을 `img[m]=0`으로 검게 칠하고 `no humans, black area`를 붙인다. 이는 ‘그 부분을 학습하지 않기’가 아니다. 기본 손실이라면 **검정 실루엣·빈 공간 자체도 목표 그림으로 학습**한다. 이것이 회색화의 주원인인지는 미검증이다.
4. **[문헌 확인]** 사용하는 버전의 [sd-scripts v0.9.1 masked loss 문서](https://github.com/kohya-ss/sd-scripts/blob/v0.9.1/docs/masked_loss_README.md)는 별도 마스크/R채널 또는 PNG alpha로 학습 손실 영역을 지정하는 방법을 제공한다. **새 도구를 찾지 않아도 현재 학습 계열에 대안이 있다.** alpha는 여기서 손실 가중치이지 모델이 투명 RGBA 이미지를 출력한다는 뜻은 아니다.
5. **[문헌 확인]** [v0.9.1 SDXL 문서](https://github.com/kohya-ss/sd-scripts/blob/v0.9.1/docs/train_SDXL-en.md)는 U-Net만 학습하는 LoRA 설정을 권장하고, TE 출력 캐시는 캡션 shuffle/drop과 함께 쓸 수 없다고 설명한다. 따라서 ‘캡션을 무작위 섞자’는 처방은 현재 캐시 설정과 충돌할 수 있다.

### 바로 해 볼 절차 [제안]

1. **클립/샷/중복 원본 단위로** train/validation/test를 나눈다. 인물 제거판과 원본, 같은 컷의 이웃 프레임은 반드시 같은 묶음이다. 1,032장을 독립 표본 1,032개라고 세지 않는다. 나카무라와 보충 작가의 샷별 비중도 기록하고 나카무라 우선 원칙을 유지한다.
2. 효과 마스크에서 흰 심·유색 테두리·어두운 연기를 분리해 채도 분포와 실제 팔레트를 조사한다. 흰 심/회색 연기를 ‘나쁜 저채도’로 지우지 않는다. 임팩트는 별도 신호/adapter를 유지하고, 컬러 효과는 색상·종류·단계 조합이 골고루 보이도록 구성한다.
3. 캡션은 관찰한 색 관계를 일관되게 쓴다. `white core, orange rim, dark smoke, no outline, layered cel shading`처럼 실제 보이는 요소를 기술한다. 카메라 흔들림·rapid expansion은 정지 한 장으로 학습되는 시간 능력이 아니다. 정지 캡션은 모양/단계 조건으로 해석하고 실제 속도 학습에는 연속 자료를 쓴다. `vivid colors`만 반복해 모든 그림이 네온색으로 치우치지 않게 한다.
4. 검정 칠하기 대신 **원본 RGB + 학습할 효과 영역의 손실 마스크**를 시험한다. 마스크 흰색은 효과/학습할 영역, 검정은 제외할 인물/배경, 모호한 경계는 낮은 가중치다. 인물에 가려져 원래 안 보이는 효과를 정답처럼 복원하지 않는다. soft mask가 latent 해상도로 줄 때 작은 불티가 없어지는지도 확인한다. 마스크된 영역도 입력 문맥으로는 남으므로 완전한 영향 제거라고 부르지 않는다.
5. 2차 결과를 먼저 평가해 현재 개선 폭을 확인한다. 추가 학습에서는 같은 자료·분할·노출 횟수로 **검정 제거판 vs 원본+masked loss**를 대조한다. 색 반복 비율과 손실 마스크를 동시에 바꾸면 원인 분리가 안 된다. 한 번에 한 축씩 바꾼다.
6. epoch 대신 `실제 optimizer step, 유효 샷 수, 이미지 반복 횟수, 누적 gradient, LR`을 함께 기록한다. 597×2+206이면 한 epoch의 명목 노출 수는 1,400이며, 배치/누적 설정에 따라 optimizer step은 달라진다 [계산]. 1차의 ‘4·6바퀴 비슷함’만으로 최적 epoch를 확정하지 않는다.
7. 고정 검증 프롬프트에 흰심 주황테 폭발·청색 빔·회색 연기·분홍 섬광·흑백 임팩트를 포함한다. 기본 모델/1차/2차 체크포인트, LoRA 강도 0·0.5·0.8·1.0, 고정 seed 여러 개를 **같은 격자**로 비교한다. 최초에는 작은 진단 격자를 쓰고 유망 후보만 넓힌다. 학습 loss 최저가 아니라 색 지시·가시·모양 다양성·배경 오염·복제 여부를 본다.
8. 결과를 먼저 그림으로 보여 주고, 효과 영역 채도/색 관계 지표는 보조로 붙인다. 새 seed·다른 색 지시에서도 형태가 살아 있는 가장 이른 체크포인트를 선택한다. 반복 자료 복제와 색 제어 저하가 시작되면 학습을 더 늘리지 않는다. 생성 시험에서 adapter 로드 실패와 모델 학습 실패도 분리한다.

## 7. 종합 경로와 첫 실험 3개

### 경로 A — 현재 자산을 살리는 주 경로

**기존 Illustrious+효과 LoRA → 새 효과 키/영상 생성 → 학습한 노출 시간표의 24fps 전 장 → 효과/배경/물체 분리 → 긴 2차 선·포함된 색 층을 시간상 공동 맞춤 → 모든 장을 (24,24) SFA에 기록.**

이것이 단기 추천 1순위다 [제안]. LoRA의 형태 학습 성과와 SFA 실물 근거가 있고, 사용자 원칙 세 가지를 명시적으로 적용할 수 있다. 변환을 모든 픽셀의 정밀 복사가 아니라 **그리는 단위의 구조 복원**으로 바꾼다. 외부 도구는 AutoTrace/VTracer/PolyVector/LIVE의 유효 부분을 비교·채택하고 우리 제약만 얇게 붙인다. 기존 트랙을 출력에 끼워 넣지 않는다.

최종 폰 경로는 두 갈래다. 실제 폰 자원이 허용하면 양자화한 병합 SDXL과 작은 분해/곡선 맞춤기를 쓴다. 허용하지 않으면 공개 소형 그림 모델로 학습/증류해 같은 변환기를 사용한다. **어느 쪽도 아직 최종 합격하지 않았으며**, 서버에서만 좋은 그림을 만들었다고 목표 완료로 선언하지 않는다. 색·구조·위상 변화 검증 데이터가 경로 B에도 남으므로 낭비가 적다.

### 경로 B — 폰에 더 잘 맞을 수 있는 장기 경로

**경로 A의 검수된 새 그림/SFA + 비공개 학습 자료의 구조·시간 정보 → 계층적 SFA 명령/계수 모델 → 작은 시간 모델·위상 사건·반복 노출 → 결정적 writer가 24fps 전 장 기록.**

장기 추천 2순위다 [제안/추정]. OmniSVG/DeepSVG/OmniLottie는 구조화 벡터 학습의 선례다. 선·면·색 층을 직접 출력하면 런타임의 대형 래스터 생성·분해 모델을 줄일 가능성이 있다. 다만 고품질 SFA 정답과 시간 대응 자료가 먼저 필요하며, 최소 데이터량·적정 모델 크기·성공 품질은 미확인이다. 큰 VLM의 축소가 자동으로 해결책인 것도 아니다.

첫 단계는 새 대형 기반 모델 학습이 아니라, 검수된 간단한 효과로 **구조 복원/조건 변경이 학습되는지** 시험하는 것이다. 종류·색·크기·방향이 새로운 조합인 보류 조건에서 새 곡선을 출력해야 한다. 이 시험이 실패하면 오류가 데이터/표현/모델 용량 중 어디에 있는지 분리하고 규모를 늘린다. 생성 시 원본 검색·조각 붙이기를 성공 대용으로 쓰지 않는다.

## Claude 의견에 대한 명시적 검토

최신 §7-1의 다섯 가설을 기준으로 한다.

1. **가운데 줄기 + DP 방향은 동의.** 다만 연결 위상을 틀리게 추출한 뒤 최소 곡선으로 맞추면 ‘매끈하게 틀린 선’이 된다. 잔가지 길이만으로 버리기, 고리마다 고정 4곡선, AC로 점 수 감소를 기대하기는 보완이 필요하다. 현재 fitter의 tol 예외 수락 조건도 놓치면 안 된다.
2. **LIVE와 ‘거의 같은 발상’은 부분만 맞다.** 점진적 중첩과 공동 최적화는 유사하지만, 어두운 넓은 층·밝은 좁은 층·의미 영역·반투명 합성이라는 사용자 제약은 별도로 필요하다. LIVE를 붙인다고 최적 층 수가 자동 결정되지는 않는다. 가려진 경계의 생략은 불투명/반투명에 따라 효과가 다르다.
3. **최신 갱신의 (24,24)·전 장 직접 그리기 정정에 동의한다.** 이전 앱 트위닝 중심안은 사용자 방식과 맞지 않았다. 영상 모델 결과도 가능한 입력이며, 이제 동일 ID·점 수보다 층/팔레트 일관성·flow 유효성·장당 복잡도를 우선해야 한다. 나카무라 효과는 분열·출현·소멸과 순간 교체를 허용해야 하며, 모든 프레임을 부드럽게 만드는 것이 목표는 아니다.
4. **LoRA 선생님 → 작은 SFA 모델은 좋은 장기 가설.** 그러나 ‘SDXL+LoRA는 휴대폰에서 무리’라는 전면 단정은 지나치다. 실제 Android SDXL 경로가 있고 생성 시간 제한도 없다. 반대로 공개 경로가 있다는 이유로 우리 LoCon/기기에서 실용적이라고 주장할 수도 없다. 먼저 자원·호환·품질을 측정해야 한다. 작은 모델은 검수 데이터·학습 성공 여부가 아직 큰 과제다.
5. **규칙 변환에 시간을 너무 썼다는 우려는 타당하다.** 여러 외부 기준선을 같은 입력에서 비교한 뒤, 부족한 제약만 구현해야 한다. 다만 SFA의 2차·굵기·층·시간 대응을 만족하는 얇은 변환/검증 계층은 남는다. 외부 도구가 이 전체 문제를 해결했다는 근거도 없다.

추가로 **색 문제를 저채도 비율 하나로 확정한 점, 인물 검정 칠하기를 학습 제외처럼 취급할 위험, 전체 화면 평균 채도로 효과색을 분류한 점**은 실질적으로 손볼 가치가 크다. 반대로 앱 형식·마스크·LoRA 형태 학습의 성과까지 무효로 볼 이유는 없다. 구조적 진전과 사용자가 아직 품질을 승인하지 않은 부분을 함께 기록해야 한다.

## 자료 검증 범위와 남은 불확실성

- 논문/공식 저장소/저자 블로그를 직접 검색·열람했다. [OmniSVG 커뮤니티 사용기](https://www.reddit.com/r/StableDiffusion/comments/1m61woy/omnisvg_weights_released/)에는 출력 실패 경험도 있지만 통제된 평가가 아니므로 모델 성능 결론의 근거로 삼지 않았다. ToonCrafter의 커뮤니티 메모리 개선도 공식 기본 구현의 보장치와 구분했다.
- 공식 Google Android image-generator 과거 문서는 검색되었으나 직접 열람에서 404가 나왔다. 현행 탑재 근거로 의존하지 않고, 실제 공개 코드가 확인되는 stable-diffusion.cpp를 우선 참조했다. 일부 PolyVector raw README 주소도 대소문자 때문에 실패하여 GitHub 본문/실제 `readme.md` 항목의 설명을 확인했다.
- 위 문헌의 벤치마크 수치는 저자 환경의 보고다. 우리 효과·앱·휴대폰에서의 시각 품질·메모리·속도는 미측정이다. 단일 이미지에서 원래 알파층과 가려진 구조를 유일하게 복구할 수 있다는 주장은 하지 않는다.
- 새 그림·영상·학습 자료·가중치·추출 곡선은 저장소에 추가하지 않았다. 향후 실험 결과도 비공개 Drive에 보관하고, 저장소에는 직접 작성한 도구·집계·보고서만 남긴다.
