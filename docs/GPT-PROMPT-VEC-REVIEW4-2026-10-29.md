## 복붙용 프롬프트

3차 반영본이자 본 학습 직전 최종본이야(사용자가 지금 RTX 5060 앞에서 실행 대기 중). 이번엔 **서버에 CPU PyTorch를 설치해서 실제로 끝까지 돌려 봤어.** 첨부 3개를 보고, 본 학습을 막을 문제가 남았는지만 짧게 판정해 줘.

### A. 3차 '꼭 고칠 것'
| 지적 | 처리 | 실행 확인 |
|---|---|---|
| 재생성 자료 혼합 | `vec_data` 시작 때 그 폴더의 옛 `.npz`·`.tmp`·`_done.json` 삭제. `_done.json`에 성공 파일 목록(`files`). 학습 `files_of()`와 건너뛰기 `done_ok()`(파일 존재 + 설정 + seed 대조)가 그 목록만 사용 | 일부러 넣은 옛 파일 삭제 확인, 표시만 있고 자료 없는 폴더 → False |
| 저장 실패와 최고 점수 | `save()`가 True일 때만 `st['best']` 갱신, `checkpoint()` 실패 기록 | (Windows 잠금은 서버에서 재현 불가) |
| 실제 GPU 확인·이어하기 시험 | 1050 Ti 확인에 이어하기 단계 추가. 사용자가 1050 Ti를 더 쓸 수 없어 **서버 CPU로 실제 실행** | 아래 B |
| 작은 것 | 검증 중 시간 확인, 올리기 스레드 join 후 살아 있으면 경고 | — |

### B. 서버 실제 실행(CPU, PyTorch 2.15)
- 자료: 60파일 × 1920·640, 성공 60/60씩.
- 짧은 시험: 종료 코드 0, 단계 1·4 실행, 자료 없는 단계 건너뜀, 손실 13항목 유한.
- 학습(`--hours 0.08`): 검증 2파일 `val_complete: true`, 단계 저장, best 없을 때 `best_fallback_last.pt`.
- 이어하기: 1회(`--hours 0.06 --plan-hours 0.2`) → `ckpt.pt` 상태 `progress 0.3047, step 18, plan 709.2, lr 0.001` → 2회 `--resume`: "이어서: 진행 30.5%, 18걸음", 끝난 단계 1 건너뛰고 단계 4에서 18→61걸음. 종료 0.
- **실행으로 찾은 버그(읽기로는 못 찾음):** 학습이 시간을 다 쓰고 끝나는 순간 검증이 시작되어 `out_of_time()`에 바로 걸림 → 마지막 단계의 마지막 검증이 거의 항상 미완료 → 마지막 모델이 최고 선택에서 빠짐. 고침: `reserve = min(300초, 실행 시간의 5%)`를 떼어 학습은 `out_of_time`(시간−reserve)까지, 검증은 `hard_stop`(시간)까지. 계획 시간도 reserve만큼 짧게.
- 서버에서 못 본 것: Windows 파일 잠금·경로, GPU 메모리·fp16, Drive 올리기. CPU라 마지막 단계 검증(40문제)은 짧은 시험 시간 안에 못 끝남 — GPU에선 수십 초 예상.

### C. Claude 최종 검토(5060 실행 흐름 따라가기)
bat은 실행마다 저장소를 새로 받음 → 최종본 사용. 자료: 시험용 37개 목록 대조·학습 352 assert·옛 파일 삭제·성공 목록만. 시간: 시작 시각 기준, 마지막 검증·저장 reserve + 마무리 6분. 학습: OOM → 조각 절반, Windows 잠금 → 재시도·건너뜀, 완전한 검증 + 저장 성공 때만 best. 이어하기: 서버 확인. 한글 출력: 1050 Ti 실행에서 정상. → 새로 고칠 것 없음으로 판단.
