# 2단계 설계 초안 — 실제 애니 → SFA → 학습 → 태그·자연어·스토리보드로 애니 만들기 (2026-11-02, 사용자 정정 반영판)

사용자 요청(11-02): "실제 애니를 스파로 변환하고, 그걸 어떻게 학습시켜서 태그(혹은 자연어)나 스토리보드를 넣어 애니를 만들게 하는가." 1단계(영상 한 장 → SFA 변환기) 본 학습 1회차가 도는 동안 쓴 **초안**이다. GPT 토론 → 사용자 결정 전까지 확정이 아니다.

## 사용자 정정(11-02) — 설계의 전제
1. **수집 SFA는 생성 학습의 주 재료가 아니다.** 이펙트·배경·인물 움직임 모두 **실제 애니를 SFA로 변환한 것**에서 배운다.
2. **인물은 기본적으로 스틱맨으로 바뀐다.**
3. **원하는 캐릭터 디자인을 넣으면 그 디자인을 입힐 수 있어야 한다.**

→ 수집 SFA의 역할은 ① 1단계 변환기의 정답지(지금 학습 중) ② SFA 문법·그리기 지식(스틱맨 본, 관절점 구조, 앱 규칙) ③ 평가 기준으로 한정한다. 동작·연출·이펙트·배경의 '내용'은 실제 애니에서 온다. (첫 초안의 '수집 SFA를 동작 1순위 자료로'는 철회.)

## 1. 실제 애니 → SFA 변환(학습 자료 공장)
장면 한 장을 세 갈래로 나눠 각각 다르게 옮긴다(AGENTS.md 인체 제외 원칙: 캐릭터 그림체는 배우지 않고 자리·상호작용만).
```
실제 애니 장
 ├─ 인물 영역 → 2D 포즈(관절 좌표) → 스틱맨 SFA(관절점 포함)      ← 그림체 버림, 움직임만
 ├─ 이펙트 영역 → 1단계 변환기 → SFA(선·면·글로우·투명도)          ← 형태·색·번짐을 배움
 └─ 배경 영역 → 1단계 변환기(또는 단순화) → SFA 배경 레이어
 + 카메라(전체 이동·확대) 추정 → 컷 정보
```
- **나누기**: 이펙트 분리 마스크(Kaggle v3, 이미 있음) + 인물 검출(포즈 모델의 사람 영역). 나머지 = 배경.
- **장 사이 잇기**: 스틱맨은 관절 번호가 고정이라 자동으로 이어진다. 이펙트·배경 오브젝트는 위치·모양 최근접 짝짓기로 ID를 이어 붙인다('2단계 추적').
- **자기 검사**: 변환한 SFA를 렌더러로 다시 그려 원래 장의 이펙트·배경 영역과 비교, 차이가 큰 장은 버린다(사람 손 없이 품질 거르기).
- **가장 큰 위험 — 영역 차이**: 1단계 변환기는 SFA 렌더 그림으로 배웠고 실제 애니는 손그림·질감·색이 다르다. 대책 후보: ① 1단계 학습 자료에 실제 애니 같은 늘리기(번짐·질감·색 흔들기) ② 선화 추출 전처리 ③ 자기 검사로 거르기. 1단계 1회차 결과가 나오면 실제 애니 20장으로 먼저 잰다(§5 P1).

## 2. 생성기 — 세 층
```
[입력] 태그 / 자연어 / 스토리보드 (+ 선택: 캐릭터 디자인)
  │ G1 연출 계획: 컷·길이·카메라·타이밍(T/F)·사건(착지, 섬광…)
  ▼
[컷 계획]
  │ G2 내용 생성: 스틱맨 뼈대 궤적 · 이펙트(형태 조각+색·글로우·투명도, 시간에 따른 변화) · 배경 · 카메라
  ▼
[장면 그래프] 장마다 뼈대 자세 + 이펙트 오브젝트 + 배경 + 카메라
  │ G3 SFA 조립: 뼈대 → 스틱맨(또는 입힌 캐릭터), 이펙트·배경 → SFA 오브젝트, 레이어·파란점 규칙
  ▼
[SFA 24/24]
```
- G2는 **실제 애니에서 변환한 SFA**로 배운다: 인물 → 스틱맨 궤적(태그 붙은 구간), 이펙트 → 생김·커짐·사라짐 과정, 배경 → 컷별 구성.
- 통짜(글 → SFA 문장 수만 단어) 대신 층을 나누는 이유: 층마다 자료가 충분하고, 사람이 컷 계획·뼈대 같은 중간 결과를 고칠 수 있다.

## 3. 캐릭터 디자인 입히기
- 기본 인물 = 스틱맨(관절점 구조). 생성은 항상 뼈대(관절 궤적)까지 만든다.
- 사용자가 캐릭터 디자인을 주면 G3에서 **뼈대에 디자인을 붙인다(리깅)**: 디자인의 부위(머리·몸통·팔·다리 조각)를 뼈대의 관절 사이에 묶고, 장마다 관절 각도대로 돌려 놓는다. 스틱파이터의 관절점(Flags 0x21)·포즈 도구와 같은 원리.
- 입력 형태 후보: ① **관절점이 있는 SFA 캐릭터**(가장 확실 — 앱 포즈 도구와 같은 구조) ② 캐릭터 그림 → 1단계 변환기로 SFA + 관절 위치 지정. ①부터.
- 이 때문에 **정답 문장에 관절점을 넣는 결정(P1)이 필요해진다**: 생성 SFA를 앱에서 포즈로 고치고, 캐릭터를 뼈대에 묶으려면 관절점이 있어야 한다.

## 4. 평가
- 기준 프롬프트 1(도시 착지)로 매번 끝까지 만들어 이전 결과와 비교(AGENTS.md).
- 자동: 동작 자연스러움(뼈 길이 유지·속도·가속 분포가 실제 애니 변환 궤적과 비슷한가), 이펙트 과정(생김→정점→사라짐 시간 분포가 나카무라 통계와 비슷한가), 태그 일치(GPT 판정), SFA 유효성(앱에서 열림·파란점 규칙·편집 가능).
- 최종: 사용자 눈. 숫자보다 영상 먼저.

## 5. 순서 제안
- **P0(지금)**: 이 초안 GPT 토론. 실제 애니 자료 목록(Drive)·태그 구간 수·이펙트 마스크 범위 재기. 인물 → 스틱맨 경로(포즈 → 스틱맨 SFA) 시험 설계.
- **P1(1단계 1회차 결과 뒤)**: 실제 애니 20장 변환 시험(영역 차이). 결과에 따라 1단계 2회차 전에 늘리기 추가 여부 결정.
- **P2**: 실제 애니 → SFA 자료 공장(나누기·변환·자기 검사·잇기) 첫 판 — 태그 붙은 구간부터.
- **P3**: G2 첫 판(인물: 태그 → 스틱맨 궤적 / 이펙트: 사건 → 과정) → G3 조립 → 영상으로 보여 드리기.
- **P4**: 연출 계획기 + 캐릭터 입히기 + 기준 프롬프트 1 끝까지.

## 6. 사용자 결정 필요
1. 관절점(Flags 0x21)을 정답 문장에 넣기(P1) — 캐릭터 입히기·앱 포즈 편집에 필요. Claude 권장: 넣음(1단계 2회차 전에 넣으면 판 11 자료가 필요).
2. 캐릭터 디자인 입력 형태: 관절점 있는 SFA부터 할지.
3. 실제 애니 자료 범위: §1-1 표대로(나카무라 뿌리 + nian41 뼈대 + 보충 3명). 시작은 나카무라·nian41부터(태그 많음) 할지.
4. 별도 경로(글 → 픽셀 영상 생성 → 변환)를 함께 조사할지.
