# 2단계 설계 초안 — 실제 애니 → SFA → 학습 → 태그·자연어·스토리보드로 애니 만들기 (2026-11-02)

사용자 요청(11-02): "실제 애니를 스파로 변환하고, 그걸 어떻게 학습시켜서 태그(혹은 자연어)나 스토리보드를 넣어 애니를 만들게 하는가." 1단계(영상 한 장 → SFA 변환기) 본 학습 1회차가 도는 동안 쓴 **초안**이다. GPT 토론 → 사용자 결정 전까지 확정이 아니다.

## 1. 실측(11-02, 수집 SFA 403파일, 이웃 장 21,525쌍)
- 장당 오브젝트 81.9개. **같은 ID로 다음 장에 이어지는 오브젝트 72.3%**, 새로 생기는 것 27.7%(이펙트·파편이 생겼다 사라짐), 장당 21.9개 사라짐.
- 이어진 오브젝트의 점 중 **62.3%가 움직인다**(24장/초로 모두 직접 그리므로 대부분 움직임).
- 해석: '첫 장 전체 + 다음 장은 바뀐 것만'으로 적어도 줄어드는 양은 크지 않다(움직이는 점이 많다). 대신 **ID가 이어진다는 정보 자체가 동작 학습의 핵심**(어느 선이 어디로 갔는가).

## 2. 큰 그림 — 세 층
```
[입력] 태그 / 자연어 / 스토리보드
   │  G1 연출 계획기: 컷 나누기·길이·카메라·타이밍(T/F)·사건(착지, 섬광…)
   ▼
[컷 계획] 컷마다: 등장 요소(스틱맨·이펙트·배경), 사건 시각, 카메라 움직임
   │  G2 동작·배치 생성기: 스틱맨 뼈대 궤적, 이펙트 사건(종류·자리·크기·시간), 카메라
   ▼
[장면 그래프] 장마다 뼈대 자세 + 이펙트 상태 + 카메라
   │  G3 그리기(SFA 조립): 뼈대 → 스틱맨 오브젝트(관절점 포함), 이펙트 → 포물선 조각+글로우·투명도 겹, 배경
   ▼
[SFA 24/24] → 렌더러로 영상 → 채점·사용자 판정
```
- 한 번에 '글 → SFA 문장 수만 단어'를 쓰는 통짜 모델은 자료(403파일)에 비해 너무 크다. 층을 나누면 층마다 자료가 충분하고, 사람이 중간 결과(컷 계획·뼈대)를 고칠 수 있다.

## 3. 자료 만들기(실제 애니 → SFA → 학습 자료)
1. **수집 SFA(변환 불필요, 먼저)**: 403파일에서 뼈대 궤적(관절점 있는 12파일 + 뼈대 추정), 이펙트 사건(생김·사라짐·크기 변화), 카메라(전체 이동) 추출. 태그는 GPT가 렌더 시트를 보고 붙인다(GPT 분담 원칙).
2. **실제 애니(변환기 사용)**: tag_index 구간(이미 태그 있음)을 장마다 변환기로 SFA로 → **다시 렌더해 원본 장과 비교(자기 검사)**, 차이가 작은 장만 쓴다. 이어진 장 사이의 오브젝트 짝은 '2단계 추적'(위치·모양 최근접 짝짓기)로 ID를 이어 붙인다.
   - 위험: 실제 애니 그림(손그림·색·질감)은 변환기가 배운 SFA 렌더와 다르다(영역 차이). 1단계 결과가 나오면 먼저 나카무라·nian41 20장으로 재 본다(§6 P1). 차이가 크면 ① 선화 추출 전처리 ② 실제 애니 같은 늘리기(번짐·질감·색 흔들기) ③ 변환 결과를 GPT·사용자가 고른 것만 쓰기.
   - 몸동작은 사용자 결정대로 3D 없이 2D(관절 궤적)만.
3. **태그·문장 묶기**: (구간 SFA, 태그 목록, 한 줄 설명, 스토리보드 조각) 짝. 설명 문장은 GPT가 쓰고 Claude가 표본 검사.

## 4. 생성기 후보
| 층 | 1안(권장 시작) | 2안 |
|---|---|---|
| G1 연출 계획 | 규칙 + 언어 모델(스토리보드 형식 JSON 채우기). 학습 없이 시작 가능 | 작은 모델을 컷 계획 짝으로 미세조정 |
| G2 동작 | 태그·컷 조건 → 뼈대 궤적을 쓰는 작은 트랜스포머(장마다 관절 좌표, 2D) | 확산 모델(궤적 전체를 한 번에) |
| G2 이펙트 | 사건(종류·자리·시작·길이) 생성 + 타이밍 통계(나카무라 T/F) | 같은 모델에 함께 |
| G3 그리기 | 규칙: 스틱맨 본(사용자 파일)·이펙트 형태 사전(포물선 조각)·글로우/투명도 겹 | 'SFA 문장 이어 쓰기' 모델(1단계 디코더를 장면 그래프 조건으로) |
- 별도 경로(보류 아님, 후보): 글 → 픽셀 영상(영상 생성 모델) → 1단계 변환기로 SFA. 품질은 높을 수 있으나 GPU가 크고 장마다 ID가 끊긴다.

## 5. 평가
- 기준 프롬프트 1(도시 착지)로 매번 끝까지 만들어 이전 결과와 비교(AGENTS.md).
- 자동: 렌더 영상의 동작 자연스러움(관절 길이 유지·속도 분포가 수집 SFA와 비슷한가), 태그 일치(GPT 판정), SFA 유효성(앱에서 열림·파란점 규칙·편집 가능).
- 최종: 사용자 눈. 숫자보다 영상 먼저.

## 6. 순서 제안
- **P0(지금, 학습 기다리는 동안)**: 이 초안 GPT 토론. 수집 SFA에서 뼈대·이펙트 사건·카메라 추출 범위 재기. 태그 붙일 클립 목록.
- **P1(1단계 1회차 결과 뒤)**: 실제 애니 20장 변환 시험(영역 차이 측정).
- **P2**: 스틱맨 동작 생성(태그 → 뼈대 → SFA) — 변환 없이 수집 SFA로 가능, 가장 빨리 영상으로 보여 줄 수 있는 것.
- **P3**: 이펙트 사건 생성 + 그리기.
- **P4**: 연출 계획기 + 기준 프롬프트 1 끝까지.

## 7. 사용자 결정 필요
1. 첫 목표를 P2(스틱맨 동작: 태그 → 동작)로 할지.
2. 태그 체계: 기존 tag_index 분류(동작·이펙트·임팩트·연출)를 그대로 쓸지, 스틱맨용 동작 단어 목록을 새로 정할지.
3. 별도 경로(픽셀 영상 생성 → 변환)를 지금 함께 조사할지.
