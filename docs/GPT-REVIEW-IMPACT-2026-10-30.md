## 4. 가장 큰 발전 — 틀린 결론을 바로잡음

- **전(2차 요청서)**: 작은 모델로 44장을 외우게 한 뒤 원래 위치에서 31%를 맞히자, "구조는 영상에서 위치를 읽는다"고 결론 냈다.
- **GPT 반론(2차 C2)**: "장면을 알아보고 외운 자세를 꺼내는 것과도 맞는 결과다. 알려진 이동으로 시험하라."
- **시험**: 같은 장면을 6% 옮기자 31% → 0%. GPT 반론이 맞았다.
- **후속(늘리기 사본 8벌로 다시 학습)**: 학습에 없던 이동에서 좌표 오차가 정상 영상 13.2% / 다른 영상 19.7% / 흰 화면 17.5%. 영상이 약하게나마 쓰이기 시작했다. 다만 생성 맞힘은 아직 0이다.
- **의미**: 이 반론이 없었다면 "구조는 됐다"는 잘못된 전제로 GPU 30시간을 썼을 것이다. 지금은 GPU 실행에 위치 시험을 붙여 이 문제를 직접 감시한다.

## 6. 아직 남은 것(정직하게)

- GPU 실제 실행은 아직 하지 않았다(Kaggle 주간 한도). GPU 메모리·속도·T4 설정은 미확인이다.
- 위치를 읽는 능력은 아직 약하다. GPU 학습에서 위치 시험 점수가 오르는지가 다음 판단 기준이다.
- sin 위치 신호의 효과는 판단 보류다. CPU 비교가 무효였다.
- (해결, 10-31) GPT 추가 검사 42개(1차 16·2차 16·3차 10) + 원래 시험 19개를 받았다. 사용자가 zip으로 전달했고, SHA-256 44개 파일이 모두 일치했다.
  - 당시 코드 사본에서: 61개 모두 이 서버에서도 재현된다(GPT 결과 확인).
  - 지금 코드에서: 결함을 재현하던 37개는 결함이 고쳐져 실패한다(정상). 원래부터 수정 확인용이던 3개는 통과한다. 2개(생성 채점 메모리 부족)는 3차 구조 변경으로 검사 쪽이 함수를 못 찾았다.
  - 우리 시험에 없던 9가지는 지금 코드의 올바른 기대값으로 옮겨 `tests/test_gpt_regressions.py`에 넣었고 모두 통과한다. 위 2개는 새 구조로 다시 써서 생성 채점 보호가 작동함을 확인했다. 전체 단위 시험은 57 → 66개.
