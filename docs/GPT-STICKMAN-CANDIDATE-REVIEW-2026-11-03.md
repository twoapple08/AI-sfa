## 공통 증상과 서로 다른 누락 원인

[파일·코드] `drawing_segments`는 이웃 장 유효 관절 이동 중앙값/몸통이 문턱을 넘을 때 새 키를 만든다. 결측 양옆 이동량이 NaN이면 경계를 만들지 않는다. 키 안 관측을 축별 평균으로 피팅하고 구간 중앙 시각에서 보간한다.

[원본 눈 판독, 사용자 미확정] 파랑 1036–1037과 1038–1039, 1086–1087과 1088–1089, 1251–1252와 1253–1254의 팔·다리 모양이 다른 그림으로 보인다. 1036의 뻗은 팔·1088의 내민 팔·1253–1254 발차기가 기존 출력에서 덜 드러난다. 관절 좌표의 해부학적 정답을 승인한 뜻은 아니다.

공통 증상은 **서로 다른 포즈가 한 평균 키에 합쳐지는 것**이다. 원인은 중앙값 문턱과 결측 경계 처리 두 갈래다. 위 대상 손목은 완전 관측(축 가중 1·1, 끝 0)이며 사슬 제거로 뺀 점이 아니다. 1253은 관측 0이며 복사값을 관측으로 세지 않았다. 1057–1059 도달 부족·1192–1199 가림과 같은 원인으로 합치지 않는다.

## 구현 — 경계 추가 선택 기능

- `tools/stickman_clip.py --key-start blue:1038 blue:1088 blue:1253`.
- `run_core`는 영상 장을 배열 위치로 바꾸고, `keypose_fit`은 자동 경계에 이를 추가한다. 기존 자동 경계·관측·리그·평활 세기는 바꾸지 않는다.
- 색·범위를 검사하고 요청/실제 적용 경계를 보고한다. 기본값은 추가 없음이다.
- 이 경계는 원본 판독을 시험하는 **진단값**이다. 확인 경계 JSON·기존 판정 JSON·학습 정답은 그대로다. 자동 분할 문제 전체의 해결 선언은 하지 않는다.
- 합성 반례: 몸통 등은 정지하고 오른팔 두 점만 바뀌면 이동 중앙값은 0이다. 경계를 추가한 두 키 중심에서 원래 팔을 복구하는지 검사했다. 범위 밖·소수 위치 거부도 확인했다.
- 단순 분위수 상향은 채택 안 했다. 75분위는 파랑 1088을 나누지만 1038은 여전히 놓쳤다(0.1778 < 자동 문턱 0.2328).

사용자 비교판은 파랑 넓은·먼 컷만 재생성했다. **빨강 전체·가까운 컷 AO는 Drive 저장본 그대로** 보존했다. 컷 안을 함께 보간하므로 경계 주변 외 장도 바뀐다. 개별 장 좌표 덧칠 방식은 아니다.

## 기준판 재현 차이

[CPU 계산] 입력 해시 일치, 컷별 재선택과 캐시 선택 차이 없음, 기존 보고와 키·보고 리그 길이도 같다. 그런데 현재 환경 재계산과 Drive 저장본은 다르다.

- 파랑 넓은/가까운/먼 컷 최대 차이: 9.49 / 27.13 / 0.00px.
- 빨강: 14.42 / 81.445 / 0.01px. 최대는 빨강 1148 머리 위 점이다.
- 현재 환경 버전은 JSON에 남겼다. 현재 환경에서 경계를 바꾸지 않은 컷의 두 계산은 일치했다. **과거 환경·수렴 차이는 추론이며 원인 확정이 아니다.** 과거 의존성 버전·종료 상태가 없어 지금 정확히 가를 수 없다.
- 저장 기준·동일 환경 기준·수정 효과를 구분했다. 가까운 컷 재계산·빨강 실험은 사용자 비교판에서 제외했다.
