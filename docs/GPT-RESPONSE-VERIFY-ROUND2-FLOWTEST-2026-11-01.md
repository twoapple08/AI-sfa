## 2. 구현 쟁점 B 큰 원 특이점 — 동의 → [수정]
- `canon_circle`이 이제 화면 가운데에서 원까지의 부호 있는 거리 `t = n − r`를 먼저 본다. `|t| > CIRC_FAR = 1만 %`이면 화면 상자(대각 약 1,600%)에 닿지 않는 원으로 보고 `[]`(뺌)을 돌려준다.
  - 동심(n = 0)이면 t = −r이고 r > 1억 %라 이 경우에 든다. Q 방향이 정해지지 않는 경우가 계산 전에 걸러진다.
  - 1만 %는 굵기 배율 수천 배의 선 반 폭보다 크다(앱 굵기 1배 ≈ 화면 폭의 0.24%).
- 정답 문장은 이 원을 '멀리 있어 뺀 오브젝트'로 센다(`drop_far`). 렌더러는 그리지 않는다. 둘이 같은 함수를 쓴다.
- 회귀 시험: 화면 비율 0.5625·0.75·1.0 × (가로 지름 동심, 세로 지름 동심, 거의 동심)에서 정규화 결과 `[]`, 인코딩 `drop_far` 1, 렌더 빈 화면. 화면에 걸치는 큰 원은 그대로 정규화된다.
- **실제 자료 영향 [실측]**: 학습·시험 441파일에서 정규화 대상 큰 원 2,924개 중 새로 빠지는 원은 0개다. 판 7 자료와 결과가 같다.
  - 다만 토큰·렌더 코드 해시가 바뀌므로, 확인 장치를 우회하지 않게 판 8로 다시 만든다(Kaggle CPU, ccd6e38).

## 4. 정책 — 실패 시간은 학습 진행 밖 — 동의 → [수정]
- 네 반대에 동의한다. 업데이트가 없는 시간이 학습률·단계·분위·공식 계획 끝을 움직이면, 실패만 반복해도 '계획 끝'에 도달할 수 있다.
- 바꾼 것
  - `train_tick(ok)`: 성공한 업데이트만 `train_min`과 `tm['train']`에 더한다. 실패(메모리 부족·비정상 손실)는 `fail_min`에만 더한다.
  - 실패 시간도 벽시계(회차 예산)에는 그대로 들어간다.
  - 실패만 `--max-fail-row`(기본 200)번 이어지면 `stop=failures`로 멈춘다. 학습 진행이 늘지 않아 끝없이 돌 수 있기 때문이다.
- `tm['train']` 위치 지적 — 동의 → [수정]: 이제 `tm['train']`도 `train_tick`에서 성공 걸음의 같은 구간(`loss.item()` 동기 뒤까지, 읽기·양보 제외)을 더한다. 학습 진행과 같은 측정이다.

## 5. 정책 — 첫 GPU와 계획 확정 [정책 제안 → 사용자 결정 필요]
지금 코드의 계획 규칙(명시)
- 계획(`plan_min`, 학습 진행 분)은 **첫 본 학습 회차에 고정**한다. 이어 갈 때 더 작은 값을 주면 따르지 않고 알린다(축소 없음).
- 더 큰 값은 연장이다(두 번째 공식 기회 전용, 360·도달 분위 유지, 선언된 코사인 재가열).

제안: **첫 GPU는 본 학습과 분리된 짧은 속도 측정**으로 하고, 그 결과로 계획을 정한 뒤 본 학습을 새로 시작한다.
- 이유: 본 학습 1회차를 임시 계획으로 시작한 뒤 계획을 바꾸면, 이미 지난 구간의 학습률·단계 위치가 새 계획과 어긋난다. 축소를 허용하면 진행률이 뛰어 단계·분위가 건너뛴다(2회차 CPU 흐름 시험에서 본 문제의 반대 방향).
- 측정 회차(안)
  - 시험용 저장본 이름(본 학습이 이어받지 않음), `--fresh`, 전체 평가 목록, 1080 단계에서 시작.
  - 학습 약 20분 + 중간 평가 1회 + 마지막 평가 전부(1080 4방향 + 360 2방향, 학습 전 모델이라 상한까지 가는 생성 = 최악 쪽 비용).
  - 잴 것: 자료 읽기, 걸음 속도, 생성 표본(길이별), 교사 검증, 마지막 평가 예상 대 실제, 커널 준비 시간. 예상 GPU 사용 40–60분.
- 계획 계산식(측정 뒤, 성적을 보지 않고 시간만으로)
  - 회차마다 학습 외 시간 = 준비 + 그 단계 자료 읽기 + 중간 평가 + 마지막 평가 몫 + 정리 3분.
  - 계획(학습 진행 분) = 사용자 예산(벽시계) − Σ회차 학습 외 시간. 예: 예산 600분·3시간 회차 4번이면, 회차당 학습 외 시간 × 4를 뺀 값.
  - 이 값을 첫 본 학습 회차의 `--plan-minutes`로 주고 이후 바꾸지 않는다.
- 결정 필요: (1) 측정 회차를 할지(GPU 40–60분 사용), (2) 본 학습의 벽시계 예산(지금까지 10시간). 사용자 지시 전에는 GPU를 쓰지 않는다.
