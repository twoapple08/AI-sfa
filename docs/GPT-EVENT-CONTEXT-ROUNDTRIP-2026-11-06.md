# 사건 문맥의 CPU 왕복과 기존 토큰 경로 소실 검사

## 결과

실제 애니에서 기록한 사건 JSON을 저장/복원하고, 구간을 자른 뒤 재결합해도 **출처·대상·관찰 단계·불확실성·미측정 null·학습준비 상태가 그대로 보존**됐다. 원본 장 대응을 따로 유지하는 작은 선택형 문맥 모듈 `tools/event_context.py`를 추가했다. 기존 생성기/토큰/컴파일러의 기본 호출에는 연결하지 않았다.

이것은 **기록을 운반하는 기능**의 검증이다. 신경망이 스미어 의미를 배운 것, 원본과 출력 장의 대응을 자동으로 맞춘 것, SFA에서 자연스럽게 보이는 것은 아직 검증하지 않았다. 모든 대응 상태는 `declared_only`다. 사건의 정확한 경계 미확정·training_ready=false도 그대로 유지했다.

## 사용한 근거와 합성 자료의 구분

- 실제 사건: `data/research/anime_smear_event_2026-11-06.json`. 승인 nian41 280544의 연속32장 판독 기록이다. 스타일/배치/타이밍의 근거는 이 애니 원본이다.
- 기록 통로: 사건 전체를 복사 보존하고 출력 장별 원본 인덱스를 별도로 운반한다. 새 미래 필드도 버리지 않으며 원본 기록을 지역 장 번호로 덮어쓰지 않는다. 대상 슬롯은 명시 바인딩이며 실제 인물 추적을 자동 검증한 값이 아니다.
- 기존 토큰 비교의 자세는 `motion_information_probe.synthetic()`의 **합성12장**이다. 실제 애니에서 관절을 추출한 것으로 취급하지 않는다. 의미상 사건 기록은 실제 자료지만 그 합성 자세가 실제 사건의 자세라고 주장하지 않는다.
- `4.sfa`는 표현 구조 참고일 뿐 이번 운반 시험의 배치/타이밍 정답이나 학습 자료로 사용하지 않았다.

## 구체적인 검사

|검사|관찰 결과|
|---|---|
|저장→복원|전체 문맥 값 동일. 출처/대상/불확실성/미측정 값/미확정 플래그 유지|
|원본1376~1407을 세 부분으로 자르고 재결합|32장 원본 대응과 사건 기록이 원래와 동일|
|지역14~19만 보기|원본1390~1395에 대응. 관찰 단계는 지역0~2,3,4~5로 계산. 원본 사건 범위 자체는 수정하지 않음|
|새 보간 장|명시 대응이 없으면 null. 같은 단계 사이에 있다고 자동 스미어 정답으로 채우지 않음|
|반복/역순|명시 출력→입력 인덱스로만 대응 변경 가능. 동작이 자연스럽다는 보장은 아님|
|잘못된 인덱스/다른 사건·대상 재결합|음수·범위 밖·비정수·bool 대응, 출처/대상 불일치 거부|
|잘못된 근거|NaN/Infinity·잘못된 구간·출처 지문 형식·임의 verified 상태 거부|
|기존 토큰 경로|같은 합성 자세에 실제 사건을 timeline에 추가해도 토큰 동일,decode의 timeline은 빈 목록|
|기존 토큰 시간 변경|합성12장→11장. 원래12장의 문맥을11장 출력에 그대로 붙이려 하면 바인딩 검사에서 거부|

즉 기존 경로가 사건을 전달하지 않는다는 사실은 그대로다. 이번 모듈은 그 문제를 숨기지 않고 **별도 보존 통로와 잘못된 연결을 검출하는 검사**를 마련했다. 기존 학습 토큰으로 문맥까지 전달되도록 고쳤다고 주장하지 않는다. 모델 입력에 사건을 어떻게 조건으로 줄지와 출력 표현은 후속 설계/검증이다.

장 수가 같고 슬롯이 존재해도 시간/의미 대응이 정확하다는 증거는 아니다. 현재 바인딩 검사는 길이와 대상 존재의 필요조건만 검사한다. 원본 FPS/PTS·리타이밍·원근/카메라 해석을 자동 정답으로 만들지 않는다. 이 단계는 하나의 사건/대상의 통로이며 서로 다른 사건·인물을 병합하는 기능은 아직 없다.

## 재현과 다음 단계

`python tools/event_context_probe.py --output data/research/event_context_probe_2026-11-06.json`

단위 검사는 `tests/test_event_context.py`. 결과 JSON에는 입력/도구 지문, 합성 여부, 왕복/소실/거부 결과를 기록한다. 원본·추출 이미지·윤곽/관절 좌표는 포함하지 않는다. 사건/기존 토큰/생산 코드·작가별 규칙은 바꾸지 않았다. GPU·새 모델 실행·학습 없음.

프로브 실행·입력/도구 SHA256·합성 분리·미확정 보존 확인 및 `git diff --check` 통과. 루트 `python -m unittest discover -s tests` **397개 OK·exit0(30.468초)**. 신규10개는 구간 대응·재결합·알 수 없는 장·오연결 거부 등 의미 있는 실패 조건을 검사한다.

다음은 이 보존 통로를 검토용 SFA 결과와 묶는 작은 비교다. 원본의 관측/추론 마디와 시각적 형태를 먼저 명시하고, 동일한 사건/시간 조건에서 신체의 투영 변화와 선택 표현층, 별도 궤적 후보가 의미를 유지하는지 비교한다. 정확한 형태/좌표가 아직 없으므로 고정 삼각형을 임의 정답으로 그리지 않는다. 새로운 표현 구조 채택 전에 결과와 앱 편집 확인이 필요하다. 권장 추론은 High다.
