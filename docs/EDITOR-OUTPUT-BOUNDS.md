# 편집 작업 공간과 실제 출력 범위 — 10_screen 검증

## 확인한 사실

사용자가 편집 화면1000326606.jpg, 영상 화면 캡처1000326608.jpg, 인코딩 영상1000326605.mp4, 프로젝트10_screen.sfa를 함께 제공했다.

- 편집 화면: 회색 작업 공간의 흰16:9사각형 위쪽에 스틱맨이 있으며 빨강/파랑 조작점과 UI가 보인다. 스틱맨은 흰 사각형 밖에 있다.
- 영상 화면 캡처: 흰16:9화면만 보이고 스틱맨은 없다. 세로 화면의 위·아래에 검정 여백이 있다.
- SFA: 원본5프레임, 매 프레임10AO/20AP의 기본 스틱맨이 저장돼 있다. 모든 프레임의 점 좌표 범위는 X 약63.0773–79.9523, Y 약−70.8491–−13.8491로 같다. 색은 검정, 글로우는0이고 배경은 흰색이다.
- 인코딩 영상:1920×1080,24FPS,5프레임,약0.208333초.64×36으로 축소 디코딩한5프레임의 모든 RGB는(253,253,253). 흰색 화면이며 스틱맨이나 검정 여백은 나타나지 않는다. 축소 검사는 원본 모든 픽셀의 정확한 동일성 주장과 구분한다.
- 영상 설정(T,P)은 이번 사용자 메시지에 별도 명시되지 않았다. 이전 작품의(24,12)를 이 실험에 적용하지 않는다.

## 이해한 관계

흰 사각형은 최종 출력 구도/화면 범위이고, 회색 영역을 포함한 편집 작업 공간은 그 밖의 오브젝트까지 다룰 수 있다. 네이티브 백분율 좌표 모델과 함께 보면 흰 영역은 X/Y0–100에 해당하고 음수Y는 위쪽이다. 이 사례의 스틱맨은 전체가 위쪽 밖에 있어 화면에 들어오지 않는다.

도형은 SFA에서 삭제된 것이 아니다. 편집 공간에서는 여전히 보이고 조작할 수 있지만 최종 출력 범위에서 제외된다. 편집 UI/조작점도 영상에 포함되지 않는다. 세로 캡처의 검정 위·아래 여백은16:9영상을 표시하는 화면의 여백이며, 이 인코딩 파일에 들어 있는 검정 배경이 아니다.

## 적용과 한계

예측은 프로젝트 전체의 저장 요소, 편집 공간의 표시, 최종 출력 화면의 표시를 구분해야 한다. 애니메이션 구도 평가는 흰 출력 사각형 기준으로 한다. 화면 밖에 있는 데이터를 임의로0–100에 clamp하거나 중앙으로 옮기면 구도와 진입 동작을 바꾼다.

현재 사례는 전프레임 화면 밖에 있고 글로우가 없는 스틱맨이다. 화면 경계를 걸치는 도형·부분 채우기·화면 밖 글로우의 안쪽 번짐, 편집 확대/팬의 정확한 변환은 아직 따로 확인해야 한다. 화면 밖이라는 이유만으로 모든 프로젝트에서 도형을 안전하게 삭제할 수 있다고 결론내리지 않는다.

이 사례를 이전 복잡한 작품의 모든 오예측 원인으로 소급 확정하지 않는다. 원본/영상/캡처는 공개 저장소에 게시하지 않고 관찰만 기록한다.
