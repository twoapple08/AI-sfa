# 기준 렌더러 v0 — 2026-10-16

- `sfa_render.py`는 SFA 프레임을 그림으로 그리는 기준 렌더러다.
- 정적 AOT 해석과 [APP-R1](APP-R1-RENDER-REFERENCE-PROTOCOL-2026-10-16.md) 실측으로 만든 **근사 구현**이며, 앱 렌더러의 복제가 아니다.
- 앱 출력과의 오차를 측정해 함께 기록한다.
- numpy가 필요하다(작성 당시 저장소의 다른 도구는 표준 라이브러리만 썼다).

```bash
python sfa_render.py 프로젝트.sfa 프레임번호 출력.png [--size 1920x1080]
python tools/compare_render.py 프로젝트.sfa 앱영상.mp4 7 19 31 --json 결과.json
```

## 구현한 규칙과 근거

| 규칙 | 근거 |
|---|---|
| 좌표: 가로 여백 P=10.52px(1920 기준), 사용 폭 W−2P, 높이=폭×9/16, 화면 중앙 정렬, 원점 +0.19/+0.08px | APP-R1 색 견본 48개 변의 서브픽셀 회귀(x 잔차 RMS 0.34px, y 0.19px) |
| 배경: Frame.BackgroundColor로 화면 전체를 칠함. 여백 영역의 화면 밖 도형도 그림 | APP-R1 경계 장면 |
| 선/곡선/원 심지: 둥근 끝, 폭 = 9.0px × ThicknessScale × (시퀀스 굵기/100) × (출력 높이 비율), 거리장 안티에일리어싱 | 선 굵기 장면에 맞춤(MAE 0.17) |
| 원: 두 점의 중점이 중심, 두 점 거리/2가 반지름(픽셀 공간에서 등방성) | 정적 circle branch, APP-R1 원 장면 |
| 곡선: 이차 Bézier P0,P1,P2 | 정적 CURVE-RING, APP-R1 |
| glow σ = √((GlowRadius)² + 0.29²) px, 띠 폭 W = 0.78 × GlowThickness px, 색=GlowColor, 불투명도=GlowAlpha | 정적 sigma 식. 계수는 glow 장면에 맞춤 |
| 직선 glow = 몸통(축 방향 erf × 횡 방향 band) + 양 끝 반원 cap의 Gaussian 적분(16-node Gauss–Legendre). 원·곡선 glow는 거리장 band 근사 | 정적 shader body/반원 적분 구조. 끝 단면이 실측과 약 5 이내 |
| 그리기 순서: LayerDef 목록 순서(앞이 아래, 숨긴 레이어 제외) → 레이어 안 묶음(AC 연결+그룹 부모의 연결 묶음, 레이어마다 분리) → 묶음마다 모든 glow → 구성원 순서대로 [가져간 채우기 → 본체]. glow 띠 폭 = 0.78×GlowThickness×객체 ThicknessScale×선굵기% | APP-R1 그룹 장면, [사용자 작품 1](USER-ARTWORK-1-RENDER-CHECK-2026-10-16.md), 정적 0x42c53c |
| 선 폭 = round(9×ThicknessScale×선굵기%/100) 정수 px. 선 굵기 설정은 glow σ·폭에도 곱함. 여백 P는 선 굵기의 함수(가설식) | APP-R1 100%/50% |
| 채우기: FS segment(직선/곡선의 StartT–EndT 구간, Kind1 원)로 다각형을 만들고 even-odd, 3×3 supersampling, src-over 합성. **채우기는 첫 outer 객체의 레이어에서, 그 레이어 outer 객체 중 그리기 순서상 첫 구성원이 가져가 그 본체 바로 앞에 그림.** 현재 `sfa_render.py`가 이 규칙을 따른다. 변경 이력: v0 초안은 가장 큰 DrawOrder 객체 앞 → APP-T1에서 틀림 → 가장 작은 DrawOrder 객체 unit 앞(테두리 선 전부가 위) → [DRAW-PLAN-GROUPS](AOT-DRAW-PLAN-GROUPS-TRACE-2026-10-16.md) 정적 확인으로 현재 규칙 | APP-R1 채우기 장면(src-over 1 이내), APP-T1, 사용자 작품 1, DRAW-PLAN-GROUPS |
| 숨긴 레이어(LayerDef Visible=false)의 객체는 그리지 않음 | APP-T1 |

## 앱 출력과의 오차 (APP-R1, 1920×1080, 각 장면 7번째 프레임)

| 장면 | MAE | 99퍼센타일 채널 오차 |
|---|---:|---:|
| 색 견본 | 0.33 | 6 |
| 선 | 0.17 | 1 |
| 원 | 0.11 | 0 |
| 곡선 | 0.05 | 0 |
| glow 선 | 0.76 | 12 |
| glow 원·곡선·점 | 0.26 | 4 |
| 그룹 glow | 0.30 | 4 |
| 채우기 겹침 | 0.30 | 2 |
| 화면 경계 | 0.09 | 2 |

- 집계는 [메트릭](RENDERER-V0-APP-R1-METRICS-2026-10-16.json)에 있다.
- 최대 오차가 큰 픽셀의 원인: 색이 바뀌는 가장자리의 4:2:0 색차 축소, 서브픽셀 차이, glow 모델 잔차.
- 같은 장면을 렌더러 계수 맞춤에도 썼으므로, **이 수치는 학습 오차에 가깝다. 새 장면에서의 일반화 오차는 아직 측정하지 않았다.**

## 정정

- APP-R1 결과에서 "여백 P가 DrawInformation 식과 같은 구조"라고 썼다.
- 그러나 정적 식을 정확히 1920×1080 캔버스에 적용하면 높이 제한 분기(높이 1080−2P)가 된다.
- 실측은 **중앙 기준 균일 축소**(세로 여백 ≈ P×9/16)다. 따라서 export 캔버스의 실제 크기나 P의 적용 방식이 그 가정과 다르다.
- 렌더러는 실측을 따른다.
