# 기준 렌더러 v0 — 2026-10-16

`sfa_render.py`는 SFA 프레임을 그림으로 그리는 기준 렌더러다. 정적 AOT 해석과 [APP-R1](APP-R1-RENDER-REFERENCE-PROTOCOL-2026-10-16.md) 실측으로 만든 **근사 구현**이며, 앱 렌더러의 복제가 아니다. 앱 출력과의 오차를 측정해 함께 기록한다. numpy가 필요하다(저장소의 다른 도구는 계속 표준 라이브러리만 쓴다).

```bash
python sfa_render.py 프로젝트.sfa 프레임번호 출력.png [--size 1920x1080]
python tools/compare_render.py 프로젝트.sfa 앱영상.mp4 7 19 31 --json 결과.json
```

## 구현한 규칙과 근거

| 규칙 | 근거 |
|---|---|
| 좌표: 가로 여백 P=10.52px(1920 기준), 사용 폭 W−2P, 높이=폭×9/16, 화면 중앙 정렬, 원점 +0.19/+0.08px | APP-R1 색 견본 48개 변의 서브픽셀 회귀(x 잔차 RMS 0.34px, y 0.19px) |
| 배경: Frame.BackgroundColor로 화면 전체를 칠함. 여백 영역의 화면 밖 도형도 그림 | APP-R1 경계 장면 |
| 선/곡선/원 심지: 둥근 끝, 폭 = 9.0px × ThicknessScale × (시퀀스 굵기/100) × (출력 높이 비율), 거리장 안티에일리어싱 | 선 굵기 장면에 맞춤(MAE 0.17) |
| 원: 두 점의 중점이 중심, 두 점 거리/2가 반지름(픽셀 공간에서 등방성) | 정적 circle branch, APP-R1 원 장면 |
| 곡선: 이차 Bézier P0,P1,P2 | 정적 CURVE-RING, APP-R1 |
| glow σ = √((GlowRadius)² + 0.29²) px, 띠 폭 W = 0.78 × GlowThickness px, 색=GlowColor, 불투명도=GlowAlpha | 정적 sigma 식. 계수는 glow 장면에 맞춤 |
| 직선 glow = 몸통(축 방향 erf × 횡 방향 band) + 양 끝 반원 cap의 Gaussian 적분(16-node Gauss–Legendre). 원·곡선 glow는 거리장 band 근사 | 정적 shader body/반원 적분 구조. 끝 단면이 실측과 약 5 이내 |
| 그리기 순서: DrawOrder 순. 독립 객체는 glow→심지. **그룹(그룹 Flags로 연결된 AO)은 모든 glow 다음에 모든 심지** | APP-R1 그룹 장면 |
| 채우기: FS segment(직선/곡선의 StartT–EndT 구간, Kind1 원)로 다각형을 만들고 even-odd, 3×3 supersampling, src-over 합성. 참조 AO 중 DrawOrder가 가장 큰 객체의 unit 바로 앞에 그림 | APP-R1 채우기 장면(src-over 1 이내) |

## 앱 출력과의 오차 (APP-R1, 1920×1080, 각 장면 7번째 프레임)

| 장면 | MAE | 99퍼센타일 채널 오차 |
|---|---:|---:|
| 색 견본 | 0.33 | 6 |
| 선 | 0.17 | 1 |
| 원 | 0.11 | 0 |
| 곡선 | 0.05 | 0 |
| glow 선 | 0.76 | 12 |
| glow 원·곡선·점 | 0.26 | 4 |
| 그룹 glow | 0.30 | 4 |
| 채우기 겹침 | 0.30 | 2 |
| 화면 경계 | 0.09 | 2 |

집계는 [메트릭](RENDERER-V0-APP-R1-METRICS-2026-10-16.json)에 있다. 최대 오차가 큰 픽셀은 색이 바뀌는 가장자리의 4:2:0 색차 축소, 서브픽셀 차이, glow 모델 잔차에서 나온다. 같은 장면을 렌더러 계수 맞춤에도 썼으므로, **이 수치는 학습 오차에 가깝다. 새 장면에서의 일반화 오차는 아직 측정하지 않았다.**

## 정정

APP-R1 결과에서 “여백 P가 DrawInformation 식과 같은 구조”라고 썼다. 그러나 정적 식을 정확히 1920×1080 캔버스에 적용하면 높이 제한 분기(높이 1080−2P)가 된다. 실측은 **중앙 기준 균일 축소**(세로 여백 ≈ P×9/16)다. 따라서 export 캔버스의 실제 크기나 P의 적용 방식이 그 가정과 다르다. 렌더러는 실측을 따른다.

## 아직 없는 것

- 보간(트위닝): 현재는 저장된 프레임만 그린다. FPS (트위닝, 재생) 시간축과 보간 규칙 구현이 다음 단계다.
- 곡선·원 glow의 정확한 shader 적분, 겹친 glow의 합성 방식 실측, 구멍·복잡 contour·T 부분 경계, layer 가시성, ObjectScale, 시퀀스 굵기 설정값의 SFA 저장 위치.
- backend별 차이, 다른 해상도·DPR에서의 검증.
