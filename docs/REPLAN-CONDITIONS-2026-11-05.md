## A. 확정 조건

### 목적·범위
1. **액션물**을 만든다(귀여운 디자인·카툰이 아님).
2. **창작 도구**: 사용자 고유의 캐릭터 디자인·능력을 표현한다.
3. **스틱파이터 (24, 24)** 로 제작(1초 24장 모두 그림, 앱 트위닝 없음).

### 화풍·캐릭터
4. 수집한 애니메이터 스타일을 **전부 섞어 하나의 스타일**로. 생성할 때 작가를 고르지 않는다.
5. **캐릭터 그림체는 제외**(작품 고유의 색). 캐릭터는 **움직임만 추출해 스틱맨화**.
6. 그 스타일을 **사용자가 원하는 연출(분위기·느낌·구도)에 적용**. 필요하면 연출 내용용 자료를 추가 수집(출처·용도는 수집 전 사용자 확인).
7. 상황에 따라 **실제 손·팔·다리·몸통·머리·머리카락·얼굴·옷**을 그릴 수 있어야 한다.
8. 수집 SFA 속 **남의 캐릭터 그림은 학습하지 않는다**(스타일이 제각각이라 파편화). 실제 신체를 그리는 방식은 나중에 따로 정한다.
9. 인물 묘사 후보: **사용자 그림체 LoRA**(Illustrious-XL v1.0 바탕 LoCon dim 32, 466장, 상반신·초상·채색 위주; 비공개). 전신 액션 포즈·선화 출력에서 그림체 유지는 시험 대상.

### 생성 입력(네 칸)
10. ① **캐릭터 시트**: 양식 파일(`data/templates/character_sheet_v2.sfa`) + 설명 글(`character_sheet_v2_설명양식.txt`). 액세서리 포함.
11. ② **능력**: 글 설명(예: "붉은 가시를 바닥에서 솟게 하는 능력").
12. ③ **무기**: 무기 파일 — 1장 = 각 부위를 설명하는 확대판, 2장 = 스틱맨이 잡는 법·크기. 생성기는 그리지 않고 손목 위치·각도만 정하는 **부품**. 각도는 한 각도 그림을 돌리기·늘이기로 근사, 어색한 무기만 옆면 추가.
13. ④ **장면 내용**: 글 · 태그(debris, dust, wind 등) · 시간 구간 문장("1~3초 걸어감, 이 구도로") · 스토리보드 · 레퍼런스 · 음악 · 앞 장면 파일.

### 조건 다루기
14. **부정 프롬프트 두 겹**: ① 조건 반대 방향 유도 ② SFA 문법 단계에서 해당 라벨 요소 생성 금지.
15. **자율 보강**: 긍정 프롬프트에 없어도 부정 프롬프트에 없으면 어울리는 요소·연출을 스스로 넣는다. **보강 정도는 사람이 조절**(0 = 쓴 것만). 부정 프롬프트가 항상 우선.
16. **자료에 태그·시간 구간 설명을 붙이는 작업이 핵심 갈래**(GPT 태깅 + Claude 검수).

### 이펙트(나중 단계)
17. **직선·곡선 조각을 모두** 쓴다. 기본 도형(원 등)은 필요 없다.
18. **면적·선 두께를 자유자재로** 조절해 밀도 있고 디테일하게.
19. 반투명 여러 겹·글로우, 그림 과정 선 → 밑색 → 명암.

### 배경
20. **3D로 공간**을 짠다(프롬프트 / 3D 모델 / 여러 이미지) → **카메라 무빙**으로 촬영 → SFA로 **윤곽선 + 밑색**, 그림자·명암은 선택.
21. 고정 구도에서 상하좌우 이동·확대만 있으면 배경을 한 번 그리고 **위치·크기만 옮긴다**.
22. **거리에 따른 윤곽선 두께 필수** — X·Y축은 선, **Z축은 면**. 구조물은 넣고 사물은 뺀다.
23. **배경에 영향을 주는 요소**(파손·파편·먼지·균열) 반영.

### 이어 만들기·음악
24. **앞 장면 파일에서 이어 만들기**(장면 전환 포함).
25. 구도가 바뀌어도 **배경 상태·위치·사물이 같아야** 한다(하나의 3D 공간에 상태 기록).
26. 마지막 장만이 아니라 **앞 파일 전체를 읽어 템포**를 맞춘다.
27. **음악 맞춤**: 빌드업·하이라이트·정적인 부분·박자.

### 학습 방식
28. **거대 사전학습 모델 위에서 시작**(글·그림 이해), **정지 → 움직임 2단계** 학습.
29. 스타일 세 겹: ① 움직임 학습 = 애니메이터 자료 ② 내용 참고용 자료는 안 보이는 표시로 구분, 생성은 항상 '우리 스타일' ③ 잴 수 있는 스타일 특징(유지 리듬·예비 동작·타격 멈춤·속도 곡선·카메라 흔들림)으로 학습 목표·생성 후 보정.

### 첫 단계
30. **이펙트 없는 일반적인 움직임만** 먼저(관절 + 타이밍).
31. 스미어가 나는 장의 그 부위는 **그리지 않고 비워 둔다**(관절 위치 + '스미어로 대체' 표시). 나중에 스미어를 배워 합친다.

### 캐릭터 시트 양식(완성, `data/templates/`)
32. 한 장, 칸 7개: 위 줄 정면·반측면·우측·좌측·후면(똑바로, 같은 키), 아래 줄 위·아래(비스듬 허용, 각도는 설명 글).
33. 정수리선·발바닥선·칸별 가운데선.
34. 레이어: 1번 **시트지 템플릿**(맨 위, 잠김) · 2번 **캐릭터 디자인**(바로 아래). 그 방향에서 안 보이는 부분은 그리지 않는다.

### 환경·제약
35. GPU = **Kaggle**(계정당 주 30시간, 한 세션 최대 12시간). 사용자 PC GTX 1050 Ti.
36. 사용자 시간은 충분, **제약은 Claude 사용량**(Pro 계정 2개 교대) → 결정·진행은 문서로, 반복은 스크립트로, 대량 눈 판정은 GPT로, 확인 고리는 짧게.
37. **지금은 계획 단계** — 시험·실행은 계획 확정 후.

## B. 유지하는 고정 규칙
- 애니메이터별 학습 범위(AGENTS.md): 나카무라 = 이펙트·배경·연출·타격 타이밍 / nian41 = 몸 뼈대 움직임 / riooo·optical-core·yukina_kosaka = 이펙트·연출(인체 제외).
- 스틱맨: 앱 연결 유지·포즈 편집 가능, 고정 뼈대(`profiles/stickman_2d_v1.json`)와 장면 데이터 분리, 거리 굵기, 가까운 팔다리 연속 면.
- SFA: 점 ID는 장마다 새로, 오브젝트 ID는 같은 대상이면 모든 장에서 같게, ID마다 레이어·종류 하나, 레이어 순서 모든 장 공유.
- 자료: 영상 원본·추출 프레임·LoRA·음악 파일은 공개 저장소에 넣지 않는다. 수집 SFA는 공유 동의로 보관.
- 3D: 캐릭터 동작 학습에는 3D 동작 모델을 쓰지 않는다. 배경에는 쓴다.
