## 2. 1단계 — 자료 수집 (먼저 한다)

Sakugabooru 밖까지 포함해, yutaka_nakamura가 그렸다고 **증명되는** 자료를 모두 찾는다.

- 찾을 곳 예: Sakugabooru(`https://www.sakugabooru.com/post?tags=yutaka_nakamura`, 공개 게시물 368개 확인됨), 作画@wiki(atwiki), seesaawiki 스태프 DB, 공식 사이트·공식 SNS 스태프 코멘트, 인터뷰 기사, 원화집·설정집·블루레이 해설, 크레딧 DB(MyAnimeList, AniDB, ANN, AniList, bangumi), 본인 SNS가 있으면 그것, YouTube·Bilibili의 공식/본인 업로드.
- 증명 등급:

| 등급 | 뜻 |
|---|---|
| A 본인 게시 | 본인이 직접 담당을 밝힌 자료(본인 SNS·본인 인터뷰 발언) |
| B 공식·DB 크레딧 | 회차 크레딧, 제작사·감독의 공식 언급, 크레딧 DB |
| C 커뮤니티 태그 | Sakugabooru 등 태그 |
| D 팬 귀속 | 팬 편집·팬 게시물 |

- 특히 찾을 것: **같은 회차 안에서 어느 컷이 yutaka_nakamura인지** 밝힌 A·B 자료. Sakugabooru `presumed`(추정) 61개를 확정하거나 반박하는 자료는 따로 표시한다.
- 출력: CSV 한 표(UTF-8). 열 이름은 정확히 아래와 같다.

```
site,url,kind,work,proof_level,effects_use,note
```

  - `effects_use`: 이펙트·배경·연출 학습에 쓸 수 있는지(최우선/보조/참고/-).
  - `note`: 어느 장면·컷인지, 출처 문장 요약, 확인 못 한 점. 모르는 것은 "미확인".
  - 끝에 찾아본 사이트 목록(찾았음/없음/접속 불가)을 붙인다.

## 3. 2단계 — 분석 (수집 뒤)

1. 출발 자료: Google Drive `AI-sfa/02_분석자료/`의 30클립(`GPT_작업목록_2026-10-17.csv`, 클립마다 `<post_id>/contact_sheet.jpg`, `<post_id>/timing.json`). contact sheet는 클립 전체에서 고르게 뽑은 그림 최대 64장이다(8열, 시간순).
2. 그다음 1단계에서 찾은 A·B 등급 자료 중 위 28개·30개에 없는 것.
3. 클립마다 관찰 한 줄(JSON Lines):

```json
{"post": 123456, "artist": "yutaka_nakamura", "work": "작품명 회차", "proof_level": "C", "timing_note": "2s는 기 모으기 구간, 나머지 1s [추론]", "effects": ["번개: 꺾인 청백 폴리라인 + 흰 core, 매 프레임 경로 변경"], "direction": ["흰 전면 플래시 1장 후 검은 1장"], "background": ["강한 원근의 벽면을 훑는 배경 작화"], "sfa": ["번개=연결 직선 + glow, 매 프레임 새 경로"], "confidence_note": "작은 타일이라 파편 모양 불확실", "evidence": "GPT 시각 판독 [추론]"}
```

4. 끝에 새로 보인 이펙트 어휘·연출 규칙 후보를 최대 10개 요약한다. 후보마다 근거 post_id를 2개 이상 붙이고, 1개뿐이면 '단일 표본'이라고 쓴다.

## 4. 공통 규칙

- 앱 재료: 직선, 원, 곡선, 닫힌 영역 채우기(FR), glow, 투명도, 색, 선 굵기, 레이어·그리기 순서, 프레임 배경색. 카메라·블러·그라데이션·촬영 발광은 앱에 없다. FPS 표기는 (트위닝 fps, 재생 fps).
- 근거 표시: 수치를 옮길 때만 [실측], 보고 판단한 것은 [추론]. 확정 규칙처럼 쓰지 않는다.
- 영상·이미지 원본을 공개된 곳(GitHub 등)에 올리지 않는다. 원본을 Drive `01_원본영상`에 넣는 일은 Claude 쪽 서버가 맡으니, GPT는 **링크와 메타데이터만** 모은다.
- 로그인 차단·접근 제한을 우회하지 않는다. 토큰·키를 출력하지 않는다.
