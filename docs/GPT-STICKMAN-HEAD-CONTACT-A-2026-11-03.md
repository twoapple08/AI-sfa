사용자가 A “머리 최소 이동”을 선택했다. 기존 몸통·팔다리와 머리 지름을 유지하면서, 원이 몸통 허브에서 떨어진 때만 접촉할 만큼 중심을 옮겼다. 일반 전 부위 튐 점검·Kaggle 추가 학습은 이번 범위에 포함하지 않았다.

## 접촉과 편집 구조를 구분한다

[파일·코드/기하] 머리 원의 중심 C, 반지름 r, 몸통 허브 N에 대해 `d=|N-C|`가 r보다 클 때만 `C ← C+(N-C)×(d-r)/d`로 이동한다. 원이 이미 허브를 덮는 숙임은 그대로다. 관측 보간을 끝낸 다음 이 조건을 적용한다.

**화면의 긴 목선은 없앴지만, 파일 내부의 연결 객체11은 남겼다.** 두 지름 끝점으로 정하는 SFA 원의 표면과, 원 내부에 들어간 몸통 허브는 같은 좌표가 될 수 없다. 원 크기·겹친 머리 중심·몸통을 모두 유지하며 직접 점 공유를 강제하는 것은 불가능하다. A안의 숙임과 몸통을 유지하기 위해 내부 연결을 쓴다. 접촉 시트의 A안에도 이 객체가 남아 있음을 선택 질문에서 명시했다.

내부 연결선은 투명 처리했다. 처음에는 인물색 선을 흰 원으로 가렸으나, 렌더 대조에서 원 가장자리 안티앨리어싱에 몇 픽셀 비치는 경우가 있었다. 투명 처리 후에는 연결선을 완전히 제거한 참조 그림과 240장 모두 픽셀 단위로 같다. 이것은 실제 앱의 편집 동작까지 검증했다는 뜻이 아니다.

## 구현

- `tools/stickman_projection.py`: `constrain_head_contact` 추가. 기존 얼굴 관측 중심·원 지름 계산 뒤 최소 이동을 적용하고, 이동 장 수·최대 이동량을 보고한다. 추가 평활이나 장별 예외는 넣지 않았다.
- `tools/stickman_clip.py`: 캐시 좌표를 받는 `person_aos` 호출에도 같은 조건을 적용한다. 입력 좌표 사전은 수정하지 않는다. 내부 객체11만 색0, 머리는 흰 내부·인물색 윤곽이다. 일반 고정 머리 모드는 유지한다.
- `tests/test_stickman_projection.py`: 떨어진 원의 최소 이동·지름·입력 불변·연결 일치, 이미 겹친 숙임 보존, 접촉 경계 전후 연속성, 투명 객체가11번 하나뿐인지 검사한다.

전달 SFA는 **직전 실제 전달 파일 `neck_visible.sfa`의 최소 수정**으로 만들었다. 원본 RTMW 재선택·리그 재피팅은 하지 않았다. 파이프라인을 다시 피팅하면서 다른 부위까지 바뀌는 혼동을 피했다. 실제 새 `person_aos`에 같은 저장 좌표를 넣은 결과가 467회 인물 등장 모두 전달 XML과 완전히 일치함을 별도로 검사했다.

## 머리 시간축 확인과 남은 범위

[CPU 계산] 새 머리 제약의 영향만 확인했다. 컷1136·1234와 등장/퇴장 경계를 제외한461개 인접 비교에서 머리 중심 이동량95분위는71.25→71.77px, 반지름으로 나눈 최대 이동량은4.535→4.535로 같다. 한 프레임 이동 증가 최대는 빨강1214의21.63→29.54px(+7.91px)다. 다음은 빨강1162(+7.86px),1067(+6.32px),1114(+6.12px)다.

접촉 경계에서 보정량 자체는 연속이지만, 이 수치가 “움직임 문제 없음”의 합격선은 아니다. 몸통 허브를 따라 머리를 옮기므로 일부 장의 이동량은 늘 수 있다. 임의 평활을 더하면 사용자 승인 최소 이동 A안과 달라지므로 넣지 않았다. 영상과 전체 시트로 확인할 수 있다. 기존 팔다리 튐을 해결하거나 전 부위를 재검토한 것으로 세지 않는다.
