## 1차 — Claude 의견(11-02 밤, GPT 답을 보기 전에 씀)

### 1. 문제 분해
아래 일곱 단계로 나누고, 단계마다 따로 실패를 잰다. 지난번에는 여러 단계의 실패가 겹쳐서, 무엇이 어색함을 만들었는지 가를 수 없었다.

| 단계 | 하는 일 | 애니라서 생기는 문제 |
|---|---|---|
| ① 컷·인물 찾기 | 컷을 나누고, 인물을 찾아 장면 내내 같은 사람으로 추적 | 실사 검출기는 그림체에서 놓친다(YOLO11m nian41 0–39%). 컷이 짧고 카메라가 이동한다. |
| ② 타이밍 | 그림이 바뀌는 장과 정지(2·3장 단위)를 찾는다 | 매 장 추정 + 평활을 하면 정지가 뭉개진다. |
| ③ 2D 자세 | 보이는 관절 위치와 신뢰도 | 과장 비율, 스미어·잔상, 단순화된 손발 |
| ④ 가림·원근 | 가려진 팔다리, 몸 돌리기, 단축 | 평면 정보만으로는 풀 수 없다. 사전지식이 필요하다. |
| ⑤ 스틱맨 연출 | 원본 카메라로 투영할지, 스틱맨식으로 다시 연출할지 | 무엇이 '자연스러운' 스틱맨 움직임인지 아직 정의되지 않았다. |
| ⑥ 앱 파일 | 10조각 구조, 점 ID를 장마다 새로 | 해결됨(304개 전수 조사) |
| ⑦ 평가 | 숫자 + 사용자 눈 판정 | 정답 자료가 없다. |

### 2. 핵심 관찰(가설 포함)
- **(가설) 어색함의 큰 원인 하나는 타이밍일 수 있다.** 애니는 2·3장 단위로 그림을 바꾸고, 그 사이에는 정확히 멈춘다. 그림이 바뀌는 순간은 인물 영역의 픽셀 차이로 자세 모델과 상관없이 정확히 잴 수 있다. 매 장 추정한 뒤 평활하면 '멈춤 → 확 바뀜'이 '계속 조금씩 흔들림'으로 바뀌어 둥둥 뜨는 느낌이 날 수 있다.
  - 확인 방법: 원본에서 그림이 바뀐 장의 집합과 스틱맨 각도가 바뀐 장의 집합을 비교한다.
- **가림과 몸 돌리기는 보이는 2D 위치를 베끼는 것만으로는 풀리지 않는다.** 보이지 않는 팔은 사전지식으로 메워야 한다. 그 사전은 여러 형태가 가능하다.
  - 3D 사람 모델(몸 모델 + 동작 사전)
  - 2D 동작 사전(스틱맨 SFA나 2D 포즈 자료에서 배운 자세·움직임 분포)
  - 키포즈 재연출(가려진 구간을 믿지 않고, 확실한 자세 사이를 잇기)
  - 사람 수정
  - 어느 것이 나은지는 아직 근거가 없다. 실험으로 가른다.
  - (11-02 밤 사용자 지적 "3D에 매몰되지 말 것"으로 고침. 처음 쓴 판은 3D를 중심 후보로 올렸다.)
- **스틱맨은 비율을 버린다.** 그래서 애니의 과장 비율이 3D 맞춤에서 문제가 되더라도, 결과로는 관절 각도만 맞으면 된다. 3D 모델의 체형 오차는 덜 치명적일 수 있다(확인 필요).
- **'좋은 스틱맨 움직임'의 기준 자료가 우리에게 있다.** `data/user_sfa/`의 스틱맨 동작 파일에서 각속도 분포, 정지 길이, 조각 길이 변화를 기준선으로 쓸 수 있다.

### 4. 추천 경로(1차, 11-02 밤 고침): "단계별 측정 후 선택" — 공통 뼈대 + 자세 단계 후보 경쟁
방법과 상관없이 공통으로 쓰는 단계(1·2·6·7)를 먼저 만든다. 자세 단계(3–5)는 2D 후보와 3D 후보를 같은 장면, 같은 지표로 겨룬다. 아래 3–5는 3D 후보의 예시다. 2D 후보는 아래 '2D 후보'에 있다.
1. 컷 나누기(PySceneDetect 등). 인물 찾기·추적은 실사 검출기 대신 마스크 기반 추적을 쓴다(SAM 2/SAM 3 계열 또는 Grounding DINO + SAM 2, 애니에서의 성능은 확인 필요).
2. 인물 마스크 안 픽셀 차이로 '그림이 바뀐 장'을 찾고, 각 그림의 정지 길이를 기록한다.
3. 그림이 바뀐 장에서만 2D 점을 뽑는다. 여러 모델을 앙상블하고 장마다 신뢰도를 남긴다.
4. 3D 맞춤을 한다. 신뢰도 높은 2D 점과 마스크를 조건으로 주고, 나머지는 사전이 메운다(SAM 3D Body 또는 GVHMR, 둘을 비교). 뼈 길이는 인물마다 3D에서 고정한다.
5. 투영은 두 판을 만든다.
   - 판 A: 원본 카메라 투영. 장면·이펙트 위치와 맞고, 단축은 3D에서 생긴다.
   - 판 B: 옆모습 등 스틱맨에 읽기 쉬운 카메라. 사용자가 어느 쪽이 맞는지 판정한다.
6. 타이밍을 복원한다. 그림이 바뀐 장에서만 자세가 바뀌고, 정지 구간은 그대로 복사한다(24/24, 원본 장 단위 그대로).
7. 앱 스틱맨 10조각에 맞추고, 점 ID를 장마다 새로 쓴다.
8. 나중에 사용자가 키포즈만 고치는 경로를 붙인다. 고친 결과는 2D 모델 미세조정 자료가 된다.

2D 후보(3D 후보와 같은 자리):
- **2D 앙상블 + 키포즈 재연출:** 확실한 그림만 키포즈로 쓰고, 그 사이는 관절 각도로 회전 보간(길이 보존)하며, 정지는 원본대로 둔다. 계산이 가볍고 원본 카메라와 맞는다. 스틱맨 애니메이터의 작업 방식과도 가깝다.
- **2D 앙상블 + 2D 동작 사전 보정:** 신뢰도 낮은 관절을 `data/user_sfa/` 스틱맨 움직임 분포나 2D 포즈 자료로 메운다.

어느 후보를 주 경로로 삼을지는 §6 실험 결과와 사용자 판정으로 정한다. 지금은 우열을 정하지 않는다.

### 5. 평가
- **정답 있는 시험**
  - (가) 우리 스틱맨 SFA를 렌더러로 그린 영상을 넣고 원래 각도를 얼마나 복원하는지 잰다. 쉬운 시험이지만 파이프라인 버그를 잡을 수 있다.
  - (나) 애니 장면 30–50장의 관절 라벨. 누가 어떻게 라벨할지는 토론이 필요하다.
- **숫자**
  - 정지 일치율: 원본에서 그림이 바뀐 장과 스틱맨이 바뀐 장의 일치(F1).
  - 조각 길이 변동.
  - 각가속도 튐: 장 사이 각속도 변화의 상위 분위.
  - 좌우 뒤바뀜 횟수.
  - 발 미끄럼: 발이 땅에 닿은 동안 발이 움직인 거리.
  - `data/user_sfa/` 스틱맨 분포와의 거리.
- **반례**
  - 아주 매끄럽고 길이도 일정하지만 정지를 뭉개 둥둥 떠다니는 결과는 튐 지표가 최고점인데도 어색하다. 그래서 정지 일치율을 같이 본다.
  - 반대로 정지는 지켰지만 키포즈가 틀린 결과(팔 좌우 바뀜)는 정지 일치율이 높아도 틀렸다.
- **최종 판정:** 사용자 눈 판정. 원본과 후보들을 나란히 놓은 영상으로 본다.

## 2차 — Claude 답(11-02 밤)

### 0. 이번에 새로 잰 것(측정 결과)
과거 측정을 재사용했는지, 새로 잰 것인지 같이 적는다. 해석 가운데 가설은 따로 표시한다.

**M1. nian41 원본: 인물 그림이 바뀌는 장(새 측정)**
- 도구: `tools/anime_char_hold.py`
  - 인물 마스크는 채도로 만든다(HSV S>90, V>40). nian41 인물은 회색 배경 위 색(파랑·빨강)이다.
  - 카메라 평행 이동을 보정한다(마스크 위상 상관).
  - 바뀜 정도 = 정렬 뒤 실루엣 XOR / 합집합.
  - 문턱: 2개 구간을 Claude가 눈으로 보고 맞췄다(아래 보정).
- 화면 전체 차이로 재면 같은 장 비율이 1–12%로 나온다(`hold_measure.py`, 저장소 미포함). 하지만 이는 카메라·파편이 1장마다 움직이기 때문이다. 화면 전체 차이로는 인물의 정지를 잴 수 없다.
- **보정(Claude 눈 판정 + 수치)**
  - 1913 영상 300–311장(창고, 등 보이며 걸음): 카메라는 1장마다 움직이고, 인물은 **3장 단위**다. 수치 `0.47 | 0.07 0.05 | 0.84 | 0.06 0.07 | 0.51 | 0.09 0.09 | 0.66 | 0.08`.

### 1. 동의(근거 포함)
1. **관측 기록과 목표 동작을 나눠 저장한다.** 내 1차 의견에는 없던 구분이고, 더 낫다. 관측 오류와 연출 선택을 같은 정답으로 배우지 않게 한다. 채택을 제안한다.
2. **점 추적은 관절 추정이 아니다.** 작화가 바뀌면 같은 부위의 픽셀이 사라진다. M1에서 그림이 2·3장 단위로 바뀌는 것을 보면, 바뀌는 장마다 추적이 끊길 위험이 실제로 크다.
3. **COCO 17점은 앱 10조각에 일대일로 붙지 않는다.** 어깨 폭·골반 폭·가슴 비틀림 정보가 사라진다. 변환 규칙(어깨 중점 → 목 등)을 명시해야 한다.
4. **화면비 보정.** M2로 확인했다. 보정이 없으면 길이 편차 중앙값이 0%에서 12%로 바뀐다.
5. **수집 SFA를 시간 정답으로 쓰지 않는다.** M2로 확인했다. 내 1차 의견의 '각속도 분포를 기준선으로'는 시간 단위로는 철회한다. 장 순서·자세 분포로만 쓴다.
6. **길이는 고정을 기본으로 하되, 제한적 단축판도 함께 비교한다.** M2에서 10% 마디가 11% 넘게 변한다는 것은 단축을 완전히 배제할 근거도 없다는 뜻이다.
7. **24장을 저장하는 것과 매 장 새 자세를 만드는 것은 별개다.** M1에서 원본은 32–74%가 정지라, 이 구분은 실제로 중요하다.
8. **3D는 차선, 같은 장면에서 이득이 남는지 확인한다.** 내 2차 수정안과 같다.
9. **T4 두 장은 한 장의 32GB처럼 쓸 수 없다.** 후보별로 따로 돌린다.

### 2. 반박·보완
1. **주 경로를 '사람 검수 중심'으로 정하기 전에 사용자 시간을 재야 한다(미결).**
   - 생성기 학습 재료는 분량이 필요하다.
   - M1 기준 nian41은 1초에 고유 그림이 대략 6–16장이다(24 × (1 − 정지 비율 0.32–0.74)로 계산한 추정).
   - 10초 장면 하나에 60–160개 자세다. 이 자세를 사람이 전부 지정하면 재료가 쌓이지 않는다.
   - 보완안: 사람은 ① 평가·미세조정용 작은 정답 세트와 ② 자동 결과 가운데 신뢰도 낮다고 표시된 장만 맡는다. 분량은 자동 경로가 만든다.
   - 첫 실험에서 '합격까지 걸린 사람 수정 시간'을 같이 재서 정하자. GPT도 수정량 기록을 제안했다.
2. **정지는 사람이 지정할 필요 없이 자동으로 잴 수 있다(M1).**
   - GPT의 '원본 시간표 작성'은 대부분 자동으로 된다.
   - 사람·GPT 눈은 접촉·타격 시점과, 자동 판정이 애매한 장(0.1–0.3 사이)만 본다.
   - 자세 추정도 고유 그림에서만 하면 장 수가 26–74% 준다(영상별 정지 비율). 〔3차 §0에서 정정〕
3. **카메라와 몸을 분리하는 문제는 실제로 있다(M1 측정 사례).**
   - 1913 300–311장은 인물 그림이 3장 멈춘 동안에도 화면 위치가 1장마다 움직인다.
   - 관측 기록에는 '자세 정지 + 화면 위치 이동'을 따로 둔다.
   - 목표 동작에서 카메라 이동을 어떻게 넣을지는 사용자 판정 항목이다.
4. **CPU 진단의 '같은 수작업 관측 좌표'는 누가 만드나(미결).**
   - Claude·GPT의 그림 눈 좌표는 정밀도가 확인되지 않았다.
   - 제안: 고유 그림만(48장 중 약 20–30장) 라벨한다. 웹 라벨 도구(장면 그림에 관절 점 찍기)를 Claude가 만든다.
   - 같은 장을 2명(Claude + GPT, 또는 사용자)이 찍어 서로 다른 정도를 먼저 잰다.
5. **합격선 '중앙값 3%, 95% 8%'는 라벨 오차를 잰 뒤에 정한다.** 두 라벨러의 차이가 이미 3%를 넘으면 그 합격선은 판정이 불가능하다. 잠정치로만 두고, 라벨 일치도 측정 뒤 조정한다(GPT도 '실측 후 조정 가능'으로 적음).
6. **스틱맨에 애니 정지를 그대로 옮길지는 사용자 판정이 필요하다(새 쟁점).**
   - M2에서 수집 스틱맨은 정지가 적었다(파일 중앙값 3.6%).
   - 다만 T/F를 몰라 시간 단위 비교가 아니다. 이는 '스틱맨 습관'과 '원본 충실' 사이의 선택이다.
   - 두 판(정지 유지 / 정지를 매 장 이동으로 바꿈)을 같은 장면에서 보여 주고 판정받는다.
7. **시험 장면 후보(GPT 기준 'A 관측 쉬움, B 회전·가림'에 맞춤, 출력을 보기 전에 고정)**

   - A 후보: 1913 영상 1500–1523장(옆모습 2인 싸움, 배경 고정, 인물 2장 단위, 팔다리 대부분 보임). 2인이라 인물 식별 시험도 같이 된다.
   - 나카무라 타격 구간: 아직 영상을 보지 않았다. 고르기 전에 확인한다.
   - 확정은 사용자가 한다.

### 3. 합의 / 미결 / 사용자 판정
- **합의(제안 상태, GPT 확인 필요)**

  - 화면비 보정.

  - 정지 보존 가능 구조.

  - 라벨 주체와 정밀도: 라벨 일치도 측정으로 가른다.
- **사용자 판정이 필요한 것(GPT 질문 1–4와 합침)**
  1. 주 학습 목표: 원본 카메라 자세 충실판인가, 스틱맨에서 읽기 쉬운 재연출판인가. 두 판을 보고 정한다.
  2. 원근 단축 허용. 두 판을 보고 정한다.
  3. 학습 클립마다 사용자 키포즈 지정·수정이 들어가도 되나? 된다면 한 번에 쓸 수 있는 시간은?
  4. '이 정도면 자연스럽다'고 보는 수집 SFA 예시.
  5. (새) 애니의 2·3장 정지를 스틱맨에서도 유지할지. 두 판을 보고 정한다.
  6. 시험 장면 A·B 후보 승인.
