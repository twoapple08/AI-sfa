## 2. SFA 형식 요점 [저장·정적·실물]
- `.sfa` = ZIP 안 XML 1개. `Sequence > Frame > LayerDef, AO(도형) > AP(점), AC(점 연결), FR(채우기) > FS(경계 조각), TweenLink`.
- AO TypeId: 1 직선, 2 원(두 점이 지름 끝), **3 곡선 = 2차 베지어(점 3개: 시작·조절·끝)**. 굵기 ThicknessScale(선 폭 ≈ 1.14·8·TS px, 화면 폭 1920 기준 [서버 대조]). **앱 굵기 하한 = 기본의 10%(TS 0.1)** [실물, 사용자].
- 채우기 FR: 자기 색·알파. FS가 AO 곡선을 번호로 가리키고 Contour별로 이어 닫음(간격은 직선), 짝홀 규칙, Contour 0 바깥·1.. 구멍. 경계 선 알파 0이어도 채우기는 보임 [실물].
- 반투명 채우기(색 알파) 앱 재생에 반영 [실물]. 글로우(가우스) 있음. LayerDef로 레이어 이름 지정 가능.
- 앱 보간은 대체로 선형, 같은 AO ID·AP Index 대응. **단, 사용자는 항상 (24,24)로 만들어 트위닝을 쓰지 않는다(2026-10-25).** 상세: `docs/AI-COLLAB-BRIEFING-2026-10-16.md`, `docs/SFA-VIEWER-2026-10-20.md`, `docs/FORMAT.md`.
- **스틱파이터는 완전한 그림 도구다**(사용자): 선화 → 점을 이은 채우기 → 밑색 → 반투명 명암 여러 겹 → 배경. 사람 작가는 **점 몇 개짜리 성긴 다각형 면을 선화 아래에 깔고**(면 가장자리는 선이 덮음), **선은 곡선 객체 한두 개로 길게** 긋는다(사용자 시연: 어깨선 하나 = 곡선 2개, 끝이 빠지는 붓선 = 곡선 4개로 닫은 면).

## 5. 사용자가 준 원칙·지적 (중요도 순)
1. **점 하나하나 따라가지 말고 곡선으로 형태를 만든다.** 곡선 하나가 휘며 긴 구간을 덮는다.
2. 선은 **곡선 + 굵기의 선 객체**. 채우기 면으로 선을 만들면 양쪽 테두리에 점이 두 배.
3. 채색은 **층층이 쌓는다**(아래가 넓고 어둡게 → 위가 좁고 밝게, 각 층 통째 덩어리). 면 가장자리는 선이 덮으니 성기게.
4. 일반 그림처럼 **부위·요소별 레이어**.
5. 선 굵기 바리에이션 필요, 기본은 너무 두꺼움(0.6 선택).
6. 이펙트는 테두리선 없는 그림이 많음 — 색 덩어리 형태가 핵심.
7. 결과를 대충 보고 잘됐다고 하지 말 것(오늘 Claude의 실수 2회).

## 7. Claude가 보는 핵심 문제
1. **래스터 → 벡터 품질:** 작은 부위(눈)·선 끝·잔가지에서 곡선이 짧게 몰림. 분할을 '오차 최대점에서 반으로'가 아니라 **전체 곡선 수 최소**로 맞춰야 함. 원·타원 맞춤, 끝점 공유(AC)도 미구현.
2. **이펙트 층 쌓기:** 영역 분할(폭발/배경/물체)을 색 규칙에 의존 — 장면마다 깨짐. 층 수·문턱을 자동으로 고르는 방법 필요.
3. **움직임:** LoRA는 정지 그림만. 이펙트를 '나카무라식으로 움직이게' 하는 방법 미정. 후보 ① 단계별 열쇠 그림 생성 + SFA 변형(같은 AO ID로 트위닝) ② 영상 모델(AnimateDiff 등) ③ 애니 보간 모델.
4. **기기 탑재:** SDXL 계열은 수 GB, 휴대폰 직접 실행 어려움. 결국 작은 모델(증류·휴대폰용 확산) 또는 **벡터를 직접 생성하는 모델**이 필요할 수 있음.
5. 그림 → SFA를 매번 변환하는 구조 자체가 맞는지(벡터 네이티브 생성과 비교) 판단 필요.

## 7-1. Claude의 현재 의견(가설 — GPT가 반박·보완해 달라)
1. **벡터화 단기안:** 학습된 선화 추출기(지금 ControlNet lineart) → 가운데 줄기 → **곡선 수 최소 맞춤**(분할점을 동적계획법으로 골라 오차 허용 안에서 곡선 개수 최소) → 짧은 잔가지 버림 → 작은 닫힌 선은 원·타원으로 맞춤 → 이어지는 곡선 끝점 공유. 채색은 층 쌓기(어두운 넓은 층 → 밝은 좁은 층), 영역은 SAM 계열 + 색 양자화. 이것만으로도 사용자 기준에 꽤 다가갈 수 있다고 본다.
2. **층 쌓기는 LIVE(층별 벡터화)와 거의 같은 발상**이라, 최적화로 '경로 몇 개를 위에서부터 쌓아 원본을 맞추는' 방식(DiffVG 기반)을 붙이면 층 수·형태가 자동으로 정해질 것 같다. 다만 계산이 무겁다(서버 CPU로 가능한지 확인 필요).
3. **움직임(사용자 결정 2026-10-25: 항상 (24,24) — 트위닝 FPS 24 = 재생 FPS 24, 앱 트위닝을 쓰지 않고 24장/초를 모두 직접 그린다):** 그래서 영상·보간 모델로 만든 장을 하나씩 벡터화하는 경로도 가능하다. 문제는 트위닝이 아니라 **장 사이 떨림**(장마다 따로 변환하면 윤곽·층 경계가 흔들림)과 **장 수만큼 늘어나는 용량**(1초 24장). 장 사이 일관성(이전 장 곡선을 시작점으로 다음 장을 맞추기 등)과 장당 객체 수 절감이 핵심. 나카무라식 타이밍(멈춤·빠름, 투스·쓰리스 = 같은 그림을 2·3장 유지)은 트랙 사전 통계로 준다.
4. **기기 탑재(장기):** SDXL+LoRA는 휴대폰에서 무리. LoRA는 '선생님'으로 써서 그림을 많이 만들고, 그것을 벡터화한 SFA를 자료로 **벡터(곡선 계수)를 직접 내는 작은 모델**을 가르치는 게 최종 목표에 가장 맞다고 본다(래스터 생성 → 변환을 기기에서 하지 않게). 근거는 아직 없음 — GPT가 실제 사례를 찾아 주길 바란다.
5. **의심 가는 점:** 지금 규칙 기반 변환을 계속 다듬는 데 시간을 너무 쓰는 것 아닌지. 이미 잘 만든 도구·연구가 있으면 그것을 쓰는 게 낫다(오늘 사용자 지적).

## 9. GPT에게 부탁 — 인터넷 조사 + 제안
각 항목마다 **찾은 근거(논문·저장소·글 링크), 우리 상황(2차 베지어·채우기·반투명 층·기기 탑재)에 맞는지, 바로 해 볼 수 있는 구체적 절차**를 적어 달라. 근거 등급(확인/추정)을 구분해 달라.
1. **래스터 → 적은 곡선의 벡터:** 선화 가운데 줄기(centerline) 벡터화, 곡선 수 최소 맞춤, 작은 원 처리. 예: potrace·autotrace centerline·VTracer·Inkscape, 선화 단순화(Sketch simplification), 학습 기반 벡터화(Deep vectorization of line drawings, PolyVector Flow 등). 2차 베지어 제약에서 최적인 것.
2. **층 쌓기(layer-wise) 벡터화:** 사용자 방식(어두운 넓은 층 → 밝은 좁은 층)과 같은 연구. 예: LIVE(Layer-wise Image Vectorization), DiffVG 기반 최적화, 색 층 분해(layer decomposition). 이펙트(테두리 없는 셀 채색)에 맞는 영역 분할·층 수 자동 결정.
3. **벡터를 직접 생성하는 모델:** 래스터 생성 후 변환 대신 SVG/벡터 경로를 직접 내는 모델(예: VectorFusion, SVGDreamer, StarVector, OmniSVG 등)과 그 학습 가능성, 우리 자료(나카무라 이펙트)로 미세조정 가능 여부.
4. **움직임:** 셀 애니 이펙트를 움직이게 하는 방법 — 열쇠 그림 사이 보간(ToonCrafter 등 애니 보간), AnimateDiff·영상 LoRA, 형태 계수(곡선 조절점) 시간 모델. **(24,24) 전 장 직접 그리기 전제**에서 장 사이 떨림 없이 벡터화하는 방법과 장당 용량 절감.
5. **기기 탑재:** 휴대폰에서 돌릴 수 있는 그림/벡터 생성 크기·방법(증류, 작은 확산 모델, 벡터 모델), 품질 손실.
6. **LoRA 개선:** 색 빠짐(저채도 자료) 대책, 이펙트만 배우게 하는 캡션·자료 구성, 적정 바퀴 수 판단.
7. 위를 종합해 **우리에게 가장 맞는 전체 경로 1–2개**를 추천하고, 첫 실험 3개를 순서대로 제안.
