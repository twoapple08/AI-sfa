# GPT 답 — 이펙트·연출 버전 계획 (2026-10-27) + Claude 조정

질문: docs/GPT-PROMPT-FX-STYLE-2026-10-27.md (사전 정보 없이 시작한 GPT 세션에 이어서). 출처 링크는 GPT 원 답변. 도구 메모리 수치는 GPT가 인용한 공식 예시, 우리 환경 실측 아님.

## 요약
**순서: 이펙트의 시간 변화와 형태를 함께 기록하는 벡터 자료집 → 검색·변형 생성기 → 필요한 부분부터 학습.** 캐릭터용 스켈레톤 중심 접근은 이펙트에선 바꾼다.
1. **중간 표현**: 레이어별 벡터 도형 + 덩어리 생성·분열·합체·소멸 관계(부모·자식) + 프레임별 변화(중심·면적·방향·속도·회전·유지 프레임) + 형태 변화(돌출부·가지·구멍 수, 끝 각도, 심 갈라지는 시점, 외곽 거칠기) + 화면 연출(2D 이동·확대·회전·흔들림·섬광·가림) + 관측 신뢰도(보임/반투명/가림/추정). 단계: 응축·발생·급팽창·분열·잔류·소멸 시작 프레임. 종류별 추가 기록(폭발·번개·불 벽·파편·연기·충격파). 홀드는 레이어별. 발화점 원점·대표 크기 정규화, 실제 프레임 수·순서는 보존. 번개 가지·연기 흐름엔 보조 중심선.
2. **움직임과 모양 디자인은 함께 배운다**(이펙트에선 끝이 뾰족해지는 방식 자체가 움직임). 3층: 시간·구조(학습) / 형태 문법 — 각진 끝·찢어진 심·덩어리 비율·색 단계 면적 배치(학습) / 작품 색·방송 색보정·촬영 글로우·압축 노이즈(조건 또는 제외). 예: 명도 순서와 면적 관계는 남기고 RGB는 교체 가능하게.
3. **자료 만들 땐 픽셀 분석, 제작 생성기는 처음부터 제한된 벡터 출력.** 픽셀 생성 후 장마다 벡터화하면 경계·도형 수가 흔들리고 글로우가 색 띠가 된다. 첫 작업: 목표 파일 읽기·쓰기 최소 편집·재생기 + 글로우 규칙 고정. VTracer는 cubic → 2차로 재근사·오차 확인, diffvg는 앱 글로우와 일치 별도 검증.
4. **레이어 분리**: 수동 로토 + 분할(SAM 2.1 Tiny/Small, 알파 복원 아님) + 배경 추정(장면 전후 관측 픽셀 먼저, 남은 구멍만 ProPainter: 640×480·50장·FP16 약 6GB, 1280×720 약 19GB) + 필요한 곳만 매팅(ViTMatte Small, PyMatting). 목표는 '원본 레이어 복원'이 아니라 '근거가 표시된 제작용 레이어 재구성'. 촬영 글로우는 복사하지 말고 허용된 글로우로 재설계. 검정·회색·흰 배경에 재합성해 확인. MatAnyone 2는 인물용이라 비추천.
5. **손 기준작 두 개**: A 복원(메인 폭발 한 장면, 발생→소멸 48–96장), B 새 장면(새 발화 위치·방향·면적; B0 메인만, B1 서브 특징 하나 추가). 글로우는 실제 엔진에서 굵기·알파별 시험표부터(반경 독립 조절 가정 금지).
6. **첫 생성기는 벡터 시퀀스 검색 + 변형·조합.** 시간 변형은 정수 프레임 재배치(홀드·급변 보존), 결합은 단계 경계에서. 학습·평가는 변형 전 원본 장면 단위로 분리. 학습 전환 조건: 한 종류 자료 일관 정리, 검색 생성기의 성공·실패 패턴 확인, 보지 못한 컷 평가 자료, 사람 수정 전후 축적. 첫 학습 대상: 시퀀스 선택 순위, 단계별 지속 시간, 파편 방출 분포, 윤곽 보정량.
7. **평가**: 단일 스타일 점수 없음. 기술 유효성 / 움직임·형태 특성(방향별 면적 증가, 피크 시점, 심·외곽 비율, 덩어리 수, 분열 빈도, 파편 지연, 홀드 분포) / 원본 암기 여부. 본체만 렌더 + 글로우 포함 따로. 사람 평가: 기준·항목 고정, 같은 조건 A/B, 블라인드·무작위, 스타일과 완성도 분리, 반복 문항으로 일관성 확인. 부드러움 점수를 주 평가로 쓰지 않음.

실행 순서(GPT): **렌더러 제약 시험표 → 폭발 복원 A → 새 폭발 B0/B1 → 벡터 시퀀스 검색 생성기 → 선택·시간·형태 보정 모델 학습.**

## Claude 조정 (2026-10-27)
- 채택. 기존 도구 대응: sfa_render.py(앱 셰이더 식 근사, 앱 실측 필요), glow_fit.py(층별 글로우 맞춤, 서버 렌더 기준), scene_layers.py·remove_lightning.py(레이어 분리·번개 떼기·앞뒤 장+LaMa 메우기), fx_timing·debris_rhythm 실측 통계.
- 3D 금지 유지: 화면 연출은 2D 이동·확대·회전만(GPT도 같은 전제).
- 기준작 A는 폭발로(불 벽 1128–1159는 레이어 분리 시험용으로 유지).
- 1단계 렌더러 시험표: 굵기 × 글로우두께 × 반경 × 알파 격자 SFA를 만들어 사용자가 앱 화면/내보내기로 확인 → 서버 렌더러 식 보정.
- 이전 시험 3–8(영상·그림 모델이 그림체·배경·움직임을 한꺼번에 생성)은 중단 유지. GPT 계획에서 영상 생성 모델은 생성기 단계에 없다.

## 1단계 결과 — 앱 시험표 1차 (2026-10-27, 사용자 앱 내보내기 1fps, 선 두께 100%)
- **앱에서 글로우가 하나도 안 나왔다**(6장 전부). 서버 렌더러는 글로우를 그렸다.
- 원인 후보(검증 중): 우리 쓰기 도구가 `GlowRadius="20.0"`처럼 소수점을 붙였다. 사용자 파일 '배'는 `GlowRadius="28" GlowThickness="50" GlowAlpha="255"` 정수. 또 '배'의 안 보이는 선은 색 알파 0이 아니라 10(`Color="167772160"`).
- 영향: effect_clip_sfa.py(curve_ao, stack_layers_sfa가 씀)·glow_fit.py·glow_testgrid.py가 모두 소수점 형식이었다 → **지금까지 우리가 만든 SFA의 글로우는 앱에서 꺼져 있었을 가능성**. 세 파일을 정수로 고쳤다.
- 2차 시험표(7장): 1–6장은 정수·안 보이는 선 알파 10으로, 7장은 원인 가르기(정수·알파 0 / 정수·알파 10 / 소수점·알파 10 / 소수점·흰 선).

## 1단계 결과 — 앱 시험표 2차 (2026-10-27, 같은 설정)
- **원인 확정: 글로우 값에 소수점을 붙이면 앱이 글로우를 끈다.** 7장 줄 3·4(소수점)는 글로우 없음, 줄 1·2(정수)는 글로우 있음 [앱 내보내기 확인].
- 안 보이는 선 색: 알파 0과 알파 10 모두 글로우가 나온다. 알파 10은 검은 선이 글로우 가운데에 옅게 비쳐 줄무늬가 생긴다 → **알파 0을 쓴다**(서버 렌더도 같은 줄무늬를 그림).
- **서버 렌더러 ≈ 앱**: 1–6장 평균 차이 0.21–0.69(0–255) — 굵기 0.1–3 × 글로우두께 10–100, 반경 0–100, 알파 32–255, 색 4종, 반투명 면·겹침·테두리 글로우 범위에서 글로우 식(띠 폭 = 8·굵기·두께/10, 흐림 ≈ 반경)이 맞다. 차이: 앱의 아주 큰 글로우(굵기 3·두께 100)에 방사형 줄무늬가 보인다(서버엔 없음, 시각 차이 작음).
- 결론: glow_fit 등 서버 렌더 기준 맞춤 결과는 정수 형식으로 쓰면 앱에서도 거의 같게 보일 것(다음에 앱으로 확인).
