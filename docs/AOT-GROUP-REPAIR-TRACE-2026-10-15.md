# 비정상 그룹 참조 복구 — 2026-10-15

- 기존 AOT/ELF 캐시에서 그룹 부모 해석, 순환 해제, 부모 재배정과 DB 반영 경로를 연결했다.
- 새 휴대폰 시험이나 기존 영상 재분석은 없다.
- 아래의 ID는 AnchorPoint ID이며 AO ID가 아니다.

## 부모 해석과 이전 표현

- `AnchorPoint.ResolveGroupParentId`(0x346860)는 그룹 bit `0x10`이 없으면 null이다.
- 현재 표현은 `Flags >> 6`의 점 ID를 입력 map에서 찾고, 부모도 그룹 자식이면 위로 반복한다.
- 방문 ID를 기록하며 재방문하면 null이다.
- 도달한 비그룹 점은 자기 자신이 아니고 `T = Flags & 0x2e`가 2여야 유효하다.

- 부모 조회가 null에서 끝난 경우에만 이전 표현 복원을 시도한다.
- `(Flags >> 6) & 0x3ff == 0`, `(Flags >> 16) & 0xffff != 0`이 필요하다.
- map 값 순서에서 자기 자신이 아닌 비그룹 T2 점 중 ID 하위 16비트가 이 토큰과 같은 첫 점을 반환한다.
- 실제 도달한 부모가 잘못된 유형이거나 자기 자신인 경우에는 이 fallback을 적용하지 않는다.
- 하위 16비트 충돌을 모든 상황에서 해결한다는 보장은 없다.

- `RemapGroupChildFlags`(0x36eea4)는 기본값 `Flags & 0x2f`를 만들고, 그룹 자식이면 위 해석 결과를 새 ID map에서 찾는다.
- 성공하면 `(새부모ID << 6) | (기본값 & 0x3f) | 0x10`, 실패하면 기본값이다.
- 부모 해석 없이 상위 비트를 그대로 복사하는 방식이 아니다.

## 복구 순서

`RepairGroupFlags`(0x520cbc)는 입력 map 값을 점 ID 오름차순으로 정렬해 다음 단계를 진행한다.

| 순서 | 조건과 처리 |
|---|---|
| 1 | 그룹의 직접 부모 ID가 자기 ID면 `Flags & 0x2f`로 그룹 참조를 해제한다. |
| 2 | 직접 부모 ID가 map에 없으면 부모 해석을 시도한다. 성공하면 해석한 ID로 다시 기록하고, 실패하면 참조를 해제한다. 직접 부모가 존재하는 경우는 이 단계에서 건너뛴다. |
| 3 | 경로 내 ID→위치 map으로 순환을 찾는다. 순환 부분에 속한 점 중 **최소 ID 한 점**의 그룹 참조를 해제한다. 경로 전체를 삭제하거나 모든 점의 좌표를 바꾸는 처리가 아니다. |
| 4 | 직접 부모가 존재하는 비그룹 비 T2 점인 경우 부모별로 중복 제거한 후 `ReassignGroupChildren`을 호출한다. |
| 5 | 남은 그룹 참조를 다시 해석하여 실패한 점은 해제한다. 비그룹 점에는 `Flags & 0x2f`를 적용해 잔여 상위 참조 비트 등을 정리한다. |

정렬 comparator 0x522380과 순환 최소 ID 선택 closure 0x522358을 구분했다. 최종 단계는 유효한 모든 간접 참조를 일괄 최상위 ID로 평탄화하는 루프가 아니다.

## 부모 재배정과 연결

- `ReassignGroupChildren`(0x52174c)의 자식은 자기 ID가 이전 부모와 다르고, 그룹 bit가 있으며, 직접 `Flags >> 6`이 그 부모 ID인 점이다(조건 closure 0x522144).
- 구조 연결 수집 결과에서 이전 부모 자신을 제외하고 비그룹 T2인 후보 중 최소 ID를 새 부모로 고른다.
- 후보가 없으면 자식의 그룹 참조를 해제한다.

- 자식과 이전 부모 사이에 어느 방향이든 연결이 있으면 양쪽 목록에서 상대 ID 연결을 모두 제거하고 제거 쌍을 기록한다.
- 새 부모가 있으면 Flags를 새 ID로 바꾼다.
- 자식↔새 부모 중 어느 한 방향 연결이라도 이미 있으면 새 연결 추가를 건너뛴다.
- **양방향 모두 없을 때** 양쪽에 하나씩 연결을 추가하고 추가 쌍을 기록한다.
- 따라서 기존 단방향 연결까지 반드시 양방향으로 보완한다고 일반화할 수 없다.

- `GroupFlagRepair.SetFlags`(0x5221a8)는 값이 같으면 아무것도 하지 않는다.
- 다르면 메모리 Flags를 바꾸고 ID→점 변경 map에 기록한다.
- 결과 객체에는 변경 map, 제거 쌍 목록, 추가 쌍 목록이 따로 있다.
- `RemoveConnection`(0x521f2c)도 메모리 목록 변경과 쌍 기록이며 자체 DB 쓰기는 아니다.

## 프레임 호출과 저장

- `_repairGroupFlagsForFrame`→0x5201e4의 복구 호출→`IsEmpty`가 참이면 false 반환, 변경이 있으면 helper 값 초기화→`DataAccess.ApplyGroupFlagRepair`→true 반환으로 연결된다.
- 복구 함수를 읽은 것만으로 모든 입력 경로에 항상 실행된다고 주장하지 않는다.

- `ApplyGroupFlagRepair`(0x520264)는 비어 있으면 반환하고, 그렇지 않으면 transaction을 연다.
- 변경 Flags는 anchor scope를 통해 반영한다.
- 제거 쌍은 양쪽 점을 구체화한 후 양방향 SQL DELETE를 실행한다(closure 0x520a44). 추가 쌍은 각 끝점에 대해 anchor scope 안에서 `_writeAnchorConnections`를 호출해 **현재 outgoing 목록을 다시 저장**한다(0x5209f4). 추가 쌍마다 INSERT 하나만 하는 구현으로 축약하지 않는다.
- 정상 경로는 commit→finish, 예외 경로는 finish→rethrow다.
- 메모리와 DB의 임의 실패 원자성까지 새로 검증한 것은 아니다.
