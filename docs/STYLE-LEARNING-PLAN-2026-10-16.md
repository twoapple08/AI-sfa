**보관 선택지**

| 선택지 | 비용 | 판단 |
|---|---|---|
| 보관하지 않음 | 0 | 분석할 때마다 서버가 임시로 받고, 분석 뒤 지운다. 저장소에는 게시물 ID·md5·태그만 남긴다. md5로 같은 영상인지 다시 확인할 수 있다 |

| GitHub 저장소 | — | 쓰지 않는다. 공개 저장소이고, 남의 영상 원본을 올리면 안 되며, 대용량에도 맞지 않는다 |

**추천:** 지금은 보관하지 않고, 필요할 때 받아 분석한 뒤 지운다. 분석 결과(관찰 기록·수치)만 저장소에 남긴다. 가중치 학습 단계에서 원본 묶음이 필요해지면 그때 Drive에 모은다.

## 서버에서 직접 분석이 가능함을 확인 [실측]

서버에는 ffmpeg가 있고 Sakugabooru API와 파일 다운로드가 동작한다. PC 없이 다음 과정이 된다.
1. 메타데이터 색인: `tools/sakuga_index.py`
2. 클립 임시 다운로드
3. 타이밍 측정과 고유 그림 contact sheet 생성: `tools/sakuga_timing.py`
4. Claude가 contact sheet를 이미지로 직접 보고 관찰 기록 작성

이 단계에서는 추가 지출이 없다. 이미지 분석은 토큰을 쓰므로, 클립마다 고유 그림 최대 64장짜리 한 장으로 압축해 본다.

### 시범 분석 1 — yutaka_nakamura, post 203287 (FMA:B NCOP2, 17.9초, 23.976fps)

- **타이밍** (화면 합성 기준, 프레임 간 차이 0.5 이하를 유지로 판정): 새 그림 387개 / 429프레임. 1s(매 프레임 새 그림) 351회, 2s 30회, 3s 6회. 연금술 기 모으기 구간은 2s, 액션·카메라 회전 구간은 1s였다.
- **이펙트**
  - 푸른 전격 glow가 점점 커지다가 화면 전체가 흰빛과 푸른빛으로 포화된다.
  - 그다음 **검은 프레임 1장**이 끼어든다.
  - 이어서 구형 에너지 덩어리들이 생겨나고, 방사형 털·가시 모양의 충격 윤곽이 따라온다.
- **연출·배경**
  - 집중선과 배경 문지르기만 남은 전환 프레임 4장이 있다.
  - 이어서 카메라가 크게 회전하는 **배경 작화**(벽면·그림자 덩어리가 손그림으로 흐른다)가 나온다.
  - 그 위에서 캐릭터 간 추격이 1s로 진행된다.
  - 이후 원근이 강한 벽면을 달리는 트래킹 샷이 이어진다.

### 시범 분석 2 — nian41, post 216075 (primitive_flame, 4.4초, 105프레임)

- **타이밍:** 105프레임 모두 새 그림(1s).
- **캐릭터:** 부츠 발걸음 클로즈업. 코트 자락의 끌림이 털 같은 들쭉날쭉한 실루엣의 스미어로 표현된다.
- **이펙트**
  - 불꽃은 **밝은 노랑·주황 외곽 + 어두운 적갈색 속(core)**의 2톤 구조이고, 외곽선이 날카롭게 톱니진다.
  - 불티는 길쭉한 타원(이동 방향으로 늘어난 streak)으로 흩뿌려진다.
  - 어두운 배경을 깔아 발광을 강조한다.

### 시범 분석 3 — yutaka_nakamura, post 281606 (MHA S4 #25, 8.1초, 195프레임, `yutapon_cubes`)

- **타이밍:** 새 그림 193개 / 195프레임. 거의 전부 1s.
- **연출:** 파스텔 보라 바탕에 크림색 방사광선(역광 배경)을 깔고, 캐릭터는 어두운 실루엣 + 흰 rim 발광으로 처리한다. 돌진할수록 흰 발광 덩어리가 커지며 화면을 덮는다.
- **파편 — 이른바 'Yutapon cubes':** 각진 다면체 파편이 밝은 면과 어두운 면의 2톤 평면 채색이다. 아주 작은 조각부터 화면을 가리는 큰 덩어리까지 크기 분포가 넓고, 회전하며 1s로 날아간다.
- **연기:** 갈색 평면 실루엣에 바깥쪽이 날카로운 가시처럼 뻗는다. 부드러운 그라데이션 없이 셀 2톤이다.
- **배경:** 원근이 강한 건물 외벽을 카메라가 훑는 배경 작화가 이어진다.
- **SFA 적합성:** 다면체 파편은 직선 3–4개로 된 닫힌 도형 + FR 면 2개(밝은 면·어두운 면)로 거의 그대로 옮길 수 있다. 회전과 크기 분포는 엔진이 계산한다. 가시형 연기도 직선·곡선 경계의 FR 2톤으로 표현할 수 있다 [추론].

이 관찰은 Claude의 시각 판독이다 [추론 포함]. 분할 수치는 [실측]이고, 카메라 이동이 있으면 유지 구간도 새 그림으로 잡히는 측정 한계가 있다.

## Stick Fighter로 옮길 때의 핵심 제약 (기존 분석 근거와 연결)

1. **트위닝은 프로젝트 전체에 하나의 설정이다.**
   - 기존 실물 시험에서 AO ID가 바뀌어 대체된 도형은 중간 보간 프레임에서 빠졌다(03 결과).
   - 매 프레임 모양이 새로 바뀌는 사쿠가식 이펙트를 T>P 프로젝트에 넣으면 깜박임이 생길 수 있다.
   - 따라서 1s·2s 작화 스타일은 **(T,P)=(24,24)처럼 보간을 끄고**, 2s·3s는 같은 프레임을 반복해 저장하는 방식이 기본이다 [기존 실물+정적 근거에서 추론].
2. **카메라 기능이 없다.** 카메라 회전·팬·셰이크는 생성 엔진이 모든 점을 변환해 표현한다. 화면 밖 좌표는 허용된다.
3. **플래시·검은 프레임**은 Frame.BackgroundColor로 1프레임만 바꾸거나, 화면 전체를 덮는 FR로 표현한다.
4. **2톤 불꽃·연기**는 FR 채우기 층 2개(밝은 외곽 + 어두운 core)와 DrawOrder·레이어로, 외곽 발광은 glow로 표현한다.
5. **불티·파편**은 짧은 직선 또는 곡선 + glow + 투명도 감쇠로, 집중선은 화면 밖에서 들어오는 직선 다발로 표현한다.
6. glow는 기본 선 알파와 독립적이다. glow가 객체별로 누적되므로, 겹치면 밝아지는 효과를 의도적으로 쓸 수 있다 [정적].

## 스타일 지식베이스 기록 단위 (초안)

클립마다 다음을 기록한다.
- post ID, md5, 작가 표기(`presumed` 여부 포함), 작품, 태그
- 컷 구간별 타이밍 분포
- 이펙트 종류와 형태 특징: 실루엣, 톤 수, 외곽 처리, 변형 방식, 수명(등장→소멸 프레임 수)
- 연출: 카메라, 전환, 플래시, 배경 작화 여부
- 캐릭터 동작 특징: 예비동작, 스미어, 오버슈트
- SFA 변환 아이디어

원본 이미지나 영상은 저장하지 않는다.

## 후보 애니메이터 선정 방법

1. 같은 게시물에 함께 태그된 작가는 '같은 컷 공동 작업자'이므로 유사도와 구분해 참고만 한다.
2. 게시물이 30개 이상인 작가(1,206명)마다 최근 게시물 최대 100개의 태그를 모아 general 태그 비율 벡터를 만든다. 뿌리와의 cosine 유사도와 중앙 점수(즐겨찾기 수 성격, 인기·최신작 편향 있음)를 표로 낸다.
3. 태그 유사도는 '다루는 소재'의 유사도이지 그림체 유사도가 아니다. 상위 후보는 대표 클립의 contact sheet로 시각 비교를 덧붙인 뒤 사용자에게 추천한다.
4. 사용자가 승낙한 작가만 수집·분석 대상에 넣는다.

## 보관 위치 확정 — 2026-10-17 (사용자 결정)

- 영상과 학습 자료는 **사용자의 Google Drive(5TB)**에 보관한다. 위의 '보관하지 않음' 추천은 이 결정으로 대체한다. GitHub 저장소에는 지금처럼 메타데이터와 분석 결과만 둔다.
- 서버 → Drive 업로드는 rclone을 쓴다. 권한은 `drive.file` 범위로 제한한다. 이 범위에서는 rclone이 직접 만든 파일만 보이고, Drive의 기존 개인 파일은 읽거나 지울 수 없다.
- 인증 정보는 채팅에 붙여넣지 않는다. 사용자가 환경 설정의 비밀값으로 다음 변수를 넣는다: `RCLONE_CONFIG_GDRIVE_TYPE=drive`, `RCLONE_CONFIG_GDRIVE_SCOPE=drive.file`, `RCLONE_CONFIG_GDRIVE_TOKEN=<rclone이 만든 token JSON>`. 새 세션부터 적용된다.
- Drive 폴더 구조(안): `AI-sfa/raw/<artist>/<post_id>_<md5>.<ext>`(원본), `AI-sfa/sheets/`(contact sheet), `AI-sfa/kb/`(지식베이스 사본). 원본 파일명에 md5를 넣어 중복 다운로드를 막는다.
- 현재 상태: 서버에서 googleapis.com 접속은 확인했다(인증 전이라 401 응답). rclone은 아직 설치하지 않았다. 토큰이 들어오기 전까지 업로드는 하지 않는다.
