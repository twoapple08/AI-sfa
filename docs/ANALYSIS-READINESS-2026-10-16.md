# 분석 근거 통합과 다음 단계 진입 조건 — 2026-10-16

기준 main은 `bf5ea5d3576e1e454c958b3e7c2692d3b8d3806a`다. 이 문서는 기존 보고서를 정리하고 현재 환경을 다시 확인한 결과다. 새 AOT 해석·ELF 명령 대조·앱 시험·렌더 재현을 완료한 보고서가 아니다. 혼자 가능한 모든 분석을 끝냈다는 뜻도 아니다.

## 현재까지 확보한 것

[기능 근거 색인](FEATURE-CONTRACT-INDEX-2026-10-16.json)은 13개 기능 범주에 기존 보고서 경로, 실제 표본의 범위, 정적으로 연결한 범위, 남은 질문을 연결한다. 범주는 작업 정리를 위한 묶음이며 전체 UI 기능의 완전한 목록은 아니다. `complete:false`는 전 범위 검증이 남았다는 뜻이며 기존의 제한된 확인 결과를 취소하지 않는다.

그룹 글로우 선택→셰이더 수학→내보내기 타임라인/FPS 연결은 [GROUP-SHADER-TIMELINE](AOT-GROUP-SHADER-TIMELINE-TRACE-2026-10-15.md)과 [EXPORT-DISPATCH](AOT-EXPORT-DISPATCH-TRACE-2026-10-15.md)의 기존 결과를 사용한다. 그룹은 객체별 글로우 호출, backend는 객체별 선택, 최종 출력 개수와 t는 timeline 산식, Java는 완성 프레임의 인코딩 단계다. 이를 실제 backend별 픽셀 동일성이나 완성된 애니메이팅 AI로 승격하지 않는다.

최근 그룹 복구·history·root rebase·DB 재작성·압축 단계·레이어 병합/삭제/추가·선택 객체 삭제 분석도 재사용한다. [기능표](FEATURE-EVIDENCE-MATRIX-2026-10-15.md)의 실제 앱/정적 분석 구분을 유지한다. 표본 수를 보고서 사이에서 독립 합산하지 않는다.

중복 대기도 정정했다. `_deleteAnchorPoint`의 note→연결/점 행 삭제→removed 기록은 [ROOT-FLAGS-LAYER-SWAP](AOT-ROOT-FLAGS-LAYER-SWAP-TRACE-2026-10-15.md)에 이미 있다. 전체 수명·다른 frame 보호가 미완이라는 이유로 이 기본 흐름까지 처음부터 다시 분석하지 않는다. `_buildCurrentFrameDialog` 역시 시간축 프레임 복사 메뉴라는 추측을 재사용하지 않는다.

캐시가 현재 보이지 않는 원인은 확인하지 못했다. 삭제 명령을 실행한 결과가 아니다. 복구한 공개 저장소의 audit는 과거 검사 기록이며 지금 원본을 재검증한 결과로 표시하지 않는다.

원본 APKS가 있어도 Blutter/도구 재설치·전체 재decompile을 수행하면 사용자의 반복 금지 지시와 충돌한다. 따라서 배포 ZIP/APKS를 다시 내려받거나 폰 설치·페어링·시작 시험을 시키는 방식으로 우회하지 않았다. 공개 저장소에 비공개 원본/역컴파일물/키가 없다는 점도 유지한다.

## 진행한 다음 단계

현재 가능한 **기존 근거 통합·검증 준비**를 진행했다. 기능 색인과 현행 인계를 맞추고, 중복 미완 항목과 오래된 ‘캐시 정상’ 전제를 정정했다. 색인의 필수 키·ID 고유성·13개 항목의 보고서 존재와 링크·JSON·diff를 검사한다. 문서/집계 변경뿐이므로 unit/probe·영상 분석·폰 시험은 반복하지 않는다.

본격적인 남은 정적 분석의 재개 조건은 기존 비공개 분석 캐시에 다시 접근하는 것이다. 적어도 해당 Dart AOT 파일과 관련 PP/objs, 명령 검증용 동일 ELF가 필요하다. 현재 자료만으로 내부 의미를 만들어 쓰거나 ‘혼자 할 일 모두 끝’이라고 보고하지 않는다. 학습·AI 통합은 계속 보류하며 사용자의 현재 PC 부재를 해소된 것으로 전제하지 않는다.
