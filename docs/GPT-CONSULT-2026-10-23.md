## 1. 최종 목표
- 안드로이드 앱 **Stick Fighter**(스틱파이터)의 애니메이션 파일 **.sfa**를 만드는 AI.
- 입력: 태그·자연어·스토리보드(장면별 카메라·사건). 출력: .sfa(5초마다 파일 하나).
- 최종적으로 **기기 안에서만 도는** 앱(APK 먼저, 개인용·비공개). 지금은 품질 확인 단계라 서버/PC 생성도 괜찮다.
- 원하는 결과물: 사쿠가(작화) 수준의 **연출·이펙트·타격감**. 뿌리 스타일은 **나카무라 유타카(이펙트·배경·연출, 압도적 1순위)**, 몸 동작 기본기는 **nian41**(스틱 애니메이터). 보충: riooo·optical-core·yukina_kosaka(이펙트·연출만).
- 기본 테스트 장면(기준 프롬프트 1): 도시 한복판, 하늘에서 붉은 섬광 → 캐릭터가 카메라 쪽으로 떨어져 화면을 가림 → 도시 구도에서 착지(균열·부유 파편) → 일어나 걸음 → 달리기(뒤로 빠지는 카메라, 솟는 붉은 가시) → 순간이동 펀치 → 암전. 사용자가 글자 애니매틱으로 의도한 시간표를 만들었다: `docs/storyboards/bench01_user_animatic_2026-10-23.md`.

## 2. 스틱파이터 / .sfa 형식 (확인된 것)
- ZIP 안의 XML 하나. `Sequence`(FrameCount, 비율, 배경색) → `Frame`(Position, 배경색) → `LayerDef` → `AO`(도형: TypeId 1 직선 / 2 원 / 3 곡선 = 2차 베지어로 가정, 색 ARGB·알파, 굵기, 레이어, 그리는 순서) → `AP`(점 좌표, 0–100 비율) / `AC`(점 연결) / `FR`·`FS`(채우기 영역: 점·곡선을 이은 경계 + 색·알파).
- 즉 **벡터 그림 도구**다: 선화(곡선) → 점을 이은 채우기 → 밑색 → 반투명 명암 여러 겹 → 배경. 프레임마다 그림을 따로 그리거나, 같은 AO ID를 유지해 트위닝(보간)할 수 있다. FPS는 (트위닝, 재생) 두 값.
- 상세: `docs/FORMAT.md`, 앱 기능 분석 다수(`docs/FEATURE-*`).
- 사용자가 정한 이펙트 그리기 원칙: 원·직선 같은 기본 도형으로 이펙트를 대신하지 않는다. 학습한 이펙트 형태를 **구간 제한 포물선 조각 수백 개**(Desmos로 그린 아이젠 영상 방식 = SFA의 곡선 AO)로 쌓고, **반투명을 적극 써서** 겹침·번짐을 만든다.

## 4. 지금까지 해 본 것과 결과 (정직하게)
1. **규칙 안무기 + 학습 자세(SFA 크리에이터 앱 v0.1)**: nian41 펀치 자세 53개 + 나카무라 타이밍 통계로 1:1 맨손 싸움을 규칙으로 조립. 동작은 되지만 단조롭다.
2. **3D 동작 모델(공개 MoMask, 글→3D 관절) 미세조정 1–8차**(GTX 1050 Ti, RTX 5060): 애니 2D 추적을 3D로 올려(2D→3D 리프터) 모캡과 섞어 학습.
   - 2D→3D 변환에서 자세가 망가졌다(예: "서 있음" 문장인데 엉덩이 높이 0.15m). 애니를 넣을수록 나빠져 6차부터 애니를 빼고 모캡만 → **사용자 판정: 결국 공개 3D 모캡을 가져다 만든 것, 의미 없음.**
   - **사용자 결정: 3D는 하지 않는다.**
3. **조립기**(스토리보드 → 장면별 동작 생성 → 3D 카메라 → SFA): 카메라·컷·장면 이음새는 사용자 애니매틱에 맞게 고쳤지만, 동작이 평범한 모캡이라 "느낌"이 안 난다(사용자 평가: 구도와 동작만 잘 잡혀도 느낌 있는 장면인데 결과가 별로).
4. **이펙트를 규칙으로 배치**(형태 사전 조각을 3D 공간에 배치): 품질 미달(붉은 가시가 빨간 벽처럼 보임). 형태 사전 자체는 쓸 만하다.
5. **키 자세를 손(코드)으로 직접 설계**: 사용자 평가 "못 만든다".
6. **이펙트 시퀀스 자료 1판**: 마스크 실루엣만이라 부족. 원본 색·선을 포함한 RGBA 판이 필요하다는 데까지 갔다.

교훈: Claude는 움직이는 영상을 직접 보지 못하고 정지 프레임·숫자로 판단해서 '보기 좋은가'를 놓쳤다. 감각 판단은 사용자가, 구현은 AI가 하는 분담이 맞다.
