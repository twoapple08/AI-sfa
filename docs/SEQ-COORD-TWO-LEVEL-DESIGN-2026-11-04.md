## 현행 토큰 체계(tools/sfa_tokens.py)

- 수 토큰 하나(NUM=8192)를 모든 분야가 공유: 좌표 0.025%(−50..154.8), FS T 0.001, 글로우 0.1, 굵기 로그 칸, 색 0–255, 점/오브젝트 번호·LINK 거리.
- 범위 밖 수: `BIG` + 8192진 세 자리.
- 학습 자료 표본(sd 페인트9 + sv38 파일, 1,234장): 장당 토큰 중앙값 630, **좌표 토큰 35%**, T 2.4%. 현재 자료는 이미 2048 이하만 남긴 상태.

## A안 세부(채택 시)

1. `sfa_tokens`: 새 특수 범위 `C0..C127`, `F0..F63`. 좌표 필드에서 `v→[C(v//64), F(v%64)]`. BIG은 그대로 두되 BIG 뒤 세 자리도 같은 두 단계로 바꿀지는 보류(BIG 2.7%).
2. 문법(grammar): 좌표 자리에서 C를 고르면 다음 자리는 F만 허용. C 범위는 기존 lo/hi에서 계산(lo//64..hi//64), F는 C가 경계 칸이면 lo%64/hi%64로 제한.
3. `seq_train.Data`: npz의 tok/fld를 불러올 때 변환(자료 커널 재실행 불필요). 손실은 C·F 각각 교차 엔트로피(이웃 ±2 부드러운 정답은 F에만 둘지 시험).
4. 모델: 어휘만 늘고 구조 동일. 기존 가중치에서 이어 학습은 출력 머리/임베딩이 바뀌므로 새로 학습 또는 인코더만 이어받기.
5. maxlen 2048→3072. 묶음 토큰 예산은 유지하고 묶음 크기가 자동으로 줄게 둔다.
6. 평가: 토큰 정확도 대신 **분야별 + 좌표 픽셀 오차 + 순서 무관 렌더 비교**를 기본 보고로(진단에서 토큰 정답 하나 기준이 반대쪽 끝점을 틀림으로 셈).

## 함께 다룰 문제(별도 과제)

- 멈추지 못함: 객체 하나 뒤 EOS 확률≈0. 객체 수가 적은 그림이 학습 자료에 적다. 쉬운 그림부터(커리큘럼)·객체 수 분포 균형 검토.
- 순서 고정: 객체·끝점 순서를 하나로 정한 정답이 맞는 다른 순서를 틀림으로 가르친다. 정규 순서 규칙(예: 왼쪽 끝 먼저)을 자료에 강제하는 방안 검토.
