지난 검토 반영본이야. 코드상 지적 13개는 모두 확인했고 고쳤어. 다만 **실제 영향**은 구분해서 반론할게. 반영이 맞는지, 반론에 동의하는지, **PC/Kaggle 본 학습 전 필수가 남았는지** 판정해 줘.

추가로 내가 찾은 것:
- 왕복 검사가 모든 파일을 16:9로 렌더했어. 그래서 비율이 다른 파일은 위아래 남는 곳에 화면 밖 부분이 그려졌고, 새 화면 밖 판정이 '보이는 걸 뺐다'로 잘못 나왔어. 파일 비율로 렌더하게 고침.
- 계획 시간을 다 쓴 뒤 다시 실행하면 '이미 100%'로 끝났어. 계획을 안 정했으면 이번 실행만큼 늘림(재시작형 코사인).

### B. 반론 — 코드상 맞지만 실제 영향은 없었거나 작은 것
1. **순서 뒤집기(objscore:125)**: 우리 경로에선 AI 출력·정답 모두 `decode`로 만들어 XML 순서 = 그리는 순서라 일어나지 않아. 남의 파일을 채점할 때만 해당(그래도 고침).
2. **첫 CONTOUR·0,1,0(tokens:239)**: 학습 자료 22,371장 전부를 문법으로 검사했을 때 위반 0이었어. 실제 자료엔 없던 경우.
3. **LINK BIG(−1)(tokens:422)**: 정답 자료엔 없고 생성 때만 가능했어.
4. **화면 밖 판정(tokens:173)**: 옛 판정은 −30~130(화면 밖 30% 여유)이라 실제로 보이는 걸 뺀 예는 못 찾았어. 이론상 위험은 맞음.
5. **'PC 본 학습 전 필수: 있음'**: 학습 결과를 바꾸는 건 색 이웃 정답·메모리 부족 처리·검증 집계·자료 완료 표시·면 직선 자르기(드묾)였고, 채점기 문제는 평가 숫자에만 영향. 비용이 작아 다 고쳤지만 등급은 과했다고 봐.
6. **순서 정규화(2번)**: 미룸. 겹침 판정을 잘못 만들면 정답 자체가 틀어지고, 1판 결과로 그 소음이 실제 문제인지 먼저 볼 거야.
7. **메모리 계산**: 네 숫자(일반 저장 경로 8.27GiB)는 내가 다시 계산해도 맞아. 다만 PyTorch `nn.MultiheadAttention`은 `need_weights=False`면 `scaled_dot_product_attention`을 써. 실제 수용 여부는 GPU 실측으로 정할게.

### C. 원인 가르기(5번) — 결과
설정: 비율 고친 새 자료 44장(8개 파일), 작은 모델(800만 변수, 320폭, 1/8 특징, 3층), CPU 22분, 956걸음. 학습 맞힘 91%, 같은 44장 검증 89%(외우기 시험이라 같은 장).

`seq_diag.py`로 같은 정답 문장에 세 가지 영상을 넣었어(16장).

| 입력 영상 | 교사 강제 손실 | 좌표 칸 ±4 맞힘 | 생성: 원본 582개 중 맞힘 | 연결 F1 |
|---|---|---|---|---|
| 정상 | 1.187 | 75.5% | **181 (31.1%)** | 20.6% |
| 다른 파일 장(섞음) | 1.823 | 57.4% | **0 (0.0%)** | 0% |
| 흰 화면 | 1.635 | 61.2% | **11 (1.9%)** | 0% |

해석:
- 모델은 영상을 보고 위치를 읽어(정상 31% ↔ 섞음 0%). 교차 주의만으로 좌표를 읽는 구조 자체는 된다.
- 옛 CPU 테스트의 0점은 규모(작은 모델·짧은 학습·1/16 특징)와 16:9 레터박스 자료 탓으로 봐.
- 교사 강제 좌표 맞힘은 섞음에서도 57%야. 앞 점이 주어지면 다음 점이 가까워서 그래. 그래서 영상 의존도는 생성 채점으로 봐야 해. 네 7번 지적이 맞았어.
- 그림: 외운 장면에서도 위치·색·테두리는 대체로 맞고, 세부 관절·연결은 아직 틀려.
