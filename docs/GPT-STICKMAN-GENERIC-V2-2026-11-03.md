구도 태그2개는 관측 범위에 대한 입력이다. 구도 종류까지 자동 분류한 결과라고 부르지 않는다. 종아리 끝은 신발 쪽 색/폭 변화에 대한 표시 해석이며 해부학적 발목 정답이 아니다. 실제 좌우,보이지 않는 쪽 궤적,틀 밖 무릎/골반/머리는 추론이다. 종아리 굵기는 같은 컷847장의 척도를 차용했고,보이는 조각 길이를 카메라 거리로 바꾸지 않았다.

팔 조정은 원본 키마다 다른 투영 길이를 사용한다. 원본의 직선 펀치를 굽히지 않고,손목을 몸 쪽으로 당겨 길이를 맞추지도 않는다. 한 허브와 고정 손목으로 해당 길이를 만족시킬 수 없으면 기존 자세를 남기고 보고한다. 두 어깨를 한 허브로 바꾸는 표현의 한계까지 해결했다고 세지 않는다. 이번834–869 제어 시험에서는 왼팔9·오른팔8개 장의 팔꿈치를 조정했고,불가능 판정도 각각9·8장 남았다. 숨긴 팔의 숫자는 실제 팔 정답으로 학습하지 않는다.

확대 얼굴에는 독립 CPU 얼굴 관측을 보조로 시험했다. 원영상 지문,인물색,기존 얼굴점과의 위치를 대조한다. 보조 모델이 놓친 얼굴은 같은 컷의 확인된 얼굴과2D 얼굴점 모양이 맞을 때 이동/확대한다. 미검출만으로 인물을 지우지 않는다. 기존 A안의 사용자 승인을 새 부분 구도 전체의 승인으로 확대하지 않는다. 이 시험에는 가려진 몸통 허브의 추론 재배치도 들어간다.

## 재사용하는 설정과 도구

11객체 연결·Flags·몸통 형식·흰 머리 Kind1·장마다 새 점 ID·장간 객체 ID는 그대로다. `profiles/stickman_2d_v1.json`은 변경하지 않았다. 수정 대상은 관측 선택/보간/표현이고,새 장면마다 점 연결 코드를 고치는 방식이 아니다.

- 기존 경로: `stickman_clip.py --projection --image-keys`. 기본v1 동작 보존.
- 공통v2 선택: 위에 `--key-motion-v2`. 좌표/척도 키,지역적 가림,중복 관측 거부 시험.
- 팔 선택 시험: `--projected-arm-lengths`. 원본 키별2D 길이와 손목을 유지하는 팔꿈치 조정.
- 부분 위몸: `--body-views scenes/nian41_432-1871_body_views_v2.json`. 구도 데이터이며 장별 좌표가 아니다.
- 얼굴 보조: `stickman_face_evidence.py`가 CPU 관측 JSON을 만들고 `--face-evidence`로 입력. ONNX는 비공개/외부 캐시만. 사용 모델 `deepghs/anime_face_detection/face_detect_v1.4_n`,SHA-256 `fd860b650a4377046842c3cd80d01b0b408bdfbdb4acee5759630f82c6ef04a9`.
- 미검출 종아리: `stickman_limb_view.py 원본.mp4 보정전기본.sfa scenes/nian41_432-1871_views_v2.json 결과.json`. 설정의 구도/범위와 같은 컷 기준 장을 읽어 기존 `partials` 형식 좌표를 생성한다. 출력은 Drive에만 보관한다. 이미 인물이 있는 장을 덮지 않는다.
- 검증: `stickman_quality.py --visibility-plan 계획.json`,면이 있으면 `--surface`도 준다. 자동 표시 계획과 실제 Color/흰 채움의 일치를 검사하며,계획의 의미적 정답을 승인하지 않는다. 연결/ID 검사는 그대로 유지한다. 표시하기로 한 부분 인물이 비어도 이제 오류다.

`--fit-cache`는 K/유효 가중/파라미터/피팅 코드 지문이 같을 때만 CPU 피팅을 재사용한다. 원본 템플릿 경계와 선택 관측도 비공개 캐시에 보존해 후단 수정 때 재피팅/템플릿 계산을 반복하지 않았다. 생성·검사 스크립트와 고정 입력은 Drive 재현 묶음으로 보존한다.

## 실제 검증과 아직 남은 일

확장부47인물·컷에서 기본v1 좌표를 수정 전 구현과 대조해 최대차0px. v2 저장 좌표 재계산 차이는 출력 소수 반올림 범위0.005px 이하였으며,이를 포즈 정답 증거로 쓰지 않는다. 팔 추가 시험 전후 실제 SFA는847–869 안의15장만 변경했고 나머지1,425장과 사용자 긍정 확인의834–846 전13장은 XML 그대로다. 팔꿈치 제어 단계에서는 손목·목/골반·다리 변화0px; 이후847–850의 부분 구도 단계는 별도로 다리/가림을 복구한다.

전체1,440장·2,027회 등장,흰 머리2,002개와 기존 근경 면2개. 구조·연결·채움·기존 접촉 검사0건. 자동 표시 계획229개 인물·장과 기존 부분 장면을 함께 검사했다. 전체 비교 영상은24fps·60초이고,부분 비교는12fps 반속 반복이다. 전체 영상을 생성한 것과 모든 장을 원본 크기로 눈 합격 판정한 것은 다르다. 이 단계의 Python 전체 시험은265개 OK·종료코드0. 실제 CLI의 종아리13장 생성과23장 구간의 새 팔/부분 구도 옵션 실행도 종료코드0. 새 SFA의 실제 앱 편집은 별도 미확인이다. 모바일 뷰어/Windows/APK는 이번에 바꾸지 않았다.

아직601 손 확대의 전신 오인,759 팔 중복,1326 근경 차기 누락,1608 일부 다리/이펙트 등이 남는다. 보조 CLIP 분류와 단순 광류 시험은 이를 안정적으로 복구하지 못해 운영 규칙에 넣지 않았다. 팔 수정 제어 시험도 중앙 허브 때문에 불가능한 경우가 남아 눈 판정이 필요하다. 학습 승인 자료가 아니다.

이60초 진단은432–1031/1032–1271/1272–1871로 나눈 실험이다. 중앙도 같은 공통 처리로 다시 피팅했으며 승인240장을 단순히 붙여 일반화 성공이라고 주장하지 않는다. 다만1032·1272는 원본 컷이 아닌 실험 분할 경계다. 최종 연속판은 원본 컷으로 합쳐 경계/척도를 다시 확인해야 한다.

이전 실패판의 새 수동 보완은 이어쓰지 않았다. 원본723에는 실제 파랑 인물이 있고,원본880에는 빨강 머리/팔도 있다. 이를 물체만/다리만이라고 지운 과거 부분 라벨은 잘못됐다. 기존 실패 이력은 보존하되 새 정답으로 재사용하지 않는다. 기존 애니메이터별 규칙·판정 JSON은 변경하지 않았다. GPU·학습·Kaggle 조회는 이번 작업에서 실행하지 않았다.
