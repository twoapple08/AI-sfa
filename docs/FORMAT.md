# 관찰한 SFA 구조

> 이 문서는 초기 관찰과 후속 정정을 날짜별로 보존한다. 구조와 그리기/편집의 최신 비교 입구는 [SFA 구조·단어체계 조사(11-06)](GPT-SFA-STRUCTURE-VOCABULARY-2026-11-06.md)다. 아래 초기 ‘미확인’을 후반 앱 확인·현행 코드보다 우선하지 않는다.

근거: 사용자가 제공한 `01_base`부터 `09_tween.sfa.sfa`까지 9개 샘플, 완성 화면, MP4와 현재 앱 사용 설명. 현재 앱 버전 번호는 아직 확보하지 않았습니다. 이 문서는 공식 전체 명세가 아닙니다.

## 컨테이너와 요소

9개 샘플 모두 ZIP 안에 XML 하나가 있습니다. 이중 `.sfa.sfa` 확장자는 컨테이너 내용을 바꾸지 않았습니다.

| 요소/속성 | 관찰 |
|---|---|
| Sequence | Name, FrameCount, RatioX, RatioY, HeightWidthRatio, BackgroundColor |
| Frame | ID, 0부터 시작하는 Position, BackgroundColor |
| LayerDef | ID, Name, Visible, Locked |
| AO | 도형 요소. ID, TypeId, Color, LayerId, DrawOrder, ThicknessScale, ObjectScale, Glow 관련 속성 |
| AP | 좌표점. ID, Flags, Index, X, Y |
| AC | ConnPtId로 같은 프레임의 AP 참조 |
| FR | 채우기 영역. Color |
| FS | 채우기 경계. Kind, ObjId, StartPtId, EndPtId, StartT, EndT |

TypeId 1은 직선, 2는 원, 3은 곡선으로 화면과 대응합니다. 삼각형/사각형은 여러 직선과 연결 참조로 구성됩니다. 곡선의 정확한 수학식은 미확인입니다. 미리보기는 이차 베지어를 가정합니다.

기본 스틱맨: AO 10개(원 1개 + 직선 9개), AP 20개입니다. AP 개수는 고유한 신체 관절 수와 다릅니다. 같은 위치의 여러 끝점이 AC로 연결됩니다.

## 비교 결과

- 02_arm: 기본과 비교해 AP 한 곳의 좌표만 변경.
- 03_position: AP 20개가 동일한 X/Y 변화량으로 이동.
- 05_same: 기본과 좌표가 동일하지만 프레임·도형·점 식별 번호 등은 다름.
- 06_shapes: AO 10개, AP 21개, TypeId 1/2/3. 연결된 선 도형 포함.
- 07_custom: AO 7개와 FR 1개/FS 3개. 별도 비트맵 파일 없음.
- 08_layers: LayerDef 2개, AO 20개. 각 AO에 레이어 번호와 색상 기록.
- 09_tween: 5개 Frame, 프레임마다 AO 10개/AP 20개. 같은 AO ID가 프레임 사이 유지되며 AP ID는 달라짐.
- 첨부 MP4: 1920×1080, 24FPS, 실제 5프레임, 길이 약 0.208333초. 사용자가 재생/트위닝을 모두 24로 설정했다고 설명했으므로 추가 보간이 없는 조건.

## 좌표와 표시의 가정

미리보기는 X/Y를 각 축 0~100 비율로 취급합니다. 프레임 밖 좌표를 허용합니다. 가로세로 비율을 적용한 뒤 원의 두 점을 지름 양 끝으로 취급합니다. 정확한 앱 렌더러 검증은 남아 있습니다.
색상은 관찰된 음수/양수 값을 모두 32비트 ARGB로 해석합니다.

## 트위닝 및 커스텀

사용자 설명:

- 재생 FPS: 원본 프레임의 초당 재생 수.
- 트위닝 FPS: 보간을 포함해 보이는 초당 프레임 수.
- 두 값이 같으면 추가 보간 없음. 재생 24 / 트위닝 48이면 중간 프레임 생성.
- 커스텀 가져오기는 SFA 첫 프레임을 사용. 커스텀 제작 UI는 이 프로젝트의 초기 범위에서 제외.

현재 9개 XML에서 명시적인 FPS/트위닝 설정을 찾지 못했습니다. 이 설정의 저장 위치, 보간 함수, 생성/삭제/변형 시 대응 규칙은 아직 미확인입니다. AO ID의 지속성만으로 트위닝 규칙을 확정하지 않습니다.

## 다음 검증 순서

1. roundtrip 파일을 현재 앱에서 열어 외형과 편집 가능 여부 확인.
2. 48프레임 wave_test를 재생 24/트위닝 24에서 확인.
3. 이후 필요할 때만 동일 원본의 재생 24/트위닝 48 결과나 APK 저장/재생 코드로 보간 동작 확인.
4. 자연어 → 간결한 동작 명령 → 결정적인 프레임 생성 → SFA 변환 구조 개발.

Flags의 비트 의미, 글로우·굵기·스케일 계산, 레이어/그리기 순서 우선순위, FR 경계의 곡선 처리도 추가 확인 대상입니다. 도구는 기존 XML의 알 수 없는 속성/요소를 삭제하지 않습니다. ZIP 부가 파일·주석·XML 공백/바이트 배열까지 보존하는 포렌식 복제 도구는 아닙니다.

첨부 순서와 길이/프레임 수의 일치로 대응을 판단했습니다. 두 영상 모두 원본 프레임 수 × (60/12) = 영상 프레임 수이고, 영상 길이는 원본 프레임 수 / 12입니다. 이 조건에서는 다섯 배의 출력 프레임 수가 확인되지만, 개별 구간 보간 방식이나 끝 프레임 처리 규칙 전체까지 입증하지는 않습니다.

추가 발견:

- 첫 작품에는 Frame 하위 TweenLink(ID, From) 10개가 있습니다. 트위닝 관련 대응 정보로 추정하지만 정확한 참조 방향과 의미는 미확인입니다. 삭제하지 않고 보존합니다.

- FS Kind=1은 점 ID 없이 ObjId만 갖는 경우가 있습니다. 두 번째 작품에는 Contour 속성도 있습니다. 정확한 의미는 미확인입니다.

제공받은 작품 원본과 영상은 저장소에 올리지 않고 분석 근거만 기록했습니다.

## 채우기 투명도 [앱 화면 확인 2026-10-23]
채우기(FR)는 자기 색과 불투명도를 따로 가진다(앱 채우기 색상 화면의 OPACITY). 경계 선의 알파를 0으로 해도 채우기는 영향을 받지 않는다. 생성 파일의 반투명 채우기(FR 색 알파)는 앱 재생에서 반영된다(녹화 대조).

## 파일을 만들 때 지킬 ID·레이어 규칙 (2026-10-29 앱 확인)
- 앱은 불러올 때 AO ID 하나를 파일 전체의 공통 오브젝트로 만들고, **레이어·종류도 ID마다 하나**로 저장한다. DrawOrder는 읽지 않고 **처음 나온 순서**로 새 순서값을 준다([AOT-PATH-TRACE](AOT-PATH-TRACE-2026-10-15.md) §1).
- 그래서 장마다 새 ID를 '그 장 최대+1'로 매기면, 장마다 오브젝트 수가 다를 때 같은 ID가 장에 따라 다른 레이어가 되어 앱이 한쪽으로 묶는다(합성 시험: 빛 레이어가 비고 빛이 배경에 들어감). → 역할별 ID 구간 고정, 같은 ID는 모든 장에서 같은 레이어·종류.
- 면을 아래에 깔거나 위에 덮을 때는 DrawOrder가 아니라 **레이어**로 나눈다(같은 레이어에 DrawOrder만 낮춘 배경이 앱에서 인물 선을 덮음).
- 점(AP) ID는 파일 전체에서 겹치지 않게.
- 검사: `ID마다 (LayerId, TypeId)가 하나인지`, `AP ID 중복 없음`.

## 레이어 전체 투명도 (2026-10-29 사용자: 최근 앱 패치로 생김)
- 레이어 하나의 전체 투명도를 조절하는 기능이 새로 나왔다. **이 기능을 쓴 파일은 아직 받지 않았다** → 저장 형식(LayerDef 속성 이름·값 범위)·렌더 방식(레이어를 따로 그린 뒤 한 번에 투명도 적용인지, 오브젝트마다 알파를 곱하는지)은 미확인.
- 우리 렌더러·학습 정답(`vec_data.targets`)은 아직 이 값을 모른다. 파일이 오면: XML에서 새 속성 찾기 → 앱 영상과 렌더 대조(겹친 반투명 오브젝트에서 두 방식이 다르게 보임) → 렌더러·정답·합성에 반영.

## 페인트(면)는 테두리 구간으로 저장된다 — 사용자 앱 확인(2026-11-01 녹화)
- 연결(AC) 없는 직선 3개를 교차시켜 생긴 삼각형을 페인트로 칠하면 둘러싸인 삼각형만 칠해진다(삐져나온 선 끝은 안 칠해짐). **관절 연결은 칠하기 조건이 아니다.**
- 칠한 뒤 선들을 떨어뜨려도 면은 사라지지 않고, 각 선의 원래 테두리 구간(FS의 StartT–EndT)을 따라가며 끊긴 틈은 직선으로 이어져 다각형이 된다.
- 즉 면은 '칠한 순간의 영역'이 아니라 '오브젝트별 T 구간 + 조각 사이 자동 연결선'으로 저장·그려진다. AOT 분석(docs/AOT-FILL-PATH-TRACE-2026-10-15.md: 이전 끝→다음 시작 거리 > 0.1이면 연결선 추가)과 일치.
- 원 구간의 T=0은 원 첫 점 방향이다 → 같은 원이라도 지름을 적은 방향이 다르면 같은 T 구간이 다른 자리를 가리킨다(채점 시 방향 대응 필요, docs/GPT-REVIEW-JUDGE-CRITERIA-ROUND2-2026-10-31.md H1).
- 원본 녹화는 저장소에 넣지 않는다.

## 앱 업데이트 내역 — 레이어 투명도 기능 판에서 함께 바뀐 것(사용자 전달, 2026-11-03)
- **레이어 투명도**(LayerDef `Opacity`)가 추가됐다. 수집 파일 중 막고라 1–11에만 있다.
- **색상 코드 통일:** 페인트 기능과 일반 색 조정 부분의 색 코드 형식이 서로 달랐다(사용자 기억: 앞에 00이 두 개 붙는 식). 지금은 통일됐다.
  - [측정] 수집 SFA 477개에서 FR(페인트) `Color`의 알파 바이트가 00인 경우는 0건이다. FR·AO 모두 부호 있는 32비트 ARGB 정수로 저장된다. 그래서 차이는 저장 형식보다 앱의 색 코드 입력·표시 쪽이었을 가능성이 크다(추정, 앱 UI 미확인).
  - AO `Color` 알파 00(52,712개)은 '안 보이는 곡선 + 글로우' 기법이라 이 항목과 무관하다.

  - `tools/sfa_render.py`는 AO 하나를 경로 하나로 한 번에 그려(drawPath 1회) 같은 오브젝트의 자기 겹침이 두 번 칠해지지 않는다. 현재 앱 동작과 같다.
  - 옛 앱으로 녹화한 영상과 대조할 때는 이 차이로 겹침 부분 밝기가 다를 수 있다.


## 레이어 이름·순서 (2026-11-05 사용자 녹화·설명)
- 레이어 이름은 불러오기 시 그대로 표시(영문 점·슬래시, 한글·밑줄 확인). 기본형 `Layer N`은 화면에 `레이어 N`으로 현지화 표시하되 파일에는 `Layer N` 그대로 저장. **저장 후 이름 보존 확인**(11-05 사용자 저장본). 저장 시 앱이 객체 ID를 새로 매긴다(DrawOrder=ID).
- **레이어 순서는 모든 프레임이 공유한다**(사용자 설명). 병합도 "모든 컷에서" 적용된다. 장마다 다른 앞뒤는 레이어 순서로 만들 수 없다.
