# 재계획 — 사용자 요구 조건 모음 (2026-11-05, 진행 중)

사용자(11-05): "모든 정보와 시스템 등 지금껏 해온 모든 것은 남겨둔 채로 처음부터 계획 수립. 너무 산발식·문어발식이었다."

## 사용자 발언(순서대로, 11-05)
1. 먼저 애니 전문 생성 AI들의 생성 구조를 알아야 한다 → docs/RESEARCH-ANIME-GEN-ARCHITECTURES-2026-11-05.md
2. **만드는 것은 액션물**이다. 디자인·카툰처럼 귀여운 것이 아니다.
3. 비슷한 느낌의 애니메이팅을 하는 사람들을 모아 왔다(자료 이미 있음). **이 사람들의 특징을 반영한 애니**를 만든다. (작가별 학습 범위는 AGENTS.md 기록 고정, 재해석·재질문 없음.)
4. 그림체: 이펙트·연출은 비슷하게 하더라도, **캐릭터는 그 작품 고유의 색이라 캐릭터 쪽 그림체는 제외**(10-28 규칙과 같음).
5. 그래서 **캐릭터는 움직이는 부분만 추출해 스틱맨화**한다.
6. **창작**이다. 스틱맨에게 **사용자만의 고유 캐릭터 디자인·능력**을 표현할 수 있어야 한다.
7. 아무 조건이 없으면 제멋대로 만드니 **레퍼런스·태그를 받을 줄 알아야** 한다. 예: "1초~3초 캐릭터가 걸어가는 장면을 어떤 구도로 무엇을 함" 같은 시간 구간 문장, `debris, dust, wind` 같은 태그. **부정 프롬프트**로 넣고 싶지 않은 요소를 뺄 수 있어야 한다. **스토리보드**도 받을 줄 알아야 한다.
   - 보강(사용자 11-05): **긍정 프롬프트에 입력하지 않았어도, 부정 프롬프트에 없다면 넣으면 좋은 요소나 연출을 스스로 넣기도 한다.** 부정 프롬프트가 항상 우선(자율 보강으로도 금지 요소는 안 넣음). 기존 스토리보드 '비우면 AI가 정함'과 같은 방향. **확정(사용자 11-05): 자율 보강 정도 값을 넣고 사람이 조절한다**(0 = 쓴 것만, 높을수록 연출을 적극적으로 더함; 부정 프롬프트는 값과 무관하게 우선). 필요한 학습: 장면 종류별로 함께 나오는 요소(착지 → 먼지·충격파, 강타 → 임팩트 프레임 등)를 태그 자료에서 배운다.
8. **스틱파이터 기준 (24, 24)로 제작**(트위닝 24 · 재생 24, 앱 트위닝 없이 24장/초 모두 직접 — 10-25 규칙과 같음). 내부 표현이 키프레임이어도 최종 .sfa는 24장/초를 모두 펼쳐 쓴다.
9. **사람이 만든 커스텀 무기 파일**을 넣어 활용할 수 있어야 한다. 스틱맨 하나와 해당 무기의 크기 비교, 어디를 잡고 어디를 휘두르는지 등 **정지 컷을 주면 활용**할 줄 알아야 한다.

10. 상황에 따라 스틱맨이 아닌 **실제 손·팔·다리·몸통·머리·머리카락·얼굴**을 그릴 수도 있어야 한다. **옷도 포함**.
    - 4번(캐릭터 그림체 제외)과의 정리(Claude 제안): 애니메이터 자료에서는 '근접 묘사를 한다는 연출 + 자세·움직임·구도'만, **그림체(선·비율·옷·머리 모양)는 가져오지 않는다**. 그림체 출처 후보: (가) 사용자 캐릭터 시트(사용자 부품으로) (나) 수집 SFA의 그리는 기술 (다) 둘 다 — 제안 (다). **확인 필요:** 수집 SFA 속 남의 캐릭터 그림을 '그리는 기술'로 배워도 되는가.
    - 스틱맨 ↔ 실제 신체 전환은 장면 내용·구도(거리)로 정한다.
11. **스틱맨 버전에 넣는 액세서리**도 다룰 수 있어야 한다(사용자 11-05). → 사용자 부품 틀(부품 + 붙는 관절 + 움직이는 방식)로 처리: 강체 액세서리(모자·장신구 등)는 붙는 관절을 따라 옮기고, 흔들리는 것(망토·끈·머리 장식 등)은 붙는 점 + 늘어짐·흔들림 규칙. 그림체는 사용자 설정에서만.

12. **배경(3D) — 사용자 11-05 보강(조건 나열 A-11 '배경 3D 허용'의 상세):**
    - 배경은 3D를 활용한 **입체적 연출**이 많을 것이다. **실제 공간을 사용자 프롬프트, 실제 3D 모델링, 또는 여러 이미지를 받아 짜고**, **카메라 무빙을 더해 촬영**한다.
    - 그렇게 나온 배경을 SFA로 그린다: **윤곽선 + 밑색**, **그림자·명암은 선택 사항**.
    - **고정 구도·각도에서 상하좌우 이동과 확대만 있을 때**는 보여 줄 만큼의 배경을 한 번 그려 두고, 다음 장에서 새로 그리지 않고 **위치·크기만 옮긴다**.
    - **거리에 따른 윤곽선 두께 조절은 필수.** X·Y축 윤곽선은 선으로 해도 되나, **Z축(안쪽으로 뻗는) 윤곽선은 면으로 거리감을 표현**.
    - 그 배경 안에서 스틱맨들과 모션이 나오며, **배경에 영향을 주는 요소**(예: 벽 파손·파편·먼지·바닥 균열 등)도 반영되어야 한다.
    - 기존 근거: tools/slice/room3d.py v2(거리 굵기 = 1.0×기준 깊이/깊이, Z축 사다리꼴 면, 정확한 가림), tools/slice/plate.py(고정 각도 컷의 판 + 장별 이동). 카메라 회전·원근 변화가 있는 무빙은 3D에서 장마다 다시 투영(평행 이동 판 방식은 쓰지 않음).

13. **이어 만들기(사용자 11-05):** 한 번에 밀도 높은 긴 애니메이션을 뽑는 것은 무리이고 장면 전환 같은 요소도 있으므로, **전 장면 파일에서 이어지는 시스템**이 있어야 한다.
    - Claude 정리(제안): 앞 .sfa의 끝 상태를 읽어 다음 생성의 조건으로 넣는다 — 인물별 마지막 자세·위치·속도(동작이 끊기지 않게), 캐릭터·무기·액세서리 설정, 카메라 위치, 배경 공간과 **바뀐 상태**(부서진 벽·쌓인 파편 등은 다음 장면에도 남음), 진행 중인 이펙트. 이어 붙이기 방식: 같은 컷 계속 / 장면 전환(컷 전환·암전·매치 컷 등, 스토리보드 형식에 전환 종류 추가). 객체 ID는 같은 대상이면 파일끼리도 이어 쓸 수 있게(합치기 쉬움).
    - 보강(사용자 11-05): **구도가 바뀌는 장면 전환에서도 배경의 상태·위치·사물이 달라지면 안 된다** → 배경·사물·파손 상태를 3D 공간 하나(장면 세계)에 계속 기록해 두고, 새 구도는 그 공간을 다른 카메라로 다시 찍는다(Claude 정리). 인물 위치도 같은 공간 좌표로 잇는다.
    - 보강(사용자 11-05): **마지막 장만 보면 템포가 어긋날 수 있으니 앞 파일 전체를 볼 줄 알아야 한다** → 앞 장면 전체에서 리듬(타격 간격·멈춤 길이·2/3장 유지 패턴·카메라 속도·고조 흐름)을 읽어 다음 장면의 조건으로 넣는다(Claude 정리).

14. **음악 맞춤(사용자 11-05):** 음악 파일을 넣어 **하이라이트, 그 전의 빌드업, 정적인 부분**, 그리고 **박자와 타이밍에 맞춘 애니메이션**을 만드는 기능.
    - Claude 정리(**사용자 확인 11-05 "응 맞아"**): 음악 분석(박자·강박·소리 시작점·세기 곡선·구간 나누기 — 빌드업/하이라이트(드롭)/정적 구간)을 24장/초 장 번호로 바꿔 '음악 시간표'를 만들고, 생성 조건으로 넣는다. 강박에 타격·컷 전환·임팩트 프레임, 빌드업에 모으기·긴장(멈춤·느린 카메라), 하이라이트에 연타·큰 이펙트, 정적 구간에 움직임 줄이기. 스토리보드 칸과 같은 형식으로 사용자가 고쳐 쓸 수 있게. 분석 도구는 기존 공개 라이브러리(박자 추적·구간 분할) 사용. 음악 파일은 공개 저장소에 넣지 않는다.

15. **스타일을 원하는 연출에 적용(사용자 11-05):** 수집한 애니메이터들만으로는 사용자가 하고 싶은 모든 연출(분위기·느낌·구도 등)을 할 수 없다. 그래서 **준비된 자료의 사람들의 스타일을, 사용자가 원하는 연출에 적용하는 방식**으로 한다. 필요하면 **추가 자료를 수집**한다.
    - Claude 정리(제안): '무엇을 연출하나'(구도·분위기·카메라·장면 구성)와 '어떻게 그리나'(애니메이터 스타일: 타이밍·멈춤·이펙트 형태와 확산·선·글로우 쓰는 법)를 분리한다. 연출 내용은 사용자 입력(글·스토리보드·레퍼런스)과 추가 연출 자료에서, 스타일은 수집 애니메이터에게서만 온다. 애니메이터가 한 번도 안 한 구도에도 그 사람 스타일이 입혀지도록, 스타일을 '잴 수 있는 특징'(타이밍 분포·이펙트 형태 사전·선 사용 통계 등)으로 뽑아 조건으로 넣는다.
    - 추가 자료: 연출 내용용(구도·분위기·카메라 레퍼런스)과 스타일용(애니메이터)을 구분해 받는다. **새 애니메이터를 스타일 학습에 넣는 것은 기존 규칙대로 사용자 승낙 후**. 연출 내용용 자료는 수집 전에 출처·용도를 사용자에게 확인.

16. **이펙트 선 종류 정정(사용자 11-05):** 곡선뿐 아니라 **직선도 포함**. 곡선과 직선 둘 다 완벽히 쓸 줄 알면 기본 도형(원 등)은 필요 없다. → 기존 원칙(AGENTS.md '이펙트 그리기 원칙': 포물선 조각=2차 베지어, 원·직선 같은 기본 도형으로 대신하지 않음)의 '직선' 부분을 고친다: **직선(TypeId 1)과 곡선(TypeId 3) 조각을 모두 쓰고, 원(TypeId 2) 같은 기본 도형으로 형태를 대신하지 않는다.** 휘지 않은 부분은 직선으로(11-05 슬라이스 때 사용자 "직선을 써도 되는 부분에서는 직선을"과 같음).

17. **이펙트 밀도·디테일(사용자 11-05):** 이펙트를 만들 때 **면의 면적이나 선의 두께를 자유자재로 조절**하여 **밀도 있고 디테일하게** 만들어야 한다.
    - Claude 정리: 두께는 조각마다 다르게(같은 이펙트 안에서도 굵은 획·가는 획 섞기, 한 획 안의 굵기 변화는 조각 나누기 또는 사다리꼴·쐐기 면), 면은 크기·모양을 자유롭게(큰 덩어리 + 작은 조각·파편·틈), 기존 원칙(반투명 여러 겹·글로우·선→밑색→명암)과 함께. 조각 수에 임의 상한을 두지 않는다(10-21 규칙과 같음). 학습 자료에서 작가별 두께 분포·면 크기 분포·밀도(장당 조각 수)를 재서 스타일 특징으로 쓴다.

## 사용자 부품(무기·고유 부속·능력) 처리(9번, Claude 제안)
- 무기는 생성하지 않고 **사용자 SFA를 그대로 옮기는 강체 부품**. 정지 컷에서 크기 비(스틱맨 대비), 잡는 점, 손목 대비 각도, 휘두르는 부분(날·끝·타격면), 한손/양손을 읽는다.
- 생성기는 장마다 손목 위치 + 무기 각도만 정하고, 컴파일러가 사용자 무기 선을 변환해 붙인다 → 디자인 불변. 휘두름 감각(속도·멈춤·스미어)은 애니메이터 자료에서, 스미어·궤적·타격 이펙트는 '휘두르는 부분'에서 발생.
- 같은 틀(부품 + 붙는 자리 + 움직이는 방식)로 캐릭터 고유 부속·능력도 다룬다.
- 질문: 잡는 점·날 표시를 (가) 그림만 보고 읽기 (나) 색·레이어 이름으로 표시 — 제안은 (가) 기본, 애매하면 (나) 요청.
