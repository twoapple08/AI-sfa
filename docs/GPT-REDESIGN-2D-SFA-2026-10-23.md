## 1. 핵심 결론

**추천은 ‘역할을 나눈 순수 2D 제작 시스템’이다.**

처음부터 완성 영상이나 SFA 전체를 생성하는 거대 모델을 만들기보다, 확보한 그림과 움직임을 충실하게 복원하고 조건에 맞게 변형하는 능력부터 학습한다.

자료 수백 개로 모든 장면을 자유롭게 만드는 사쿠가 생성기를 확보하기는 어렵다. 하지만 **범위를 정한 이펙트·연출에서 좋은 후보를 만들고, 사용자가 골라 완성하는 시스템**은 시도할 가치가 있다. 검증된 범위를 차례로 넓힌다.

첫 산출물은 큰 생성 모델이 아니다. **좋은 이펙트 약 20개를 실제 SFA에서 살려 내고, 그중 하나를 새로운 조건으로 바꿔도 좋은지 판단할 수 있는 시험 도구**다. 그 결과로 이후 학습 방향과 투자 규모를 결정한다.

## 2. 전체 구조: 역할은 나누고 사건·시간표는 공유

| 역할 | 추천 방식 | 사용하는 자료 |
|---|---|---|
| 장면 계획 | 기존 언어 모델이 구조화된 스토리보드 작성. 처음에는 사용자 시간표 그대로 사용 | 기준 프롬프트, 사용자 애니매틱, 태그 |
| 연출 | 유사 장면 검색 + 사건에 맞춘 시간·구도 조정. 이후 작은 선택 모델 | 카메라 흐름, 타격·임팩트 통계 |
| 이펙트 | 시퀀스 단위 검색·변형부터 시작하고 제한된 생성 모델로 확장 | 원본 색·선, 마스크, 형태 사전, 임팩트 책 |
| 캐릭터 | 2D 동작 검색·리타기팅 → 조건부 동작 수정 모델 | nian41 2D 추적, 신뢰할 수 있는 나카무라 추적 |
| 배경 | 장면마다 일관된 배경 그림과 분리된 2D 레이어 제작 | 원본의 배경 참고, 별도로 정리한 배경 자료 |
| SFA 출력 | 결정적인 변환기·검사기 | 곡선, 채우기, 알파, 레이어 |

별도 모듈이라고 서로 독립적으로 생성해서는 안 된다. 예를 들어 착지 사건에는 다음을 함께 기록하고 모든 모듈이 공유한다.

- 접촉 프레임과 화면 속 접촉 위치.
- 충격의 진행 방향.
- 이펙트 발생·최대 확장·소멸 시점.
- 인물과 이펙트의 앞뒤 관계.
- 카메라 변화와 임팩트 프레임.

이것이 동작과 이펙트가 따로 노는 문제를 줄이는 연결점이다. 타이밍 통계는 전역 평균을 그대로 적용하지 않고 착지·펀치·폭발 등 사건별 후보를 고르는 근거로 사용한다.

카메라는 **2D 이동·확대·회전과 레이어별 변환**으로 표현한다. 인물 크기를 유지하면서 배경만 작아지는 구도도 별도 변환으로 구현할 수 있다. 시점이 크게 달라지면 다른 배경 그림과 컷 전환을 사용한다. 3D 모캡·2D→3D 변환·3D 카메라 경로는 사용하지 않는다.

## 3. 출력 표현: 캐릭터는 벡터, 이펙트·배경은 그림을 거쳐 벡터

### 3.1 캐릭터

2D 관절·선 굵기·몸 비율에서 SFA 벡터로 바로 옮긴다. 이미 유용한 2D 추적이 있으므로 그림으로 바꿨다가 다시 관절을 찾을 필요가 없다.

관절만으로 표현할 수 없는 스미어·잔상·극단적인 변형은 별도 그림 레이어로 처리한다.

### 3.2 이펙트·배경

색·선·명암이 있는 래스터 또는 층별 그림을 만든 뒤, 기존 분해기로 곡선·채우기·반투명 레이어로 변환한다. 최종 출력은 편집 가능한 SFA 벡터다. 래스터 제작 단계가 있다는 뜻이지 최종 SFA에 비트맵을 넣는 제안이 아니다.

사용자 원칙대로 이펙트는 곡선 선화·채우기·반투명 명암을 사용하며 원·직선으로 대체하지 않는다. 그림 층의 의미와 실제 합성 순서를 구분하고, 밑색·명암·선의 의도한 외형을 보존한다.

### 3.3 SFA 전체 직접 생성 모델을 먼저 만들지 않는 이유

- 원본 영상은 있지만 대응하는 정답 SFA 학습쌍은 거의 없다.
- 같은 그림을 수많은 곡선 분할·ID 배치로 표현할 수 있다.
- 그림 실력과 파일 참조 규칙을 동시에 배워야 한다.
- 프레임마다 곡선 수와 연결 구조가 달라지면 시간 일관성도 어려워진다.

나중에 직접 벡터를 학습하더라도 XML 문자열보다 **정규화된 곡선·영역·레이어 구조**를 출력하게 하는 편이 적합하다. XML과 ID 참조는 변환기가 책임진다.

### 3.4 기존 도구에서 남길 부분과 보강할 부분

기존 곡선 맞춤 도구는 살릴 가치가 있다. 필요하면 래스터 재현 오차를 이용해 곡선을 추가 최적화할 수 있다. [DiffVG 연구](https://people.csail.mit.edu/tzumao/diffvg/)는 이 접근의 근거지만 SFA 전용 처리는 별도로 필요하다.

프레임마다 독립적으로 벡터화하면 원본에 없던 경계 떨림이 생길 수 있다. 같은 덩어리의 색·윤곽 대응을 시간축으로 추적하되, 실제 작화의 갑작스러운 형태 변화까지 매끈하게 지우지 않는다.

곡선 수를 임의로 제한해 품질을 낮추지는 않는다. 실제 표현량·파일 크기·재생 비용을 측정하고, 눈에 보이는 품질을 유지하는 최적화를 한다.

## 4. 첫 목표: 짧은 착지 충격 이펙트의 복원·변형 시험

첫 목표로 기준 프롬프트 전체를 새 모델 하나에 맡기지 않는다. **착지 순간의 섬광·파편·임팩트·카메라 반응을 다루는 약 1초짜리 시험**부터 만든다.

두 시험을 분리한다.

1. **복원 시험:** 원래 이펙트의 형태·선·색·시간을 SFA에서 얼마나 보존하는가.
2. **변형 시험:** 발생 위치·방향·규모·지속시간을 바꿔도 자연스러운가.

복원이 실패하면 변환·자료 문제다. 복원은 되지만 변형이 실패하면 변형·학습 문제다. 이 구분이 있어야 다음 GPU 사용에 의미가 있다.

좁은 시험으로 원인을 확인하면서, 기존 기준 프롬프트 전체 비교도 유지한다. 국소 개선이 실제 전체 장면 개선으로 이어지는지는 별도로 판단한다. 기존의 실패한 캐릭터 결과를 새 이펙트 모델의 성과나 실패로 혼동하지 않는다.

## 5. 단계별 실행 계획

### 단계 A — 학습 전에 재현 가능한 자료와 출력 경로 확보

- **무엇을:** 상태가 좋은 이펙트 시퀀스 약 20개를 골라 원본 → 층 분해 → SFA → 실제 앱 재생 비교.
- **자료:** 나카무라 디지털 이펙트, 기존 마스크, 형태 사전, 임팩트 책.
- **모델:** 새 학습 없음. 기존 분해기와 필요한 분리·추적 모델만 사용.
- **장소:** CPU 서버 중심. 무거운 분리 추론만 Kaggle·Colab.
- **확인:** 내부 선, 날카로운 끝, 반투명 겹침, 발생·소멸 타이밍을 움직이는 영상으로 확인.
- **범위:** 20개는 첫 검증 표본이며 최종 자료 상한이 아니다.

#### 반드시 수정할 전제: 마스크 RGB 잘라내기 ≠ 깨끗한 RGBA 추출

반투명 연기·빛의 픽셀에는 원래 배경색이 섞여 있다. 마스크는 영역을 알려줄 뿐 원래 전경색과 투명도를 복원하지 않는다.

| 자료 상태 | 처리 |
|---|---|
| 불투명 파편·명확한 선화 | 직접 추출해 사용 |
| 배경이 단순한 반투명 이펙트 | 배경 추정과 매팅을 시도하고 확인 |
| 복잡한 배경에 섞인 연기·발광 | 소수는 수작업 정리하거나 장면 전체 학습용으로 보존 |

완벽한 자동 분리를 전제로 수천 개를 먼저 만들지 않는다. 소수의 좋은 정답을 우선 확보한다.

화면 대부분을 덮는 사각형 마스크도 전부 버리지 않는다. 잘못 잡힌 마스크일 수 있지만 정상적인 전면 임팩트·암전·섬광일 수도 있다. 종류와 시간 맥락으로 구분한다.

#### 실제 앱 검증

이미 확인된 앱 동작은 재사용하고 새 출력의 미해결 부분만 확인한다. 서버 미리보기와 실제 Stick Fighter 결과가 같다고 가정하지 않는다.

현재 `effect_clip_sfa.py --check`는 일부 정지 프레임 비교이므로 시간 품질을 보장하지 않는다. 앱에서 여는지, 의도한 합성 순서인지, 재생·편집·저장이 가능한지를 확인한다.

`FORMAT.md`는 공식 전체 명세가 아니다. 곡선의 수학식·보간·FPS 저장 등 문서의 미확인 사항을 확인된 사실로 승격하지 않는다. 초기 이펙트 출력은 명시적인 프레임 그림과 의도한 노출시간을 우선하며, AO ID 유지 자체로 보간 결과를 보장하지 않는다.

### 단계 B — 검색한 시퀀스 전체를 조건에 맞게 변형

- **무엇을:** 종류·방향·발생점·규모·시간을 입력하면 관련 시퀀스를 찾고 변형하는 도구.
- **자료:** 단계 A에서 통과한 시퀀스부터 시작해 확장.
- **모델:** 처음에는 태그 검색과 기존 CLIP 같은 고정 특징 추출기. 변형은 시간에 따라 연속적인 2D 변형으로 시작.
- **장소:** 특징 추출만 GPU를 쓰고 검색·기본 변형은 CPU에서도 실행.
- **확인:** 같은 원본을 다른 조건에 적용했을 때 형태와 타격감이 유지되는지 비교.

기존 규칙 배치와의 차이는 정지 형태 조각을 뿌리는 대신 **발생→확장→분열→소멸의 관계를 함께 가져오는 것**이다.

검색·재생만 성공했다면 새로운 이펙트 생성에 도달한 것이 아니다. 이 단계는 품질 기준과 변형 범위를 확보하는 기반이다. 최종적으로 곡선·명암·궤적을 조건에 맞게 수정해야 하며 원본 덩어리를 찍어 붙이는 것으로 완료 처리하지 않는다.

### 단계 C — 작은 모델이 시간·변형·보정을 학습

첫 학습 대상은 다음과 같다.

> 참고 이펙트 시퀀스와 목표 조건을 받아 시간 재배치·2D 변형장·색/알파 보정을 예측하는 작은 조건부 모델.

- **무엇을:** 참고 시퀀스를 새로운 조건으로 바꾸는 모델.
- **자료:** 정리한 이펙트 시퀀스와 변형 예제. 실제 사용 중 선택·수정한 결과도 축적.
- **모델:** 작은 시간 합성곱 모델 또는 Transformer와 2D 보정 네트워크.
- **장소:** Kaggle·Colab의 16GB급 GPU 우선. 축소 실험은 RTX 5060 8GB.
- **확인:** 단순 검색·변형 기준선보다 좋아졌는지, 보지 않은 원본에서도 작동하는지 평가.

초기 학습 부분은 수백만 파라미터 수준으로 작게 시작하고 필요성을 확인한 뒤 늘린다. 품질 상한이 아니라 과적합과 자원 낭비를 줄이기 위한 출발점이다.

합성 변형으로 정답쌍을 늘릴 수 있지만 그것만으로 새 작화 능력을 배웠다고 보면 안 된다. 이미 적용한 변형을 되풀이하는 모델이 될 수 있다. 실제 다른 시퀀스와 사용자 수정 결과에서 개선이 확인돼야 한다.

시간 변형은 전체를 균일하게 늘리지 않는다. 준비·발생·최대 확장·잔향을 나눠 조정하고 임팩트의 짧은 노출은 별도로 보존한다.

### 단계 D — 새 그림 생성은 좁은 범위에서 추가

앞 단계가 통과한 뒤 한 종류에서 새 형태를 만드는 실험을 한다. 예: 착지 때 옆으로 퍼지는 날카로운 섬광.

두 경로를 비교한다.

| 경로 | 장점 | 위험 |
|---|---|---|
| 기존 이미지 모델 + 소규모 LoRA | 사전학습된 그림 능력으로 선·색·명암이 있는 주요 프레임 후보 생성 | 프레임별 독립 생성 시 형태 흔들림. 앞뒤 시간 변화는 별도 처리 필요 |
| 작은 조건부 시퀀스 생성기 | 한 종류의 짧은 이펙트 시간 구조를 직접 다룸 | 적은 자료에서 암기·과적합 위험 |

둘 다 기존 시퀀스 변형 기준선보다 좋아야 채택한다. 자료 품질과 초기 실측을 보기 전에 특정 대형 영상 체크포인트를 주력으로 확정하지 않는다.

LoRA는 메모리를 줄이는 방법이며 애니메이션 품질 보장 수단이 아니다. [Diffusers 공식 이미지 LoRA 문서](https://huggingface.co/docs/diffusers/training/lora)는 11GB GPU 학습 사례를 안내한다. 8GB 장비에 맞춘 축소·메모리 절약 설정은 별도 확인이 필요하다. 이 사례의 시간은 우리 실험 시간 보장이 아니다.

## 6. 적은 자료로 품질을 내기 위한 데이터 원칙

현재 1,694개 시퀀스와 15,165행 태그를 독립적인 창작 예제 수로 보면 안 된다. 같은 클립의 여러 물체·겹친 구간·인접 프레임이 포함되기 때문이다.

1. **같은 원본 클립의 모든 구간은 같은 학습/검증 묶음에 넣는다.** 가능하면 같은 원작 장면도 묶는다.
2. 실루엣뿐 아니라 내부 선·색·명암과 원래 시간을 보존한다.
3. 128×128은 거친 형태 실험에만 사용하고 최종 작화 품질은 더 높은 해상도에서 확인한다.
4. 모든 구간을 무조건 16프레임으로 재표본화하지 않는다. 원래 노출시간과 사건 시점을 따로 저장한다.
5. 증강은 방향·규모·색 등 의미가 유지되는 범위에 한정한다. 좌우 반전도 조명·진행 방향·구도를 틀리게 할 수 있다.
6. 사람이 고른 좋은 후보와 수정 내용을 다음 학습 자료로 축적한다.

기존 분포는 파편 683·연기 494·불 230·임팩트 161·폭발 73·섬광 46·불꽃 7개다. **불꽃 7개로 독립적인 자유 생성 능력을 기대하지 않는다.** 그 종류는 우선 검색·변형으로 제공하거나 자료를 추가 확보한다.

사용자 판정은 ‘맞음/아님’에서 한 단계 구체화한다. 형태·내부 선·시간·장면과의 결합 중 무엇이 실패했는지 기록한다. 초기에는 큰 취향 모델보다 후보 순위 기록과 간단한 선택 모델이면 충분하다.

증강된 프레임 수와 원본 장면 수를 별도로 보고한다. 검색·재현 성능과 새로운 조건에 대한 생성 성능도 별도로 보고한다.

## 7. 성공 판정

다음 수치는 보장된 성능이 아니라 **초기 통과 기준 제안**이다.

| 시험 | 통과 기준 |
|---|---|
| 복원 | 평가 표본 20개 중 16개 이상에서 사용자가 핵심 형태·선·리듬 보존을 인정 |
| 실제 SFA | 선택한 결과가 앱에서 열리고 재생·편집·저장되며 주요 외형 오류가 없음 |
| 조건 제어 | 발생점·방향·규모·시간을 바꿨을 때 각각 의도대로 반응 |
| 학습 효과 | 보지 않은 원본의 비교에서 단순 검색·변형보다 일관되게 선호됨 |
| 실사용성 | 좋은 결과 하나를 얻는 데 필요한 후보 수와 수작업 수정량이 줄어듦 |
| 전체 장면 | 기준 프롬프트 전체에서 이펙트·연출 개선이 실제로 보임 |

정상 속도 영상으로 먼저 판단한다. 느린 재생·프레임 비교는 원인 분석에 쓴다. 자동 지표는 윤곽 오차·색 오차·누락을 찾는 보조 수단이다. 타격감을 숫자 하나로 판정하지 않는다.

후보 순서를 섞어 비교하고 원본 재현과 새로운 조건 일반화를 분리한다. 작은 평가에서 한 번 이겼다고 확정하지 않고 별도 표본에서도 확인한다.

## 8. 연출·배경·캐릭터 확장

### 8.1 연출

연출은 이펙트와 일찍 결합한다. 카메라 흐름 추정값을 실제 카메라 정답으로 바로 학습하지 않는다. 움직이는 파편이나 화면 전체 변형을 카메라 이동으로 잘못 읽었을 수 있다.

소수의 좋은 장면에서 화면 가림 전환·배경만 후퇴·임팩트 직후 흔들림·암전 같은 사건 관계를 정리한다.

최신 인수인계에 기록된 **인물이 화면을 가려서 전환한다는 수정**을 적용한다. 과거 애니매틱 시간표의 빠른 틸트를 무조건 정답으로 고정하지 않는다. 사용자 최신 의도와 원문을 보존하고 구분한다.

### 8.2 배경

처음부터 배경 영상을 생성하지 않는다. 소수의 일관된 도시 배경과 분리 레이어를 준비하고 같은 장면에서는 유지한다. 큰 시점 변화는 다른 배경 컷으로 처리한다.

이는 초기 시험의 통제 조건이다. 좋은 배경을 자동으로 만드는 능력까지 확보됐다는 뜻은 아니다.

### 8.3 캐릭터

이펙트·연출 이후 다음 순서로 진행한다.

1. nian41 2D 추적을 스틱 캐릭터에 직접 옮긴 결과 확인.
2. 동작 검색과 캐릭터 비율 조정 구현.
3. 시작·끝 자세, 디딤점, 사건 시점을 조건으로 짧은 연결·수정 모델 학습.
4. 자료가 쌓인 동작부터 제한된 생성으로 확대.

캐릭터 동작 자료는 nian41 기본기와 신뢰 가능한 나카무라 자료를 쓰되, 보충 작가의 몸동작 사용 범위를 임의로 확대하지 않는다.

관절 간 선형 보간이나 앱 트위닝만으로 사쿠가 타이밍을 만들지 않는다. 멈춤·급격한 이동·스미어·임팩트를 명시적으로 유지한다.

### 8.4 5초 분할

5초 파일 분할은 최종 출력 단계에서 한다. 내부 시간축·상태는 연속 유지한다. 파일을 나눌 때 자세·배경·이펙트 진행 상태가 이어지게 한다.

## 9. GPU·시간·위험 예상

다음은 직접 벤치마크한 시간이 아니라 **작업 예산 추정**이다. 개발·자료 정리 기간과 GPU 실행시간을 구분한다. 무료 GPU 가용성에 따라 달력상 기간이 늘어날 수 있다. 단계별 개발 기간은 일부 겹칠 수 있으며 총 소요기간 보장이 아니다.

| 단계 | 장비·장소 | 개발·정리 예상 | GPU 실행 예산 | 주요 위험 |
|---|---|---:|---:|---|
| 복원·SFA 검증 | CPU 서버, 필요시 무료 GPU | 3–7일 | 0–4시간 | 분리 오염, 앱과 렌더러 차이, 파일 크기 |
| 시퀀스 검색·변형 | CPU 중심, 특징 추출용 GPU | 3–7일 | 1–4시간 | 재사용 범위를 벗어나면 품질 하락 |
| 작은 변형·시간 모델 | 16GB급 무료 GPU 우선, 5060 축소 실험 | 1–2주 | 초기 비교 실험 합계 10–30시간 | 과적합, 합성 변형만 학습 |
| 새 그림·시퀀스 생성 | 이미지 LoRA는 16GB급 우선, 영상 모델은 더 큰 메모리 선호 | 2–4주 이상 | 비교 실험 합계 20–80시간 이상 | 암기, 시간 불안정, 자료 부족 |
| 연출·배경 결합 | CPU 중심 | 1–2주 | 초기에는 거의 불필요 | 구도 부조화, 잘못된 카메라 추정 |
| 2D 동작 수정 | 8–16GB GPU | 2–4주 | 초기 실험 5–20시간 | 가림, 관절 ID 오류, 제한된 시점 |
| 온디바이스 이전 | 실제 안드로이드 기기 | 1–3주 이상 | 학습보다 기기 측정 중심 | 메모리, 발열, 벡터 렌더링 비용 |

장비별 배분:

- **GTX 1050 Ti 4GB:** 작은 모델의 동작 확인·소규모 학습·자료 검사. 이미지·영상 생성 연구의 주력으로 삼지 않는다.
- **RTX 5060 8GB, 약 2시간 세션:** 준비된 실험 실행·짧은 학습·후보 생성. 상담 문서의 CUDA 12.8 대응 torch 조건을 확인하고 설치를 사전 검증한다. 중단 후 재개 가능한 체크포인트를 남긴다.
- **Kaggle·Colab:** 본 학습·비교 실험. 먼저 작은 실행으로 VRAM과 처리속도를 실측한다.
- **CPU 서버:** 색인·가공·벡터 변환·출력 검사. 긴 영상은 구간 단위로 처리하고 중간 결과를 Drive에 보존한다.

우선 **1–2주 안에 복원·검색·변형의 가능성을 판단**하고 통과했을 때만 다음 GPU 예산을 사용한다.

원본 영상·추출 형태·학습 자료·가중치는 Drive 등 비공개 위치에 둔다. 공개 저장소에는 직접 작성한 코드·문서·허용된 집계만 둔다. 자료와 모델의 이용 조건은 지키며 우회를 전제로 설계하지 않는다.

## 10. 최종 온디바이스 경로

검색·작은 수정 모델·벡터 변환은 최종 기기 실행 목표에 잘 맞는다. 큰 영상 확산 모델이 그대로 휴대폰에 들어간다는 보장은 없다.

큰 모델을 실험하더라도 PC의 교사·후보 제작 도구로 두고, 기기에서는 승인된 자료와 작은 모델로 실행하는 경로를 유지한다. 결과 생성 시간 제한을 임의로 두기보다 실제 기기의 메모리·발열·완료 시간을 측정한다.

좋은 그림이 나와도 SFA가 너무 커서 실제 앱에서 못 다루면 완료가 아니다. 기존 시험에 수십~수백 MB 출력 기록이 있으므로 렌더링·편집·저장 비용도 초기부터 확인한다.

## 11. 버릴 것과 남길 것

### 버릴 것

- MoMask·모캡·2D→3D 리프팅 경로 전체.
- 수백 클립으로 캐릭터·이펙트·카메라·배경을 한꺼번에 배우는 모델.
- 실루엣 생성 뒤 팔레트만 입히면 작화 품질이 나온다는 전제.
- 서로 다른 길이를 모두 16프레임으로 통일하는 처리.
- 이펙트 형태 조각을 규칙적으로 뿌리는 최종 생성 방식.
- 코드로 못 만든 키 자세를 학습 정답으로 삼는 방식.
- 임팩트까지 매끈하게 보간하는 처리.
- 정지 화면·학습 손실·좌표 통계만으로 품질 향상을 선언하는 평가.

여기서 폐기는 기존 파일·원본·기록을 삭제하라는 뜻이 아니다. 새 설계의 주력 경로에서 제외한다는 뜻이다.

### 남길 것

- 정확했던 2D 포즈 추적.
- 형태 사전과 임팩트 책.
- 원본과 연결된 태그·동작 문장.
- 사건별 타이밍과 카메라 자료.
- 곡선·채우기·반투명 분해 도구.
- 사용자 애니매틱과 실제 사용자 판정.

## 12. 가장 불확실한 부분

### 12.1 깨끗한 시간 연결 정답을 얼마나 확보할 수 있는가

가장 큰 불확실성은 현재 자료에서 배경 오염이 적고 시간적으로 연결된 **선·밑색·반투명 명암 정답**을 얼마나 확보할 수 있는가다. 자료 개수보다 먼저 확인해야 한다.

### 12.2 참고 변형을 넘어 일반화할 수 있는가

제한된 자료로 학습한 모델이 참고 시퀀스 변형을 넘어 보지 않은 구도·새로운 형태에서도 품질을 유지할지는 불확실하다. 검색·변형이 잘된다고 자유 생성도 된다고 볼 수 없다.

### 12.3 실제 SFA와 기기가 표현량을 감당하는가

복잡한 곡선·반투명 층을 실제 Stick Fighter와 휴대폰이 감당할 수 있는지 확인해야 한다. 임의로 조각 수를 제한하기보다 품질을 유지하면서 필요한 표현량을 측정하고 줄인다.

따라서 처음에는 이펙트 약 20개를 실제 SFA에서 복원하고 새로운 조건에서도 좋은지 확인한다. 이 결과가 이후 학습 방향과 자원 투입을 결정한다.
