# GPT 확장 조사 — 애니메이션 밖에서 가져올 시스템(2026-11-06)

사용자 요청: “아예 애니메이션이나 스파와 연관없어 보이는 것도 혹시 모르니까 전부 싹싹 조사해 봐.”

**이번에는 21개 분야, 40개 후보를 조사했다. 유망한 것은 영상 모델 하나를 바꾸는 일보다, 자료의 잡음·시간 표현·구조 제약·생성 역할을 나누고 다른 분야의 기술을 연결하는 방법이다.** 특히 동물 행동 분석, 음악의 사건/시간 표현, 로봇의 동작 묶음 생성, CAD의 제약 기하가 직접 검토할 가치가 있다.

이것은 조사·설계 판단이다. 40개를 설치하거나 같은 시험으로 성능 비교한 결과가 아니다. 모든 분야·시스템을 빠짐없이 찾았다는 뜻도 아니다. 확인 범위와 미검증을 남기고, 더 좋은 후보를 추가할 수 있는 목록으로 보존한다. 이전 [애니메이션 시스템 결합 검토](GPT-SYSTEM-COMBINATION-REVIEW-2026-11-06.md)의 영상 모델 결합은 여러 후보 중 하나로 유지하며, 유일한 정답으로 고정하지 않는다.

## 1. 조사 방법과 검증 범위

- 후보마다 입출력, 우리 문제에 옮길 기능, 공식 구현, 원래 분야의 가중치 공개, 추가 구현, 자료·계산 부담, 실패 반례, 가장 작은 시험을 정리했다.
- 공식 README 39개의 지문과 공식 문서로 확인한 DVC를 [후보 목록 JSON](../data/research/cross_domain_systems_2026-11-06.json)에 저장했다. 필요 항목은 저자 논문·문서를 더 읽었다. README 확인은 구현 전체 감사나 실행 재현을 뜻하지 않는다.
- 검색 결과보다 공식 출처를 우선했다. 예를 들어 TimesFM은 현행 3.0과 이전 2.5를 구분했고, VAME의 이전 저장소에서 현행 EthoML 저장소를 확인했다. GraphCast 주소는 WeatherNext 저장소로 이동한 것을 확인했다.
- 애니메이터 학습 범위·사용자 캐릭터·SFA 편집 조건은 그대로다. 로봇·분자·기상 모델을 조사한 것은 그 자료나 3D 사람 동작 모델을 새 학습 자료로 넣을 허가가 아니다.
- 외부 모델 실행·새 학습·GPU·유료 API·새 원본 영상 다운로드는 하지 않았다. 원래 분야의 가중치 링크가 있어도 애니 동작에 바로 쓸 가중치라고 표시하지 않았다.

## 4. 더 깊게 볼 가치가 있는 연결점

### A. 동물 행동 분석 — “흔들린 좌표”와 “움직인 신체”를 구분

Keypoint-MoSeq는 점 좌표와 신뢰도를 받아 행동 구간과 관측 잡음을 함께 추정한다. 별도 로더의 입력은 `(장, 점, 2D 또는 3D)` 좌표와 신뢰도다. 사람용 고정 모델을 전제로 하지 않는 점이 흥미롭다. VAME도 관절열의 시간 특징을 압축하고 군집화한다. [Keypoint-MoSeq 공식 FAQ](https://keypoint-moseq.readthedocs.io/en/latest/FAQs.html), [VAME 공식 설명](https://ethoml.github.io/VAME/docs/intro/).

우리에게 옮길 발상은 **진동을 일괄 평활하기보다 실제 동작 상태와 관측 오차를 따로 두는 것**이다. 검출기의 자신감이 높아도 잘못된 점이면 틀릴 수 있으므로 원본과 비교해야 한다. 짧은 행동 단위가 발견되더라도 그것을 “펀치” 정답으로 자동 승격하지 않는다.

한계도 크다. 공식 FAQ는 수 시간·수십만 장 수준을 권장하고 주 검증 범위는 자유롭게 움직이는 동물의 구도다. 우리처럼 컷·줌·원근·스미어·그림 유지가 섞인 짧은 애니에 그대로 넣어 성공할 근거는 없다. 기존의 수백 장을 증강해 그 권장량을 채웠다고 하지 않는다. 원리의 채택과 도구 전체의 채택을 나눈다.

### B. 음악·음성 — “무엇을 하는가”와 “언제 어떻게 표현하는가”를 구분

REMI는 음악을 시점과 템포를 가진 사건열로 다룬다. Compound Word Transformer는 관련 속성을 묶어 표현하는 방법을 제시한다. StyleTTS2는 내용에 어울리는 표현 스타일을 조건화하는 설계의 참고가 된다. 이들의 학습된 음악·음성 가중치를 관절에 사용하는 제안은 아니다. [REMI](https://github.com/YatingMusic/remi), [Compound Word](https://github.com/YatingMusic/compound-word-transformer), [StyleTTS2](https://github.com/yl4579/StyleTTS2).

우리에게는 `예비 동작 → 타격 → 최대 뻗기 → 마무리`의 **사건·지속 시간·해당 자세**를 연결해 다루는 표현이 후보가 된다. 같은 포즈 경로라도 어느 부분을 짧게 통과하고 어느 자세를 붙잡는지가 다르면 느낌이 바뀐다.

현재 `retime.py`가 전체 유지 비율에 맞춰 중간 자세를 덮는 것과 다르다. 중요한 자세·접촉을 보존하고 사건별로 시간을 배워야 한다. 사건열만 만들고 관절 움직임을 해결했다고 하지도 않는다. 새 표현이 실제 원본을 왕복했을 때 타격 장과 디딤 장을 유지하는지 먼저 비교한다.

### C. 로봇 — 한 점씩이 아니라 짧은 행동 전체를 조건으로 생성

Diffusion Policy와 ACT는 여러 시점의 행동을 묶어서 예측하는 공개 구현을 제공한다. 우리 자체 토큰 언어 모델과 달리 연속적인 짧은 행동열 자체를 다루는 설계가 참고 대상이다. openpi는 언어와 행동 생성부를 결합하는 더 큰 사례지만 로봇 입력·출력과 자원 부담이 현재 목적과 다르다. [Diffusion Policy 저자 페이지](https://diffusion-policy.cs.columbia.edu/), [ACT 코드](https://github.com/tonyzhaozh/act), [openpi](https://github.com/Physical-Intelligence/openpi).

이식 후보는 2D 관절의 앞뒤 자세·시간·동작 조건을 받아 짧은 구간을 생성하는 부분이다. 로봇 각도나 3D 사람 동작 모델을 기본으로 바꾸자는 뜻이 아니다. 이 설계도 우리 자료로 적응·검증해야 하므로 “사전학습 로봇 가중치를 가져오면 즉시 액션이 나온다”고 기대하지 않는다.

평균과 반복의 실패도 봐야 한다. ACT의 시간 결합은 타격의 뾰족한 최고 자세를 무디게 할 수 있다. 또한 [ALT의 소규모 로봇 시연 연구](https://stanfordmsl.github.io/alt/)는 확산 정책의 좋은 결과에도 학습 행동의 검색·재사용이 큰 역할을 할 수 있음을 보인다. 이를 모든 확산 모델이 외운다는 결론으로 확대하지 않되, **확산이니까 새 동작을 창작한다**는 보증도 하지 않는다.

### D. CAD + 최적화 — 구조는 유지하면서 관측에 맞춰 움직임을 조정

SketchGraphs는 도형을 노드, 관계를 제약으로 다루는 자료/모델이다. CAD Sketcher는 실제 2D 제약 편집의 예다. Theseus는 관측 오차 등을 정의하는 최적화 층, CasADi는 최적화 문제를 구성하는 도구다. [SketchGraphs](https://github.com/PrincetonLIPS/SketchGraphs), [CAD Sketcher](https://hlorus.github.io/CAD_Sketcher/), [Theseus](https://github.com/facebookresearch/theseus), [CasADi](https://web.casadi.org/docs/).

우리 연결부에는 “같은 마디의 좌표는 하나”, “확인된 접촉 구간에서는 대상과 만남”, “시작·끝 자세는 조건대로” 같은 제약을 둘 수 있다. 편집망을 자유 곡선으로 바꾼 뒤 뒤늦게 수리하는 일을 줄일 가능성이 있다. 현재 컴파일러가 이미 보장하는 연결을 새 기능으로 다시 만들자는 뜻은 아니다. **동작을 영상/관측에 맞추는 과정에서도 같은 관계를 유지**하는 것이 추가 목적이다.

몸 길이 고정·실제 물리 준수 전체를 강제하면 허용된 원근·과장까지 지울 수 있다. 솔버는 선언한 식을 만족시킬 뿐 자연스러움을 학습하지 않는다. 잘못된 관측·접촉을 주면 틀린 결과를 잘 맞출 수 있다. 이 방식은 거부된 계산 걷기를 기본으로 되돌리는 제안이 아니다.

### E. 의료 결측 복원 + 상태 추정 — 가림을 정답처럼 굳히지 않기

CSDI는 관측된 채널/시점을 조건으로 결측치를 확률적으로 복원한다. Dynamax 같은 상태공간 도구는 숨은 상태와 관측 오차를 구분한다. [CSDI](https://github.com/ermongroup/CSDI), [Dynamax](https://probml.github.io/dynamax/).

우리에게는 안 보이는 팔·다리에 정답 좌표 하나를 부여하는 대신 가능한 궤적과 불확실성을 남기는 설계가 후보가 된다. 실제 보이는 관절 일부를 가려 복원 성능을 잴 수 있다. 원래부터 안 보였던 관절의 추측을 정답으로 두고 성능을 재면 안 된다.

의료용 가중치에는 신체 부위와 액션 의미가 없다. 단순 결측과 오검출도 다르다. 엉뚱한 고신뢰 관측을 고정하면 모델은 잘못된 값에 맞춰 복원한다. 적용은 짧은 복원 과제로 제한하고 선형/PCHIP 등 기존 대조와 비교한다.

### F. 범용 시계열 모델 — 시도할 수 있는 작은 기준선

Chronos-2·TimesFM·Moirai에는 공개된 시계열 사전학습 모델이 있다. Chronos-2는 다변량과 공변량 지원을, TimesFM 현행 3.0은 다변량 지원을 명시한다. 버전이 다른 기능을 섞어 기록하지 않는다. [Chronos 공식 배포](https://github.com/amazon-science/chronos-forecasting), [TimesFM](https://github.com/google-research/timesfm), [Moirai/Uni2TS](https://github.com/SalesforceAIResearch/uni2ts).

관절을 여러 시계열로 놓고 짧게 이어 예측하는 시험은 가능하다. 그러나 글의 동작 의미, 좌우 다리의 역할, 발 접촉, 새로운 타격을 만드는 능력은 해당 예측 기능에서 따라오지 않는다. 개별 분위수나 평균을 합쳐 불가능한 자세가 생길 수도 있다. 마지막 자세 유지·등속 같은 싼 기준선과 비교해 이득이 있을 때만 남긴다. 자연어 창작의 주력으로 바로 고르지 않는다.

### G. 프로그램 라이브러리 학습 — 곡선과 동작을 재사용 가능한 표현으로

DreamCoder·LILO는 영역별 작은 프로그램과 재사용 라이브러리를 학습하는 사례다. EnCodec의 압축 발상과 함께 보면 “긴 점열” 대신 “짧은 표현 + 복원기”라는 후보를 생각할 수 있다. [DreamCoder](https://github.com/ellisk42/ec), [LILO 논문](https://arxiv.org/abs/2310.19791), [EnCodec](https://github.com/facebookresearch/encodec).

SFA에서는 승인된 이펙트 곡선의 형태·변형을 함수로 표현하고 이름·역할을 붙이는 방향이 후보가 된다. 사용자가 요구한 곡선 조각 방식과 연결된다. 무조건 단순 원·직선으로 대체하거나 원본 덩어리를 붙이는 방식으로 바꾸지 않는다.

동작 압축은 희귀 타격 자세와 타이밍을 복원해야 가치가 있다. 새 코드북이 항상 손 토큰보다 낫다는 가정은 하지 않는다. 먼저 재구성 비교가 필요하며, 전체 DreamCoder/LILO 실행 환경의 이식·검색 비용은 현재 미측정이다.

### H. 계획·검증·자료 관리 — 큰 모델 없이 줄일 수 있는 낭비

Unified Planning/행동 트리는 순서·지속 시간·장면 상태, XGrammar는 생성 형식, Z3는 선언한 논리 제약을 맡길 수 있다. Cleanlab/Snorkel은 검토할 라벨 후보를 돕고 DVC는 자료와 실험을 연결한다. 각 공식 링크는 전체 목록에 있다.

하지만 이들은 움직임 자체를 만들지 않는다. 문법이 맞는 정지 인물은 여전히 실패다. 검출 오류를 공유하는 규칙 세 개는 독립 증거 세 개가 아니고, 특이한 타격을 이상치라 지워도 안 된다. 기존 manifest·해시·컴파일 검사로 충분한 기능에 새 프레임워크를 더할 필요는 없다.

DoWhy에서 참고할 가장 실용적인 점도 도구 자체보다 **원인 가정과 대조 실험을 분리**하는 습관이다. 자료·표현·시간·생성 조건을 동시에 바꾼 과거 세 회차에서 어떤 하나가 원인이라고 자동 판정할 수는 없다. [DoWhy 공식 문서](https://www.pywhy.org/dowhy/main/user_guide/causal_tasks/estimating_causal_effects/index.html).

## 5. 서로 연결했을 때 의미가 있는 조합

모든 도구를 한꺼번에 실행하는 설계가 아니다. 각 조합은 필요한 자리의 구현 하나를 선택해 비교한다.

|조합|해결하려는 문제|기존 자산과의 연결|새로 검증할 부분|
|---|---|---|---|
|**① 사용자 정의 점 추적 + 잡음/상태 추정 + 제약 맞춤**|검출 떨림·가림·사람 바뀜을 학습 자료에 섞는 문제|RTMW·편집 기록·motion-ir·품질 검사 재사용|실제 타격을 보존하면서 오검출만 줄이는가|
|**② 음악형 사건 시간표 + 로봇형 동작 묶음 생성 + 접촉 검사**|포즈 나열은 되지만 동작의 진행과 타격 리듬이 없는 문제|태그·그림 유지 구간·2D 관절·SFA 컴파일러|중요 자세/접지/시간을 유지하는 새 동작을 만드는가|
|**③ 기존 영상 엔진 + 검토 가능한 목표 영상 + 구조 제약 맞춤**|이미 학습된 시각적 동작 지식을 활용|이전 보고서의 AniSora/Wan·시트·컴파일러|목표 영상은 좋은데 구조 변환이 망가뜨리지 않는가|
|**④ 행동 단위 발견 + 시간 정렬 + 조각 검색/계획**|짧은 조각의 부정확한 선택과 경계|현재 compose·태그·출처 추적|잘못된 행동 군집·반복 이음매를 줄이는가; 창작 학습과 구분|
|**⑤ 곡선 프로그램 사전 + 렌더 오차 맞춤 + SFA 출력**|이펙트 전체 파일 토큰 생성의 부담|비공개 형태 사전·곡선 도구·명암/글로우|새 형태 변주·출현/소멸·저장 형식을 보존하는가|
|**⑥ 시계열 예측/결측 복원 + 관측 고정 + 구조 검사**|짧은 빈 구간·이어 만들기의 싼 비교군|motion-ir·기존 관측·길이/연결 검사|간단한 보간보다 실제로 낫고 불확실성을 정직하게 남기는가|

이 중 **①은 자료 품질**, **②는 우리가 원하는 동작 학습**, **③은 큰 사전학습 모델 활용**이라는 서로 다른 문제를 푼다. 하나를 도입해 나머지도 해결됐다고 하지 않는다. ④는 바로 개선할 기준선 후보지만 완성된 창작 AI가 아니다.

## 6. 이번 조사로 수정하는 추천

1. **앞단 자료의 관측/추론/잡음을 분리하는 작업을 우선한다.** 영상 모델이든 자체 동작 모델이든 잘못 추출된 움직임을 정답으로 쓰는 문제는 공통이다. 기존 원본·관측·수정 기록을 재사용하고 같은 분석의 반복은 피한다.
2. **시간 표현의 비교를 큰 학습 전에 한다.** 현재 토큰, 원본 관절, 사건·길이를 묶은 후보를 왕복해 타격·디딤·최대 뻗기·마무리가 유지되는지 확인한다. “짧아졌다”와 “정상 동작을 담는다”를 구분한다.
3. **구조 제약을 둔 2D 맞춤을 공통 연결부로 시험한다.** 자체 동작 생성과 외부 영상 엔진 양쪽에서 쓸 수 있어, 한 생성 모델에 전체를 묶는 위험을 줄인다. 작은 문제는 기존 SciPy/PyTorch로 충분할 수도 있으므로 Theseus·CasADi 등을 무조건 설치하지 않는다.
4. **그 뒤 ②와 ③을 같은 좁은 과제로 비교한다.** 앞뒤 조건이 있는 짧은 동작, 중요한 자세 보존, 같은 캐릭터·카메라·시간을 먼저 고정한다. 새 GPU는 그 실행안과 예산을 정해 허락받은 뒤 사용한다.
5. **예측·압축·자료 관리 도구는 이득이 입증될 때만 더한다.** Chronos 등을 넣었기 때문에 동작 의미를 배웠다고 하지 않고, 프레임워크 수를 성과로 세지 않는다.

## 7. 채택/제외를 가르는 반례

- **평활:** 검출 떨림은 줄이지만 진짜 빠른 타격과 의도된 임팩트 프레임까지 지우는가.
- **시간 정렬:** 잘못 늦어진 펀치를 늘이기/줄이기로 정답처럼 채점하는가. 원래 시간과 정렬 후 비교를 따로 낸다.
- **제약 최적화:** 같은 부위 연결은 유지해도 잘못된 관측에 맞춰 무릎을 반대로 꺾는가. 길이 고정으로 원근을 망가뜨리는가.
- **생성:** 여러 가능한 동작의 평균인 정지 자세나 불가능한 중간 자세를 내는가. 짧은 시연을 외운 결과를 새 창작으로 세는가.
- **행동 군집:** 실제 행동 대신 줌·카메라 흔들림·그림 유지 길이를 분류하는가.
- **자료 오류 탐지:** 정상적인 희귀 액션을 오류로 제거하는가. 사람이 동의한 판정 없이 자동 정답으로 승격하는가.
- **계획/문법 검사:** 동작을 전혀 안 하는데 파일 형식과 시간표만 맞아서 통과하는가.

성능 주장은 출력 영상·편집망·원본 대비 변화로 따로 평가한다. 한 모델의 손실이나 점수 하나로 다른 단계의 실패를 상쇄하지 않는다. 현재 생성 경로와 사용자 판정이 있는 기존 결과를 비교 기준으로 보존한다.

## 8. 직접 쓰지 않기로 한 먼 분야도 남김

GraphCast/WeatherNext, AlphaFold 3, DreamerV3도 조사했다. 공간 관계 학습·확률적 구조·내부 미래 시뮬레이션이라는 발상은 참고할 수 있다. 그러나 기상 격자·분자 구조·환경 상호작용은 현재 2D 액션 자료와 입출력이 다르다. 큰 가중치를 받거나 SFA 구조로 억지 변환하는 비용에 비해 당장 얻을 이득을 확인하지 못했다. 현재 직접 도입을 제외하는 판단이며 이 분야 전체가 쓸모없다는 결론은 아니다.

조사의 목적은 겉보기 관련성으로 후보를 놓치지 않으면서 **우리 문제에 실제로 전달되는 기능**을 찾는 것이다. 현재 가장 강한 결합 가설은 **관측을 정리하는 과학 도구 + 시간과 행동을 배우는 표현/모델 + 구조를 지키는 기하·컴파일러**다. 영상 모델 결합은 이 구조의 생성 엔진 후보 중 하나다.

## 9. 다음 행동과 보존할 상태

- 이 조사까지는 완료했다. 40개 설치·모델 실행·SFA 결합 성능·새 스타일 학습은 미수행이다.
- 다음으로 제안하는 CPU 비교는 기존 자료의 시간 왕복/중요 자세 보존과 정답을 알고 있는 렌더의 연결부 시험이다. 이후의 학습 후보는 ②/③ 비교로 정한다.
- 사용자에게 받은 진동→가면 원근→걷기 출처 순서는 보존하되, 뒤이은 구조 검토 요청으로 수정은 보류 중이다. 진동 원인을 새로 확인했다고 기록하지 않는다.
