# 향후 추가 계획 (사용자 2026-10-18) — 미착수

현재 단계(스타일 지식베이스, 작업표 15번 편입)가 끝난 뒤 진행한다. 아래 "검토 메모"는 Claude의 초안이며 [추론]이다. 구현·실물 검증은 하지 않았다.

## 1. 캐릭터 디자인 → 등장인물

사용자가 캐릭터 디자인(파일·사진)을 주면 그 캐릭터가 Stick Fighter 애니메이션의 등장인물이 된다.

검토 메모:
- 디자인에서 뽑을 것: 실루엣 비율(머리·몸통·팔다리 길이), 대표 색 2–4개, 특징 부착물(머리 모양, 무기, 망토 등).
- 앱 재료로 옮기는 방법: 막대 뼈대 길이·굵기, 머리 원 크기, 닫힌 면(FR) 부착물, 단색 채우기.
- 몸 움직임은 nian41 규칙(2s 바탕 + 순간 1s, 예비→순간→후속, 1프레임 스미어)을 쓰고, 이펙트는 승낙 작가 지식베이스를 쓴다.
- 사용자가 준 디자인 원본은 남의 저작물일 수 있으므로 Drive에만 두고 GitHub에는 올리지 않는다.
- 먼저 확인할 것: 앱의 캐릭터·부착물 저장 구조(기존 AOT/기능 분석 문서 재사용), 사진 한 장으로 정면 외 각도를 어떻게 정할지.

## 2. 배경음악(BGM)에 맞춘 제작

사용자가 BGM 파일과 분량·타이밍을 주면, 음악에 맞춰 애니메이션을 만든다.

검토 메모:
- 음악에서 뽑을 것: 템포(BPM), 박 위치, 강박·드롭, 구간(인트로·절정 등), 음량 변화. 서버 도구(예: librosa·ffmpeg) 사용은 분석 도구 설치 허용 범위다.
- 박자 → 프레임 변환: FPS 순서는 (tween_fps, playback_fps)이고 기본은 (24,24)다. 박 위치를 프레임 번호로 바꿔 타격 순간(1s)·임팩트·카메라 전환을 강박에 맞춘다.
- 사용자가 지정한 분량(초)·타이밍(예: 몇 초에 무엇)이 음악 분석보다 우선한다.
- 앱이 소리를 넣을 수 있는지, 영상 내보내기에 음악을 합칠 수 있는지는 확인이 필요하다(기존 내보내기 분석 문서 재사용).
- BGM 원본도 Drive에만 둔다.
