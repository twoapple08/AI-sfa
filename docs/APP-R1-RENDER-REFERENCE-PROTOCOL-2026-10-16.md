# APP-R1 렌더 기준 영상 — 시험 파일과 요청 — 2026-10-16

- 목적: 앱과 같은 결과를 내는 기준 렌더러를 만들기 위한 **실제 앱 출력 정답 자료**를 확보한다.
- 정적 분석으로 식은 확인했지만 실제 픽셀은 아직 측정하지 않은 항목을 대상으로 한다.
- 곡선 분할, 링 node, glow 반폭/sigma, 그룹 glow, 채우기 알파 겹침, 화면 경계가 여기에 해당한다([CURVE-RING](AOT-CURVE-RING-TRACE-2026-10-15.md), [DRAW-GLOW](AOT-DRAW-GLOW-TRACE-2026-10-15.md), [GLOW-BACKEND](AOT-GLOW-BACKEND-TRACE-2026-10-15.md), [EDITOR-OUTPUT-BOUNDS](EDITOR-OUTPUT-BOUNDS.md)). **이 문서 시점에는 앱 결과가 없다.**

## 파일

- `examples/render_v1/07_render_reference.sfa`는 `python build_render_probe.py`로 다시 만들 수 있다.
- 9구간 × 12프레임 = 108프레임이다.
- 각 구간은 12프레임 동안 같은 그림을 유지해, 영상 압축 잡음을 평균으로 줄일 수 있게 했다.

| 프레임 | 구간 | 내용 |
|---|---|---|
| 1–12 | colors | 회색 배경 위 불투명 색 견본 12개(빨·초·파·노·청록·자홍·흰·검·어두운 회색·밝은 회색·주황·파랑). 색 변환 보정용 |
| 13–24 | lines | 흰 선 굵기 0.5/1/2/4, 세로선, 대각선, 거의 점인 선 |
| 25–36 | circles | 원 지름 8/20/40(굵기 1), 지름 20(굵기 3) |
| 37–48 | curves | 대칭 곡선, 거의 직선, 시작=끝인 되돌아오는 곡선 |
| 49–60 | glow_lines | 주황 선 + 청록 glow, (반경,두께)=(4,20),(12,20),(24,20),(12,5),(12,60) |
| 61–72 | glow_shapes | 원·곡선·거의 점인 선에 glow 12/20 |
| 73–84 | group_glow | 교차하는 glow 선 두 쌍. 왼쪽은 독립, 오른쪽은 그룹 |
| 85–96 | fill_overlap | 흰 배경 위 반투명 빨강/파랑 겹침, 불투명 초록과 반투명 빨강 겹침 |
| 97–108 | boundary | 오른쪽·위·왼쪽 화면 경계를 걸친 도형(화면 밖 좌표 유지) |

## 사용자 요청

1. 새 프로젝트로 가져온다. **수정하지 않는다.**
2. 설정을 (트위닝 FPS, 재생 FPS) = **(24, 24)**로 맞춘다.
3. 영상(MP4)으로 내보낸다. 기대값은 108프레임, 4.5초, 1920×1080이다. 해상도 옵션이 다르면 그대로 두고 알려 준다.
4. 반환물은 MP4 1개다. 가능하면 같은 상태에서 SFA 재내보내기 1개도 보낸다(가져오기 단계의 변환 확인용, 선택).

설정 사진은 필요 없다. 다른 값으로 내보냈다면 그 값만 알려 준다.

## 판정 계획

- 각 구간 가운데 프레임(예: 7번째)을 원본 해상도로 디코딩한다.
- 견본 색으로 영상의 색 변환(YUV, 범위)을 보정한다.
- 선·원 폭, glow 단면 profile, 겹침 색을 측정한다.
- 측정값을 이후 만들 기준 렌더러의 출력과 비교한다.
- 원본 영상은 공개하지 않고 측정 집계만 기록한다.
- 이 자료로 확인되는 것은 이 9가지 상황의 실제 출력이다. 모든 조합의 픽셀 동일성을 확인하는 것은 아니다.

## 실제 앱 결과 — 2026-10-16

- 사용자가 보낸 파일은 MP4 1개와, 수정 없이 다시 내보낸 SFA 1개다.
- 원본은 공개하지 않는다.
- 측정 집계는 [APP-R1-RENDER-MEASUREMENTS](APP-R1-RENDER-MEASUREMENTS-2026-10-16.json)에 있다.
- 아래 측정은 **실제 앱 출력 픽셀**이다.
- 다만 대상은 이 9개 장면뿐이다.

- **형식:** 1920×1080, H.264, yuv420p, BT.709 TV 범위, 24FPS, 108프레임, 4.5초. (24,24)에서 프레임 수와 길이가 기대값과 같다.
- **재내보내기 SFA:** 108프레임, 검사 오류 없음, 모든 좌표 차이 0이다. AO ID는 재배정됐고, 그룹 Flags는 새 부모 점 ID로 다시 쓰였다.
- **색 변환:** BT.709 TV 범위를 full 범위로 디코딩하면 회색 64/128/192/흰/검은 오차가 0이다. 채도가 높은 색은 오차가 최대 3 정도다(4:2:0 색차 축소 영향으로 본다). 이 측정 방법을 신뢰할 수 있다.
- **출력 좌표 변환(새 실측):**
  - x_px ≈ 10.65 + x×18.987, y_px ≈ 5.98 + y×10.680. 사용 영역은 약 1898.7×1068.0px이고, 양쪽 여백 P는 약 10.65px다.
  - (정정, [RENDERER-V0](RENDERER-V0-2026-10-16.md)) 정밀 회귀값은 x=10.708+18.9896x, y=5.813+10.6853y다. 이는 중앙 기준 균일 축소이며, 정적 `DrawInformation` 식을 1920×1080에 그대로 적용한 결과(높이 제한)와는 다르다. **0–100을 1920×1080 전체에 바로 대응시키면 화면 가장자리에서 최대 약 11px가 틀린다.**
  - P 값의 공급식(stroke 여백 helper)은 이번에 수치로 맞춰 보지 않았다.
- **화면 밖 내용:** 오른쪽 경계를 넘은 glow 선, 왼쪽으로 나간 채우기 사각형은 여백 P 영역(0–100 바깥)에도 그려진다. 사용 영역으로 잘라내지 않는다.
- **선 굵기:** ThicknessScale 0.5/1/2/4에서 FWHM이 5/9/17/36px(시퀀스 굵기 100%)다. 끝은 둥글다. 거의 점인 선은 둥근 점으로 그려진다.
- **원:** 지름 끝점 사이 거리의 절반이 반지름이다. 픽셀 공간에서 등방성 원이다(세로 단위 10.68px 기준 반지름 일치). 고리 FWHM은 굵기 1에서 9px, 굵기 3에서 27px다.
- **곡선:** 시작=끝인 되돌아오는 곡선은 중간점 B(0.5)까지 갔다 돌아오는 직선 모양이다. 이차 Bézier 식과 부합한다.
- **Glow(선 단면, box×Gaussian 모델 맞춤):**
  - 잘 맞는 경우(RMSE ≤ 2): (GlowRadius 24, 두께 20) → σ ≈ 23.5px, W ≈ 15.5px. (12, 5) → σ ≈ 12.3px, W ≈ 3.5px.
  - **σ ≈ GlowRadius(px), W ≈ 0.7–0.77 × GlowThickness(px)**로 읽힌다.
  - 반경이 작거나 두께가 큰 경우는 모델 오차가 크다(RMSE 10–24). 이 경우는 shader 적분식으로 다시 맞춰야 한다.
  - 정적 sigma=√(R²+(0.29/DPR)²)과 방향은 맞다. 정확한 단위 환산은 미확정이다.
- **채우기 알파 겹침:** 측정값이 src-over 예측과 1 이내로 일치한다. 반투명 빨강+흰 배경 = (253,125,125), 그 위의 파랑 = (127,62,191) 등. DrawOrder가 큰 객체가 위에 그려진다.
- **그룹 glow(새 실측):**
  - 독립인 두 선은 객체 순서대로 각자 glow 다음 심지를 그린다. 그래서 나중 선의 glow가 앞 선의 주황 심지를 덮어, 교차점이 청록빛으로 물든다.
  - **그룹인 두 선은 두 심지가 모두 glow 위에 그려진다.**
  - 교차점 밖의 glow 세기는 같다(차이는 0.35px 서브픽셀 위치에서 오는 가장자리 차이뿐).
  - 그룹 glow를 객체별로 호출한다는 기존 정적 해석과 함께 보면 **그리기 순서가 그룹 단위**라는 실물 근거다. 겹친 glow가 서로 더해지는 방식(덧셈인지 src-over인지)은 따로 측정하지 않았다.

이 결과는 기준 렌더러의 정답 자료로 쓴다. 모든 FPS 조합·backend·복잡한 채우기의 픽셀 동일성은 계속 미완이다.
