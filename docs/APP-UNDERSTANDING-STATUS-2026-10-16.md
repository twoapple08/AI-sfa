# Stick Fighter 51.0.0 앱 이해 — 단계 마감 정리 — 2026-10-16

학습 단계로 넘어가기 전 기준 문서다. 각 항목의 근거 유형은 다음과 같다.

- **실물:** 앱 출력·저장 파일로 확인
- **정적:** AOT 명령 대조
- **추정:** 가설

전체 기능의 완전한 증명이나 모든 비정상 입력의 보장은 아니다.

## 실물로 확인한 핵심 (기준 렌더러로 재현됨)

| 영역 | 확정 내용 | 근거 |
|---|---|---|
| 파일 | SFA = ZIP 안 XML 1개. 가져오기에서 AO·AP·Frame ID 재배정, 좌표 보존, 화면 밖 좌표 유지. 앱 DB ID는 앱 전체 누적 번호 | 실물(00 왕복, APP-V3, R1 재내보내기) |
| 시간축 | (트위닝 T, 재생 P): T>P일 때 Q=T, K=round(T/P)(0에서 먼 반올림), N=ceil(F·Q/P), t=m/K 양자화, 마지막 원본 반복. 설정 창은 T≥P로 정규화 | 실물(APP-T1 (30,12)→35, 작품 (24,12)→244), 정적 |
| 보간 | 같은 ID 또는 수동 TweenLink로 짝. 짝 없는 객체는 중간 프레임에서 빠짐. 점은 Index 대응 선형. 색·배경색은 채널별 앞값+round(델타·t). glow 반경·두께 round, 알파 trunc. 채우기는 대응 시 색·T 보간, 앞에만 있으면 t<1 유지, 뒤에만 있으면 t=1에서 등장 | 실물(APP-T1, 03, 05, 작품), 정적 |
| 출력 좌표 | 중앙 기준 균일 축소: 사용 폭 W−2P, 높이=폭×9/16. P는 선 굵기의 함수(100% 10.52px, 50% 6.30px; 식은 추정) | 실물(R1 100%/50%) |
| 선 | 폭 = round(9×ThicknessScale×선굵기%/100) px, 둥근 끝. ObjectScale은 선 굵기에 반영되지 않음 | 실물 |
| 원·곡선 | 원 = 두 점의 중점·거리/2. 곡선 = 이차 Bézier | 실물, 정적 |
| glow | σ=GlowRadius px(×선굵기%), 띠 폭=0.78×GlowThickness×객체 ThicknessScale×선굵기%, 몸통 erf×band + 반원 캡 | 실물(R1, 작품), 정적 shader 구조 |
| 그리기 순서 | 레이어 목록 순(앞이 아래, 숨긴 레이어 제외) → 레이어 안 연결 묶음(AC 연결+그룹 부모, 레이어마다 분리) → 묶음별 모든 glow → 구성원 순서대로 [가져간 채우기 → 본체]. 채우기는 첫 outer 객체의 레이어, 그 레이어 outer 객체 중 첫 구성원이 가져감 | 실물(작품 MAE 0.908), 정적(BuildDrawPlan 등 27명령) |
| 채우기 합성 | even-odd 구멍, src-over 알파 합성 | 실물(R1, 01) |
| 시간축 명령 | 복사/앞뒤 붙여넣기/앞뒤 새 프레임/삭제, ID 재매핑, 마지막 삭제 시 빈 새 프레임 | 실물(APP-V3), 정적 |
| 편집 보조 | 양파 스킨·앵커·점 표시·빈공간 색은 편집기 환경설정. 축 고정·회전 스냅은 편집 조작 제한. 모두 출력에 무관 | 정적, 사용자 확인 |

기준 렌더러(`sfa_render.py`+`sfa_tween.py`)의 앱 영상 대비 MAE는 다음과 같다.

- R1 9장면: 0.05–0.76(맞춤용)
- 50% 선 굵기: 0.05–0.58
- APP-T1 35프레임: ≤0.26(새 장면)
- 실제 작품 244프레임: 평균 0.908, 최대 3.38(255 기준)

## 정적으로만 확인 (실물 미확인)

- DB 내부 처리: root/base 압축, ID 예약, unused AO 정리, undo history·FastHash. 이들은 SFA 출력에 드러나지 않는다.
- 객체별 glow backend 선택: shader → raster plan/캐시 → MaskFilter. 실물 결과는 shader 식과 맞았다.
- 그룹 Flags 인코딩·복구, 원근 변형, 크기·늘이기 패널 식, 레이어 병합·삭제·추가.

## 남은 소규모 항목

- 큰 glow의 raster 경로와 끝 모양 세부(작품 최대 오차 약 3.4의 원인 후보).
- InterpolatedFrame 그리기 본문 전체.
- 여백 P 식의 추가 실측(100%/50% 외 값).
- 정배수가 아닌 FPS에서 1프레임 효과가 "씹히는" 체감: 정적 해석은 프레임별 출력 장수 불균등이며 실물 미확인.
- 비정상 입력·DB 실패 원자성·전체 UI 조작의 완전한 목록.

## 생성 AI에 주는 실용 규칙(지금까지의 근거)

- 트위닝 설정은 재생 FPS의 정배수를 기본으로 한다.
- 1프레임 효과를 원본 프레임 길이만큼 유지하려면 같은 객체를 이어 두거나 TweenLink를 쓴다. 짝 없는 객체는 트위닝 중간 프레임에서 사라진다.
- 채우기 색을 보간하려면 FS 점 참조가 대응 가능해야 한다(−1 참조는 대응이 쉽다). 점 ID 참조는 대응에 실패해 색이 유지되기 쉽다.
- 숨긴 레이어는 출력되지 않는다. 레이어 목록 순서가 앞뒤 순서를 정한다.
- 선 굵기는 기본으로 얇게 두고, 영상에 따라 가변적으로 쓴다(사용자 방향).
