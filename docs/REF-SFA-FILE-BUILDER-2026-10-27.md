# 외부 스킬 sfa-file-builder 검토 — 받아갈 것 / 버릴 것 (2026-10-27)

사용자가 받은 다른 사람의 Claude 스킬(SKILL.md 534줄 + 코드, 실사·그림·영상 → SFA 변환)을 읽고 우리 규칙과 대조했다.
스킬 원문과 그 변환 결과물(ink_12fps.sfa 등)은 다른 사람 것이라 저장소에 넣지 않는다(scratch만). 여기에는 요약과 우리 판단만 둔다.
범위: 문서 읽기 + 결과물 1개(ink_12fps.sfa) 구조 측정·서버 렌더. 스킬 코드는 실행하지 않았다. 앱 화면 대조는 아직 없다.

## 받아갈 것 (2단계 영상 → SFA 변환기에 넣을 목록)
1. **파란점 규칙**: 떨어진 덩어리마다 파란점(`Flags=3`) 1개, 주변이 트인 곳. 조각이 많으면 가까운 빨간점끼리 연결해 덩어리 하나로(`link_pieces`).
   우리 기존 출력(glow_fit 등)은 첫 점 `8`/나머지 `9`만 써서 파란점이 없다 → 앱에서 손볼 파일이면 필요. (sfa_slim.py는 반영함)
2. **기본본 + `_최적화`본 두 벌**: 색 수↓, 흡수 면적 3–6배, 곡선 오차 2–3배. 장당 오브젝트 수천 개면 손편집이 어렵다.
3. **작은 유채색 보충**: 회색이 넓은 그림에서 k-means가 놓치는 채도 높은 작은 영역을 따로 추가 → 나카무라 섬광의 얇은 색 테에 해당.
4. **반짝이 점**: 밝기 top-hat으로 작은 밝은 점을 찾아 작은 원(곡선 4–6개)으로. 불티·빛 방울.
5. **`FS Kind="1" ObjId`**: 오브젝트 하나 통째 채우기(점·T 없음). 원 등 닫힌 단일 오브젝트 채우기를 가볍게.
6. **변환 후 자동 비교 단계**: 스킬의 `simulate_fill` 대신 우리 `sfa_render.py`(앱과 거의 같음)로 원본과 화소 비교를 기본 순서에 넣는다.

## 버릴 것
- 12fps 추출·12fps 미리보기 가정 — 우리는 24fps 직접 그리기, 2s·3s 리듬 보존이 원칙.
- 그 사용자 취향(말투, 방·소품 나누기, 스티커 흰 배경 지우기).
- 블랙햇 먹선 덧그리기를 기본으로 켜기 — 실사·얼굴용. 나카무라 이펙트는 먹선 없는 색 면이 많아 없던 선이 생긴다. 필요한 컷만.
- 글로우 없는 출력 — 섬광은 우리 앱 확인 규칙(글로우 정수, 띠 폭 = 8·굵기·두께/10)으로 글로우 선을 써야 한다.
- SVG·폰트·방 장면·메시 그라데이션 처리 — 대상이 다르다(참고만).

## 이미 같은 것
- 좌표: X·Y 각각 0–100(16:9), glow_fit Writer와 같다. 구멍 채우기 `Contour="1.."`도 이미 사용.
- 영상은 팔레트를 모든 장에서 한 번만 뽑아 공유(색 깜빡임 방지) — palette_sfa.py와 같은 구조.

## 결과물 측정: ink_12fps.sfa (실사 잉크 영상 변환본, 창작 아님)
- 96장(앱 12,12면 8초), 오브젝트 158,224(장당 501–2,825, 중간값 약 1,170), 압축 11.1MB / XML 90.5MB, 색 12개, 글로우·구멍 없음, 홀드 없음.
- 구조: 모든 선이 정확히 한 FR의 테두리(같은 색, 굵기 0.1), FR은 구멍 없는 고리 하나, 한 장 전체가 AC로 이어진 덩어리 하나(파란점 1개).
  큰 영역을 먼저 칠하고 작은 영역을 위에 덮는 겹쳐 칠하기(화면 한 곳을 평균 1.2–1.7번 칠함).

## 같은 겉모습으로 가볍게 만들기 시험: tools/sfa_slim.py (2026-10-27)
- 방법: ① 보이는 경계는 허용 오차(1920×1080 화소) 안에서 더 적은 2차 곡선·직선으로 다시 맞춤.
  ② 겹쳐 칠하기를 이용 — 먼저 칠하는 영역의 경계 중 나중 영역이 덮는 쪽은 나중 영역 밑으로 부풀린 곡선/지름길로 대체
  (바뀐 넓이가 전부 나중 영역 안쪽 1px 이상 또는 원래 경계 1px 띠 안일 때만, 래스터로 검사). 맞닿은 경계가 두 번 저장되던 것을 한 번으로 줄이는 효과.
  ③ 좌표 소수 3자리. 영역 순서·색·굵기·덩어리 하나·파란점 1개는 원본 그대로.
- 결과(96장 전체, sfa_render.py 1920×1080 대조):

| 버전 | 곡선 | 압축 | XML | 평균 차 | 16 넘게 다른 화소(평균/최대) | 96 넘게 다른 화소 최대 |
|---|---|---|---|---|---|---|
| 원본 | 158,224 | 11.1MB | 90.5MB | — | — | — |
| tol 0.6 | 117,789 (74%) | 6.3MB | 62.0MB | 0.097 | 0.21% / 0.38% | 0.010% |
| tol 1.0 | 104,657 (66%) | 5.6MB | 55.1MB | 0.165 | 0.43% / 0.73% | 0.032% |

  차이는 경계 가장자리 번짐 수준이고 최악 장(62)을 4배 확대해도 구분 안 됨. 구조 검사(선-영역 1:1, 고리 이음매 연결, 덩어리 하나, 파란점 1개, ID 중복 없음) 96장 통과.
- 덜 준 이유: 원본 곡선은 이미 잘 맞춰져 있어 보이는 경계만 다시 맞추면 0.4px에서 102%, 0.8px에서 89%뿐. 줄어든 대부분은 ②(잉크 장면은 경계의 43–45%가 덮이는 쪽, 비커만 있는 첫 장은 7%).
- XML이 곡선 수만큼 안 주는 이유: 곡선마다 글로우·ObjectScale 등 속성 문자열이 크다(곡선당 약 520바이트).
- 미확인: 앱에서 열기·재생 속도·표시(사용자 휴대폰 확인 필요). 범위: 구멍·원·채우기 없는 선이 있는 파일은 도구가 거절.
