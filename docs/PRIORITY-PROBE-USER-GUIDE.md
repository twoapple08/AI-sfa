# 모바일 실행 안내 — 네 가지 협력 작업

- 작성일 2026-10-14의 실행 절차 기록이다.
- 2026-10-15 현재 00–05 반환 자료 분석을 완료했으며, 재실행 요청이 아니다.
- 최신 UI 결과는 [UI-04-05-RESULTS-2026-10-15.md](UI-04-05-RESULTS-2026-10-15.md).

## 준비물과 공통 원칙

필요한 것:
- 현재 휴대폰의 스파, SFA 가져오기·내보내기, 영상 내보내기, 화면 녹화 기능.
- PC / 루팅 / Termux 명령 / 새 APK 설치는 이번 작업에 필요하지 않다.
- ZIP을 저장한 뒤 압축을 풀 수 있는 파일 앱에서 연다.
- 원본 6개 SFA는 수정하지 않고 남긴다. 기존 사용자 작품을 이 시험에 사용하지 않는다.

메뉴 표기:
- 스파의 실제 메뉴 경로와 버튼 아이콘은 완전히 확인되지 않았다.
- 아래 "가져오기 / 프로젝트 SFA 내보내기 / 영상 내보내기 / 선택 / 복제"는 수행할 기능을 뜻하며, 특정 아이콘 위치를 추측한 안내가 아니다.
- 기능이 안 보이면 해당 메뉴 화면을 보내고 멈춘다. 비슷한 이름의 다른 기능으로 대체하지 않는다.

공통 원칙:
- FPS 표기 = (트위닝 FPS, 재생 FPS). 위/아래·왼쪽/오른쪽 위치로 판단하지 말고 각 항목 이름으로 맞춘다.
- FPS가 파일에 지정돼 들어온다고 가정하지 않는다. 가져온 직후 값과 직접 바꾼 값을 구분한다.
- 전체 선 굵기·캔버스 비율·배경·색·레이어·점·도형은 시험에서 지시한 것 외에는 변경하지 않는다.
  - 전체 굵기 항목이 보이면 첫 값을 기록하고, 이후 같은 값으로 유지한다.
  - 이름·위치가 불명확하면 임의로 설정하지 않는다.
- 영상은 가능하면 1920×1080 원본 MP4로 보낸다.
  - 이 해상도 선택이 없으면 제공되는 해상도를 쓰고 그 값을 알려 준다.
  - 다른 앱으로 편집·속도 변경·재인코딩하지 않는다.
- 그림이 회색 작업 공간에 보이는지, 흰 출력 사각형 안에 보이는지를 구분한다. 편집 화면의 조작점·플레이어 여백은 출력 내용이 아니다.
- 파일 이름을 지정할 수 없으면 앱의 원래 이름으로 보내고 "어느 입력 → 어느 작업 → 어느 결과"인지 적는다. 입력 파일을 결과로 다시 첨부하지 않도록 구분한다.

## 1. 수정 없는 저장 왕복 — 먼저 실행

1. 화면 녹화를 켠다. 스파에서 00_roundtrip.sfa를 새 프로젝트로 가져온다. 기존 작품에 덧붙이지 않는다.
2. 첫 프레임의 편집 화면 전체를 기록한다.
   - 왼쪽 청록 영역 / 가운데 원 / 오른쪽 발광선이 보이는지 그대로 남긴다.
   - 구멍이나 붉은 띠의 정확한 가림은 검사 대상이므로 임의로 수정하지 않는다.
3. 설정을 아직 바꾸지 말고, 가져온 직후 FPS 항목과 전체 굵기가 보이면 기록한다. 값을 적거나 화면을 캡처한다.
4. **도형·좌표·색·프레임을 수정하지 않고** 프로젝트를 SFA로 내보낸다.
   - 가능하면 00_roundtrip_initial.sfa로 저장한다.
   - 영상 파일이 아니라 편집 프로젝트 SFA다.
5. 이제 (T,P) = (24,24)로 직접 맞추고 설정 화면을 기록한다. 다른 설정은 그대로 둔다.
6. 다시 SFA로 내보내 00_roundtrip_24_24.sfa로 구분한다. FPS 설정이 프로젝트 저장에 들어가는지도 비교하므로, 두 SFA가 같아도 정상적인 결과다.
7. 영상 내보내기로 00_roundtrip_24_24.mp4를 만든다. 목표 1초다. 화면 녹화도 종료한다.

보내 줄 것: 재저장 SFA 2개, MP4, 가져온 직후·변경 후 FPS와 초기 굵기 기록(녹화에 보이면 추가 캡처 불필요).

오류가 나면:
- 가져오기 오류 / 빈 프로젝트 / 내보내기 오류가 나면 오류 화면과 여기까지의 기록을 먼저 보낸다.
- 파일을 직접 수정하거나 앱을 재설치하지 않는다.
- 새 생성 데이터의 importer 문제일 수 있으며, 앱 오류로 단정하지 않는다.
- 다음 합본 3개는 정상 가져오기가 확인된 뒤 진행한다. 00 결과만 먼저 보내 분석받아도 된다.

## 2. 통제 실험 합본 세 개

공통 절차:
1. 해당 SFA를 새로 가져온다.
2. 지정 FPS를 직접 설정한다.
3. 설정이 보이도록 한 번 기록한다.
4. 수정 없이 SFA를 재내보낸다.
5. MP4를 출력한다.

- 편집 도형의 모양이나 순서를 사용자가 맞추지 않는다.
- 마지막 SFA가 설정 후 저장인지 함께 적는다.

### 01_fill_order — (24,24), 8초

| 시간 | 시험 구간 | 기록할 관찰 |
|---|---|---|
| 0–1초 | 청록 외곽만 채우기 | 청록 면이 있는가 |
| 1–2초 | 안쪽 Contour 추가 | 안쪽이 열리는가, 뒤 붉은 띠가 보이는가 |
| 2–3초 | 안쪽 Contour 방향 반전 | 1–2초와 차이가 있는가 |
| 3–4초 | 겹친 FR: 빨강→파랑 목록 | 겹친 중앙의 색 |
| 4–5초 | 같은 구성 FR 목록 반대 | 겹친 중앙 색이 바뀌는가 |
| 5–6초 | 교차선: 빨강 앞 순서, 파랑 뒤 순서 저장 | 교차점 색 |
| 6–7초 | 별도 ID의 교차선, 순서 반대 저장 | 교차점 색이 바뀌는가 |
| 7–8초 | 청록 FR과 굵은 선 함께 | 선이 채우기를 덮는가 / 가려지는가 |

- 구멍 구간의 붉은 띠도 FR로 작성해 기본 선 패스와의 혼동을 줄였다.
- 순서가 각 프레임에서 상충하지 않도록 구간별 AO ID를 분리했다.
- 색 면이 안 나오거나 구멍이 막히면 중요한 검사 결과이므로 그대로 보낸다.
- 결과 이름 예: 01_fill_order_rt.sfa, 01_fill_order_24_24.mp4.

### 02_glow — (24,24), 12초

- 가운데 주황 선 / 푸른 글로우. **비교 기준은 2–3초 구간**이다.
- 다른 구간은 아래 변수 하나만 바꿨다(마지막 구간은 객체 수 비교).
- 각 구간은 1초이며, 프로젝트를 사용자가 따로 만들 필요가 없다.

| 시간 | 기준에서 바꾼 것 |
|---|---|
| 0–1초 | GlowAlpha = 0: 발광 없는 대조 |
| 1–2초 | GlowRadius = 4 |
| 2–3초 | 기준: Radius 12 / Thickness 20 / Alpha 255 / ObjectScale 1 |
| 3–4초 | GlowRadius = 28 |
| 4–5초 | GlowThickness = 10 |
| 5–6초 | GlowThickness = 40 |
| 6–7초 | GlowAlpha = 64 |
| 7–8초 | GlowAlpha = 128 |
| 8–9초 | 기본 선 Color 알파 0, 글로우 유지 |
| 9–10초 | GlowColor 자체의 ARGB 알파 64, GlowAlpha 255 유지 |
| 10–11초 | ObjectScale = 2, 좌표 유지 |
| 11–12초 | 완전히 겹친 동일 도형 2개 |

- 핵심: 기본 선이 투명해도 발광이 나오는지, 두 알파가 어떻게 작동하는지, 같은 위치 2개가 더 밝아지는지.
- 영상 편집기로 밝기·감마를 바꾸지 않는다.
- 결과 이름 예: 02_glow_rt.sfa, 02_glow_24_24.mp4.

### 03_tween — 같은 프로젝트에서 영상 두 개

1. 03_tween.sfa를 새로 가져온다. (24,24)로 맞추고 03_tween_24_24.mp4를 출력한다(7초 목표).
2. 도형을 수정하지 않고 (24,12)로 바꿔 03_tween_24_12.mp4를 출력한다(14초 목표).
3. 마지막 설정 (24,12) 상태의 프로젝트를 03_tween_rt.sfa로 재내보낸다. 두 설정 화면이 녹화에 보이면 별도 사진은 필요 없다.

- 각 구간은 4상태 × 6 원본 프레임이다.
- (24,12)에서는 상태당 0.5초, 구간당 2초.
- (24,24)에서는 길이가 절반이므로, 같은 초 번호가 아니라 같은 원본 프레임으로 비교한다.
- 회색 세로선은 모든 프레임에 남는 대조다.

| 보간 영상 시간 | 구간 | 바뀌는 것 |
|---|---|---|
| 0–2초 | 같은 ID 이동 | 원이 좌/우 위치를 번갈아 사용 |
| 2–4초 | 생성·삭제 | 원 없음 → 있음 → 없음 → 있음 |
| 4–6초 | 같은 자리 새 ID 교체 | 모양·색·위치는 같고 AO ID만 번갈아 변경 |
| 6–8초 | FR 생성·삭제 | 삼각형 선은 유지, 채우기만 없음/있음 |
| 8–10초 | 경계 하나 삭제 | 투명 경계 3개 + FR ↔ 경계 2개 / FR 없음. 잘못된 참조를 남기지 않도록 연결도 정리 |
| 10–12초 | 기본 선 알파 | 같은 ID·좌표의 원 알파 255/0 |
| 12–14초 | FR 색 | 같은 삼각형 경계, 빨강/파랑 채우기 |

- 발생 프레임이 짧아서 휴대폰 재생으로 못 봐도 괜찮다. 원본 MP4를 받아 프레임 단위로 분석한다.
- 직접 슬로모션으로 저장하지 않는다.

## 3. 실제 편집 버튼 — 결과 상태와 UI 연산 연결

- 04_ui_seed.sfa는 한 프레임이다.
- 스틱맨의 화면 오른쪽 팔은 빨강, 왼쪽 팔은 파랑이다.
- 오른쪽의 주황 수평선 2개는 서로 연결되지 않았다.
- 도형 선택·앵커·기준점이 화면에 보이게 녹화한다.

### 공통 절차 — 매 실험마다 원본에서 다시 시작

1. 04_ui_seed.sfa를 새 프로젝트로 가져온다. 기존 실험 결과 위에 다른 조작을 누적하지 않는다.
2. 입력 왕복 차이를 분리하기 위해 앱에서 SFA로 저장한다.
   - 첫 정상 가져오기 기준은 04_ui_baseline.sfa로 한 번 보내면 된다.
   - 다음 실험에서 자동 설정이 달라졌다면 알려 준다.
3. 화면 녹화를 켠 상태에서 선택 대상 → 선택 도구·메뉴 → 옵션 값 → 기준점 → 한 번의 조작을 모두 기록한다.
   - 메뉴가 열린 채 잠깐 멈춰 이름과 값을 읽을 수 있게 한다.
   - 촬영 시간을 특정 초로 맞출 필요는 없다.
4. 조작 후 정지 화면을 보여 주고 SFA로 내보낸다. 해당 실험 이름으로 파일을 구분한다.
5. 다음 실험은 다시 04_ui_seed에서 시작한다. undo로 기준이 완전히 복원됐다고 가정하지 않는다.

### U1 늘리기

- 빨강 팔 중 팔꿈치와 손을 잇는 아래 선 1개를 선택한다. 화면 오른쪽의 손끝은 팔꿈치보다 오른쪽 아래다.
- 실제 "늘리기" 기능을 열어 옵션·기준점이 있으면 녹화한다. 단순 점 이동 도구로 대체하지 않는다.
- 숫자 배율 입력이 가능하면 2배로 한 번만 설정한다.
  - 배율 대신 다른 값을 입력하는 UI라면 기존 값·새 값을 기록한다.
  - 드래그만 가능하면 팔의 방향으로 눈에 띄게 늘리는 한 번의 드래그를 기록한다.
- 어깨·팔꿈치·위팔·몸통 중 어디가 따라 움직였는지 보여 준다.
- 결과: U1_stretch.sfa와 녹화.

### U2 원근

- 새 04_ui_seed에서 스틱맨 전체만 선택하고 주황 선 2개는 제외한다. 선택 표시로 범위를 확인한다.
- 실제 원근 기능을 열고 표시되는 방식·옵션을 기록한다. 여러 방식이 있다면 처음 선택한 방식 이름을 남기며, 이번에는 한 방식만 쓴다.
- 조작 핸들이 있으면 오른쪽 위 핸들 하나를 왼쪽으로 이동한다.
  - 다른 UI라면 그 UI가 허용하는 조작 한 번을 기록한다.
  - 최종 형태를 맞추기 위한 추가 수정은 하지 않는다.
- 결과: U2_perspective.sfa와 녹화. 원근이 선택 대상에 적용되지 않으면 오류·반응 없음도 그대로 기록한다.

2. 새 04_ui_seed에서 주황 선 2개만 선택하고 실제 그룹 기능을 적용한다. 이동 전 상태를 U4_grouped.sfa로 저장한다.
3. 위 주황 선 하나를 선택하려는 동작부터 녹화하고 한 번 오른쪽으로 옮긴다. 선택이 그룹 전체로 확장되는지도 기록한다. U4_grouped_move.sfa로 저장한다.
4. 그룹 해제를 실행하고 이동하지 않은 상태를 U4_ungrouped.sfa로 저장한다. 다시 위 선만 이동하는 동작을 기록하고 U4_after_ungroup_move.sfa로 저장한다.

- 정밀하게 같은 픽셀 수로 옮길 필요는 없다. 이번 핵심은 선택·이동의 범위와 저장 표현이다.
- 원근 실험과 섞지 않는다. 올그룹은 이번에는 사용하지 않는다.

### U5 수동 트위닝 잇기 — 메뉴가 확인될 때만

- 05_link_seed.sfa는 원본 1–12가 왼쪽 원, 13–24가 오른쪽 원이며 서로 다른 AO ID다. 현재 TweenLink는 저장돼 있지 않다.

1. 가져온 뒤 수정 없이 05_link_before.sfa로 저장한다. (24,12) 영상을 05_link_before.mp4로 출력한다.
2. 원본 12/13 사이 경계를 편집 화면에서 확인한다.
   - 수동 트위닝 연결·잇기 기능이 실제로 보이면 메뉴부터 녹화하고 왼쪽 원과 오른쪽 원 하나를 연결한다.
   - 기능의 방향·화면 조작법을 아직 확인하지 못했으므로 정확한 버튼 순서를 추측하지 않는다.
3. 그 기능을 사용하는 방법을 알고 있다면 평소 방식으로 한 번 연결하고, 선택 순서를 모두 녹화한다.
   - 모르겠으면 연결 메뉴·화면을 먼저 보내면, 그 화면을 기준으로 다음 동작을 안내한다.
   - 점의 일반 연결 AC나 그룹으로 대체하지 않는다.
4. 05_link_after.sfa와 (24,12)의 05_link_after.mp4를 보낸다. 이 영상은 2초 목표다.

## 4. 제작자 문의 — 현재 제외

- 사용자가 제작자와 소통할 수 없다고 확인해, 아래 문의 단계는 진행하지 않는다. 남은 세 작업만 수행한다.
- 아래 문안 관련 설명은 과거 준비 이력이다.

과거 준비 내용:
- ZIP의 DEVELOPER-REQUEST-KO.txt를 복사해 제작자와 기존에 연락하던 경로로 전달한다. 내가 대신 발송하지 않았다.
- 전체 소스·서명 키·개인 DB를 요구하는 문안이 아니다.
- 우선 정확히 **51.0.0의 실제 영상 출력 렌더 경로**와 FR/Contour, 글로우, 보간, importer 관련 설명 또는 해당 함수 코드만 요청한다.
- 설명·의사코드·관련 소스 파일 일부 모두 도움이 된다. 제작자가 소스 공유를 못 한다면 각 질문의 동작 설명만 받아도 된다.
- 답변과 첨부 파일을 그대로 전달하고, 공개 가능 범위가 있으면 함께 알려 준다.
- 원본 코드는 허가 없이 공개 저장소에 넣지 않는다.

## 반환 자료 체크리스트

- 처음은 00 묶음부터 보내도 된다. 파일 수가 많으면 주제별로 나눠 첨부한다.
- 재저장 파일·출력 영상은 각각 연결되는 입력 파일 이름을 적는다.

체크리스트:
- 왕복: 00_initial / 00_24_24 SFA 2개 + 1초 MP4 + 설정 기록.
- 통제 실험: 01/02/03 재저장 SFA 3개 + 01/02 MP4 각 1개 + 03 MP4 두 개 + 설정 기록.
- 실제 편집: 04_ui_baseline, U1/U2 각 SFA + 녹화, U4의 각 단계 SFA + 녹화. U5는 메뉴 확인 후 전후 자료.
- 제작자 문의는 제외. 답변이나 소스가 없어도 나머지 시험을 진행한다.
- 성공·실패 모두 "입력 파일 / 수행 동작 / (T,P) / 출력 파일 / 이상점" 형식으로 짧게 적는다.

- 이 자료로 앱 전체 이해가 즉시 완료되는 것은 아니다.
- importer가 속성을 바꾸면 먼저 왕복 차이를 분석하고, 통제 시험의 실제 입력이 무엇이었는지 확인한 뒤 규칙을 판정한다.
