# 모바일 실행 안내 — 네 가지 협력 작업

작성일2026-10-14의실행절차기록. 2026-10-15 현재00–05반환자료분석완료이며재실행요청이아니다. 최신UI결과는[UI-04-05-RESULTS-2026-10-15.md](UI-04-05-RESULTS-2026-10-15.md). 최초자동검사는파일구조/변수분리검사이고실제앱결과와구분한다.

## 준비물과 공통 원칙

필요한 것은 현재 휴대폰의스파, SFA가져오기/내보내기, 영상내보내기, 화면녹화 기능이다. PC/루팅/Termux 명령/새APK 설치는 이번 작업에 필요하지 않다. ZIP을 저장한 뒤 압축을 풀 수 있는 파일앱에서 연다. 원본6개SFA는 수정하지 않고 남긴다. 기존 사용자 작품을 이 시험에 사용하지 않는다.

스파의 실제 메뉴 경로와 버튼 아이콘은 완전히 확인되지 않았다. 아래 “가져오기/프로젝트SFA내보내기/영상내보내기/선택/복제”는 수행할 기능을 뜻하며 특정 아이콘 위치를 추측한 안내가 아니다. 기능이 안 보이면 해당 메뉴 화면을 보내고 멈춘다. 비슷한 이름의 다른 기능으로 대체하지 않는다.

- FPS표기=(트위닝FPS,재생FPS). 위/아래·왼쪽/오른쪽 위치로 판단하지 말고 각 항목 이름으로 맞춘다.
- FPS는 파일에 지정돼 들어온다고 가정하지 않는다. 가져온 직후값과 직접 바꾼값을 구분한다.
- 전체 선굵기·캔버스비율·배경·색·레이어·점·도형은 시험에서 지시한 것 외에는 변경하지 않는다. 전체굵기 항목이 보이면 첫값을 기록하고 이후 같은값으로 유지한다. 이름/위치가 불명확하면 임의설정하지 않는다.
- 영상은 가능하면1920×1080으로 원본MP4를 보낸다. 이 해상도 선택이 없으면 제공되는 해상도를 쓰고 그값을 알려준다. 다른 앱으로 편집/속도변경/재인코딩하지 않는다.
- 그림이 회색 작업공간에 보이는지와 흰 출력사각형 안에 보이는지를 구분한다. 편집화면의 조작점/플레이어여백은 출력내용이 아니다.
- 파일 이름을 지정할 수 없으면 앱의 원래 이름으로 보내고 “어느 입력→어느 작업→어느 결과”인지 적는다. 입력파일을 결과로 다시 첨부하지 않도록 구분한다.

## 1. 수정 없는 저장 왕복 — 먼저 실행

1. 화면녹화를 켠다. 스파에서00_roundtrip.sfa를 새 프로젝트로 가져온다. 기존 작품에 덧붙이지 않는다.
2. 첫프레임의 편집화면 전체를 기록한다. 왼쪽청록영역/가운데원/오른쪽발광선이 보이는지 그대로 남긴다. 구멍이나붉은띠의정확한가림은검사대상이므로 임의수정하지 않는다.
3. 설정을 아직 바꾸지 말고, 가져온 직후FPS항목과 전체굵기가 보이면 기록한다. 값을적거나화면을캡처한다.
4. **도형·좌표·색·프레임을 수정하지 않고** 프로젝트를 SFA로 내보낸다. 가능하면00_roundtrip_initial.sfa로 저장한다. 영상파일이 아니라 편집프로젝트SFA다.
5. 이제(T,P)=(24,24)로 직접 맞추고 설정화면을 기록한다. 다른설정은 그대로둔다.
6. 다시SFA로 내보내00_roundtrip_24_24.sfa로 구분한다. FPS설정이프로젝트저장에들어가는지도비교하므로 두SFA가같아도정상적인결과다.
7. 영상내보내기로00_roundtrip_24_24.mp4를 만든다. 목표1초다. 화면녹화도 종료한다.

보내줄 것: 재저장SFA2개,MP4,가져온직후/변경후FPS와초기굵기기록(녹화에보이면추가캡처불필요).

가져오기 오류/빈프로젝트/내보내기 오류가 나면 오류화면과 여기까지의기록을 먼저보낸다. 파일을직접수정하거나앱을재설치하지않는다. 새생성데이터의importer문제일수있고앱오류로단정하지않는다. 다음합본3개는정상가져오기가확인된뒤진행한다.00결과만먼저보내분석받아도된다.

## 2. 통제 실험 합본 세 개

공통절차: 해당SFA를새로가져오기 → 지정FPS직접설정 → 설정이보이도록한번기록 → 수정없이SFA재내보내기 → MP4출력. 편집도형의 모양이나순서를사용자가맞추지않는다. 마지막SFA가설정후저장인지함께적는다.

### 03_tween — 같은 프로젝트에서 영상 두 개

1.03_tween.sfa를새로가져온다. (24,24)로맞추고03_tween_24_24.mp4를출력한다(7초목표).

각구간은4상태×6원본프레임이다. (24,12)에서는상태당0.5초,구간당2초. (24,24)에서는길이가절반이므로같은초번호가아니라같은원본프레임으로비교한다. 회색세로선은모든프레임에남는대조다.

| 보간영상시간 | 구간 | 바뀌는것 |
|---|---|---|
|0–2초|같은ID이동|원이좌/우위치를번갈아사용|

발생프레임이짧아서휴대폰재생으로못봐도괜찮다. 원본MP4를받아프레임단위로분석한다. 직접슬로모션으로저장하지않는다.

## 3. 실제 편집 버튼 — 결과상태와 UI연산 연결

04_ui_seed.sfa는한프레임이다. 스틱맨의화면오른쪽팔은빨강,왼쪽팔은파랑. 오른쪽의주황수평선2개는서로연결되지않았다. 도형선택/앵커/기준점이화면에보이게녹화한다.

### 공통절차 — 매 실험마다 원본에서 다시 시작

1.04_ui_seed.sfa를새프로젝트로가져온다. 기존실험결과위에다른조작을누적하지않는다.
2.입력왕복차이를분리하기위해앱에서SFA로저장한다. 첫정상가져오기기준은04_ui_baseline.sfa로한번보내면된다. 다음실험에서자동설정이달라졌다면알려준다.
3.화면녹화를켠상태에서선택대상→선택도구/메뉴→옵션값→기준점→한번의조작을모두기록한다. 메뉴가열린채잠깐멈춰이름과값을읽을수있게한다. 촬영시간을특정초로맞출필요는없다.
4.조작후정지화면을보여주고SFA로내보낸다. 해당실험이름으로파일을구분한다.
5.다음실험은다시04_ui_seed에서시작한다. undo로기준이완전히복원됐다고가정하지않는다.

### U1 늘리기

- 빨강팔중팔꿈치와손을잇는아래선1개를선택한다. 화면오른쪽의손끝은팔꿈치보다오른쪽아래다.
- 실제‘늘리기’기능을열어옵션/기준점이있으면녹화한다. 단순점이동도구로대체하지않는다.
- 숫자배율입력이가능하면2배로한번만설정한다. 배율대신다른값을입력하는UI라면기존값/새값을기록한다. 드래그만가능하면팔의방향으로눈에띄게늘리는한번의드래그를기록한다.
- 어깨·팔꿈치·위팔·몸통중어디가따라움직였는지보여준다. 결과:U1_stretch.sfa와녹화.

### U2 원근

- 새04_ui_seed에서스틱맨전체만선택하고주황선2개는제외한다. 선택표시로범위를확인한다.
- 실제원근기능을열고표시되는방식/옵션을기록한다. 여러방식이있다면처음선택한방식이름을남기며이번에는한방식만쓴다.
- 조작핸들이있으면오른쪽위핸들하나를왼쪽으로이동한다. 다른UI라면그UI가허용하는조작한번을기록한다. 최종형태를맞추기위한추가수정은하지않는다.

- 그기능을사용하는방법을알고있다면평소방식으로한번연결하고선택순서를모두녹화한다. 모르겠으면연결메뉴/화면을먼저보내면그화면을기준으로다음동작을안내한다. 점의일반연결AC나그룹으로대체하지않는다.

## 4. 제작자 문의 — 현재 제외

ZIP의DEVELOPER-REQUEST-KO.txt를복사해제작자와기존에연락하던경로로전달한다. 내가대신발송하지않았다. 전체소스/서명키/개인DB를요구하는문안이아니다.

## 반환자료 체크리스트
