## 2. 놓친 위험과 코드에서 확인한 경로

### ① 입력에는 없는 면이 정답에 나타날 수 있습니다 — 직접 재현했습니다.

`seq_data.save_frames()`는 원래 SFA를 렌더하고, 정답은 `K.encode()`로 만듭니다. 그런데 두 경로의 숨긴 레이어 처리가 완전히 같지 않습니다.

면의 첫 참조 오브젝트가 숨긴 레이어에 있고 나머지 참조는 보이는 레이어에 있으면, 렌더러는 그 면을 숨깁니다. 토큰 변환기는 숨긴 오브젝트를 제거하면서 남은 참조로 면을 다시 적을 수 있습니다.

인공 반례에서 결과는 다음과 같았습니다.

- 입력: 완전한 흰 화면.
- 정답 토큰 복원: 빨간 면이 있는 화면.
- 문법 검사: 통과.
- 640×360에서 채널 차이 24 초과 화소: **62,242개**.

이는 실제 장을 변환하는 `real_frame()` 경로에서도 재현했습니다. **같은 SFA에서 그림과 정답을 만들었다는 사실만으로 정합성이 보장되지는 않습니다.** 원래 렌더와 토큰 복원 렌더를 함께 대조해야 합니다.

근거: [토큰 변환기](https://github.com/twoapple08/AI-sfa/blob/5b078d419945d727b10addeb4db154342f237bfe/tools/sfa_tokens.py), [렌더러](https://github.com/twoapple08/AI-sfa/blob/5b078d419945d727b10addeb4db154342f237bfe/tools/sfa_render.py).

### ② 숨긴 레이어만 있는 장을 조합기가 되살립니다 — 직접 재현했습니다.

[`sfa_compose.py` 36행](https://github.com/twoapple08/AI-sfa/blob/5b078d419945d727b10addeb4db154342f237bfe/tools/sfa_compose.py#L36)의 가시 레이어 집합 뒤에 붙은 `or None`이 원인입니다.

‘레이어 정의가 없음’과 ‘정의는 있지만 모두 숨김’을 똑같이 처리합니다. 숨긴 레이어만 있는 장에서도 묶음 1개가 추출됐고, `place()`는 새 레이어를 보이도록 만듭니다.

그림·정답이 함께 바뀌므로 반드시 둘 사이의 불일치는 아닙니다. 하지만 **숨긴 내용을 학습에서 제외한다는 명세를 어깁니다.**

### ③ 실제 장 자르기가 원래 앞뒤 순서를 보존하지 않습니다 — 직접 재현했습니다.

`real_crop()`는 묶음의 최소 순서 `z`로 정렬하고, 묶음 안 오브젝트를 연속해서 배치합니다. 면으로 연결된 두 오브젝트 사이에 다른 묶음이 끼어 있으면 원래 순서가 바뀝니다.

재현에서는 **빨강 → 파랑 → 초록**이 **빨강 → 초록 → 파랑**으로 바뀌었고, 차이 화소가 **4,728개**였습니다.

또한 `place()`의 레이어 순서는 원래 `LayerDef` 순서 대신 AO에서 처음 발견한 순서로 정합니다. 자르기에서는 선택한 오브젝트들을 **원래 전체 그리기 순서와 레이어 순서로 다시 구성**해야 합니다. `real_crop()`에는 원래 시퀀스 배경색도 전달되지 않아, 장에 배경색 속성이 없으면 상속받던 배경이 흰색으로 바뀔 수 있습니다.

### ④ 원 부분 면의 좌우 반전은 현재 단순 반전이 아닙니다.

코드 주석처럼 원의 AP만 반전하고 면의 T를 유지하면, 원 테두리는 반전되지만 부분 면은 원래 그림을 뒤집은 모양과 달라질 수 있습니다. 현재 렌더러 방향 규칙에서 순수한 좌우 반사를 보존하려면 원 조각의 구간도 대응시켜야 합니다.

현재도 변형된 SFA로 그림과 정답을 함께 만들기 때문에 이것을 곧바로 정답 불일치라고 부를 수는 없습니다. 다만 **실제 장의 반전이라는 설명과 결과가 다르며, 원래 면 형태를 깨뜨릴 수 있습니다.**

아울러 배치 경계 상자는 선 굵기·글로우와 직선 면 조각의 바깥 T 구간까지 보장하지 않습니다. ‘모두 화면 안’이라는 설명도 기하 점과 실제 렌더 범위를 구분해야 합니다.

### ⑤ 방향별 정답 길이를 생성 조건으로 쓰면 입력 교환 판정이 오염될 수 있습니다.

평가 목록에서 공식 두 방향의 토큰 길이가 다른 장은 3개였습니다. 그중 기본 제한이 실제로 달라지는 장은 2개입니다.

| 장 | 두 방향 정답 길이 | 적용되는 생성 상한 |
|---|---:|---:|
| 스가구신버2 | 25 / 22 | **178 / 172** |
| Jsjw_SPECTRUM | 97 / 100 | **322 / 328** |

나머지 `922`는 양쪽 모두 모델 최대 길이 2,048에 걸립니다.

따라서 **입력을 무시하고 같은 토큰 흐름을 내는 모델도 방향별 절단 결과가 달라질 수 있습니다.** Δ가 순수하게 입력 차이에서 나온다고 보장할 수 없습니다.

또한 [`generate()`](https://github.com/twoapple08/AI-sfa/blob/5b078d419945d727b10addeb4db154342f237bfe/tools/seq_train.py#L328)는 한도 64토큰 전부터 가능한 자리에서 EOS를 강제합니다. 모델 최대 길이에서는 이 강제 종료도 `done=True`로 남을 수 있습니다. **`--gen-len-mult 0`만 적용하는 것으로 종료 사유 문제가 모두 해결되지는 않습니다.**

공식 판정에는 동일한 생성 한도를 적용하고, 종료 이유를 생성기에서 직접 반환해야 합니다.

### ⑥ 공식 두 방향과 진단 네 방향의 지표가 섞입니다.

[`seq_judge.evaluate()`](https://github.com/twoapple08/AI-sfa/blob/5b078d419945d727b10addeb4db154342f237bfe/tools/seq_judge.py#L354)의 공식 승수는 0·1 방향으로 계산하지만, A·엄격 F1·건전성은 전달받은 모든 방향으로 계산합니다.

중간 두 방향과 마지막 네 방향을 그대로 비교하면 **모델 변화와 평가 대상 변화가 섞입니다.** 공식 두 방향의 A·건전성을 항상 따로 출력하고, 나머지는 진단으로 분리하는 편이 좋습니다. OOM 장은 승수 계산에서는 실패로 남지만 일부 점수 집계에서는 빠지므로, 점수에도 측정 완료 수를 붙여야 합니다.

### ⑦ 자료 비율과 오염 방지에서 추가 확인이 필요합니다.

- ‘같은 장 최대 3회’는 현재 보장되지 않습니다. 파일 전체 요청 수만 `3 × 장 수`로 제한하고 추가 장은 복원 추출합니다. 두 장에서 여섯 번 뽑는 코드를 재현하니 **한 장 4회·다른 장 2회**가 나왔습니다.
- 조합 모드는 내부에서 `V.file_list()`를 다시 사용하므로, `--compose --holdout`을 조합 검증 자료 생성에 그대로 쓰면 학습 파일을 사용할 수 있습니다. 현재 일반 학습 경로가 시험 파일을 포함한다는 뜻은 아닙니다.
- 조합 장의 출처 파일·원래 장·변환·자르기 여부가 충분히 저장되지 않아, 이후 중복과 노출 편향을 추적하기 어렵습니다.
- Kaggle 자료 코드 해시 목록에는 `sfa_paint_synth.py`가 빠져 있습니다. 합성기가 바뀌어도 기존 자료와의 차이를 놓칠 수 있습니다.

무작위 조합의 완전 가림·배경과 같은 색·저해상도에서 사라지는 얇은 선도 측정 대상입니다. 정답 오브젝트가 입력에서 전혀 식별되지 않는 비율이 높으면, 생성 실력과 별개로 도달 가능한 점수가 제한됩니다.

## 3. 짧은 Kaggle CPU 흐름 시험에서 꼭 잴 것

이번 시험은 **학습 효과보다 자료와 실행 경로의 정확성**을 확인하는 시험으로 정하는 것이 좋겠습니다.

| 확인 항목 | 반드시 남길 결과 |
|---|---|
| **실행 식별** | 코드 커밋, 자료 판·코드 해시, 씨앗, 평가 목록 해시, 생성 옵션, 시작·종료 체크포인트 식별값. |

CPU에서 즉시 EOS가 나왔다면 긴 생성 경로의 비용은 아직 측정하지 못한 것입니다. 별도로 긴 출력 경로를 확인해야 하며, CPU 속도로 GPU 판정 시간을 확정해서는 안 됩니다.

**17%가 충분한지, 쉬운 것부터가 더 좋은지, 새 작품 실력이 향상되는지는 이 짧은 CPU 시험으로 결정하지 않습니다.** 첫 GPU 회차에서는 고정된 실제 장·조합 장 점수와 길이별 추세로 판단하면 됩니다.

## 4. 논증거리 없음과 남은 일을 구분하면

**논증거리 없음:** 현재 단계 해상도로 추세 확인, 최종 360 확인, 공식 기회 두 번, 확정된 동점 범위 유지, 연결·면 묶음을 보존하는 조합 학습 방향, 전체 계획을 유지한 회차 분할입니다.

**논증이 남음:** 조기 생성 제한이 결론을 보존한다는 주장, 높은 B 자체를 이상 신호로 보는 주장, 묶음을 합치면 항상 보수적이라는 주장입니다.

**구현으로 고칠 일:** 숨긴 면 처리, 숨긴 레이어 추출, 자르기의 순서·배경 보존, 종료 사유, 공식·진단 집계 분리입니다.

**측정으로 정할 일:** 실제 장 비율, 단계별 긴 장 유지 능력, 중복 검출의 누락률, 판정 비용과 회차당 실제 학습량입니다.

이번에 기존 원 면 채점 시험 **22개**와 토큰 변환 시험 **3개**는 모두 통과했습니다. 전체 108개 시험이나 Kaggle·GPU·앱 열기를 새로 검증한 것은 아닙니다. 직접 재현한 결과와 실행 코드는 아래 부록에 보존했습니다.

## 부록: 재현 근거와 실행 코드

이 부록은 전달 시 재현 근거가 사라지지 않게 추가한 것이다. 위의 검토 본문과 구분한다.

- 아래 스크립트는 사용자 원본 SFA를 사용하지 않는다. XML을 메모리에서 직접 만드는 인공 반례다.
- 검토 당시 코드에서 나타난 결과이며, 수정 뒤에는 결과가 달라질 수 있다. 수정 뒤 반례가 사라졌다면 회귀 방지 시험으로 바꾸면 된다.
- 차이 화소는 640×360에서 RGB 채널 최대 절댓값 차이가 24를 초과한 화소 수다. H.264 압축 전 서버 렌더 결과다. 앱 렌더 결과로 해석하지 않는다.
- 스크립트가 직접 재현하는 항목은 모두 숨긴 레이어 추출, 숨긴 면 주인의 입력·정답 불일치, 자르기의 앞뒤 순서 변경, 장별 3회 제한 초과, N=45 승수다. 본문 다른 항목 전체를 실행 검증했다는 뜻은 아니다.
- N=45에서 30승의 단측 이항 꼬리는 `0.017848901777597348`이다.
- 외움 기준선 12.07점은 읽은 구현 문서의 실측값이며 이번 검토에서 원본 자료로 다시 계산하지 않았다.
- 평가 목록의 길이 차이 3개는 `data/judge_manifest.json`을 직접 읽어 확인했다. 스가구신버2는 25/22, 922는 1724/1712, Jsjw_SPECTRUM은 97/100이다.

```python
import copy
import json
import random
import sys
import xml.etree.ElementTree as ET
from collections import Counter
from pathlib import Path

import numpy as np

sys.path.insert(0, str(Path(__file__).parent / 'tools'))
import sfa_compose as C
import sfa_tokens as K
import sfa_render as R
import seq_judge as J

R.PARAMS.update(pad=0.0, thick_mul=640 / 1920)


def scene():
    seq = ET.Element('Sequence', HeightWidthRatio='0.5625', BackgroundColor='-1')
    fr = ET.SubElement(seq, 'Frame', ID='1', Position='0')
    return seq, fr


def layer(fr, key, visible=True):
    ET.SubElement(fr, 'LayerDef', ID=key, Visible='true' if visible else 'false')


def line(fr, key, lid, col, xy, order):
    ao = ET.SubElement(fr, 'AO', ID=str(key), TypeId='1', LayerId=lid, Color=str(col),
                       ThicknessScale=repr(C.snap_th(4)), DrawOrder=str(order))
    for i, (x, y) in enumerate(xy):
        ET.SubElement(ao, 'AP', ID=str(key * 10 + i), X=str(x), Y=str(y))
    return ao


def changed(a, b):
    return int((np.abs(a.astype(int) - b.astype(int)).max(axis=2) > 24).sum())


out = {}
sq, fr = scene()
layer(fr, '0', False)
line(fr, 1, '0', -16777216, [(20, 50), (80, 50)], 0)
us = C.units_of(fr, 0.5625)
out['all_hidden_units'] = len(us)
assert len(us) == 1

sq, fr = scene()
layer(fr, 'hidden', False)
layer(fr, 'visible')
line(fr, 1, 'hidden', 0, [(20, 20), (80, 20)], 0)
line(fr, 2, 'visible', 0, [(80, 20), (50, 80)], 1)
line(fr, 3, 'visible', 0, [(50, 80), (20, 20)], 2)
fill = ET.SubElement(fr, 'FR', Color='-65536')
for key in (1, 2, 3):
    ET.SubElement(fill, 'FS', ObjId=str(key), Kind='0', StartPtId=str(key * 10),
                  EndPtId=str(key * 10 + 1), StartT='0', EndT='1')
sq2, fr2 = C.real_frame(sq, fr, random.Random(2), 0.5625)
t, stats = K.encode(sq2, fr2)
K.fields(t)
raw = R.render_frame(sq2, fr2, 640, 360)
decoded = R.render_frame(sq2, K.decode(t), 640, 360)
out['hidden_fill_owner'] = dict(changed_pixels=changed(raw, decoded),
    input_nonwhite=int((raw != 255).any(axis=2).sum()), answer_nonwhite=int((decoded != 255).any(axis=2).sum()),
    objects=stats['objs'], fills=stats['fills'])
assert out['hidden_fill_owner']['input_nonwhite'] == 0
assert out['hidden_fill_owner']['changed_pixels'] > 1000

sq, fr = scene()
layer(fr, '0')
for key, col in ((1, -65536), (2, -16776961), (3, -16711936)):
    line(fr, key, '0', col, [(20, 50), (80, 50)], key - 1)
fill = ET.SubElement(fr, 'FR', Color='0')
for key in (1, 3):
    ET.SubElement(fill, 'FS', ObjId=str(key), Kind='1')
sq2, fr2 = C.real_crop(fr, random.Random(0), 0.5625, 2048)
out['crop_order'] = dict(original=[a.get('Color') for _, a in K.order_objects(sq, fr)],
                        cropped=[a.get('Color') for _, a in K.order_objects(sq2, fr2)],
                        changed_pixels=changed(R.render_frame(sq, fr, 640, 360), R.render_frame(sq2, fr2, 640, 360)))
assert out['crop_order']['original'] != out['crop_order']['cropped']
assert out['crop_order']['changed_pixels'] > 1000

for seed in range(100):
    rng = random.Random(seed)
    pick = rng.sample([0, 1], 2)
    pick += [rng.choice([0, 1]) for _ in range(4)]
    if max(Counter(pick).values()) > 3:
        out['per_frame_repeat'] = dict(seed=seed, picks=pick, counts=dict(Counter(pick)))
        break

out['binomial_N45'] = dict(need=J.need_wins(45), p_at_30=J.binom_tail(30, 45))
print(json.dumps(out, ensure_ascii=False, indent=2))
```
