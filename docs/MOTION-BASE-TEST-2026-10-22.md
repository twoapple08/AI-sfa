# 기초 동작 모델 시험 — MoMask 공개 가중치(학습 없음) (2026-10-22)

목적: '기초 모델 + 우리 자료 추가 학습' 구조의 첫 단계. 공개 글→동작 모델이 기준 프롬프트 1의 동작을 기본기 수준으로 만드는지 서버 CPU로 확인.

## 환경(서버, GPU 없음)
- 코드: github.com/EricGuo5513/momask-codes(얕은 복제, 저장소 밖 scratchpad/motion). 가중치: HumanML3D 학습판(188MB, README의 Google Drive 링크).
- 서버 Python 3.13·numpy 2 호환을 위해 고친 곳(외부 코드라 저장소에 넣지 않음): `numpy.core.umath_tests` → `np.matmul`, `np.float/np.int/np.bool` → 내장형, 글 파일 줄끝 개행 때문에 길이(`#프레임`)가 무시되던 것(`line.strip()`), matplotlib 3D 그림 저장(서버에서 실패) 생략.
- 실행: 문장 5개(아래), 20fps 기준 길이 지정 → CPU 약 40초. 출력: 22관절(SMPL 순서) 3D 좌표 npy + BVH.

## 넣은 문장(기준 프롬프트 1의 동작 부분, 영어)
1. 하늘에서 떨어져 한쪽 무릎·주먹을 짚는 착지(80프레임)
2. 웅크린 착지 자세에서 천천히 일어섬(40)
3. 카메라 쪽으로 천천히 걸어옴(96)
4. 걷다가 점점 빨라져 달리기(80)
5. 오른 주먹을 뒤로 당겼다 강하게 내지름(32)

## 결과(정면 투영 눈 확인)
- 돌아간다: 공개 모델만으로 문장 → 3D 관절이 나온다. 걷기·일어서기는 자연스럽다.
- 1번: 공중에서 내려와 웅크렸다 일어서는 정도. '한쪽 무릎·주먹을 짚는' 슈퍼히어로 착지 자세는 약하다.
- 4번: 가속해서 달리기로 넘어가는 변화가 작다.
- 5번: 앞으로 내지르는 펀치가 아니라 위로 크게 휘두르는 동작에 가깝다.
- 전체가 실제 사람(모캡) 움직임이라 부드럽다. 애니식 끊어짐(2프레임 유지, 빠른 정점)·과장은 없다 → 우리 자료로 입혀야 할 부분이 그대로 보인다.

## 다음
1. 22관절(SMPL) → SFA 뼈대(리그 A) 변환과 3D 카메라 투영(뒤로 빠지는 카메라)을 붙여 SFA로 본다.
2. 추가 학습 자료 준비: 애니 3D(nian41·나카무라)와 모캡을 HumanML3D 특징(263차원)으로 바꾸기 + 클립마다 영어 설명 문장(GPT).
3. Kaggle GPU에서 미세조정(MoMask 변환기, 필요하면 VQ까지).

## SFA 연결 (`tools/motion_to_sfa.py`, 같은 날)
- SMPL 22관절 → 리그 A 모양 14점(직선 TypeId 1 + 머리 원 TypeId 2, AC 연결, AO ID 프레임마다 고정) → 3D 핀홀 카메라 투영 → SFA. 먼 쪽 팔다리 회색(뒤), 선 굵기는 거리에 반비례.
- 시간: 20fps → F(24)로 다시 뽑고 hold 2(2프레임마다 새 자세). 카메라는 키 프레임(인물 기준 상대 위치 가능) 선형 보간.
- 기준 프롬프트 1 동작·카메라만(이펙트·배경 없음): 393프레임(16.4초). 계획 파일 `docs/storyboards/bench01_motion_plan.json`.
- 확인(서버 렌더): 하늘 올려다보기 → 떨어짐 → 착지 → 뒤로 빠지는 카메라 앞으로 걸어옴(점점 작아짐) → 달리기 → 카메라 앞 펀치까지 이어진다.
- 문제: ① 땅·배경이 없어 원근·속도감이 안 보인다. ② 낙하는 기초 모델이 못 만들어 높이를 더해 넣었다(착지 순간 자세가 서 있음). ③ 펀치가 카메라 쪽 내지르기가 아니다. ④ 걷기→달리기 가속이 약하다. ⑤ 길이가 AI 추정(9.6초)보다 긴 16.4초 — 동작 조각 길이를 장면 길이에 맞추는 단계가 아직 없다.

## 첫 추가 학습(같은 날, 진행 중)
- 자료(`tools/motion_dataset.py`, 서버 scratch·원본 유래라 저장소 밖): 애니 3D(lift_apply로 다시 뽑음: 전체 2,510추적 105,901프레임 → nian41·나카무라만, 위 방향 정렬·평활·디딤발로 엉덩이 이동 복원) 창 471개(동작 판정 문장 275, 나머지 "a person fights, in anime style") + 모캡 창 4,000개(설명 원문, 공격·피격·점프 위주). 합계 4,297(학습 4,083·검증 214).
- 트리거: 애니 문장 끝에 "in anime style"(그림체 LoRA 트리거와 같은 원리). 학습 때 애니 자료를 4배로 본다.
- 학습(`tools/momask_finetune.py`): VQ는 그대로, 마스크·잔차 트랜스포머만 미세조정(AdamW 2e-5, 배치 16). 서버 CPU 약 4초/단계, 3,000단계(약 3.3시간)로 시작.
- 알려진 한계: 애니 3D는 2D→3D 추정이라 떨림·깊이 오류가 있고, 엉덩이 이동은 디딤발 가정으로 되살린 근사다. 동작 문장은 12프레임 판정 묶음에서 만든 짧은 라벨 문장이다.

## 첫 학습 결과와 2차 자료(2026-10-23)
- 첫 학습(3,000단계, 검증 손실 mask 3.0·res 4.0)으로 기준 프롬프트 1 동작 + "in anime style": 걷기는 비슷, 달리기는 빨라짐, **낙하·착지는 바닥에 누워 기는 동작, 일어섬은 계속 웅크림, 펀치는 거의 안 움직임(학습 전보다 나빠짐)**.
- 원인: ① 문장 빈약("falls to the ground"를 "falls from the sky"와 혼동, 판정 없는 창 40%가 "fights" 한 문장) ② 2D→3D 창 일부가 팔다리 꼬임·몸 비틀림·큰 떨림 ③ 애니 4배 반복이 이 문제를 키움.
- 2차 자료(`motion_dataset.py` 수정): 품질 필터(가속 95% > 0.17 m/프레임², 어깨-골반 비틀림 90% > 45° 버림 — 133구간 제외), 판정 없는 창 제외, "falls to the ground" → "is knocked down to the ground", 외부 동작 문장 csv(`--captions`, Codex 작성 예정) 지원, 학습 때 애니 2배. 결과: 애니 182 + 모캡 4,000 = 4,034. 서버 CPU 1,500단계 시험 중(ft_v2).

## 3차 결과(PC `ft_v3_gpu`, 6,000단계)와 원인 — 2026-10-23
- 학습: GTX 1050 Ti 3,360초. 검증 손실은 1,000단계부터 제자리(mask 2.78–3.24, res 3.93–4.09; 마지막 3.035/3.978). 학습 전 기본 모델의 같은 종류 검증 손실은 약 4.8/5.0(4차 자료 검증으로 잼)이라 자료에 맞춰지긴 했다. 저장은 검증마다 덮어써서 남은 것은 6,000단계 가중치.
- 비교(`tools/bench_compare.py`, 기준 프롬프트 1의 7개 동작 문장, 씨앗 1·2·3, 기본 vs 3차+"in anime style"). 그림: Drive `04_SFA시험작/bench01_2026-10-23_base_vs_v3gpu/`(동작비교_s1·s2·s3.png = 관절 막대 8컷, 비교.jpg = 조립 장면).

- **원인 확인(자료 버그):** 3차 자료 애니 117개 모두 엉덩이 높이 변화가 0.00m(모캡 평균 0.25m). 2D→3D 결과가 골반 기준인데 `foot_lock_root`가 수평 이동만 되살렸다 → 쪼그림·일어서기·착지가 '골반은 그대로, 다리만 접힘'으로 배워짐. 일어서기·착지 실패와 구부정한 제자리 걸음이 이것과 맞는다.
- 고침(`motion_dataset.py`): 다리에서 가장 낮은 점(발목·발끝·무릎)을 매 프레임 바닥에 붙여 높이도 되살린다(두 발이 다 뜬 점프는 잃음). 고친 자료: 애니 111개 높이 변화 평균 0.16m.
- **남은 문제(고침으로 안 풀림):** 그림으로 보면 2D→3D 자세 자체가 문장과 어긋나는 창이 많다(예: "stands upright"인데 바닥 근처에 구겨짐, 무릎 꿇기 다리 모양 이상). 또 애니 자료에 기준 프롬프트 동작이 거의 없다(문장 기준: 일어서기 13·걷기 6·웅크림 4·펀치 1·착지/낙하 0). 그래서 애니 미세조정으로 기준 프롬프트의 착지·펀치가 좋아지길 기대하기 어렵다 — 펀치·낙하가 나아진 것은 모캡 3,000개 몫일 가능성이 있다(따로 확인 안 함).
- 4차 자료 `motion_data_mds4.zip`(Drive `07_도구/동작학습_1050ti/`): 고친 애니 111 + 3차 모캡 2,881 그대로. 학습 스크립트로 읽기 확인(2단계 시험).
