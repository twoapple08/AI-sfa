# GTX 1050 Ti로 짧은 시간에 많은 자료 거르기 (2026-10-19)

사용자 질문: "1050 Ti로 가장 짧은 시간 안에 최대한 많은 자료를 걸러내려면?" 훈련이 아니라 거르기(추론)다.
[실측]은 이 서버(CPU 4코어, GPU 없음)에서 잰 값, [추정]은 그로부터 계산한 값, [확인 필요]는 설치 때 직접 봐야 하는 값이다.

## 1. 결론

1. **GPU가 병목이 아니다.**
   - 거르기의 대부분(후보 찾기·문맥 비교)은 CPU에서 빠르다.
   - 1050 Ti는 마지막 X-CLIP 점수 단계만 빠르게 한다.
   - 정확도를 막는 것은 계산량이 아니라 '단색 섬광·이펙트 vs 임팩트' 판단이다(IMPACT-CONTEXT 4절: 재검사 291 중 단색 64·애매 35).
2. 가장 빠른 순서: **영상당 한 번만 디코딩 → CPU로 후보 찾기 → CPU로 문맥 같은 그림 걸러내기 → 남은 후보만 GPU X-CLIP → 애매한 것만 사람·Claude가 본다.**
   - 이 순서를 `tools/impact_pipeline.py` 한 명령으로 묶었다.
3. 411영상(약 33만 프레임 [추정])은 4코어 PC에서 대략 1–2시간이면 끝날 것으로 본다 [추정].
   - 사람이 볼 몫은 후보의 약 3분의 1(재검사·애매)이다.

## 2. 단계별 시간

| 단계 | 장치 | 서버 실측 | 411영상 추정 |
|---|---|---|---|
| 0. 원본 받기 | 네트워크 | 162개 1.9GB(md5 대조) 약 10분 | 약 5GB, 회선에 따라 20–40분 |
| 1. 후보 찾기 `impact_scan2` | CPU | 1669프레임 15.7초(약 106프레임/초, 1코어) | 33만 프레임 ÷ (106×3작업) ≈ 17분 |
| 2. 문맥 비교 `impact_context` | CPU | 후보당 1.4초(디코딩 포함), 캐시 있으면 0.5초 | 후보 약 1,200–1,500개 → 30–35분(1작업) |
| 3. X-CLIP `impact_xclip` | **GPU** | CPU에서 구간당 약 10초(다른 작업과 공유) | GPU 계산은 구간당 0.1–0.3초 [추정]. 디코딩이 남아 구간당 1–2초 → 20–50분 |
| 4. 3분류 합치기 | CPU | 수 초 | 수 초 |

- 디코딩만 따로 재면 256x144로 줄이며 초당 약 880프레임이다 [실측]. 그래서 1단계 시간은 디코딩보다 지표 계산이 대부분이다.
- 2·3단계는 후보마다 영상 앞부분부터 다시 디코딩한다. 더 줄이려면 1단계에서 저해상도 프레임을 남겨 재사용하면 된다(`IMPACT_CACHE`가 그 일부다).
- 후보 수는 지금까지의 비율(145영상 → 436구간)로 잡았다.

## 3. 1050 Ti 설정

- 사양: Pascal(GP107), 계산 능력 6.1, 메모리 4GB.
  - FP16이 매우 느리다. **FP32 그대로** 돌린다(코드 기본값).
- X-CLIP base(patch32) 가중치는 약 0.8GB라 4GB에 충분하다. 한 번에 1구간씩 돌려도 GPU가 놀지 않을 만큼 계산이 작다.
- 드라이버 [확인 필요]: Pascal은 R580 계열 드라이버까지 지원하는 것으로 안다. 설치된 드라이버로 `nvidia-smi`가 GPU를 보이면 된다.
- PyTorch [확인 필요]: Pascal(sm_61)을 포함하는 CUDA 12.6 빌드를 쓴다.
  ```
  pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126
  pip install transformers pillow numpy opencv-python-headless
  python -c "import torch;print(torch.cuda.is_available(), torch.cuda.get_arch_list())"
  ```
  - 목록에 `sm_61`이 없으면 그 빌드는 1050 Ti를 지원하지 않는다. 최신 cu128 이상 빌드는 Pascal을 뺀 것으로 알고 있으니 피한다.
- ffmpeg가 PATH에 있어야 한다(디코딩은 CPU로 충분하다. NVDEC은 필요 없다).

## 4. 실행 방법 (토큰을 쓰지 않는 무인 실행)

1. 원본을 한 폴더에 `<post_id>.<확장자>`로 모은다. 방법은 사용자가 정한다. 후보:
   - (가) 사용자 계정으로 Drive `01_원본영상`을 받는다. 사용자 계정은 GPT가 올린 yutaka ZIP도 보인다.
   - (나) catalog의 md5로 Sakugabooru에서 직접 받는다. 이번 서버 복구에 쓴 방법이고, md5가 162개 모두 일치했다.
2. 실행한다.
   ```
   set IMPACT_DEVICE=cuda          (리눅스는 export IMPACT_DEVICE=cuda)
   python tools/impact_pipeline.py <원본폴더> <출력폴더> --workers 3 --refs <예시이미지폴더>
   ```
   - 예시 이미지 폴더는 Drive `03_스타일지식베이스/참고_임팩트예시/`의 ref*.png다(공개 금지).
   - 중간에 끊겨도 다시 실행하면 이어서 한다(1단계는 `scanned.txt`, 2·3단계는 출력 CSV의 key 기준).
3. `출력폴더/final.csv` 하나만 Drive에 올린다(지표·프레임 번호만 있고 이미지는 없다). Claude는 그 CSV만 읽고, '유력·재검사'만 띠 이미지로 확인한다.
- 서버에서 3영상으로 끝까지 시험했다 [실측]: CPU만 써서 66초, 후보 21개 → 아님(같은그림) 3·재검사 12·아님유력 6(단색섬광 분리 추가 전).

## 5. 주의

- 1번 문맥 문제를 완전히 고친 것은 아니다. 색 비교로 '같은 그림 이어 보여 주기'는 걸러지지만, 먼지·물·섬광 같은 다른 색 이펙트는 못 거른다(IMPACT-CONTEXT 5절). 더 많이 돌릴수록 사람이 볼 '재검사'도 함께 늘어난다.
- 단색 섬광(그림 없는 흰·검정)은 규칙상 low 또는 cel_light다.
  - final.csv에서 `단색섬광(옆 확인)`으로 따로 뺀다(후보 전부 그림 없음).
  - 재검사 291 대조 [실측]: 그림 없음 56 = 육안 단색 44·옆에실제 9·아님 3, 임팩트 0.
  - 그만큼 사람이 볼 몫이 준다. 옆 프레임에 실제 임팩트가 있는지는 확인해야 한다.
- 1050 Ti 위치(본인 PC/PC방), 운영체제, CPU 코어 수, 디스크 여유, 원본 옮기는 방법은 사용자에게 받아야 한다.
