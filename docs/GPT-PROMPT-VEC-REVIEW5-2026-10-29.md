## 복붙용 프롬프트

4차 검토 뒤 RTX 5060에서 1차 본 학습을 했고, 결과를 보고 2차 학습을 준비했어. 첨부 5개가 2차 실행본이야. **2차 실행을 막을 문제가 있는지** 판정해 줘.

### A. 1차 학습 결과(5060, 2.76시간, 16,623걸음, 정상 종료)
- 자료 20분(1920·1280·854·640, 실패 0), 학습 160.8분, Drive 올리기·바탕화면 zip 정상. 저장 잠금 2번은 재시도 장치대로 건너뛰고 다음에 저장.
- 최고 검증 4.87(75% 지점, 마지막 단계) → best.pt. 그 뒤 마지막 단계 검증이 4.9–14.4로 크게 출렁이고 **검증 25회 중 11회 NaN**.
- **NaN 원인(서버에서 잼):** 같은 모델을 fp32로 돌려 층마다 최댓값을 재니 디코더 `u4.conv.0` 출력이 흰 바탕이 넓은 장면에서 66,464–78,080 → **fp16 한계 65,504 초과** → inf → BatchNorm에서 NaN. 저장 가중치에는 비유한 값 없음, running_var 최대 25,807.
- 시험용 앱 영상(학습 안 쓴 S2aqoie_pt·sr)에서: 선 찾기·배경색 좋음, 끝점 후보 0 → 77–211개로 늘어남. 선 색은 계속 틀림(파란 선을 검게). 마지막 모델은 75% 모델보다 나쁨(파란 인물 일부 놓침).
- 애니 장면: 화면 전체를 선으로 칠함(흰 바탕 스틱맨 위주 자료의 영역 차이).
- 기록 파일: Windows가 열린 채 쓰는 파일의 크기·시각을 늦게 갱신해 15분 올리기가 log.jsonl을 계속 건너뜀(ckpt.pt는 정상).

### B. 2차 변경
| 변경 | 내용 | 확인 |
|---|---|---|
| bf16 | 계산 능력 8.0 이상이면 bf16 autocast, GradScaler 끔. 아니면 fp16 + GradScaler | 서버는 CPU라 GPU 경로 미확인 |
| 헛걸음 기록 | 학습 손실이 비유한이면 건너뛰고 `skipped` 증가, fp16은 배율 감소도 셈 | CPU 짧은 시험 |
| NaN 검증 | 문제 손실이 비유한이면 평균에서 빼고 `val_complete=False`(best 제외), `val_bad` 기록 | 코드 읽기만(짧은 시험에 검증 문제 0) |
| 선 색 | 가운데선 1px 외에 3px 띠에서 선 RGB L1, 띠 정답 = `max_pool(색 × 가운데선)`, 가중 3 | CPU 짧은 시험 |
| 페인트 자료 가중 | 이름에 `묶음5_페인트`·`면변환`이 있는 npz를 4배 자주 뽑음(`random.choices`) | 〃 |
| 2차 출발 | `--init`: 1차 best.pt 가중치만 불러와 새 계획(커리큘럼 처음부터), 학습률 절반(5e-4) | CPU에서 불러오기 확인 |
| 로그 | 기록마다 열고 닫기 | 〃 |
| 실행 분리 | `pc_vec_run --run pc2 --init-from pc`: Drive `vec/pc2`, 출력 폴더 `vec_out_pc2`(1차 ckpt를 이어받아 '이미 100%'로 끝나지 않게). 처음이면 Drive `vec/pc/best.pt`를 init.pt로 받음 | Windows 미확인 |
| Drive 재연결 | 1차 뒤 사용자가 rclone 접근을 끊음 → mkdir 실패 시 `rclone config reconnect gdrive: --auto-confirm` 한 번 | Windows 미확인 |
| 자료 | 학습 파일 352 → 404(페인트 묶음 10개·일반 46개·선 칠 → 면 교체본 4개 추가, 시험용 37 그대로). `DATA_VERSION` 4 | 서버에서 404개 전부 생성, 실패 0 |
| **페인트 합성(추가)** | 원본 작업은 모두 그대로 + 흰 바탕 파일(339/404)의 30%만큼 합성 작업을 **추가**. 합성 = SFA 복사본에 배경 면·그라데이션 띠(반투명)·땅·발밑 그림자(반투명)·머리 채우기(`FS Kind=1`)·빛(위/옆/없음)·비네팅·색조 덮개, 어두운 장면은 검은 선을 밝게. 반투명 알파는 실제 페인트 파일 5개 분위 10–90%(90–215). 이름 끝 `_syn`(검증 나누기 키는 원본과 같아 누수 없음) | 640에서 반복 2: 원본 808 + 합성 204, 실패 0. 앱에서 열어 확인(레이어·ID 규칙 반영 후) |

### C. 앱 확인으로 알게 된 합성 규칙(반영함)
- 같은 레이어에 DrawOrder만 낮춰 깐 배경이 앱에서 인물 선을 덮음 → **레이어로 분리**(배경 0 / 원래 레이어 +1 / 빛 맨 위).
- 앱은 불러올 때 DrawOrder를 읽지 않고, **AO ID마다 레이어 하나**(파일 전체 공통 오브젝트). 장마다 '최대+1'로 ID를 매기면 같은 ID가 장마다 다른 레이어 → 앱이 한쪽으로 묶음(빛이 배경 레이어로) → **역할별 ID 구간 고정**, 검사: ID마다 (LayerId, TypeId) 하나, 점 ID 중복 0.
- 앱의 12,12 내보내기 영상과 우리 렌더러 비교: 다른 픽셀 0.3%(레이어 문제 수정 전 순서 기준).
- 파란점 규칙: 면 테두리 고리마다 Flags 3 하나, 꼭짓점마다 표시(bit0) 하나.

### 봐 줄 것
1. B의 변경(특히 bf16 판정과 GradScaler 끄기, 비유한 손실 `continue`의 위치, NaN 검증 처리, 3px 색 띠 손실의 정답 만들기, `random.choices` 가중, `--init`과 학습률, `pc_vec_run`의 init 받기·출력 폴더 분리)에 버그가 없는지.
2. 합성 자료가 학습을 해칠 위험(지름길 학습, 정답과 화면 불일치, 원본과 합성 비율 30%)과 더 나은 비율·방식.
3. 1차 결과 해석(fp16 넘침 원인, 마지막 모델이 나빠진 이유)에 반론이 있는지.
4. **2차 실행 전 필수: 있음/없음** — 있으면 파일:줄과 최소 수정, 학습 뒤 고쳐도 되는 것은 '나중에'.

출력: 짧은 표(번호 | 판정 | 근거 | 할 일) + '2차 실행 전 필수: 있음/없음'.
