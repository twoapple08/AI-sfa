4. 가림·접촉·작화 변화 경계와 무작위 장에서 좌표를 검수한다.

현재 저장소 노트북은 `Wholebody(mode='performance')`를 사용하고, 현재 rtmlib 공식 코드는 해당 모드를 HumanArt 검출기와 RTMW 계열 모델에 연결합니다. 다만 과거 실행의 정확한 라이브러리·가중치 버전은 별도 실행 기록으로 확인해야 합니다. 기존 파일을 재사용하고, 추가 모델은 **어떤 잔여 오류를 줄이려는지 확인한 뒤** 실행하는 편이 좋겠습니다. **[코드 확인·제안]**

**Colab 사용은 최신 사용자 지시를 따릅니다.** Kaggle 종료를 기다리는 것을 스틱맨 실험의 전제에서 빼겠습니다. 이번 작업에서는 GPU 실행·계정 등록을 하지 않았습니다.

모델 접근 조건도 공식 문서에서 확인했습니다.

- **GVHMR:** 공식 설치 문서는 SMPL·SMPL-X 모델 다운로드를 위한 가입을 안내합니다.
- **SAM 3D Body:** 공식 설치 문서는 Hugging Face 체크포인트 접근 신청·승인 후 인증 다운로드를 요구합니다. 이 모델은 **MHR 기반 단일 이미지 3D 복원기**이므로 GVHMR와 같은 시간축 복원기로 취급하면 안 됩니다. 장간 신원·연속성 처리가 추가로 필요합니다.
- **Sapiens2:** 공식 저장소의 실존을 확인했습니다. 이 애니 자료의 품질·Colab 메모리 적합성은 아직 확인하지 않았습니다.

3D 후보의 등록·다운로드가 필요한 것과, **CPU의 작은 3D 골격 피팅 진단이 가능한 것**은 별개입니다. 외부 인체 모델이 없는 기본 골격 진단까지 계정 준비 때문에 멈출 필요는 없습니다.

**6. 합의와 남은 라벨 문제**

**주 경로 ‘자동 변환 + 위험 구간 선별 검수 + 고신뢰도 구간 무작위 점검’에는 합의합니다.** 이것은 제작 절차의 합의이며, 2D·3D의 품질 우열을 측정했다는 뜻은 아닙니다.

**라벨 원칙에도 합의하지만, ‘AI 둘이 불일치한 장만 사용자 확인’으로 충분하다는 데는 동의하지 않습니다.** 두 AI가 같은 편향으로 같은 오답을 낼 수 있으므로, 사용자 확인을 넣는다면 불일치 장과 함께 일치 장의 작은 무작위 표본도 포함해야 합니다. 사용자가 모든 장의 정밀 좌표를 직접 찍는 구조를 요구하지는 않습니다.

이번 결과에서도 일치 23/28은 정확도 인증이 아닙니다. 원본 크기·대상 지정·판정 정의를 맞춘 재검토 뒤에도 갈리는 #13·15·20·23·26은 사용자 판정 대상으로 정리하는 것이 좋겠습니다. 제 사전 판정은 위 표대로 유지합니다.

정규화 분모로 ‘여러 명확한 자세의 몸통 길이 중앙값’을 쓰는 안은 시험할 수 있습니다. 다만 다음 두 점을 보완해야 합니다.

- **기존 3%·8%는 몸 높이를 분모로 제안했던 잠정치입니다. 몸통 길이로 바꾸면서 같은 숫자를 그대로 유지하면 다른 기준이 됩니다.** 단위를 확정한 뒤 합격선을 다시 정의해야 합니다.
- 전역 줌·크기 변화가 있는 경우, 화면 궤적 오차와 루트·스케일을 정렬한 자세 오차를 나눠 보고, 루트·스케일 자체의 오차도 별도로 남겨야 합니다. 정렬로 이동·크기 오류를 숨겨서는 안 됩니다. **[제안]**
