# 영상 → SFA 변환 AI: 처음부터 끝까지 (2026-10-31)

> 대상: 컴퓨터는 좀 쓰지만 코딩은 안 해 본 사람
> 범위: 무엇을 왜 만들었고, 어떻게 돌아가며, 지금 어디까지 왔는지
> 숫자: 모두 실제로 잰 값이다. 추정은 '추정'이라고 표시했다.

## 0. 세 줄 요약

1. 스틱파이터 영상을 넣으면 **앱에서 바로 열리는 .sfa 파일**을 만들어 주는 AI를 만들고 있다.
2. AI는 그림을 그리는 게 아니라 **"선 하나, 좌표 몇, 색 몇, 이 점이랑 연결…" 같은 SFA 문장을 한 단어씩 받아쓴다**.
3. 학습 장치, 채점 장치, 실행 장치(PC·Kaggle)는 다 갖췄다. 이제 **GPU로 오래 학습시키는 단계**만 남았다.

## 1. 배경: 우리가 다루는 SFA 파일

### 1-1. .sfa의 정체
- .sfa 파일은 사실 **zip 압축 파일**이다. 압축을 풀면 안에 **XML 파일**이 하나 들어 있다.
- **XML**은 `<태그 이름="값">` 모양으로 정보를 적는 텍스트 형식이다. 웹페이지의 HTML과 비슷하게 생겼다. 메모장으로 열어도 읽힌다.
- SFA의 XML 구조를 간단히 그리면 이렇다.

```
<Sequence 비율="0.5625" 배경색="흰색">          ← 애니메이션 전체
  <Frame Position="0">                             ← 1번째 장
    <LayerDef 이름="Layer 1"/>                     ← 레이어
    <AO TypeId="1" Color="검정" 굵기="1.0">        ← 오브젝트(AO) 하나: 직선
      <AP X="20" Y="50"/>                          ← 점(AP) 1
      <AP X="40" Y="50"> <AC ConnPtId="..."/> </AP> ← 점 2, 다른 점과 연결(AC)
    </AO>
    <FR Color="빨강"> <FS ObjId="..."/> </FR>       ← 면(채우기)
  </Frame>
  <Frame Position="1"> ... </Frame>                ← 2번째 장
</Sequence>
```

### 1-2. 오브젝트 종류
| 이름 | XML 표기 | 점 개수 | 설명 |
|---|---|---|---|
| 직선 | TypeId=1 | 2개 | 양 끝점 |
| 원 | TypeId=2 | 2개 | 지름의 양 끝 |
| 곡선 | TypeId=3 | 3개 | 2차 베지어 곡선(시작·조절점·끝) |

여기에 색(ARGB = 투명도·빨강·초록·파랑), 굵기, 글로우(빛 번짐), 레이어가 붙는다. **면(FR)**은 "이 오브젝트들로 둘러싼 영역을 이 색으로 칠해라"는 지시다.

### 1-3. 좌표는 %다
- SFA는 위치를 픽셀이 아니라 **화면의 %**로 저장한다. X=50, Y=50이면 해상도와 상관없이 화면 정중앙이다.
- 그래서 1920×1080으로 내보내든 640×360으로 내보내든 같은 파일이 같은 그림으로 나온다.
- 화면 밖(−값, 100 초과)도 쓸 수 있다. 화면을 가로지르는 긴 선이나 화면 밖에서 들어오는 물체를 표현할 때 쓴다.

### 1-4. 비율
- 파일마다 화면 비율(HeightWidthRatio)이 다르다. 학습 파일 중 16:9는 78개뿐이고, 0.45나 0.46 같은 더 넓적한 비율이 더 많다.
- 앱은 **파일 비율 그대로** 영상을 내보낸다(확인: 비율 0.45 파일 → 1920×864 영상).

## 2. AI가 배우는 방식: 문제집 + 정답지

- 지금 만드는 AI는 **지도학습** 방식이다. 문제(영상 한 장)와 정답(그 장의 SFA)을 수만 번 보여 주면, AI가 "이런 그림이면 이런 SFA"라는 규칙을 스스로 찾는다.
- 문제집은 사용자가 모은 **.sfa 파일 441개**다. 원래는 영상이 없지만, SFA를 우리 렌더러로 그려서 영상을 만들면 영상과 정답이 짝으로 생긴다. 정답이 100% 정확한 문제집을 무한히 찍어 낼 수 있는 셈이다.
- 파일은 세 갈래로 나눠 쓴다.

| 갈래 | 개수 | 용도 | 비유 |
|---|---|---|---|
| 학습용 | 403개 파일 | AI가 보고 배움 | 교과서·문제집 |
| 시험용 | 38개 파일(4711_2 합작 등) | 학습에 절대 안 씀. 처음 보는 것도 잘하는지 확인 | 수능 |
| 위치 시험용 | 학습 파일 일부를 고정으로 옮긴 사본 | 외운 것인지, 위치를 읽는 것인지 확인 | 숫자만 바꾼 기출문제 |

## 3. 1차 시도와 실패: 정답지를 잘못 만들었다

- 처음 방식은 정답을 **"화면에 보이는 선 픽셀이 어디 있는지"** 지도로 줬다.
- 결과는 망했다. 사용자 평가: "이게 맞냐?"
- 원인은 정답지에 SFA 정보 대부분이 빠져 있었던 것이다.
  - 다른 선에 가려진 부분은 정답에서 지워졌다. 그래서 끊겨 보이는 선이 사실 한 오브젝트라는 걸 배울 수 없었다.
  - 어떤 픽셀들이 한 오브젝트인지, 어디가 연결됐는지, 어느 레이어인지가 없었다.
- 비유하면, 요리를 가르치면서 레시피 대신 **완성된 음식 사진만** 준 것이다. 사진을 보고 "대충 이렇게 생겼네"는 배워도 "소금 몇 g"은 못 배운다.
- 사용자 지시: "스파 파일을 정답지로 보고 스파를 직접 해 보게끔 해라." → **재설계**

## 4. 새 설계의 핵심: SFA를 '문장'으로 받아쓰기

### 4-1. 아이디어
- 사진 설명 AI가 사진을 보고 "강아지가 공을 물고 있다"를 한 단어씩 쓰듯이, 우리 AI는 영상 한 장을 보고 **SFA 문장**을 한 단어(토큰)씩 쓴다.
- 쓴 문장을 XML로 바꾸면 앱에서 바로 열리는 .sfa가 된다. **중간에 픽셀 그림을 그리는 단계는 없다.** 사용자 원칙 "스파로 그린다"를 그대로 지킨다. 일반 그림 도구로 그리고 나중에 옮기는 방식이 아니다.

### 4-2. SFA 문장은 이렇게 생겼다(`sfa_tokens.py`)
```
BOS BG 255 255 255 255            ← 시작, 배경 흰색
LAYER                             ← 레이어 시작
LINE COLOR 255 0 0 0 THICK 921    ← 직선, 검정, 굵기
  2800 4000 PT                    ← 점1 (좌표를 0.025% 칸 번호로)
  3600 4000 PT LINK 1             ← 점2, 바로 앞 점과 연결
CIRC SAME 3700 3200 PT 3900 3200 PT   ← 원, 앞 오브젝트와 같은 스타일
FILL 255 255 0 0 WHOLE 1          ← 빨간 면, 마지막 오브젝트 전체 채우기
EOS                               ← 끝
```
- **단어장(토큰)**: 특수 단어 19개(LINE, CIRC, PT, LINK…)와 숫자 8,192개, 합계 8,211개
- **좌표**: 0.025% 단위 칸 번호. 1920폭 화면에서 약 0.5픽셀이다.
- **그리는 순서 = 문장 순서**: 나중에 적힌 게 위에 그려진다. 가림 관계가 문장에 그대로 담긴다.
- **LINK d**: "d개 앞의 점과 연결". 스틱맨은 대부분 1이나 3이라 배우기 쉽다. 실측으로 1이 30%, 3이 30%다.
- **SAME**: 앞 오브젝트와 색·굵기가 같으면 한 단어로 끝낸다. 문장이 짧아진다.
- **BIG**: 화면 밖 아주 먼 좌표처럼 칸 번호 범위를 넘는 수를 적는 특수 표기
- **빼는 것**: 영상이 달라지지 않는 정보다.
  - 숨긴 레이어, 안 보이는 오브젝트, 화면에 닿지 않는 오브젝트
  - 파란점 표시(규칙으로 다시 만듦)
  - 오브젝트 ID(새로 매김)

### 4-3. 문법 검사기
- AI가 문장을 쓸 때 문법상 올 수 없는 단어는 아예 고르지 못하게 막는다. 예를 들어 직선은 점이 반드시 2개여야 하고, 색 숫자는 0~255여야 한다.
- 키보드 자동완성이 틀린 단어를 제안조차 하지 않는 것과 같다. 그래서 AI가 아무리 엉터리여도 **결과는 항상 앱이 여는 파일**이다.
- 학습 자료 22,371장 전체를 이 문법으로 검사해서 위반 0건을 확인했다.

### 4-4. 정답지가 SFA를 빠짐없이 담는지: 왕복 검사
- 번역기 테스트처럼 **SFA → 문장 → 다시 SFA**로 돌린 뒤, 원본과 되돌린 것을 그려서 비교했다.
- 결과
  - 연결 1,576,561개와 면 10,653개가 하나도 안 빠지고 되돌아왔다.
  - 그림 차이는 최대 0.70%이고, 그것도 선 가장자리 안티에일리어싱(경계를 부드럽게 하는 처리) 수준이다.
- 이 과정에서 버그를 여럿 잡았다.
  - 먼 곡선 조절점을 잘못 처리하던 것: 그림이 45% 달라짐
  - 4,096을 넘는 번호가 잘리던 것
  - 다른 오브젝트 좌표가 섞여 들어가던 것
- 앱의 "점 삭제" 기능으로 점이 모자란 오브젝트도 버리지 않고 보존한다(사용자 지적).

## 5. 학습 자료 만들기(`seq_data.py`)

파일 하나를 학습 자료로 바꾸는 과정이다.

1. .sfa를 연다.
2. (늘리기 사본이면) 좌표 전체를 무작위로 바꾼다. 좌우 반전, 0.8~1.2배, ±8% 이동.
3. 장마다 SFA 문장(정답)을 만든다. 2,048단어를 넘는 장은 1판에서 뺀다(전체의 약 90%가 2,048 이하).
4. **렌더러**(`sfa_render.py`)로 그림을 그린다. 이 렌더러는 앱이 내보낸 영상과 0.3%만 다르게 맞춰 둔 것이다.
5. 파일 비율 그대로 그리고 **H.264로 압축했다 푼다**. 실제 영상처럼 뭉개짐을 넣기 위해서다. 압축 세기(crf)는 23~35에서 무작위로 정한다.
6. 640×360으로 늘이거나 줄인다. 좌표가 %라서 늘여도 위치와 좌표가 정확히 맞는다. 원래 비율은 숫자로 따로 알려 준다.
7. 그림 + 정답 문장을 .npz 파일(넘파이 압축 묶음)로 저장한다.

| 자료 | 양(실측) |
|---|---|
| 학습용 원본 | 403개 파일 → 15,544장, 830만 단어 |
| 늘리기 포함 | 약 3.1만 장(추정, 사본 1벌) |
| 시험용 | 38개 파일 → 935장 |

**늘리기**는 외우기 방지 장치다. 같은 문제를 숫자만 바꿔 내면 답을 외워서는 못 풀고 푸는 법을 익혀야 한다. 이게 왜 필요한지는 10장의 실험에서 드러났다.

## 6. 모델 구조(`seq_train.py`): 눈 + 손

```
영상 한 장(640×360) ──▶ [눈: ResNet34] ──▶ 80×45 칸짜리 특징 지도
                                                │ (교차 주의: 쓰면서 그림을 다시 봄)
지금까지 쓴 문장 ─────────▶ [손: 트랜스포머 8층] ──▶ 다음 단어 확률 8,211개
                                                │
                                [문법 검사기]가 틀린 단어를 지움 → 하나 고름 → 반복
```

| 부품 | 정체 | 비유 |
|---|---|---|
| 눈(인코더) | **ResNet34**: 사진 인식용으로 이미 학습된 유명한 이미지 신경망. ImageNet 사전학습 가중치로 시작 | 이미 그림 보는 법을 아는 사람을 채용 |
| 특징 지도 | 화면을 80×45 칸으로 나눠 칸마다 "여기 뭐가 있는지" 요약 | 모눈종이 위의 메모 |
| 손(디코더) | **트랜스포머**: ChatGPT 같은 언어 모델의 기본 구조. 8층, 폭 512 | 받아쓰기하는 손 |
| 교차 주의 | 단어를 쓸 때마다 그림의 어느 칸을 볼지 스스로 정함 | 받아쓰다 고개 들어 칠판 보기 |
| 비율 입력 | 원래 비율 숫자를 따로 넣음 | "이거 원래 넓적한 화면이었어" 메모 |
| KV 캐시 | 앞 단어 계산을 저장해 두고 새 단어만 계산 | 앞 문장을 매번 다시 읽지 않기 |

크기는 약 **5,160만 개 숫자(가중치)**다. ChatGPT급(수천억)에 비하면 아주 작고, 게이밍 GPU 하나로 학습할 수 있는 크기다.

## 7. 학습은 어떻게 하나

### 7-1. 한 걸음
1. 영상 몇 장과 정답 문장을 가져온다(한 묶음).
2. AI에게 "정답 앞부분을 보고 다음 단어를 맞혀 봐"를 문장 전체 위치에서 한 번에 시킨다.
3. 틀린 정도(**손실**, loss)를 계산한다.
4. 손실이 줄어드는 방향으로 가중치를 아주 조금 고친다.

이걸 수만~수십만 번 반복한다.

### 7-2. 세부 장치

| 장치 | 내용 | 왜 |
|---|---|---|
| 부드러운 정답 | 좌표는 정답 칸 50% + 근처 ±2칸 50%로 점수를 줌 | 1칸(0.5픽셀) 틀린 걸 완전 오답 취급하면 너무 가혹함 |
| 학습률 계획 | 처음 500걸음은 천천히 올렸다가 계획 시간에 맞춰 코사인 곡선으로 줄임 | 처음엔 조심, 중간엔 과감, 끝엔 미세 조정 |
| 토큰 한도 묶음 | 한 묶음 = 가장 긴 장 길이 × 장 수 ≤ 12,288 | 긴 장이 몰려도 GPU 메모리가 안 넘치게 |
| bf16 / fp16 | 숫자를 반 정밀도로 계산(5060·4060은 bf16, T4는 fp16) | 속도 2배·메모리 절반 |
| 메모리 부족 대처 | ① 중간값을 버렸다 다시 계산(체크포인팅) ② 그래도 안 되면 묶음 줄이기 | "CUDA out of memory"로 몇 시간짜리 학습이 죽지 않게 |
| 체크포인트 | 10분마다 학습 상태 전부(ckpt.pt)를 저장 | 꺼져도 이어서. 게임 세이브와 같음 |
| 검증 | 20분마다 시험 파일 400장으로 점수 | 처음 보는 것도 잘하는지 확인 |
| 생성 채점 | 1시간마다 시험 20장 + 위치 시험 20장을 **진짜로 그리게** 해서 채점 | 아래 7-3 참고 |
| 양보 모드 | 콜오브듀티 실행 중이면 멈춤, 롤·클립스튜디오면 천천히 | 4060 PC를 같이 쓰기 위해 |

### 7-3. "다음 단어 맞히기" 점수의 함정
- 학습 중 점수는 정답 앞부분을 보여 주고 다음 단어를 맞히는 방식이다. 답지 앞장을 보면서 다음 문제 푸는 셈이다.
- 앞 점이 주어지면 다음 점은 근처에 있을 확률이 높다. 그래서 그림을 안 봐도 꽤 맞힌다. 실험에서 다른 영상을 줘도 좌표를 57% 맞혔다.
- 그래서 진짜 실력은 **처음부터 혼자 쓰게 해서** 재야 한다. 이게 생성 채점이다.

## 8. 채점(`sfa_objscore.py`): 파일로 채점한다

사용자 원칙: **"만든 파일을 원본 파일과 채점한다. 만점이면 인코딩한 영상도 똑같다."**
- 파일이 같으면 영상은 반드시 같다. 하지만 영상이 같다고 파일이 같지는 않다. 연결이 빠졌거나 곡선 대신 직선 여러 개로 그려도 겉보기는 같을 수 있다.
- 그래서 픽셀이 아니라 오브젝트 단위로 비교한다.

### 8-1. 짝짓기
- AI가 만든 오브젝트와 원본 오브젝트를 1:1로 짝짓는다. **헝가리안 알고리즘**이라는, 전체 거리 합이 가장 작게 짝을 맺어 주는 유명한 방법을 쓴다. 소개팅 주선자가 모든 커플의 궁합 합이 최대가 되게 짝을 맺어 주는 것과 같다.
- 단, "맞는 짝(같은 종류, 점이 1% 안)" 수를 먼저 최대로 하고, 그다음에 거리를 줄인다.

### 8-2. 점수표
| 항목 | 뜻 |
|---|---|
| 재현율 | 원본 오브젝트 중 몇 %를 맞혔나(놓친 것) |
| 정밀도 | AI가 만든 것 중 몇 %가 맞나(지어낸 것) |
| 점 오차 | 맞은 오브젝트의 좌표가 얼마나 떨어졌나 |
| 색·굵기·글로우 | 맞은 오브젝트끼리 같나 |
| 연결 F1 | 연결이 원본과 얼마나 같나(F1 = 재현율과 정밀도를 합친 점수) |
| 면 F1 | 면의 색·테두리·구간이 같나 |
| 가림 순서 | 겹치고 겉모습이 다른 쌍만, 앞뒤가 같나 |
| **perfect** | 위 전부가 같고 모든 점이 같은 칸 = **같은 영상** |
| near_perfect | 점이 평균적으로 거의 같음 |

### 8-3. 영상이 안 달라지는 차이는 정답으로 친다(사용자 결정)
- ID, 면 칠하는 순서, 파란점, 점 방향(앞뒤 바뀜), 관절 연결(10-31 추가 — 24,24라 영상에 안 보임)
- 겹치지 않거나 겉모습이 같은 오브젝트끼리의 순서
- 24,24(트위닝 없음)로 만들기 때문에 장 사이 ID가 이어지는지도 상관없다.

## 10. 실험 이야기: "외운 거였어?" 사건

서버 CPU로 작게 해 본 실험들이다. GPU 본 학습 전에 구조가 말이 되는지 보려고 했다.

1. **첫 테스트(80분, 작은 모델)**: 결과는 0점. 문법은 지켰고, 연결된 스틱맨과 영상 색은 따라 했다. 하지만 위치와 자세는 영상과 무관하게 외운 모양(서 있는 스틱맨)을 그렸다.
2. **외우기 시험(44장, 22분)**: 같은 44장만 계속 학습시키니 원래 위치에서 31%를 맞혔다. 다른 영상을 주면 0%, 흰 화면을 주면 2%였다. "오, 영상을 보네!"
3. **GPT 반론**: "장면을 알아보고 외운 자세를 꺼내는 거랑 구별이 안 되는데요?"
4. **이동 시험**: 같은 44장을 오른쪽 6%, 아래 4% 옮겨서 보여 줬다. 결과는 **0%**. 장면만 알아보고 답을 외워 쓰고 있었다. 벼락치기로 기출 답만 외운 학생이 숫자 바뀐 문제에서 전멸한 셈이다. GPT 승.
5. **늘리기 시험(사본 8벌, 25분)**: 외우기를 막자 학습에 없던 이동에서 좌표 오차가 영상 13.2% / 다른 영상 19.7% / 흰 화면 17.5%가 됐다. 영상이 약하게나마 쓰이기 시작했지만, 아직 맞힌 오브젝트는 0이다. CPU 25분으로는 판단이 어렵다.

**결론**: 이 구조로 위치를 제대로 읽을 수 있는지는 GPU로 충분히 학습해 봐야 안다. 그래서 GPU 학습에 위치 시험을 붙여서 직접 감시한다.

이 과정에서 생긴 제 실수도 기록해 둔다.
- 학습이 두 개 동시에 돌았다(결과 무효).
- 정리 명령이 자기 셸까지 꺼 버렸다.
- 예약 날짜를 하루 틀리게 넣었다.

모두 바로잡았다.

## 11. GPT와의 검토 토론(3라운드)

- **구조**: Claude가 만들고, GPT가 코드를 직접 돌려 반례를 찾고, Claude가 근거로 동의하거나 반대한다. 사용자가 중계한다.
- **결과**: 버그 지적 25개를 반영했다. 그중 학습에 실제로 영향을 주는 건 다음과 같았다.
  - 색 정답 확률이 있을 수 없는 값(256, 257)으로 새던 것
  - 메모리 부족 때 학습이 멈추는 경로
- **GPT가 과했던 것**: '필수' 등급을 과하게 매긴 것, 옛 파일 기준 지적. 반론해서 GPT가 인정했다.
- **GPT가 맞았던 결정적인 것**: 10장의 "외운 거였어?" 사건
- **GPT가 돌린 검사 42개**: 사용자가 zip으로 전달했다. 당시 코드에서 전부 재현됐고, 지금 코드에서는 결함 37개가 고쳐진 걸 확인했다. 9개는 우리 시험으로 옮겼다.
