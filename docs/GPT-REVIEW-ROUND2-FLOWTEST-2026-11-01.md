# GPT 2라운드 검토 — Kaggle CPU 흐름 시험·진행률·회차 시간 (2026-11-01)

대상: `twoapple08/AI-sfa`, `claude/new-session-gknz4t`, 커밋 `ea6f2516fab8515dca0b013341ed1d3456874c68`의 `docs/GPT-ROUND2-FLOWTEST-2026-11-01.md` 전체. 이전 응답 문서와 VERIFY 답변 §7, 현재 학습기·작업자·먼 곡선 코드를 대조했다.

Kaggle 두 회차의 숫자는 요청 문서에 보고된 실측을 해석한 것이다. 원본 Kaggle 로그를 새로 수집하거나 Kaggle/GPU를 실행하지 않았다. 아래의 함수 계산과 회귀 검사는 이 환경에서 직접 실행했다.

## 1. 두 회차 결과 해석 — 부분 동의

- **동의**: 학습·교사 강제 평가·생성 평가·저장·재개가 연결되어 동작한다. 손실 9.20→5.90, 맞힘 약 0→40%는 초기 학습이 진행됐다는 근거다.
- **제한**: 40%는 정답 접두어를 주는 교사 강제 다음 토큰 맞힘이다. 구조 78점·좌표 0점, 생성 강제 종료라는 결과와 함께 해석해야 한다. 영상 좌표 읽기나 생성 정확도 40%를 뜻하지 않는다.
- **제한**: 1080→720→480→360 실제 전환, 각 단계의 하위 20%→전체 길이 경로는 아직 통합 검증되지 않았다. rc 0 두 번으로 이 경로까지 완료했다고 보기는 어렵다.
- **제한**: 60분 요청에 110·81분이 걸렸다. 회차 시간 제어는 아직 의도대로 검증되지 않았다.
- `valk`의 0.32~0.41은 코드상 비율이므로 32~41%다. 실제 장이 조합 장보다 뒤처진다는 초기 근거는 이 숫자에서 나오지 않는다. 이 초기 CPU 결과만으로 17% 비율의 충분함을 결정할 수는 없다.

추가 진단은 고정 소수 장에서 같은 정답 접두어를 두고 입력 그림을 교환하거나 가린 경우의 좌표 손실 차이를 보는 것이다. 이는 초기의 영상 사용 진단이고, 기존 공식 입력 교환 생성 판정을 대체하지 않는다.

## 2. 쟁점 3-1 — 부분 동의: 읽기·평가를 학습 진행에서 빼되 학습률도 함께 정해야 함

제안 (나)의 목적에는 동의한다. 읽기·검증·생성 중 학습 없이 단계와 길이 분위가 진행되는 현재 상태는 고쳐야 한다.

실제 함수로 계산하면, 600분 계획에서 학습 없이 15분이 지나기만 해도 첫 단계의 허용 길이가 **하위 20%→35%**가 된다. 재개의 **105/140=0.75 → 360 단계·하위 40%**도 코드와 문서가 일치한다.

다만 **학습률은 벽시계에 남기고 단계·쉬운 것부터만 학습 계산 시간으로 옮기는 안에는 조건부 동의**다. 학습은 아직 앞 단계인데 학습률 감쇠는 계획 끝으로 향할 수 있다. 현재 cosine 계수는 예열을 마친 같은 step에서 진행 30%일 때 약 0.804, 80%일 때 약 0.141이다.

권고:

1. 회차 종료·Kaggle 최대 사용 예산은 작업자 시작부터의 벽시계로 관리한다.
2. 학습률·해상도 단계·쉬운 것부터는 명시적으로 정한 공통 학습 진행도를 사용한다. 성공한 학습 구간의 누적 시간 또는 사전에 정한 업데이트/토큰 예산을 쓸 수 있다.
3. 600분을 Kaggle 점유 예산으로 유지한다면, 학습 계산 시간 목표는 준비·평가·저장 몫을 뺀 별도 값으로 먼저 정한다. 600 계산 분을 요구하면서 600 벽시계 분도 보장할 수는 없다.
4. 누적 학습 진행·현재 단계·단계 안 진행·허용 길이를 저장본에 남긴다. 읽기·평가·재개로 학습률·분위가 임의로 바뀌지 않게 한다.
5. 계산 시간은 본 장 수와 같지 않으므로 `expo`의 장·토큰·업데이트도 함께 본다. GPU 시간은 비동기 실행이므로 현재 `tm['train']`을 그대로 학습 시계로 쓰기 전에 측정 구간·동기화 기준을 확인해야 한다.

6. 공식 판정의 ‘계획 끝’이 어느 진행도를 뜻하는지도 함께 명시한다. 학습 진행 변수의 단위를 바꾸면서 벽시계 예산과 공식 종료 조건을 혼용하지 않도록 한다.

검증 방법:

- 같은 학습 상태에 읽기/검증/생성 지연만 주입한다. 학습 진행·단계·분위·학습률은 그대로이고 벽시계 잔여 시간만 줄어야 한다.
- 성공한 업데이트 뒤에는 학습 진행이 증가해야 한다. 저장·재개 전후에 같은 진행도와 학습률을 확인한다.
- 실제 GPU에서 학습 구간·평가·읽기·저장·커널 전체 시간을 따로 재어 계산 시간 목표가 점유 예산 안에 들어가는지 확인한다.

## 3. 쟁점 3-2 — 부분 동의: (1)을 기본으로 하고 (2)는 초기 예상값으로 사용

첫 GPU 중간 판정에서 실측하는 계획에는 동의한다. 다만 **그 실측 한 번으로 고정된 마지막 몫을 정하는 것만으로는 회차 시간을 보장할 수 없다.**

첫 중간 판정은 2방향·추세 상한이고, 마지막은 입력 해상도·방향 수·출력 길이가 달라진다. 고해상도에서 끝나면 46장×4방향 + 46장×2방향 = 276회 생성이고, 기본 360에서 4방향이면 184회다. 별도의 새 작품/위치 시험 생성, 교사 강제 검증, 종류별 검증, 채점·시트·저장 비용도 있다. 공식 모델 최대 길이 생성은 짧은 추세 생성과 비용이 같지 않다.

권고는 **남은 시간에 맞춰 학습을 일찍 멈추는 (1)**이다. **실측으로 정한 몫 (2)**는 초기 예상값과 안전 여유로 쓰고, 실행 중 갱신한다.

- 작업자의 절대 종료 시각을 학습기에 전달한다. 현재처럼 학습기 시작 전에 분 단위 `left`를 한 번 계산하는 것만으로는, 그 뒤 학습기 초기 준비·자료 읽기·긴 검증을 모두 제어하지 못한다.
- 다음 학습 걸음이나 중간 평가를 시작하기 전에 마지막 필수 평가·저장에 필요한 보수적인 몫이 남는지 확인한다.
- 학습 루프만 멈추게 하는 것으로 끝내지 말고, 중간 검증·생성도 잔여 시간 규칙을 적용한다.
- 공식 평가 목록을 줄여 시간을 맞추지 않는다. 마칠 시간이 부족하면 체크포인트를 보존하고 판정 미완료/자료 부족으로 기록한다.
- 마지막 평가 예상은 검증·종류별 검증·해상도별 생성·길이별 생성·채점·시트·저장으로 나눠 잡는다.

측정 방법:

- GPU에서 짧은·중간·긴 출력과 실제로 쓰는 해상도의 생성 시간을 잰다. 짧은 출력뿐이었다면 모델 최대 길이 비용을 측정했다고 할 수 없다.
- 첫 2방향 추세와 마지막 4방향/360 추가 판정의 비용을 구분한다. 모형은 출력 길이와 해상도를 함께 사용하고 실제 마지막 평가 시간과 대조한다.
- 느린 평가·저장 시간을 주입해 마감 전에 학습을 멈추는지 시험한다. 단일 작업 중의 초과 가능성도 남겨 기록한다.

현재 준비·검증 비용을 포함하면 **첫 180분 회차가 곧 내부 진행 0.3이라는 계산은 정확하지 않다.** 작업자는 준비 시간과 20분을 뺀 `left`를 준다. 예를 들어 준비 5분이면 학습기에 155분이 전달되어 155/600≈0.258이다. 마지막 평가가 저장 진행을 더 늘릴 수도 있다.

또 `--gen-minutes 20`은 정확히 20분에 생성 판정을 시작한다는 예약이 아니다. 현재 생성은 검증 분기 뒤에서 호출된다.

비용 산정에서 문서의 시험 자료 965장과 실제 평가 장 수도 구분해야 한다. 별도 `--val-n` 지정이 없으면 기본 교사 강제 검증은 최대 400장이고, 종류별 검증은 별도 목록을 쓴다.

근거: [작업자의 left 계산](https://github.com/twoapple08/AI-sfa/blob/ea6f2516fab8515dca0b013341ed1d3456874c68/tools/kaggle_seq_worker.py#L144).

## 4. 쟁점 3-3 — 부분 동의: 연장 시 360 유지에는 동의, 미검증 전환을 GPU에 맡기는 데에는 반대

연장 때 360 단계에 머무는 방향에는 동의한다. 하지만 다음 두 가지를 보완해야 한다.

### 4-1. 연장하면 해상도는 유지돼도 길이 분위는 되돌아감

현재 `max(st['stage'], stage_of(...))`는 해상도 후퇴만 막는다. 길이 분위는 늘어난 계획 분모로 다시 계산한다. 실제 함수로 확인한 결과:

| 이미 360까지 배운 저장본 | 재개 해상도 | 허용 길이 분위 |
|---|---|---:|
| 600/600분 | 360 | 100% |
| 계획을 780분으로 늘림, 600/780 | 360 | **45%** |
| 계획을 1200분으로 늘림, 600/1200 | 360 | **20%** |

연장이 같은 360 단계의 추가 학습이라면 이미 도달한 전체 길이를 유지하는 것이 맞다. 단계별 학습 진행/허용 분위의 최고 도달값을 저장하거나, 연장에서는 완료한 단계의 분위가 내려가지 않도록 정책을 명시해야 한다. 새 해상도로 넘어갈 때의 하위 20% 시작과는 구분한다.

회귀 시험은 **360·전체 길이 저장 → 계획 연장 → 360·전체 길이 유지**를 포함해야 한다.

### 4-2. 네 단계 통합 경로는 GPU 전에 가볍게 확인

첫 GPU 회차에서 1080→720이 나타나는 것은 유용한 확인이다. 그러나 480·360까지의 전환, 자료 교체·섞기·배치 큐·판정 폭 연결을 검증하지는 못한다.

추가로 긴 CPU 학습을 반복하자는 뜻이 아니다. 각 해상도와 검증 자료를 소수 장으로 줄이고 작은 모델/짧은 문제로 수분 단위 통합 시험을 한다. 시계 변경 뒤에는 다음을 확인한다.

- 네 단계가 순서대로 나타나고 각 현재 단계에서 실제 업데이트가 수행됨.
- 각 단계의 길이 제한이 의도대로 시작·확대됨.
- 단계 전환 전후의 저장·재개가 단계·분위를 보존함.
- 현재 단계와 이전 단계 섞기가 구분되어 기록됨.
- 판정 해상도와 공식/추세 표시가 따라감.

단순히 전체 자료로 계획을 40분으로 줄이면 읽기·마지막 검증이 또 단계를 잠식할 수 있다. 작은 자료와 적절한 평가 크기를 같이 써야 한다. 시간 함수의 단위 시험과 자료 교체를 포함한 통합 시험은 확인하는 범위가 다르다.

## 5. 쟁점 3-4 — 동의: 이전 단계 섞기는 전체 길이 유지

이미 배운 단계의 긴 장을 유지하려는 목적에 맞으므로, 섞기까지 현재 단계의 짧은 분위로 제한할 이유는 아직 없다. 두 경로를 모두 짧게 제한하면 긴 장 연습이 함께 줄어든다.

조건은 **그 이전 단계를 실제로 배웠다는 것**이다. 이번 480의 77걸음은 480을 정규 단계로 배운 뒤 복습한 경우가 아니다. 단계 건너뛰기가 먼저 해결돼야 한다.

37% 해석은 정정이 필요하다.

- 30%는 코드에서 **반복당 배치 선택 확률**이다.
- 따라서 장 수·토큰 수 비율은 30%와 직접 같지 않지만, **걸음/배치 선택 비율은 직접 점검할 수 있다.**
- 77/206≈37.38%는 유한 표본에서 가능하다. 다만 장 수가 다르다는 이유만으로 걸음 비율 차이를 설명할 수는 없다.
- 단계별 선택 시도 수, 성공한 업데이트 수, OOM/건너뜀, 장·토큰·시간 노출을 따로 기록한다. `expo`는 성공 경로에 기록되므로 선택 시도 수와 같다고 가정하지 않는다.

참고 계산으로 N=206 고정·독립 선택을 가정한 Binomial(206,0.3)의 P(X≥77)는 약 0.0139다. 시간으로 끝나는 실행·실패한 시도 등의 조건이 있으므로 정식 이상 판정용 p값으로 쓰지 않는다. 한 회차로 섞기 코드 오류라고 단정할 근거도 아니다.

수정 효과를 비교할 때는 다음 실제 단계 전환 전후의 고정 긴 장 손실·생성 점수와 노출량을 본다. 이 37% 하나 때문에 섞기의 길이 제한을 바꿀 필요는 없다.

### 6-1. 공식 횟수·640 고정 — 이번 코드에서 해결 확인

**이전의 공식 횟수 저장·640 고정 두 지적에는 추가 논증거리 없음.**

### 6-2. 먼 곡선 자르기 — 현재 보고된 단일 구간 문제의 수정에 동의

`tests/test_far_quad.py` 5개도 직접 실행해 통과했다. 블로섬으로 구한 부분 곡선이 원래 구간과 같은지 독립적인 베지어 식으로 비교하고, 큰 좌표의 두 렌더 및 변환 후 입력·정답 비교도 한다.

렌더러와 정답 변환이 같은 `clip_quad`를 쓰고, 면 참조가 있는 곡선은 그대로 두는 구현을 확인했다. 자료 판 6·판정 자료 판 3·외움 기준선 12.94로 무효화/갱신한 방향도 타당하다.

다만 범위를 정확히 유지해야 한다.

1. **여러 안쪽 구간**: 코드가 이미 인정하듯, 두 구간 이상이면 첫 시작~마지막 끝을 한 곡선으로 반환한다. 예를 들어 [(0,0),(1000000,1000000),(100,100)]은 자른 뒤에도 같은 큰 조절점이 남는다. 원본 실측 708개에서 0건이었다는 것과, 변환·자르기·조합 이후에도 0건인 것은 별도다. 생성 후 이런 경우의 수를 기록하고, 발견되면 안전한 처리 범위를 정한다. 이번에 실제 학습 자료에서 새 불일치가 발견됐다는 뜻은 아니다.
2. **면 곡선·넓은 스타일**: 면이 쓰는 먼 곡선 0건이라는 실측 범위와, 선 굵기·글로우의 지원 범위를 유지해서 기록한다. 공통 함수의 내부 일치는 앱 렌더와의 일치 증명이 아니다.
3. **미확인 해상도**: sd1920·sd854의 done.json 정합성 표본을 확인한다. 장 수가 약 4만이라는 것만으로 해당 폭의 정합성 확인을 대신하지 않는다.

단일 구간의 수학적 처리와 현재 회귀 시험에 추가 반대는 없다. 위 한계는 측정·범위 확인으로 남긴다.

### 6-3. 시험 두 장 제외·검증 목록

사용자가 정한 “장 전체가 같은 그림인 경우 제외” 기준과 두 장만 제외하는 결정을 따른다. 조합 학습의 요소 공유 자체를 새 제외 사유로 되돌리지 않는다.

다음 실행에는 제외된 원본 (파일, Frame.Position)과 실제 검증 목록의 해시를 남기는 것이 좋다. 현재 검증 표본은 자료 길이에 따라 np.linspace로 다시 고르므로, 제외 후에는 두 장 이외의 선택도 달라질 수 있다. 제외 전후 성적을 같은 고정 장의 개선처럼 비교하지 않도록 평가 목록을 식별한다.

### 6-4. §3-5 기록 보완

마지막 검증·종류별 검증 시간을 누적하는 수정과 run.json의 학습/자료 커밋·재개 기록을 확인했다. 다만 time_sec.wall과 작업자 run.json은 시작 시점·포함 범위가 다르므로 회차 예산의 기준은 작업자 시작부터의 전체 시간으로 둬야 한다.

## 부록: 이 환경에서 직접 계산한 값

아래 코드는 검토 기준 커밋의 저장소 루트에서 실행할 수 있다. 모델 학습 없이 실제 스케줄 함수만 추출한다.

```python
import ast
import math
from pathlib import Path

tree = ast.parse(Path("tools/seq_train.py").read_text())
names = {"stage_of", "stage_progress", "cur_quantile", "lr_at"}
env = dict(math=math, CUR_Q0=.2, CUR_RAMP=.8, CUR_STEPS=20)
functions = [n for n in tree.body
             if isinstance(n, ast.FunctionDef) and n.name in names]
exec(compile(ast.Module(body=functions, type_ignores=[]), "<scheduler>", "exec"), env)
frac = [.2, .25, .25, .3]

for done, plan in [(0, 600), (15, 600), (105, 140), (155, 600), (180, 600)]:
    p = done / plan
    k = env["stage_of"](p, frac)
    q = env["cur_quantile"](env["stage_progress"](p, frac, k))
    print(done, plan, [1080, 720, 480, 360][k], q)

for done, plan in [(600, 600), (600, 780), (600, 1200)]:
    p = done / plan
    k = max(3, env["stage_of"](p, frac))
    q = env["cur_quantile"](env["stage_progress"](p, frac, k))
    print("extension", done, plan, k, q)

print("lr at .3:", env["lr_at"](999, .3, 1))
print("lr at .8:", env["lr_at"](999, .8, 1))
```

출력 요점:
- 15/600: 1080, 하위 35%.
- 105/140: 360, 하위 40%.
- 155/600: 720, 하위 45%.
- 180/600: 720, 하위 60%.
- 이미 360까지 배운 600/780: 하위 45%.
- 이미 360까지 배운 600/1200: 하위 20%.
