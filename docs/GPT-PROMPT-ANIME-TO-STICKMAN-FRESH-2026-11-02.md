### 1. 목표와 쓰임
- 최종 목표는 태그·자연어·스토리보드를 받아 .sfa 애니메이션을 만드는 창작 AI다. 이번 변환 결과는 그 생성기(2단계)의 **인물 움직임 학습 재료**다. 실제 애니를 SFA로 바꾸고, 인물은 스틱맨이 된다. 이펙트·배경은 별도 변환기가 맡는다. 나중에 캐릭터 디자인을 입힌다.
- 결과 스틱맨은 **사람이 앱에서 편집할 수 있어야 한다**(앱 기본 스틱맨처럼 연결이 살아 있고, 포즈 도구로 꺾여야 함).
- 24/24로 만든다(트위닝 없이 1초에 24장을 모두 그림). 앱은 평면 2D다.
- 사용자 판단: 이전 결과는 움직임이 **어색했다**. 이유는 정해져 있지 않다. 무엇이 '자연스러운 스틱맨 움직임'인지도 토론 대상이다.

### 2. 바꿀 수 없는 사실(앱·자료)
- 앱 기본 스틱맨: `data/app_templates/stickman_default.sfa`(사용자가 앱에서 만들어 내보냄). 10조각 = 머리 원(TypeId 2, 지름 양끝 점) + 몸통 + 위팔·아래팔 ×2 + 허벅지·정강이 ×2. 목·골반·팔꿈치·무릎에서 점으로 이어진다(AC). 파란점(Flags 3) = 골반 = 뿌리. 관절점(주황, Flags 33)은 기본에는 없고 사용자가 따로 지정한다.
- 좌표는 화면 %(X 가로 %, Y 세로 %, HeightWidthRatio 0.5625).
- 파일 ID 규칙(실제 파일 304개 전수 조사 + 앱 시험): **오브젝트 ID는 장끼리 이어지고, 점 ID는 장마다 새로 쓴다.** 점 ID를 모든 장에서 같게 쓰면 앱에서 편집할 때 조각이 떨어진다.
- 실제 앱 스틱맨 파일 4개는 조각 길이가 장마다 거의 일정하다(중앙값 변화 0%).
- 형식 문서: `docs/FORMAT.md`. 사용자 수집 SFA: `data/user_sfa/`(공개, 스틱맨 동작 파일 포함). 렌더러: `tools/sfa_render.py`.
- 참고 측정(방식과 무관한 사실): 실사 학습 포즈 모델 YOLO11m-pose로 nian41 영상 8개를 6장 간격으로 훑었더니 사람 검출률이 0–39%였다.

### 3. 자원과 범위
- 계산: Kaggle T4×2(주 30시간), 사용자 PC GTX 1050 Ti 4GB(상시), RTX 5060(가끔 2시간 미만), 서버 CPU 4개(GPU 없음). GPU 실행은 사용자 허락을 받고 한다.
- 원본 영상: nian41, 나카무라(yutaka_nakamura) 등. Drive `AI-sfa/01_원본영상/`.
- 애니메이터별 범위(고정, 재해석 금지): nian41은 몸 뼈대 움직임 1순위다. 나카무라는 타격 타이밍·간격, 이펙트와 몸의 맞물림이다(검출이 어려워 타이밍 위주였다). riooo·optical-core·yukina 몸동작은 쓰지 않는다. 원문은 `AGENTS.md`.

### 4. 1차 답에 쓸 것
1. **문제 분해:** 애니 → 스틱맨 전환을 어떤 단계로 나누는가? 각 단계에서 애니가 실사 영상과 다른 점(작화 2·3장 단위 정지, 스미어·잔상, 과장 비율, 컷·카메라 이동, 가림, 몸 돌리기)이 어떻게 문제를 만드는가?
2. **가능한 방법을 넓게:** 2D 추적, 3D 경유, 학습된 변환기, 키포즈 재연출, 사람 참여, 기타. 이 목록에 얽매이지 말고 더 나은 게 있으면 추가한다. 방법마다 기대 품질, 실패 방식, 계산량(T4 기준), 구현 난이도, 앱 편집 가능성, 생성기 학습 재료로서의 적합성을 적는다. 구체적인 모델·논문·도구 이름을 대고, 실존·버전을 확인 못 하면 '확인 필요'로 표시한다.
3. **'자연스러운 스틱맨 움직임'의 정의:** 원본 카메라 투영을 그대로 따라야 하나, 스틱맨 애니메이터식으로 다시 연출해야 하나? 생성기 재료라는 목적에서 어느 쪽이 맞는지 근거를 댄다.
4. **추천 경로 1개 + 차선 1개.**
5. **가장 작은 첫 실험:** 무엇을 재서 무엇을 가르는지, 합격선, 필요한 계산, 시험 장면을 고르는 기준(nian41·나카무라 중 어떤 구간이 공정한가).
6. **평가:** '어색함'을 숫자로 잴 방법과, 그 숫자의 반례(점수는 좋은데 어색한 경우)를 적는다. 정답 자료를 어떻게 얻을지도 적는다.
7. **사용자에게 물을 것.**
