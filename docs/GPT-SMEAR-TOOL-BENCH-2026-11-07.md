## 실제 출력과 비교 범위

- AniLines 기본/세부·MangaLine·Anime2Sketch: 공개 가중치로 실제 CPU 추론, 각6영역. 모델 결과는 밝기 자동 보정 없이 보관했다.
- SAM2.1 Hiera Tiny: 수동 전경점+모서리 배경점, 색마스크 상자 추가 조건 각각6영역. X-AnyLabeling/ISAT 두 GUI를 독립적으로 실행한 결과로 세지 않는다. 공통 SAM2 백엔드만 시험했다.
- Thin Object Selection: 실제 TOSNet/공식 전처리, 색마스크 극점 입력6영역. CPU 전환, 삭제된 NumPy int/float 별칭만 호환 보완. 모델 구조나 알고리즘은 바꾸지 않았다.
- Cutie: SAM2가 만든13장 초기 마스크로13~20장8장 추적,6영역 결과 추출. 초기 입력과 후속 예측을 구분한다. 완성 가중치 누락키0 확인 후 중복 ImageNet 초기화 다운로드만 생략했다.

- Skeleton Tracing: 공식 Python 코드를 실제 호출해 중심선→꺾은선 좌표 추출. OpenCV의 색/GrabCut/윤곽 및 각 모델 출력과 연결했다.
- AutoTrace: Ubuntu구버전 실행기는 공유라이브러리 부족으로 실패했지만, 현재 Inkscape1.4 내장 실제 AutoTrace 라이브러리와 대응 헤더를 사용해 외곽/중심선 각6영역을 실행했다. 색/선추출 결과와 조합했다. 평활4회 기본값을0회, 곡선오차 .5로 설정한 시험이며 손실 없는 작가 획 복원이라고 부르지 않는다.
- ilastik1.4.1.post1: 실제 특징 연산자와 Lazyflow/VIGRA RF를 실행했다. 색/경계/헤시안 특징, 척도 .7/1.6/3.5,100트리. 같은6영역의 중심3×3전경/모서리3×3배경으로 학습·예측했으므로 독립평가가 아니다. 전체배포본 추출 중 공간 부족 발생, 실제 사용 모듈의 로드·실행만 확인했다. GUI 전체 설치 성공은 아니다.

- PolyVectorization/PolyVector Flow: 실제 CMake 구성을 시도했으나 Qt5 개발 파일 부재로 차단. Flow에는 Gurobi/PAAL 의존성도 준비되지 않았다. 다른 알고리즘 그림을 해당 도구 결과로 넣지 않았다.
- SmearSmith: 생성용 도구이고 무료판의 사용자 스프라이트 입력이 없어 이번 원본 추출 비교에는 적용하지 않았다. 구매/유료판 실행 없음.

## 관찰과 한계

여러 영역에서 색거리 분리는 밝은 배경을 함께 잡고, 일반 분리기는 가는 끝을 짧고 둥글게 만든다. MangaLine/Anime2Sketch는 이 입력의 흐린 잔상을 상당 부분 없앴다. AniLines 세부는 일부 모양을 남겼지만 배경도 뽑았고, SAM2와의 교집합은 배경을 줄이는 동시에 원본17 위팔의 필요한 획까지 지웠다. 면 중심선의 가지 형태는 실제 작가의 지그재그와 다른 정보다. 이 표본·이 파라미터에서의 관찰이지 각 도구의 최대성능/일반화 순위가 아니다.

따라서 원본 스미어 전체를 정확히 뽑아 편집 가능한 SFA로 옮길 수 있는 조합은 아직 확인하지 못했다. 새 SFA/기본 생성경로/기존 관절축/학습정답을 변경하지 않았다. 가린 어깨/팔꿈치는 여전히 v6 수동 추정이며 v7은 사용자 반려 상태를 유지한다. 실제 애니메이터 원본과 사용자4.sfa의 표현구조 참고 역할도 구분한다.
