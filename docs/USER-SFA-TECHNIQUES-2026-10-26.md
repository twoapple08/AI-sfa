## 우리 변환기와 다른 점(배울 것)
1. **끝점 연결(AC, ConnPtId):** 곡선의 끝점이 다음 곡선의 시작점과 연결돼 한 줄처럼 이어진다(점 ID를 서로 가리킴). 우리 변환기는 곡선마다 점 3개를 따로 둔다 → 이어진 줄로 만들면 점이 줄고 앱에서 한 선으로 편집된다(docs/SFA-CURVE-OPTIMIZATION-2026-10-25.md '다음에 할 방법 2'와 같은 것, 실제 파일로 확인).
2. **채우기 경계는 성긴 직선(TypeId 1)이 많다:** 안녕 루야 채우기 경계 객체 2,884개가 직선, 1,001개가 곡선. 면은 성긴 다각형, 둥근 곳만 곡선(우리 원칙 3과 일치).
3. **훨씬 적은 객체:** 사람 그림은 장당 AO 약 400, 채우기 약 50. 우리 변환 결과는 이펙트 장당 3,000–6,000 → 사람 그림은 큰 면 몇 개 + 반투명 명암 겹으로 형태를 만든다.
4. **반투명 겹 명암:** 알파 10–51의 면을 겹쳐 그림자·빛(눈 뜨기 알파 23/38/48, 안녕 루야 28). 우리 번짐 층(알파 0.35)과 같은 방향, 사람 그림이 더 옅고 겹이 많다.
5. **글로우 = 투명 곡선에 글로우만:** 색 0(투명) 곡선에 GlowRadius 8–9, GlowThickness 84–126, GlowAlpha 163–176 → 빛 번짐. 우리 `--glow`와 같은 방식(맞게 하고 있음 확인).
6. **화면 전체 톤:** 굵기 200, 반투명 검정(알파 128) 직선 하나로 화면을 어둡게 덮는다(눈 뜨기 14개) — 면 대신 굵은 선 하나로 색 덮개를 만드는 요령.
7. **장 사이 같은 객체 재사용:** 이웃 장의 AO ID가 많이 겹친다(눈 뜨기 387/387 → 125, 안녕 루야 111–141). 안 움직이는 부분은 같은 객체를 그대로 두고 움직이는 부분만 다시 그린다 → 우리 영상 변환에서 배경 층을 장마다 다시 따지 말고 그대로 두면 배경 깜빡임 0, 크기도 줄어듦.
8. **선 굵기:** 중앙 ThicknessScale 0.2–0.3(우리 선 기본 0.6보다 가늘다), 붓선은 2.1.

## 적용 후보(우선순위 제안)
1. 영상 변환: 안 바뀐 배경 층 객체를 다음 장에 그대로 재사용(7).
2. 곡선 끝점 연결(AC)로 이어진 줄 만들기(1).
3. 채우기 경계를 성긴 직선 위주로(2·3) — 객체 수 감소.

## 추가 분석 (2026-10-26, 사용자: "움직이는 예시가 아니라 색칠공부를 보냈었나 보네", "선 10%로 보는 걸 추천")
- **색칠공부:** 중간 레이어(Layer 3)는 파일에 '숨김'으로 저장돼 있다. 앱은 밑그림 선만 보여 주는데 서버 렌더러는 숨긴 레이어의 채색 면도 그렸다 → **렌더러 고침**(주인 곡선이 숨긴 레이어에 있는 채우기는 안 그림). 고친 뒤 선 10% 렌더가 사용자 앱 화면과 같음.
- **움직이는 예시(외전) — 가장 중요한 발견:** 10장 전부 같은 객체 1,801개를 그대로 쓰고, **움직이는 부분만 점을 옮긴다.** 장마다 움직인 객체: Layer 1(785개 중 약 280), Layer 5(168개 중 약 100), Layer 2(222개 중 65–89), Layer 9(114개 중 약 15), Layer 8(172개 중 5). 나머지 11개 레이어(배경 등)는 10장 내내 한 점도 안 움직임. 장간 화면 차 평균 0.5(0–255) — 숨쉬기·머리카락 같은 작은 움직임.
  - 우리 영상 변환은 장마다 윤곽을 새로 따서 곡선 구조가 바뀐다 → 깜빡임의 근본 원인. 사람 애니메이터는 **같은 곡선을 변형**한다.
  - 적용 방향: 첫 장(또는 새 그림이 나온 장)에서만 곡선을 따고, 다음 장은 그 곡선의 점을 그림 움직임(광류)만큼 옮긴다. 맞지 않을 때(오차 큼·새 그림)만 다시 딴다. GPT 2차 조사의 LiveSVG(기존 곡선을 영상에 맞춰 변형)와 같은 생각이다.

## 선 굵기 10%씩 줄여 보기 (2026-10-26, 사용자: "애셔 엘리아는 100%여도 상관없고 색칠공부만 10%, 10%씩 줄여 보면서 최적 확인")
[서버 렌더, 같은 파일의 ThicknessScale만 배율]
- **색칠공부 밑그림(원래 굵기 2.09):** 100–60%는 눈 주변 선이 뭉쳐 검은 덩어리, 50–30%는 굵은 마커 느낌, **20%(0.42)는 진한 연필, 10%(0.21)가 가장 깔끔한 스케치**(사용자 추천과 일치). 10%의 실제 굵기 0.21은 사람이 그린 다른 파일 선의 중앙값(0.2–0.3)과 같다.
- **우리 선 객체 변환(광사, 선 배율 1.0판):** 보이는 선 563개의 굵기가 이미 0.1–0.2(중앙 0.1)로 **앱 하한 0.1에 붙어 있다.** 80%로만 줄여도 84%의 선이 하한 아래가 돼 앱에서는 더 얇아지지 않는다(서버 렌더러는 하한 없이 그려서 더 얇게 보일 뿐). 서버 렌더로는 60–70%가 균형이 좋아 보이지만 앱에선 재현 불가.
- 결론: 선을 더 '얇게'가 아니라 **굵기 범위를 사람 그림처럼 0.1(가는 결)–0.3(주 윤곽)으로 넓히는 쪽**이 맞다. 우리 변환기의 지금 굵기는 대부분 0.1이라 오히려 사람 그림보다 가늘고 고르다.

## 길가메시 vs 세이버 (2026-10-26, 사용자: "기본 100이고 (12,12), 두께는 줄여서 봐도 괜찮아")

- **모든 장에서 같은 객체를 유지**(이웃 장 같은 ID 117–162개, 사라지는 객체 거의 없음)하고, 새 선만 더한다(1장째 +14, 5장째 +30 — 머리카락 가시 등 디테일 추가).
- **움직임 = 화면 전체 이동·확대 + 남은 작은 변형:** 이웃 장 점들에 닮음 변환(확대·회전·이동)을 맞추면 확대 0.96–1.03, 이동 최대 화면의 약 10%/장(4→5장)이고, 그것을 빼고 남는 움직임은 평균 0.5–2.4%(표정·입 모양). 즉 카메라 흔들림·밀기를 같은 선 전체의 변환으로, 연기는 선 일부의 작은 변형으로 나눠 그렸다(GPT 조사의 '이펙트 변형과 화면 흔들림을 따로' 제안을 사람 파일로 확인).
- 렌더: 100%는 굵은 만화 선, 50%(0.5)는 더 날카롭고 깔끔. 머리카락은 직선 지그재그(뾰족한 끝)로 그린다.
- 적용: 우리 '같은 곡선 변형' 방식에 **장 전체 닮음 변환(카메라) + 남은 변형** 두 단계를 넣는다.

- 채색 면은 **불투명 큰 면 몇십 개, 면 하나를 경계 조각 약 6개로** 성기게 닫는다. 경계는 주로 투명 곡선(보이지 않는 테두리)이고 선화는 따로 위 레이어.
- **명암·빛은 반투명 면이 아니라 반투명 선(굵은 붓선)과 투명 곡선 글로우**로 얹는다(면 알파는 전부 255, 낮은 알파는 선에만).
- 움직임: 같은 객체 유지 + 점 이동, 카메라는 전체 변환.
### Claude 변환기에서 틀렸던 것
1. 픽셀 경계를 따라 밝기 단계마다 불투명 면을 겹겹이(불 10단계) → 장당 3,000–6,000 객체. 사람은 기본 면 몇 개 + 반투명 선 명암.
2. 면 경계를 픽셀 윤곽대로 촘촘히(면당 조각 수십) — 사람은 약 6조각, 선이 덮으니 정확할 필요 없음.
3. 번짐을 '반투명 면(알파 0.35)'으로 — 사람은 반투명 굵은 선.
4. 곡선 끝점 연결 없음, 선 굵기가 앱 하한 0.1에 몰려 고름(사람 0.2–0.3, B는 1.0).
5. 영상에서 장마다 새로 따서 구조가 바뀜(깜빡임의 근본 원인) — 사람은 같은 객체 변형, 카메라 분리.
6. 서버 렌더러가 숨긴 레이어 채우기를 그림(고침).

## 명암 참고 '배' (2026-10-26, 사용자: "명암 참고에 도움될 것 같은 파일, 선 두께에 따라 글로우 크기도 달라짐, 10%씩 줄여 봐, 캡처는 봐야 하는 레이어 순서")

- Layer 2: **투명 곡선 113개 전부 글로우만**(GlowRadius 24–65, GlowThickness 97–300, GlowColor 연분홍·연살구, GlowAlpha 255, 굵기 1.0). 면을 겹겹이 칠하지 않고 **큰 글로우 여러 개로 부드러운 그라데이션 명암**을 만든다.
