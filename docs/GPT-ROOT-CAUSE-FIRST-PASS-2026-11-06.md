# 전용 도구 — 근본 원인 1차 진단과 다음 검증

## 범위와 현재 판단

사용자 “자 가보자”로 계획 기록 대기를 해제하고 첫 진단을 시작했다. 권장 추론은 High다. 목적은 원본 애니에서 동작·타이밍·구도·가림·원근·스미어·이펙트를 읽고, 원하는 표현을 학습·생성하여 편집 가능한 SFA로 만드는 전체 흐름이다. 영상→SFA 사례 분석과 글→새 장면 생성은 별도 평가한다. 작가별 학습 범위·24/24·기존 기본 편집망 규칙은 바꾸지 않는다.

**확인된 문제는 표현 범위와 최종 목표 사이의 간극이다. SFA 자체가 실패 원인이라고 확정한 것이 아니다.** 자세 흐름 시험용 토큰은 여러 의미를 의도적으로 담지 않는다. 이를 최종 애니 생성 전체의 언어로 간주하면 정보가 빠진다. 기존 중간 표현과 SFA 컴파일러는 이미 분리돼 있으며 새 분리 설계를 발명할 필요는 없다.

이번에는 코드 대조·합성 반례·기존 공개 IR 집계만 수행했다. 원본 애니/최신84장 비교판의 새 눈 판독, 실제 앱 시험, 모델 추론·학습·GPU 실행은 하지 않았다. 기존 보고의 사용자 판정은 과거 근거로 재사용한다.

## 1. 단계별 진단

|단계|확인 근거|판단과 남은 검증|
|---|---|---|
|원본 관측|`stage2_extract.convert`는 RTMW 관측을 보정·추론하고 joints/drawings/facing 등을 저장. camera는 기본값, timeline은 빈 목록으로 생성|몸 관절 추출에 범위를 둔 경로다. 이 경로만으로 원본 카메라·이펙트·연출 해석 전체를 학습한다고 볼 수 없다. 새 원본 판독 필요|
|관측/추론 구분|IR에 inferred·smear_mark 등 기록이 존재|이 기록이 후속 언어까지 살아 있는지 별도 확인해야 한다. 추론한 점을 관측 정답과 섞지 않는 것이 중요|
|학습 표현|`motion_tokens.encode/decode`의 메타데이터 충돌 합성 실험|방향·가림·스미어·스미어 표시·추론 표시·굵기·머리 채움·색·카메라·타임라인 변경에도 같은 토큰. 기본 호출은 한 인물 슬롯만 표현. 토큰만으로 차이를 구별할 수 없음|
|시간 표현|그림 구간의 가운데를 키로 선택. 첫 키 간격을1로 쓰고 decode는 첫 키를0으로 둠. 좌표 사이 선형 보간|합성 12장→11장, 그림 유지 중 움직임 발생. 특정 입력의 경계/유지 의미 손실 확인. 모든 자료 오류나 현재 진동의 원인이라는 뜻은 아님|
|학습 결과|`stage5_v3_result`, `stage6_gen_v3_result` 기존 JSON|정지 제외 후 학습3,886쌍. 32장 창/8장 간격·뒤집기 때문에 독립 동작 수와 다름. 생성 full 정지 비율0.25는 기존 절차의 측정으로, 새 모델 실행 결과 아님. 손실 개선만으로 걷기 성공을 주장할 수 없음|
|현재 조합|`compose.compose`는 관절·방향을 조합하고 hidden/smear/thickness 등을 새로 초기화. 크기 정규화·루프·이음매 보간·추적 카메라 적용|학습 토큰과 다른 경로이므로 양쪽 문제를 혼동하지 않는다. 입력 메타데이터 전체를 보존하는 조합기는 아님. 변경 단계별 차이를 측정해야 함|
|걷기 출처|`loco_style_clips_2026-11-06.json`의 현재 선정1개|숙여 물러나는16장을 시간 반전해 사용. 일반 앞으로 걷기의 근거가 아니며 구부정함과 관련된 명확한 출처 한계. 새 눈 판독은 미수행|
|SFA 출력|`motion_ir.compile_ir`, `tokens_to_sfa.finalize`|기본 스틱맨 편집망용 경로. camera 필드는 v1에서 컴파일에 미사용. finalize의 굵기 재계산은 기존 설계다. 별도 그림 토큰의 Flags 손실을 이 컴파일러 결함으로 옮겨 주장하지 않음|

## 2. 재현한 근거

실행: `python tools/motion_information_probe.py --output data/research/motion_information_probe_2026-11-06.json`

- 사용자 그림 없이 만든 합성 12장/4그림 입력. 키는 `[1,4,7,10,11]`, 출력11장. 첫 두 입력 장은 동일하지만 첫 두 출력 장은 다르다. 원래 그림 경계와 재생성 경계도 다르다.
- 위 표의11개 메타데이터 변경 각각이 동일한 토큰을 낳는다. 이는 손실 채널의 반례이지 시각 품질 점수나 신경망 실패율이 아니다. 두 번째 인물은 기본 slot0 호출에서 제외되며, 인물별 호출 자체가 불가능하다는 뜻은 아니다.
- 공개 기존 IR510개 모두 디코딩 가능, 장 수510개 전부 동일. 이 집계는 그림 구간이 있는 모든 애니 자료의 대표 평가가 아니다. 그림 유지·좌표·스타일의 보존도 증명하지 않는다.
- 코드/입력 SHA256은 JSON에 기록. 기존 생성기·어휘·컴파일러·자료·승인 출력은 수정하지 않았다.

현행 토큰의 생략은 문서화된 시험 범위다. 지금 즉시 토큰을 늘리거나 새 모델을 학습하면 검증되지 않은 SFA 스미어 의미를 또 고정할 수 있다. 이 단계에서는 진단기를 추가하고 다음 실제 사례를 먼저 확보한다. 시간 문제도 재학습/출력 호환성에 영향을 주므로 기존 생산 경로를 몰래 바꾸지 않는다.

## 3. 가져올 요소의 1차 우선순위 — 채택 전

진단기 실행·출처 지문·집계 확인 및 `git diff --check` 통과. 기존 회귀 검사 `python -m unittest discover -s tests` 387개 OK·exit0(30.513초). 이는 외부 시스템 적용 성능이나 애니 원본 충실도 검증이 아니다.

1. **정보 보존 계약부터:** 원본 관측·그림 시간·가림/추론 근거와, 목표 SFA에서의 대상·연결·표현 선택을 대응시킨다. 관측 부족과 표현 부족을 구별한다. 기존 IR 필드를 먼저 재사용할 수 있는지 본다.
2. **시간 사건과 대상 추적:** 음악/행동 묶음의 사건 경계와 획 대응 연구를 참고한다. 유지·예비·타격·회복과 대상 정체성을 좌표 평활만으로 대체하지 않는다. LayerInbetween 전체 설치보다 대응 개념과 입출력 적합성을 먼저 확인한다.
3. **타입 있는 도형/참조 언어:** Vitruvion/SketchGen의 기하+참조 생성 관점을 비교한다. SFA의 AC/Flags/FS 의미를 CAD 고정 길이/좌표 일치와 동일하게 취급하지 않는다.
4. **효과 부품과 인터페이스:** GarmentCode식 경계/접합 개념을 연기·스미어 형태 사전에 쓸 수 있는지 검토한다. 실제 사람이 SFA에서 사용하는 사례를 보기 전에는 스미어를 잔상·늘이기 중 하나로 고정하지 않는다.
5. **검증과 수정 재사용:** 원본 대비 의미, 표현 왕복, 장간 동일 대상, 앱 편집 가능성, 사용자 수정량을 따로 잰다. 사용자 수정은 출처와 이유를 남기고 검증 없이 학습 정답으로 승격하지 않는다.

이는 후보 역할의 초안이며 도구 구조 확정이 아니다. 외부 모델 가중치가 SFA에 그대로 맞는다고 가정하지 않는다. 임의 영상 완전자동 변환과 제한 장면의 보조 도구 성공을 분리한다.

## 4. 다음에 필요한 정확한 사례

### 사용자에게 요청한 첫 사례: 스미어 SFA 하나

파일명/경로와 대략 장 번호 또는 재생 시점. 빠른 팔 동작이나 타격의 스미어를 우선한다. 가능하면 스미어 직전→발생→사라진 뒤가 들어 있는 파일. 애니를 참고한 파일이면 원본 링크/구간도 함께 대응하고, 없으면 SFA 표현만 먼저 분석한다. 새 파일 수집·새 작가 승인을 요구하는 것이 아니라 사용자가 가진 사례를 지정하는 요청이다.

확인 항목: 늘어난 신체인지/덧댄 획·면인지/복수 형태인지, 앞뒤 장의 대상 ID·숨김·연결·채움·알파/글로우·앞뒤 순서 변화, 편집 시 유지해야 하는 관계. 한 사례를 보편 규칙으로 만들지 않는다. 파일만으로 편집 조작을 확정할 수 없으면 해당 조작만 사용자 앱 확인을 요청한다.

### 현재 진동의 실제 원인에 필요한 보관본

최신84장판과 리듬 보정 없는 비교판(`scratch compose6`로 기록), 보정 전 관절/선정 조각 IR, 사용한 캐릭터 시트, 관련 원본 구간의 동일 판본. 이 환경의 `/workspace/scratch`는 비어 있으며 스킬 private-data와 `/root/sfa-cache`도 없다. 공개 집계/코드만으로 진동 원인을 새로 확정할 수 없다.

연결 Drive에서 compose6/compose/stage2/loco 이름 검색은 결과가 없었다. 220930 이름으로 과거 이펙트 폴더는 검색됐지만 최신 비교판/입력과 동일하다는 근거는 없어서 대용하지 않았다. 이름 검색 무결과는 Drive 전체에 파일이 없다는 증거가 아니다. 사용자가 보관 경로를 지정하면 복원해 사용하고, 없으면 재구성은 별도 새 실행으로 기록한다.

## 5. 다음 작업 순서

스미어 사례가 정해지면 SFA 내부 구조와 앞뒤 장을 판독하고 원본이 있으면 함께 비교한다(High 권장). 동시에 최신 진동 입력이 확보되면 원관측→보정→정규화→반복/이음매→카메라→리듬→SFA 좌표를 같은 장 기준으로 측정한다. 진동→가면 원근→걷기 출처의 기존 순서를 유지한다. 그 결과와 이번 손실 반례로 최소 입출력 계약을 정한 뒤 수정/구현 범위를 정한다. 모델 규모 변경·신규 학습·GPU는 아직 필요성이 증명되지 않았다.
