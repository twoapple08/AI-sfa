# SFA화 중간 표현 규격 — 초안 v0 (2026-11-04 Claude)

상태: **초안, 사용자 미승인.** 아래 '정해 주실 것'의 답과 처음부터 끝까지 시험판(10초 클립 하나)의 실제 결과로 고친다. 기존 판정 JSON·작가별 학습 범위·스틱맨 규칙은 바꾸지 않는다.

## 왜 필요한가

- 60초 스틱맨만으로 객체 25,669개·점 53,778개다. 배경·이펙트까지 더한 .sfa 전체를 토큰으로 직접 생성하는 최종 AI는 규모가 맞지 않는다(변환기는 한 장 2048토큰 한도에서 이미 34/92장이 강제 종료).
- 그래서 **최종 AI는 압축된 중간 표현을 생성하고, .sfa는 정해진 컴파일러가 만든다.** SFA화의 결과물도 "중간 표현 + 그것을 컴파일한 .sfa" 두 가지다.
- 각 요소가 무엇인지(배경/이펙트 종류/스미어 등)를 라벨로 남겨야 최종 학습에서 "무엇을 그리는지"를 배울 수 있다(사용자 11-04 계획).

## 구성 (클립 하나 = 파일 하나, JSON)

```
clip:
  meta        출처(비공개 참조 ID만), 원본 장 범위, fps(24,24), 화면비, 원본=재생+오프셋
  quality     자료 등급, 수동/추론/자동 비율, 사용자 확인 범위, held_out/training_ready
  tags        장면 태그·자연어 설명(GPT 태깅 후 Claude 검수)
  timeline    컷 경계, 카메라(이동/확대/흔들림), 정지(2/3컷 유지), 타격 순간
  actors[]    스틱맨 트랙
  elements[]  배경·이펙트·연출 요소 트랙
  order       장별 앞뒤(인물↔요소, 인물↔인물)
  contacts    실제 접촉(타격점·잡기), 이펙트가 붙는 신체 부위
```

### actors[] — 스틱맨 (기존 기술 재사용)

- 기본11편집망 고정 구조, 키 = 원본 그림 하나(image key), 키마다 12관절 2D 좌표 + 가시성 + 추론 표시.
- 선택 표시층: 근경 연속 면(폭 키, 표시 척도 근거), 머리 A안. 손가락·발가락·발길이 0.
- 지금의 `resolved_edits.json`/`root_keys.json`/`visibility.json`/`surface_sources.json`이 사실상 이 트랙의 원형이다. 컴파일러 = 현재 `build.py`/`stickman_clip.person_aos`.

### elements[] — 요소 트랙

요소 하나 = 장끼리 이어지는 대상 하나(예: "타격 섬광 #3"). 한 장짜리도 된다.

```
element:
  id, label           라벨(아래 분류)
  span                시작~끝 장
  layers[]            그림 과정 층: line(선) / base(밑색) / shade(반투명 명암 여러 겹) / glow
  shape_keys[]        키 장마다 형태: 2차 베지어 조각 목록(점·굵기·색·알파·글로우), 면은 성긴 다각형
  motion              키 사이 보간(이동·회전·크기·알파 곡선), 또는 장마다 형태(보간 불가 시)
  anchor              붙는 대상(화면/배경/인물 관절) — 예: 오른손목에 붙은 스미어
  source              관측(분해 도구 결과)/수동/추론/생성
```

라벨 분류 초안(사용자 확정 필요):

|큰 분류|세부 예|
|---|---|
|background|하늘, 건물, 바닥, 원경, 실내|
|effect.impact|타격 섬광, 충격파, 임팩트 프레임(연필/디지털/단색 섬광)|
|effect.energy|빔, 번개, 불, 오라|
|effect.particle|파편, 먼지, 불똥, 연기|
|smear|신체 스미어(사람 추출 대상과 연결), 물체 스미어|
|motion_line|속도선, 집중선|
|lighting|명암 덮기, 역광, 색 덮기|
|camera_fx|흔들림, 암전, 화면 번쩍임|
|object|소품·무기(사물)|

### 컴파일 규칙 (중간 표현 → .sfa)

- (24,24), 장마다 새 점 ID, 객체 ID는 같은 대상에 장끼리 고정(기존 불변 조건).
- 앱은 객체 ID 하나를 파일 전체에서 한 레이어·한 종류로 묶어 저장한다(docs/FORMAT.md 2026-10-29). → **요소 라벨을 레이어 단위로 둔다**: LayerDef Name = 라벨(예 `effect.impact/03`), 역할별 객체 ID 구간 고정.
- 앞뒤 순서는 DrawOrder가 아니라 레이어로 나눈다(FORMAT.md). 장마다 앞뒤가 바뀌는 경우(인물↔인물)는 기존 `apply_actor_order` 방식.
- 글로우/투명도는 형태 키의 값 그대로. 레이어 투명도(Opacity)는 앱 새 기능이며 렌더 방식 미확인.
- 컴파일 결과는 기존 검사(`stickman_quality.py`, ID/레이어/종류 일관성)를 통과해야 한다.

## 세 부품과의 관계

|부품|만드는 것|
|---|---|
|스틱맨화|actors[], contacts 일부|
|변환기(학습형) 또는 분해 도구(`effect_layers.py`류)|elements[]의 shape_keys/layers|
|라벨·태그(분할 마스크 + GPT 태깅 + 검수)|elements[].label, tags, timeline 일부|
|최종 생성 AI|태그/문장/스토리보드 → 이 중간 표현 → 컴파일러 → .sfa|

변환기 진단(docs/SEQ-CONVERTER-DIAGNOSIS-2026-11-04.md)이 정리되기 전까지 시험판의 elements는 분해 도구 + 수동 보정으로 만든다. 학습형 변환기가 좋아지면 같은 자리를 바꿔 끼운다.

## 정해 주실 것

1. 라벨 분류표: 위 큰 분류/세부가 적당한지, 빠지거나 합칠 것.
2. 라벨을 레이어 이름에 담는 방식: 앱이 LayerDef Name을 저장·편집 후에도 보존하는지 실제 앱 확인이 필요하다. 시험 SFA `tools/layer_label_probe.py` → Drive `AI-sfa/04_SFA시험작/레이어이름_확인_2026-11-04/layer_label_probe_v1.sfa`(1G7KHyDcU0JK2vsAsG54T_gF_JP6sJ_GC): 3장, 레이어4개(`background/sky`, `effect.impact/01`, `이펙트_타격섬광_02`, `Layer 4`). **앱 확인 전.**
3. 시험판 클립: 기존 10초 구간(원본1032–1271)으로 할지, 이펙트가 더 많은 구간으로 할지.
4. 요소 형태를 "장마다 따로"와 "키+보간" 중 어느 쪽 우선으로 할지(편집성 vs 충실도).
