## 복붙용 프롬프트

5차 지적 반영본이야. 필수 2개는 고쳤고, 나머지는 아래처럼 처리했어. 반영이 맞는지, **2차 실행 전 필수가 남았는지**만 봐 줘.

### A. 필수 2개
| 번호 | 지적 | 처리 | 실행 확인(서버) |
|---|---|---|---|
| 1 | 채널별 max pooling이 색을 섞음(빨강+파랑 → 자홍) | 띠를 버리지 않고 바르게 구현: `max_pool2d(on_line, 3, return_indices=True)`로 3×3 안 **가운데선 픽셀 하나**를 고르고 그 픽셀의 RGB 3채널을 `gather`로 통째로 가져옴. 가운데선 픽셀은 `torch.where(on_line>0, 자기 RGB, 가져온 RGB)`로 자기 색 그대로(기존 속성 정답과 충돌 없음) | 1×7 시험: x=2 빨강선, x=4 파랑선 → 띠 정답 x=1·2·3 빨강, x=4·5 파랑, 섞인 색 없음. 손실 유한 |
| 2 | 시작 가중치 실패 시 조용히 처음부터 | `pc_vec_run`: 이어하기가 없고 `--init-from`이면 ① 남은 `init.pt` 먼저 삭제 ② `rclone copyto` 반환 코드 확인 ③ `torch.load`로 열어 키 10개 이상 확인 ④ 실패면 **데이터 만들기 전에** `SystemExit`(처음부터 하려면 `pc_vec_5060.bat 시간 scratch`). bat: Drive 연결 실패 문구도 '멈춤'으로. `vec_train`: 지정한 `--init` 파일이 없으면 오류로 종료 | 서버: rclone 없음 → 멈춤 문구로 종료(코드 1). 서버 rclone 있음 → '시작 가중치: pc best.pt'. `--init /없는파일` → '시작 가중치 없음'으로 종료. 정상 `--init` 짧은 학습 통과(학습률 5e-4) |

### B. 나머지
- 3·4: 유지.
- 5(나중에, 동의): 비유한 forward의 BatchNorm 통계 오염, bf16 경로의 기울기 유한성 검사, 성공 업데이트 수 분리 → 2차 기록에서 `skipped`가 0이 아니면 보강.
- 6(동의): 페인트·합성·원본 검증을 따로 기록하는 건 다음 판. 2차 총 검증 손실은 1차 4.87과 직접 비교하지 않는다(손실 항·자료·가중이 바뀜). 대신 같은 시험 장면(학습에 안 쓴 앱 영상)을 1차 best와 2차 best로 그려 비교한다.
- 7: `sfa_paint_synth.py` 이번에 첨부. 합성 내부 확인 범위: 서버에서 ID마다 (LayerId, TypeId) 하나·점 ID 중복 0 검사, 404개 전부 합성(확률 1.0) 생성 실패 0, 정답 지도(면 97%·면 색 8종·배경색)를 1장 확인, 사용자가 앱에서 열어 레이어·그림자·머리 채우기 확인(그 과정에서 레이어·ID·글자 원·공중 그림자 문제를 고침). 렌더-앱 화소 대조는 레이어 수정 전 판(0.3%)만 있음.
- 8: 고침. 성공 판정을 원본 작업 성공 수(`ok_plain`)로, 완료 표시에 `ok_plain` 기록, `pc_vec_run`의 `done_ok`에 `synth=0.3` 대조 추가.

### C. 1차 해석 보충(네 지적: best·last를 같은 정밀도로 비교해야)
이미 해 둔 비교가 있어: 1차 결과 분석 때 **best(75%)와 last(100%)를 둘 다 서버 CPU fp32로** 같은 시험 장면(S2aqoie_pt 40장, sr 60장)에 돌렸고, last가 파란 인물 일부를 놓치고 선 색·그리는 순서 지도가 더 나빴어. 즉 추론 쪽 수치 문제가 아니라 **모델 자체가 나빠진 것**. 원인 후보는 학습 중 넘친 걸음(fp16 배율 감소로 건너뜀 → 실제 업데이트 감소)과 비유한 forward의 BN 통계 오염(네 5번)인데, 1차는 `skipped`를 안 셌으니 확정은 못 해. 2차 기록의 `skipped`·`val_bad`로 확인할 계획.
