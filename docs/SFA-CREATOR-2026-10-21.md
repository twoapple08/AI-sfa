# SFA 크리에이터(안드로이드) v0.1 — 2026-10-21

사용자 요청: "내가 직접 해보게 어플을 구성해봐. UI는 저번 SFA 뷰어처럼(화면 비율에 따른 편의성 모두 반영), 스틱파이터 비슷하게, 다크 테마."

프롬프트(태그)와 길이·FPS를 넣으면 **기기 안에서** 1v1 맨손 육탄전 애니메이션을 만들어 5초 단위 SFA 파일로 저장하는 앱이다. 서버나 네트워크를 쓰지 않는다. 최종 목표(AGENTS.md '최종 목표')의 첫 시험판이다.

## 지금 되는 것과 안 되는 것

| 항목 | 상태 |
|---|---|
| 입력 | 태그(NAI식 쉼표 구분). 지원 태그는 `1v1`(맨손 둘, 도구·배경 없음)뿐이다. 다른 태그는 무시하고 알려 준다. 자연어·스토리보드 탭은 '준비 중' |
| 설정 | 총 길이 1–120초, FPS (트위닝, 재생) 1–120, 배경(흰색/검정), 시드(같은 값이면 같은 결과, 주사위로 새 값) |

| 미리보기 | SFA 뷰어 1.0의 플레이어(미리 그리기 캐시, (T,P) 보간 규칙, 이동 막대, 앞뒤 프레임, MP4 내보내기 → 동영상/SfaCreator) |
| 결과 화면에서 FPS 변경 | 같은 시드로 다시 만든다. 싸움 내용(기준 24fps 안무)은 같고 프레임만 다시 고른다 |
| 화면 배치 | 뷰어와 같은 창 크기 기준 배치. 세로·가로·멀티윈도우(화면 반)·팝업·펼친 폴드. 넓은 창(폭 600dp 이상)은 왼쪽 입력/오른쪽 최근 생성 두 칸. 시스템 바·키보드 높이만큼 여백 |

## 생성 방식 (v0.1)

학습 모델이 아니라 **학습 자료 + 규칙 안무기**다. 모델 학습은 이 결과를 보고 다음 단계에서 정한다.

1. **학습 자료(`tools/motion_lib.py` → `app/src/main/assets/motion_lib.txt`)**
   - nian41 포즈 48개(YOLO11m-pose)에서 온몸이 잡힌 연속 구간 214개(5,266프레임)를 리그 A 각도로 바꿨다.
   - 그중 손이 앞으로 크게 뻗는 순간 285개를 찾고, 자세 조건을 통과한 **펀치 타격 자세 53개**를 골랐다. 조건은 서 있는 몸통, 아래를 향한 다리, 펴진 팔, 반대팔이 앞으로 뻗지 않음(T자 제외)이다.
   - 나카무라 포즈 186개에서 **타이밍**만 뽑았다(24fps 프레임, 중앙값·75%). 타격 전 멈춤 1·1, 타격 5·10, 타격 뒤 멈춤 0·1, 타격 간격 7·11, 정지 프레임 비율 0.374(nian41 0.178).
   - 사용자 규칙(nian41 = 몸 구조, 나카무라 = 타이밍)을 따랐다.
2. **안무(`gen/Choreo.kt`)**: 거리 재기(들썩임·걸음, 2프레임에 한 장) → 공격 1–3연타 → 반응.
   - 공격 동작
     - 펀치: 학습 자세. 준비 자세는 학습 자료의 준비 프레임이 흔들려서, 타격 자세에서 팔을 당겨 만든다.
     - 발차기: 규칙 자세 2종. nian41 발차기 조각 9개는 대부분 넘어짐·구르기라 쓰지 않았다.
   - 타이밍: 준비 3–5프레임 → 멈춤(나카무라) → 1–2프레임 타격 → 세기별 멈춤 → 연타 간격(나카무라 7–11).
   - 반응: 맞음(머리/몸), 막음, 피함(숙이기/젖히기), 결정타(날아감 → 쓰러짐 → 일어남). 모두 규칙 자세다.
   - 두 캐릭터는 서로 지나치지 않는다. 화면 밖으로 밀려나지 않게 x를 ±10.5로 제한한다.
3. **장면·이펙트(`gen/Scene.kt`)**: 사용자가 정한 세기 단계를 따른다.
   - 가벼움: 스미어(2차 곡선 3겹) + 속도선
   - 중간: + 타격 섬광(사방 선, 주황 글로우) + 먼지
   - 결정타: + 임팩트 프레임 2장(검은 바탕 흰 그림 → 흰 바탕 검은 그림, 집중선) + 충격파 고리(같은 AO ID로 커짐) + 화면 흔들림
   - 막음: 작은 파란 섬광. 빗나감: 스미어·속도선만.
4. **SFA 쓰기(`gen/Generator.kt`)**
   - 원래 앱 내보내기와 같은 요소·속성을 쓴다: Sequence/Frame/LayerDef/AO/AP/AC.
   - 캐릭터 AO ID는 프레임마다 같아서 Stick Fighter 트위닝이 이어진다.
   - 관절은 AC로 양쪽 연결한다. 캐릭터 하나는 13개 오브젝트다: 머리 원, 목, 몸통, 팔 4, 다리 4, 발 2.
   - 리그 A 크기는 머리 지름 76px(1920×1080 기준)이고, 선 굵기는 앱 기본 ThicknessScale 1.0이다.

## 검증 [서버 실측]

- `GenTest`(JVM)는 길이·FPS별 프레임 수(초×재생 fps), 5초 분할 개수, SFA 쓰기를 확인한다. 조합은 (12초,24,24), (7초,24,12), (10초,30,15)이다.
- 만든 SFA 7개는 `sfa.py validate` 오류가 0개다.
- 서버 기준 렌더러(`tools/sfa_render.py`)로 12초 결과를 그려 흐름을 확인했다: 접근 → 준비 → 타격 섬광 → 결정타 흑백 → 충격파 → 날아감·쓰러짐 → 일어남.
- 화면 배치는 `UiShotTest`(Robolectric)로 다섯 창 크기의 첫 화면·결과 화면을 캡처해 확인했다.
- **아직 확인 안 함:**
  - 실제 휴대폰(Z Fold4, Android 16)에서의 설치·생성 속도·저장 위치
  - Stick Fighter 앱에서 생성 SFA 열기와 트위닝 결과
  - 키보드가 열릴 때의 배치

## 알려진 한계

- 학습 자료가 작다. 펀치 자세는 53개이고, 발차기·반응은 규칙 자세다. 그래서 동작 종류가 적고 반복이 보일 수 있다.
- nian41 포즈는 2D 추정이다. 팔다리 앞뒤(왼/오른)가 뒤바뀌는 프레임이 있어서 타격 순간 한 장만 쓴다.
- 이펙트는 세기 단계 규칙이다. 나카무라 이펙트 모양(연기·파편 형태)은 아직 학습하지 않았다.
- 한 프레임에만 나오는 이펙트(임팩트 프레임 등)는 트위닝 중간 장면에 그려지지 않는다. 원래 앱 규칙(짝 없는 오브젝트는 중간에 안 그림)과 같다.

## 재현

```
python tools/motion_lib.py --nian <nian41 포즈 폴더> --nak <나카무라 포즈 폴더> --out motion_lib.json --asset creator-android/app/src/main/assets/motion_lib.txt
cd creator-android
echo "sdk.dir=<Android SDK>" > local.properties
gradle assembleRelease
SFA_OUT_DIR=<폴더> gradle testReleaseUnitTest --tests com.aisfa.creator.GenTest      # 생성 SFA 남기기
SFA_OUT_DIR=<폴더> gradle testReleaseUnitTest --tests com.aisfa.creator.UiShotTest   # 화면 캡처
python tools/sfa_render.py <생성.sfa> <출력 폴더> --size 480x270
```

포즈 원본(jsonl.gz)은 저장소에 넣지 않는다(Drive `AI-sfa/02_분석자료/포즈_claude/`). assets의 motion_lib.txt는 관절 각도 요약(자세 53개와 타이밍 통계)이다.
