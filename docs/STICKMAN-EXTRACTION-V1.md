2026-11-03 사용자 확인판을 기준으로 추출·장면 보완·저장 검사·재현 절차를 묶었다. 새 장면마다 뼈대 구조를 수정하지 않는다. 이펙트 가림과 접촉의 판독을 포함한 반자동 절차이며, 임의 영상의 팔다리·접촉을 모두 자동 판정하는 새 학습 모델은 아니다.

**60초 확장 실패 뒤:** 기본v1은 기존 결과 재현용으로 보존한다. 새 공통 처리/부분 구도/팔 길이 선택 시험은 [v2 보고](GPT-STICKMAN-GENERIC-V2-2026-11-03.md)를 따른다. 405장 미검출 종아리 복구는 사용자 긍정 확인을 받았으나,다른 구도의 자동 추출 전체가 완성된 것은 아니다. 고정 연결 구조와 달리 투영 길이·좌표·부위 가시성은 원본에 맞춰 바뀐다.

## 새 장면

원본 SHA·장 범위·컷·좌표계·인물 색·거리 굵기 기준을 먼저 정한다. 예시 영상의 좌표·굵기 기준을 다른 영상에 그대로 복사하지 않는다. 새 인물/여캐는 비율표와 관절 확인 그림부터 검토한다. 좌표는 원본 화소이고, 재생 번호1은 원본 `start`다.

```sh
# 1. 보정 전 투영본 보존. 실제 새 영상의 범위/컷/잘라낼 높이로 바꾼다.
python tools/stickman_clip.py /비공개/관측.jsonl.gz /비공개/원본.mp4 /비공개/투영본.sfa \
  --start 1032 --end 1271 --cuts 1136 1234 --crop-y 63 \
  --select coverage --side-rule valid --projection --image-keys \
  --thick-ref 40:blue:1.0 120:red:5.0 \
  --report /비공개/추출보고.json --joints /비공개/출력좌표.json

# 2. 원본 판독 후 장면 JSON을 적용. 이미 보정한 결과를 입력으로 다시 쓰지 않는다.
python tools/stickman_finalize.py /비공개/투영본.sfa /비공개/결과.sfa \
  --scene scenes/새장면.json --width 1152 --crop-y 63 \
  --expect-input-sha256 입력파일의_SHA256 --report /비공개/보정보고.json

# 3. 독립적인 저장 파일 검사. 오류가 있으면 종료코드1, 후보는 판독 대상으로 남긴다.
python tools/stickman_quality.py /비공개/결과.sfa \
  --scene scenes/새장면.json --width 1152 --crop-y 63 --report /비공개/검사.json
```

`--image-keys`는 새 장면 작업의 시작 설정으로 정착하되, 기존 옵션 없는 경로의 기본값을 몰래 바꾸지는 않는다. 임의 관측의 오검출까지 보장하지 않으며 같은 그림의 원관측 불일치가 있으면 판독·장면 보완이 필요하다. 현재 기준판은 저장한 보정 전 입력을 재사용해야 정확히 재현된다. 새로 피팅한 파일을 기존 전달본과 같다고 가정하지 않는다.

장면 필드·좌표계·접촉·feather의 상세는 `docs/STICKMAN-SCENE-CONFIG.md`를 따른다. 기본 feather2는 이벤트 바깥 한 장에0.5로 적용되고 컷을 넘지 않는다. feather1은 구간 밖에 적용되지 않는다. 이벤트를 같은 컷에 두며 빠른 차기를 감속/삭제하기 위해 보간하지 않는다.

## 검사의 의미

실제 저장 SFA에서 장 수·재생 위치·고정11객체·ID·형식·Flags·AC/좌표 일치·인물별 단일 연결망·흰 머리·머리 접합·부분 가시성·확정 접촉 잔차를 검사한다. 좌표는 틀 밖이어도 허용한다. 출력은 다음으로 나눈다.

- `errors`: 파일 구조/명시한 접촉·가시성 규칙 위반. 종료코드로 차단한다.
- `review_candidates`: 컷·부분 인물·결측 경계를 빼고 몸통 길이 대비 상대 가속도가 큰 순위. 속도 상한이나 품질 합격선이 아니다.
- `overlap_candidates`: 화면 안 양쪽 무릎/발목 또는 팔꿈치/손목이 몸통 길이5% 미만으로 가까우며 끝점까지 길이는25%보다 긴 사슬. 중복 검출 수색용 휴리스틱이다. 정상 겹침도 포함할 수 있고 모든 오검출을 찾지는 못한다. 후보 전후·같은 그림까지 확대 검토한다.

검사 도구는 포즈를 수정하지 않는다. 점수 높은 중복 검출, 화면 밖 추정, 원본의 빠른 움직임을 구별하려면 원관측·뺀 점·출력과 원본을 대조해야 한다. 접촉 잔차가0이어도 원본의 회피를 접촉으로 해석했다면 잘못된 결과다.

## 이후 변경과 인수인계

재사용 스킬은 `.claude/skills/stickman-extraction/SKILL.md`다. 사용자가 승인한 현재 결과를 기준으로 비교하고, 작은 미확정 잔차를 모두 해결했다고 주장하지 않는다. 남은 한계는 최종 검토 보고서에 장 번호로 보존했다.

구조를 바꾸지 않는 장면 보완에는 프로필 버전 갱신이 필요 없다. 실제 공통 구조 결함은 근거·버전·기존 장면 회귀와 함께 수정한다. 커밋 전 전체 시험 OK·종료코드0을 따로 확인하고, 지정 브랜치 fetch 후 커밋/푸시한다. HANDOFF·GPT 전담 로그에 결과와 구현 SHA를 남긴다. 결과물은 Drive, 도구·스킬·소량 통계는 저장소다.

## 가까운 팔다리의 선택 면 표시층

사용자가 부위별 선 굵기의 이음 경계를 지적해 가까운 다리는 같은 스틱맨 모양의 연속 면으로 시험했다. `docs/GPT-STICKMAN-LIMB-SURFACE-TRIAL-2026-11-03.md`와 `scenes/nian41_1032-1271_limb_surface_trial.json`을 따른다. `stickman_limb_surface.py`는 고정 뼈대 위에 선택 표시층을 추가하며, 기본11객체를 최종 전체 객체 수라고 부르지 않는다. 현재는 거의 직선인 두 마디 사슬만 지원한다. 품질 검사는 `stickman_quality.py --surface 설정.json`으로 면 포함 연결망과 표시층을 벗긴 기존 뼈대를 함께 검사한다. 원본 깊이 자동 인식/앱 편집 추종까지 검증된 것으로 세지 않는다.
