# GPT 조사 — SFA 구조와 그림·움직임의 단어체계(2026-11-06)

사용자 요청: SFA 구조와 관련된 시스템도 조사. 추가 명시: **“스파가 애니메이션을 그리는 방식인 단어체계도 포함이야.”**

**저장 형식, 실제 그리기/편집 의미, AI의 학습 어휘를 함께 검토했다.** 구조적으로 특히 가까운 것은 OpenToonz의 2차 획/채움 구간, Synfig의 공유 매개변수, VPaint의 시간별 위상이다. 학습 어휘에는 DeepSVG의 계층과 StrokeNUWA의 획 압축이 참고가 된다. 어느 하나를 통째로 SFA와 같다고 보거나, 정지 SVG 생성 성과를 액션 생성 성과로 확대하지 않는다.

15개 형식·시스템·모델의 공식 출처를 [목록 JSON](../data/research/sfa_structure_sources_2026-11-06.json)에 보존했다. 선택 구현 파일/README16개의 지문도 있다. 외부 편집기·모델을 실행한 결과는 아니며, 이번에 실행한 것은 **합성 곡선6개와 합성 XML의 CPU 비교**다. 사용자 원본·보호 파일·기본 생성 경로·어휘 모듈은 바꾸지 않았다.

## 1. ‘단어체계’의 세 층을 구분

|층|예|다루는 것|
|---|---|---|
|저장 요소|`AO`, `AP`, `AC`, `FR`, `FS`, `LayerDef`|앱이 파일을 읽고 참조하는 구조|
|그리기·편집 의미|곡선을 긋기, 점을 연결하기, 경계 구간으로 칠하기, 점 역할에 맞게 꺾기, 묶음 글로우 합성|그 요소들이 실제로 어떻게 그려지고 편집되는지|
|AI가 다룰 표현|획/모양 묶음, 경계 참조, 부위와 편집 역할, 시간별 자세, 타격 사건|그림과 동작을 배우기 위해 선택하는 단위|

현재 `tools/sfa_tokens.py`의 `LINE/CIRC/CURVE/LINK/FILL/SEG/WHOLE/GLOW` 등은 **우리가 만든 한 장 변환용 어휘**다. 앱 자체가 이 토큰열로 파일을 저장하는 것은 아니다. `tools/motion_tokens.py`는 또 별도의 **몸동작용 어휘**이며, 둘의 목적과 정보 손실도 다르다.

이미 의미 단위를 전혀 사용하지 않는 상태는 아니다. 기존 어휘는 도형 종류·스타일 재사용·상대 연결·채움 구간을 표현한다. 이제 필요한 검토는 “이 단위로 그림뿐 아니라 편집 역할과 시간에 따른 동작까지 충분히 담기는가”다.

## 2. 실제 SFA의 그리기 의미와 대응 단위

기존 근거를 재사용했다. [FORMAT 후반 기록](FORMAT.md), AGENTS.md의 최신 규칙, `sfa_tokens.py`, `motion_ir.py`, `char_sheet.py`, `sfa_render.py`, 기존 앱 시험 기록을 대조했다. FORMAT 앞부분의 초기 ‘미확인’을 최신 상태로 다시 세지 않았다. 새로운 APK 분석·앱 실행·기존 영상 재분석은 하지 않았다.

|SFA의 요소/동작|그림·편집에서의 의미|어휘 설계에서 보존할 것|
|---|---|---|
|`AP` 좌표·`Index`|도형 안의 끝점/제어점|순서, 좌표계·화면비, 화면 밖 값|
|`AO TypeId=1/2/3`|직선/원/2차 곡선|타입별 매개변수와 편집 방식. 원을 전부 일반 경로로 바꾸면 머리 원 편집 의미는 달라질 수 있음|
|`AC`|같은 장의 점을 참조하는 연결|어느 점과 연결됐는지. **모든 연결을 회전 관절이나 좌표 동일화로 해석하지 않음**|
|`Flags`|기준점·관절점 등 편집 역할|연결 존재와 별개의 역할. 관절점 판별은 현행 `(Flags & 0x2f) == 0x21` 규칙과 기존 근거를 따름|
|`FR` + `FS`|선/곡선/원의 경계 구간을 따라 만드는 채움|오브젝트 참조·구간 방향·`StartT/EndT`·윤곽 구분. 단순 색 다각형으로 대체하면 편집 종속성이 사라짐|
|`FS Kind=1` 원 전체|머리 원 같은 전체 채움|원 전체와 구간 채움의 종류를 구분. 서버가 임의 보완한 그림을 앱 호환 증거로 쓰지 않음|
|색·알파·굵기·글로우|선과 면의 외형, 번짐|면의 알파와 선의 알파, 선 굵기와 글로우 폭/반경을 별도 유지|
|연결 묶음의 합성|묶음 안 글로우들을 먼저 그리고 본체들을 그림|획 순서뿐 아니라 묶음 관계가 렌더에도 영향을 줌. 연결을 버려 같은 그림이라고 가정하지 않음|
|AO 나열/`DrawOrder`|앱 로드 시 최초 등장 순서가 공통 객체 순서에 영향을 줌|단어열·파일 순서와 논리적 앞뒤가 충돌하지 않게 컴파일. DrawOrder 숫자만 바꾸면 순서가 바뀐다고 가정하지 않음|
|레이어 순서/투명도|앞뒤·그룹 합성|레이어 순서는 장 전체에 공통. 레이어 알파와 각 객체 알파의 일괄 곱은 겹침에서 다른 결과일 수 있음|
|장간 `AO` 식별|같은 대상의 시간 변화|같은 대상은 같은 논리적 객체로 유지. 동일 ID의 레이어·타입을 장마다 바꾸지 않음|
|장별 `AP` ID|그 장의 실제 편집 점|최종 저장에서는 장마다 새 점 ID. 같은 점 ID 재사용을 ‘시간 일관성’이라고 하지 않음|
|모양·시트·방향|같은 인물/부품을 자세와 방향에 맞게 표시|캐릭터 정체성과 동작을 구분. 대응하는 모양이 어떤 것인지 명시|
|그림 유지·키·시간|자세와 타격/멈춤의 시간 관계|최종 (24,24). 내부 키·명령 표현과 앱 트위닝 사용은 별개|

SFA의 채움은 특히 중요하다. 앱 확인 기록상 AC 없이 교차한 선으로도 칠할 수 있고, 선을 벌리면 경계 구간과 그 사이 연결선을 따라 면이 변한다. 그러므로 **점 연결 그래프만 가지고 모든 면을 복구**하거나 **같은 위치의 끝점을 모두 하나로 합치는 것**은 충분하지 않다.

## 3. 기존 단어체계의 실제 보존 범위 — 작은 반례

현재 한 장 변환용 `sfa_tokens.py`는 의도적으로 Flags를 버리고, 복원 시 기본 점 역할을 다시 만든다. ID·숨긴 층·일부 화면 밖 형상의 처리도 렌더 변환 목적에 맞춰져 있다. 이 형식을 완전한 편집 가능한 SFA 언어로 그대로 승격시키면 빠지는 정보가 있다.

합성 예제를 직접 왕복했다. 두 직선·점4개·연결2개 중 점 하나에 관절 역할 `Flags=33`을 지정했다.

|항목|입력|현재 어휘로 왕복 후|
|---|---:|---:|
|오브젝트|2|2|
|점|4|4|
|좌표의 집합|기준|동일|
|AC 개수|2|2|
|관절 역할 표시|1|**0**|

이것은 **저장/어휘 수준의 반례**이며 새 앱 편집 시험은 아니다. 좌표와 연결의 개수가 같아도 편집 의미가 완전히 보존됐다고 할 수 없다는 증거다. 전체 그래프의 의미적 동등성을 이 작은 검사로 증명한 것도 아니다.

현재 스틱맨 생성은 별도의 `motion_ir.compile_ir`·고정 편집망 경로를 사용한다. 위 결과를 현재 compose의 모든 스틱맨에서 역할이 사라진다는 결론으로 확대하지 않는다. 한 장 변환기의 의도된 범위를 새 결함으로 부르지도 않는다. **통합 학습 언어를 설계할 때 정보 손실을 분리해야 한다**는 결론이다.

## 4. 구조적으로 가까운 외부 시스템

|후보|확인한 구조|가져올 부분|SFA와 다른 점|
|---|---|---|---|
|**OpenToonz**|`TStroke`가 `TThickQuadratic` 조각 사용. `TEdge`에 획 참조와 `m_w0/m_w1` 구간|획·영역·채움 경계를 함께 관리하는 구조|획마다 가변 굵기와 여러 조각. SFA 한 AO/굵기/FS 매개변수와 별도 대응 필요|
|**Synfig**|선과 면이 같은 Spline/ValueNode를 공유하도록 연결 가능|선·밑색이 같은 형상 정의를 참조하는 방식|ValueNode 연결이 SFA AC와 같은 편집 동작을 의미하지 않음|
|**VPaint / VAC**|그림의 선·면이 시간에 따라 합침·분할·출현·소멸하는 위상 표현|이펙트·파편·스미어의 대상 생성/소멸과 대응|모든 장을 같은 경로 구조로 억지 보간하지 않아도 되는 설계 근거. 자동 액션 생성기는 아님|
|**Rive**|부품의 계층 변환과 벡터의 가중 변형, 속성/실행 형식|캐릭터 정의·포즈·변형을 구분하고 재사용|`.riv` 실행 자산은 SFA 편집 파일이 아님. SFA에는 매 장의 결과를 펼쳐야 함|
|**SVG 2**|직선·2차/3차 경로·채움·필터 표준|외부 벡터 도구/모델과 연결하는 제한된 교환 형식|AC·Flags·경계 참조·묶음 글로우를 자체적으로 보장하지 않음|
|**Lottie**|도형 묶음·레이어·속성별 키와 시간|그림 정의와 시간별 값의 분리|아이콘/모션그래픽 표현이 액션 작화·SFA 편집망의 정답은 아님|
|**OpenUSD**|대상 정의·참조·계층·시간별 속성|일관된 대상 식별과 장면 중간 표현의 설계|USD의 layer는 합성 의견의 층이며 SFA 화면 레이어와 같은 개념이 아님. 전체 도입은 무거울 수 있음|
|**OpenTimelineIO**|컷·클립·시간 구간·외부 미디어 참조|정확한 장면 시간표와 이어 만들기|도형·관절·채움 언어는 아님|
|**fontTools**|3차를 허용 오차의 2차 spline으로 변환, 여러 변형의 조각 수 통일|외부 곡선을 SFA의 2차 조각으로 옮기는 부품|암시적 끝점 해석·FR 구간·점 역할은 별도. 조각 수 통일만으로 의미적 대응은 생기지 않음|
|**Skia PathOps**|윤곽의 교차·합집합 등 경로 연산|선/면 경계 계산과 기하 검사|결과 윤곽만 남기면 원래 선·면 참조 관계를 잃을 수 있음|

## 5. ‘무슨 단위로 그림을 배우는가’에 가까운 모델

|후보|표현의 단위와 확인 범위|우리 단어체계에 주는 교훈|한계|
|---|---|---|---|
|**DeepSVG**|상위 모양과 하위 경로 명령을 구분하는 계층. 공식 코드/사전학습 예 제공|인물·이펙트 묶음과 개별 획의 기하를 다른 층으로 다루는 후보|아이콘 생성/잠재 보간의 성과. 액션 타이밍·AC·Flags·FS 학습 성공 아님|
|**StrokeNUWA**|SVG를 행렬로 바꾸고 VQ-Stroke로 압축한 획 단위 표현. 공식 학습 코드 확인|좌표 숫자 하나보다 큰 학습 단위 후보|재구성 손실·희귀 획·채움 참조·편집 역할 보존 확인 필요. 새 코드북 학습 부담|
|**OmniSVG**|사전학습 VLM에 SVG 명령/좌표를 매개변수화한 어휘. 공식 추론/가중치 링크 확인|그림 이해와 구조·기하를 연결하는 이미 학습된 출발점 후보|정지 SVG가 출력. SFA 전용 관계·시간·스타일 적응은 별도|
|**StarVector**|그림/글을 SVG 코드로 생성. 공식 코드/가중치 링크 확인|일반 경로뿐 아니라 도형 의미와 코드 구성을 활용하는 후보|SVG 코드의 정합성과 SFA의 편집 의미는 다름|
|**SketchRNN**|펜의 상대 이동과 획 종료/그림 종료 상태|그림을 ‘펜이 하는 일’로 표현할 수 있다는 사례|선 스케치 중심. 면·글로우·관절·장간 식별은 별도이며 액션 주력 추천은 아님|

근거: [DeepSVG 논문](https://papers.neurips.cc/paper_files/paper/2020/hash/bcf9d6bd14a2095866ce8c950b702341-Abstract.html), [코드](https://github.com/alexandre01/deepsvg); [StrokeNUWA 논문](https://proceedings.mlr.press/v235/tang24h.html), [코드](https://github.com/ProjectNUWA/StrokeNUWA); [OmniSVG](https://github.com/OmniSVG/OmniSVG); [StarVector](https://github.com/joanrod/star-vector); [SketchRNN](https://research.google/pubs/a-neural-representation-of-sketch-drawings/).

공통 교훈은 모델 이름이나 큰 어휘 수가 아니라 **도형의 구조·획의 기하·표현 속성·시간 관계를 적절한 단위로 나누는 것**이다. `CURVE`라는 이름을 붙였다는 사실만으로 곡선의 형태를 배웠다고 할 수 없고, 여러 숫자를 한 단어로 합친다고 학습 문제가 자동 해결되지는 않는다.

외부 SVG 어휘를 그대로 쓸 때는 SFA의 추가 의미를 보존할 자리가 필요하다. 외형을 배우는 잠재 표현과, 반드시 보존할 연결/편집 역할/대상 식별은 구분하는 편이 유력하다. 이 주장은 제안이며 새 모델을 학습해 검증하지 않았다.

## 6. CPU로 확인한 실제 곡선 연결 부품

기존 `tools/potrace_lines.py:cubic_to_quads`는 3차 곡선을 항상 2개의 2차로 근사한다. fontTools는 허용 오차를 주고 필요한 조각 수로 근사한다. **이미 3차→2차 변환은 구현되어 있으므로 새 발견으로 세지 않는다.** 비교한 것은 오차를 관리하는 방식이다.

합성 곡선6개, fontTools **4.61.1**, 허용값 **0.1**. 좌표 단위는 합성 도형의 단위이며 앱 픽셀/화면 백분율이 아니다. 각 조각에 같은 길이의 원래 `t` 구간을 대응시켜 4,001개 위치에서 비교했다. 실제 외곽선 픽셀 오차나 전 구간의 독립 증명은 아니다.

|합성 예|기존 고정 2조각의 표본 최대 오차|적응 변환의 조각 수|적응 변환의 표본 최대 오차|
|---|---:|---:|---:|
|아치|1.20281240|9|0.07357706|
|S 모양|5.41298989|14|0.09059556|
|고리형|4.57068711|13|0.09517255|
|거의 직선|0.12557730|4|0.07675378|
|원래 2차를 차수 올린 것|0|1|0|
|한 점으로 퇴화|0|1|0|

끝점·조각 사이 연결, 위 표본 오차가 허용값 이하인 것을 검사했다. 단순한 것은 조각이 줄고 복잡한 것은 늘었다. 같은 모양의 변형들을 공동 변환할 때에는 개별 **9/13조각**을 **13/13조각**으로 맞출 수 있었다.

이 기능은 장마다 다른 곡선 수 때문에 대응이 바뀌는 일을 줄일 수 있다. 그러나 어떤 곡선끼리 같은 부위인지 알려주거나, 바뀐 곡선에 FR의 구간 참조를 자동 매핑하지는 않는다. 곡선 방향·원본 구간과 대응을 함께 기록해야 한다. 라이브러리의 실패 예외와 내부 조각 수 한계도 처리해야 하며 이를 사용자 품질 상한으로 삼지 않는다.

재현: `python tools/sfa_structure_probe.py --out data/research/sfa_structure_probe_2026-11-06.json`.

결과: [합성 CPU 프로브 JSON](../data/research/sfa_structure_probe_2026-11-06.json). 기본 변환기를 교체하지 않았다. 조각 수·파일 크기·실제 원본의 시각 품질을 함께 비교하기 전에는 기본값 채택으로 세지 않는다.

## 7. 제안하는 SFA 학습 언어의 구성 — 미채택 초안

실제 저장 요소와 AI 표현을 억지로 일대일로 묶지 않고 다음을 구분하는 구성이 유력하다.

1. **대상·부위·모양 정의:** 인물, 몸 부위, 부품, 이펙트의 논리적 대상. 현재 프로필·시트·형태 사전 재사용.
2. **구조 문법:** 도형 타입, 끝점/제어점, 연결 참조, 편집 역할, 채움의 경계 구간. 관계와 역할을 생략하지 않음.
3. **기하·외형 값:** 좌표·곡률·색·알파·굵기·글로우·표시 폭. 연속값/분해 좌표/학습된 획 표현을 재구성 시험으로 선택.
4. **시간·변화:** 어느 그림을 얼마나 유지하고 어떻게 바꾸는지, 중요한 자세·사건, 방향, 대상의 출현/소멸. 최종24장/초로 펼침.
5. **결정적 저장:** 실제 ID 배정·FS 참조·레이어·장별 새 점 ID는 컴파일러가 처리. 모델에게 임의의 파일 식별 번호를 외우게 하지 않음.

이를테면 아래는 이해를 돕는 **의미 표현 예시**다. 실제 SFA 명령이나 구현된 새 문법이 아니다.

```text
대상: 인물 A, 오른팔, 타격 이펙트 E
구조: 오른팔은 기존 편집망 / E는 곡선 획 묶음과 경계 구간 채움
외형: 테두리, 밑색, 반투명 명암, 글로우를 구분
시간: 예비 자세 → 최대 뻗기·타격 → 마무리
관계: 타격 순간 E의 기준 위치를 오른손목에 연결
저장: 각 장의 실제 점과 객체·채움 참조를 컴파일러가 배정
```

그리기 과정인 **선 → 경계로 연결된 밑색 → 반투명 명암/글로우 → 시간 변화**를 표현하되 실제 렌더 순서는 레이어/연결 묶음 규칙을 따른다. 단어열의 작성 순서와 모든 화면 합성 순서가 같다고 가정하지 않는다.

신체 쪽은 기존 편집망과 몸동작 관절열을 재사용하고, 이펙트 쪽은 새 모양의 생성·분할·소멸을 허용한다. 둘을 동일한 고정 경로 하나로 만들지 않는다. 현재 모델/코드/정본 조건을 바꾸는 결정은 아직 없다.

## 8. 채택 전에 필요한 검사

- **그림 보존:** 도형·면·원 구간·구멍·반투명·글로우가 같은가. 다른 t 매개변수나 곡선 조각 수가 채움을 바꾸지 않는가.
- **편집 보존:** 점 역할·연결 대상·그룹·레이어·색 조정이 같은 의미를 가지는가. 관절과 연결을 혼동하지 않는가.
- **시간 보존:** 같은 대상의 AO가 이어지고 장별 AP는 새로 쓰는가. 키 보간이 타격·유지·스미어를 지우지 않는가.
- **형식 범위:** 숨긴 층·미지 속성·원본 편집 메타데이터의 보존 여부를 명시하는가. 보이는 그림만의 변환과 완전 왕복을 구분하는가.
- **학습 검증:** 문자열/토큰 정확도 외에 실제 그림 입력을 바꿨을 때 결과가 바뀌는가. 새 출처의 편집 가능한 결과가 나오는가.
- **실제 앱:** 서버의 수치/렌더 검사를 앱 열기·편집·재저장 시험으로 확대하지 않는가.

추천 순서는 **보존할 의미를 정리 → 기존 어휘로 표현 왕복 → 계층/획 표현 후보 비교 → 작은 학습 → 앱 비교**다. 큰 SVG 모델을 먼저 학습해 출력만 SFA로 바꾸는 방식은 편집 의미가 빠지는지 먼저 확인해야 한다.

현재 구조와 단어체계에서 가장 중요한 결론은 **‘보이는 모양’, ‘편집할 수 있는 관계’, ‘시간에 따른 같은 대상’이 각각 보존되어야 한다**는 점이다. SFA와 관련된 외부 시스템을 고를 때도 이 세 가지 중 무엇을 담당하는지로 비교해야 한다.
