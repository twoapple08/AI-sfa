# 영상 → SFA 재설계 — 2026-10-30

사용자 지시(10-30): "스파파일을 정답지로 보고 스파를 직접 해보게끔 할려했는데 … 설계를 다시해."
이전 설계: [VIDEO-TO-SFA-2026-10-29](VIDEO-TO-SFA-2026-10-29.md)(픽셀 지도 방식, 이 문서로 대체).

## 1. 이전 설계가 틀린 이유
- 정답이 **화면에 보이는 선 픽셀 지도**였다(`vec_data.py`: `vis = buf == i`).
- 그 결과 SFA 정보 대부분이 정답에서 빠졌다.
  - 가려진 부분이 지워졌다. 그래서 레이어에 가려 끊긴 선이 실제로는 한 오브젝트로 이어진다는 걸 배울 수 없었다.
  - 어떤 픽셀들이 한 오브젝트인지, 어디가 연결(AC)됐는지, 어느 레이어인지, 어떤 순서로 그렸는지가 없었다.
- 조립 코드(`vec_assemble.py`)가 픽셀 지도에서 구조를 짐작해야 했다. 결과적으로 오브젝트가 사람 파일의 절반 수준이었고, 연결은 거의 없었다.
- 원인은 정답지 설계였다. 학습량 문제가 아니었다.

## 2. 새 설계 한 줄
사용자 표현(10-30): SFA 인코딩 영상을 보고 스틱파이터 도구로 따라 만들고, 만든 파일을 원본 파일과 비교 채점해 깎아내면, 나중엔 정답 SFA가 없는 영상도 SFA로 만들 수 있다.

**모델이 SFA 파일 내용을 직접 써 내려간다.** 정답 = 그 장의 SFA 오브젝트를 그리는 순서대로 적은 문장(토큰열)이고, 모델은 영상 한 장을 보고 그 문장을 한 토큰씩 만든다. 사진 → 문장 번역과 같은 구조(이미지 인코더 + 문장 디코더, 이미 검증된 Pix2Seq·벡터 그림 생성 계열)다.

## 3. 정답지(토큰열) — `tools/sfa_tokens.py`
그리는 순서 = 레이어 → 연결 묶음 → 오브젝트(렌더러·앱과 같다). **문장 순서가 곧 가림 관계**다. 뒤에 적힌 것이 앞의 것을 덮는다.

```
BOS BG a r g b
LAYER
LINE  COLOR a r g b THICK t [GLOW 반경 두께 알파 r g b]  x y PT  x y PT LINK d
CURVE SAME  x y PT  x y PT  x y PT
CIRC  SAME  x y PT  x y PT           (원 = 지름 양끝 두 점)
LAYER …
FILL a r g b  SEG o s e t0 t1  SEG …  CONTOUR  SEG …   (면: 오브젝트 o의 점 s→e, T 구간)
FILL a r g b  WHOLE o                                 (오브젝트 전체 채우기)
EOS
```
- **오브젝트 전체 모양**을 적는다. 가려진 부분도 같은 오브젝트로 이어진다.
- **연결**: `LINK d` = d개 앞의 점과 AC 연결(상대 거리, 스틱맨은 대개 1·2 — 10-30 변경). 위치 추정이 아니라 점을 가리키므로 위치가 다른 연결(실측 5%)도 정확하다.
- **스타일**: 앞 오브젝트와 같으면 `SAME` 한 토큰이다. 색 ARGB, 굵기(로그 칸, 오차 0.25%), 글로우(반경·두께 0.1 단위, 알파, 색)를 적는다.
- **수**: 수 토큰 8,192개를 공유한다.
  - 좌표는 0.025 단위다(−50~154.8). 0.05 단위는 렌더 차이가 1%라서 줄였다.
  - 범위를 넘는 수(화면 밖으로 뻗은 곡선 조절점, 4,096개 넘는 번호)는 `BIG` + 세 자리로 정확히 적는다.
  - 직선은 상자(−1000~1100) 안으로 정확히 자른다. 보이는 모양은 그대로다.
- **빼는 것**(모두 화면에 영향이 없거나 규칙으로 다시 만든다):
  - 숨긴 레이어
  - 안 보이고(색·글로우 알파 0) 면에도 안 쓰인 오브젝트
  - 화면에서 아주 먼 오브젝트
  - Flags(파란점 — 규칙으로 다시 만든다)
  - ID(파일 전체에서 새로 매겨 앱 규칙 'ID마다 레이어 하나'를 지킨다)
  - ObjectScale(렌더 영향 없음)
- 해독(`decode`)은 토큰열을 바로 앱이 여는 Frame XML로 바꾼다.

## 4. 모델 — 1판 구현(`tools/seq_train.py`, 10-30)
- **입력**: 파일 비율로 렌더 → H.264 압축(crf 23–35) → 640×360으로 늘이거나 줄인 장 하나 + 비율 값(6.0절). 메모리에는 JPEG 95로 보관(1.55만 장 333MB).
- **인코더**: ResNet34(ImageNet 사전학습) 1/8 특징(layer2, 128채널) + 1/16 특징(layer3)을 올려 더함 → 80×45 = 3,600칸, 폭 512, 행·열 위치 임베딩 + 비율 임베딩(log(비율/0.5625)을 선형으로).
- **디코더**: 트랜스포머 8층, 폭 512, 머리 8, norm-first, 이미지 특징에 교차 주의. 전체 약 5,160만 변수. 입력 토큰에 칸 종류(좌표·색·연결 등, 문법이 정함) 임베딩을 더한다.
- **출력**: 머리 하나(8,211 토큰 분류). 수 칸 중 좌표·T·굵기·글로우·색은 정확한 칸 50% + 이웃 ±2칸 분포 50%(0.1/0.25/0.3/0.25/0.1). 연결 `LINK d`와 면 오브젝트 참조는 **상대 거리 수**(1 = 바로 앞 점/마지막 오브젝트)로 분류한다 — 설계 초안의 포인터 머리 대신(LINK 거리 실측: 1 30%, 3 30%, 20 이상 10%). 포인터 머리는 결과를 보고 판단.
- **문법 강제 생성**(`sfa_tokens.grammar`): 상태 기계가 다음에 올 수 있는 토큰만 허용 → 출력은 항상 앱이 여는 SFA. 학습 데이터 22,371장 중 위반 0(빈 장·점 모자란 오브젝트 허용 후). KV 캐시 생성(전체 계산과 차이 1e-6).
- **학습**: AdamW 3e-4, 예열 500걸음 → 진행률(쓴 시간/계획 시간) 기준 코사인(끊어서 돌려도 계획대로). 묶음 = 길이 비슷한 장끼리, 가장 긴 장 길이 × 장 수 ≤ 12,288 토큰, 최대 16장. bf16(계산 능력 ≥ 8) 또는 fp16 + GradScaler. 메모리 부족 → ① 디코더 층별 체크포인팅(같은 장 CPU 10.6 → 2.45GB, 손실·기울기 같음) ② 토큰 한도 0.8배(한도보다 긴 장은 뺌). 검증 = 시험 파일 400장 손실·다음 토큰 맞힘(20분마다), 오브젝트 채점은 `draw`에서.
- **늘리기는 1판에 아직 없다**(압축 세기만 파일마다 다름). 6절은 계획.

## 5. 단계
1. **한 장 → 한 장의 SFA**(먼저).
   - 길이 2,048 이하 장(90.5%)으로 시작하고, 잘 되면 4,096(97%)으로 늘린다.
   - 출력 파일은 장마다 새 ID다(앱에서 그대로 열린다). 사용자는 24,24로 만들기 때문에 트위닝이 필요 없다.
2. **장 사이 추적(스틱맨 움직임, 사용자 주 목적)**.
   - 앞 장의 문장을 앞에 붙인다. `KEEP j`(앞 장 j번째 오브젝트와 같은 것) 토큰을 추가해서 같은 오브젝트가 같은 ID를 유지하게 한다.
   - 이렇게 하면 관절 궤적을 그대로 뽑을 수 있고 앱에서 편집하기도 쉽다.
   - 정답은 SFA의 AO ID가 장 사이에 공통인 데서 바로 나온다.
3. **정답 없는 영상으로 깎아내기(최종 목표, 사용자 10-30)**: 채점은 **오브젝트 단위 대입**이다(사용자 10-30: "스파는 픽셀로 보는 게 아니라 오브젝트로 보는 거야, 대입하는 거야"). 화면 전체 픽셀 비율로 채점하지 않는다. AI가 놓은 오브젝트마다 영상 속 획에 값(점·굵기·색)을 대입해 그 오브젝트가 자기 획 위에 놓였는지, 획 중 어느 오브젝트도 덮지 않은 부분(놓친 획)이 있는지를 오브젝트별로 센다. 1·2단계에서 원본 파일과 오브젝트 짝짓기 채점으로 SFA 짜는 법(연결·레이어·순서)을 먼저 배운 뒤 한다. 구조 점수(사람 파일 통계: 연결된 끝 비율 등)도 같이 본다. 세부 방식은 1단계 결과를 본 뒤 정한다.
4. **긴 장(> 4,096)**: 레이어·영역별로 나눠 이어 쓰기. 나중에 한다.

## 6. 늘리기(계획 — 1판 미구현, 정답과 그림이 정확히 같이 변한다)
SFA를 먼저 바꾸고 렌더하므로 정답이 늘 정확하다.
- 이동·확대·좌우 뒤집기(좌표 변환)
- 색 바꾸기
- 배경색
- 페인트 합성(`sfa_paint_synth.py`) — **10-31 넣음**: 사용자 10-29 결정(흰 바탕이 너무 많음). 학습 파일 30%를 골라 흰 바탕인 것만 합성판을 원본과 별도로 추가(`seq_data --synth 0.3`, 해상도 단계 자료끼리 같은 파일). 합성한 배경·면도 정답 문장에 들어간다
- 굵기 배율 — **10-31 넣음**(사용자: "굵기 조절도 다양한 기능을 고루 쓸 줄 알아야"): 늘린 사본마다 모든 오브젝트 ThicknessScale × 0.5–2(로그 고르게), 정답 굵기 칸도 같이. 글로우 폭은 굵기를 따른다. 자료 판 3
- 압축 세기

같은 장도 매번 다른 그림이 되므로 22,371장 × 무한 변형이다.

## 6.0 화면 비율(사용자 10-30 "비율이 다른 파일도 따라 만들어?")
- 비율(HeightWidthRatio)은 파일의 일부 → 따라 만든다. 학습 파일 중 16:9(0.5625)는 78개뿐이고 0.45(54개, 8,915장)·0.4615(78개) 등이 더 많다. 세로 1.78·정사각 1.0도 1개씩.
- 앱은 **파일 비율 그대로** 영상을 내보낸다(오버드라이브 0.45 → 1920×864, 확인). 그래서 비율은 영상 크기에서 정확히 재고 AI가 추측하지 않는다.
- 테스트 학습(10-30 CPU)의 잘못: 모든 장을 16:9에 레터박스(남는 곳 배경색)로 렌더 → 화면 경계가 안 보여 같은 그림이 비율마다 다른 좌표가 됨(정답 모호).
- 고침: 파일 비율로 렌더·압축 → 모델 입력(640×360)으로 늘이거나 줄임. SFA 좌표는 가로·세로 각각 0–100이라 그림 위치 ↔ 좌표가 비율과 무관하게 맞는다. 비율은 log(비율/0.5625)를 이미지 특징에 더해 따로 알려 준다(늘인 그림에서 원이 타원으로 보이는 정도). 만든 파일의 비율 = 영상 크기에서 잰 값.

## 6.1 그리는 방식 원칙(사용자 10-30)
- **스파로 그린다**: 출력은 처음부터 SFA 오브젝트뿐(일반 그림 도구로 픽셀을 그린 뒤 옮기지 않는다).
- **둥근 곳은 곡선 오브젝트로**: 실제 유저 트레이싱 장면(총 장비, 참고 그림 위에 선만 먼저 따는 중)에서 둥근 곳을 짧은 직선으로 꺾은 건 그 사람 습관일 뿐. 우리는 둥글게 간다.
- 면은 선 오브젝트를 가리켜 만든다(정답 문장에서 면은 끝에). **면 칠 순서는 중요하지 않다**(사용자 10-30) → 정답에서는 주인 오브젝트 순으로 정렬해 고정(렌더 그대로), 채점에서 면 순서는 보지 않는다.
- 그 트레이싱 장면은 **참고용일 뿐 학습 자료가 아니다**(사용자 10-30). 파일·그림을 요청하거나 학습에 넣지 않는다.

## 6.2 해상도 단계 1080 → 720 → 480 → 360(사용자 10-29 지시, 재설계 때 빠졌다가 10-31 복원)
- 목적(사용자 10-31): 이 단계가 끝나면 모아 둔 애니 자료를 SFA로 바꾸는데, 그 자료는 화질이 360까지 떨어진다. 깨끗한 1080에서 먼저 배우고 화소를 점점 낮춰, 나쁜 화질도 깔끔하게 옮기는 실력을 만든다.
- 학습 시간 비율은 1080 20% → 720 25% → 480 25% → 360 30%(10-29 픽셀 지도 방식과 같음). 단계마다 앞 단계 자료를 30% 섞는다.
  - 단계는 전체 계획(`--plan-minutes`) 기준이다. 이어하기로 계획이 늘어 진행률이 줄어도 지난 단계로 되돌아가지 않는다.
- 그림 칸 고정: 1080·720·480 입력도 그 해상도로 끝까지 읽는다. 마지막 특징만 360 입력과 같은 45×80칸으로 모은다(`cfg grid`).
  - 글자 쪽 메모리는 해상도와 상관없다.
  - 같은 칸 = 같은 화면 위치다. 단계가 바뀌어도 위치 칸의 뜻이 그대로다.
- 한 묶음의 그림 수는 화소 예산(`--px-budget` 800만)으로 정한다. 1080은 3장, 720은 8장, 480·360은 16장이다.
  - 메모리가 부족하면 체크포인팅 다음으로 이 예산을 줄인다.
- 고해상도 자료는 그림을 풀지 않고 H.264 mp4 그대로 저장한다(`seq_data --video`, 1080 전체 약 0.2GB). 학습이 읽을 때 여러 프로세스로 푼다.
  - 360 자료는 이전과 바이트까지 같다.
- 시험·생성 채점은 항상 360 입력으로 한다. 최종 대상 화질의 실력을 보기 위해서다.
- 측정(서버 CPU, 그림 처리 1장 메모리 fp32): 360은 173MB, 1080은 1,681MB.
  - 실제 GPU 메모리와 속도는 PC 빠른 시험(첫 4분이 1080 단계)에서 처음 확인한다.
- 실행: Kaggle `push-data` / `push --prebuilt`, PC `pc_seq_*.bat` 모두 기본으로 켠다. 끄려면 `--no-stages`.
  - 단계 없이 시작한 학습은 이어하기에서도 단계 없이 계속된다.

## 7. 평가(시험용 38개 파일, `holdout_vec.txt`) — 오브젝트 단위(`tools/sfa_objscore.py`)
AI가 만든 장과 원본 장의 오브젝트를 하나씩 짝지어(헝가리안, 종류 + 점 평균 거리) **오브젝트마다 대입한 값**을 비교한다. 픽셀은 주 지표가 아니다(사용자 10-30).
제자리 오브젝트 비교가 주 지표. 구조 채점(이동·같은 비율로 맞춘 뒤)은 보조 — 10-30 사용자 영상을 '크기 무관'으로 잘못 읽고 만든 것이고, 사용자 뜻은 **'일반 그림 도구로 그리지 말고 스파(오브젝트)로 그려라'**(X: 그림 도구로 손으로 그은 선, O: 앱에서 선 오브젝트로 그린 선). 새 설계는 출력이 처음부터 SFA 오브젝트뿐이라 이 원칙을 따른다.
1. **오브젝트**: 맞음 = 같은 종류 + 점 평균 거리 1.0 단위 이하. 원본 중 맞힌 비율(놓친 것), AI 것 중 맞은 비율(지어낸 것).
2. **값**: 맞은 오브젝트의 점 오차, 색 일치, 굵기 일치.
3. **연결**: 짝지은 점끼리 연결 F1. 이전 방식이 가장 못한 항목.
4. **가림 순서**: 짝지은 오브젝트 중 겹치고 색이 다른 쌍(영상이 달라지는 쌍)만 앞뒤 일치 비율.

**만점의 뜻(사용자 10-30)**: 영상 봄 → 스파로 만듦 → 만든 파일을 원본 파일로 채점 → 만점이면 인코딩한 영상도 똑같다. 파일이 같으면 영상은 같지만 그 반대는 아니므로(연결 빠짐·곡선 대신 직선 여러 개도 겉보기는 같을 수 있음) 파일로 채점한다. 연결·오브젝트 구성은 원본 파일에 있으니 채점에 들어간다. **정정(사용자 10-31): 관절 연결은 만점에서 뺀다** — 24,24라 트위닝이 없어 한 장 그림에 영향이 없다(연결 F1은 참고 점수로 계속 기록). 오브젝트 구성(곡선 대신 직선 여럿 등)은 그대로 채점한다. 빼는 것은 영상이 달라지지 않는 차이뿐: ID·장 사이 ID 이어짐(24,24라 트위닝 없음)·면 칠 순서·파란점·점 방향·겹치지 않거나 같은 색인 오브젝트끼리 순서.
5. **문법**: 앱이 여는 파일 100%(문법 강제로 보장, 시험으로 확인).
6. **사용자 앱 확인**: 오버드라이브·S2aqoie 등 시험 장면.

결과는 그림(입력 | AI SFA | 원본 SFA)으로 먼저 보여 드리고 위 숫자를 붙인다.

## 8. 계산·시간
- 자료[서버]: 학습 403파일 → 15,544장(파일당 이어진 300장까지, 2,048 토큰 이하, 728MB), 시험 38파일 → 935장(파일당 40장).
- 서버 CPU 테스트 학습(10-30, 작은 모델 1,100만 변수·320폭·1/16·512 토큰 이하 4,676장·80분 5,484걸음, **비율 수정 전 16:9 레터박스 자료**): 시험 다음 토큰 맞힘 49%에서 정체(학습 64%). 생성 10장 모두 문법대로 끝까지, 연결된 스틱맨·영상 색은 따라감, 위치·자세는 못 따라감(오브젝트 맞음 0/105, 0/69). 시트: scratch `sq_cpu1/`.
- 실행 흐름[서버 CPU, 작은 모델로 대체]: `pc_seq_run.py` 빠른 시험(자료 → 4분 → 이어하기)·본 학습(자료 → 학습 → 저장·zip) 끝까지 통과. 자료 읽기 버그(npz를 장마다 다시 풂, 30분+) 고쳐 49초.
- GPU 메모리·속도는 미측정 → 1050 Ti 빠른 시험(`pc_seq_1050ti_quick.bat`)으로 잰 뒤 5060(`pc_seq_5060.bat`, Drive `seq/s1`)·4060(`pc_seq_4060.bat`, 양보 모드, Drive `seq/s1_4060`).
- 생성 속도: 장당 수백–수천 토큰(KV 캐시). 서버 생성(10-26 임시 결정 B).

## 8.1 원인 가르기(GPT 검토 5번, 10-30 서버) — 모델은 영상을 본다
비율 고친 새 자료 44장으로 작은 모델(800만 변수, 1/8 특징)을 22분 외우게 한 뒤 `tools/seq_diag.py`: 생성 맞힘 정상 31.1%(181/582) ↔ 다른 파일 장 0% ↔ 흰 화면 1.9%, 연결 F1 20.6% ↔ 0 ↔ 0. 교사 강제 좌표 맞힘은 섞음에서도 57%(앞 점 단서) → 영상 의존도는 생성 채점으로 본다. ~~결론: 구조는 영상에서 위치를 읽는다~~ → **정정(GPT 2차 C2 반론이 맞음)**: 같은 44장을 SFA에서 오른쪽 6%·아래 4% 옮긴 사본에서는 생성 맞힘 0%(섞음·흰 화면과 같음). 이 작은 모델은 장면을 알아보고 외운 자세를 꺼냈을 뿐 위치를 읽지 않았다. 44장·늘리기 없음이라 외우기가 가장 쉬운 길이었으므로, 늘린 사본 8벌(395장)로 다시 학습해 학습에 없던 이동에서 따라가는지 시험 중.

## 9. 위험과 대책
| 위험 | 대책 |
|---|---|
| 긴 문장에서 뒤로 갈수록 틀림이 쌓임 | 짧은 장부터(커리큘럼), 문법 강제, 2단계에서 앞 장 문장으로 안정화 |
| 좌표 정밀도(0.025 단위 = 1920폭에서 약 0.5픽셀) | 부드러운 정답, 필요하면 대강 칸 + 세밀 칸 두 토큰 |
| 자료 22,371장, 비슷한 장이 많음 | 6절 늘리기, 합성, 이전 인코더 가중치 |
| 화면 밖 오브젝트(7.7%)를 버림 → 2단계에서 화면 안으로 들어오는 오브젝트 | 2단계에서 앞 장 문장에 남긴다(장 사이 정보) |
| 같은 그림을 다른 오브젝트 조합으로 그릴 수 있음(정답이 하나가 아님) | 사람 파일 순서를 그대로 정답으로(지도 학습). 평가는 그림 + 구조 둘 다 |
