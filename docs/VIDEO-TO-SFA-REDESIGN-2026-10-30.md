# 영상 → SFA 재설계 — 2026-10-30

사용자 지시(10-30): "스파파일을 정답지로 보고 스파를 직접 해보게끔 할려했는데 … 설계를 다시해."
이전 설계: [VIDEO-TO-SFA-2026-10-29](VIDEO-TO-SFA-2026-10-29.md)(픽셀 지도 방식, 이 문서로 대체).

## 1. 이전 설계가 틀린 이유
- 정답이 **화면에 보이는 선 픽셀 지도**였다(`vec_data.py`: `vis = buf == i`).
- 그 결과 SFA 정보 대부분이 정답에서 빠졌다.
  - 가려진 부분이 지워졌다. 그래서 레이어에 가려 끊긴 선이 실제로는 한 오브젝트로 이어진다는 걸 배울 수 없었다.
  - 어떤 픽셀들이 한 오브젝트인지, 어디가 연결(AC)됐는지, 어느 레이어인지, 어떤 순서로 그렸는지가 없었다.
- 조립 코드(`vec_assemble.py`)가 픽셀 지도에서 구조를 짐작해야 했다. 결과적으로 오브젝트가 사람 파일의 절반 수준이었고, 연결은 거의 없었다.
- 원인은 정답지 설계였다. 학습량 문제가 아니었다.

## 2. 새 설계 한 줄
사용자 표현(10-30): SFA 인코딩 영상을 보고 스틱파이터 도구로 따라 만들고, 만든 파일을 원본 파일과 비교 채점해 깎아내면, 나중엔 정답 SFA가 없는 영상도 SFA로 만들 수 있다.

**모델이 SFA 파일 내용을 직접 써 내려간다.** 정답 = 그 장의 SFA 오브젝트를 그리는 순서대로 적은 문장(토큰열)이고, 모델은 영상 한 장을 보고 그 문장을 한 토큰씩 만든다. 사진 → 문장 번역과 같은 구조(이미지 인코더 + 문장 디코더, 이미 검증된 Pix2Seq·벡터 그림 생성 계열)다.

## 3. 정답지(토큰열) — `tools/sfa_tokens.py`
그리는 순서 = 레이어 → 연결 묶음 → 오브젝트(렌더러·앱과 같다). **문장 순서가 곧 가림 관계**다. 뒤에 적힌 것이 앞의 것을 덮는다.

```
BOS BG a r g b
LAYER
LINE  COLOR a r g b THICK t [GLOW 반경 두께 알파 r g b]  x y PT  x y PT LINK d
CURVE SAME  x y PT  x y PT  x y PT
CIRC  SAME  x y PT  x y PT           (원 = 지름 양끝 두 점)
LAYER …
FILL a r g b  SEG o s e t0 t1  SEG …  CONTOUR  SEG …   (면: 오브젝트 o의 점 s→e, T 구간)
FILL a r g b  WHOLE o                                 (오브젝트 전체 채우기)
EOS
```
- **오브젝트 전체 모양**을 적는다. 가려진 부분도 같은 오브젝트로 이어진다.
- **연결**: `LINK d` = d개 앞의 점과 AC 연결(상대 거리, 스틱맨은 대개 1·2 — 10-30 변경). 위치 추정이 아니라 점을 가리키므로 위치가 다른 연결(실측 5%)도 정확하다.
- **스타일**: 앞 오브젝트와 같으면 `SAME` 한 토큰이다. 색 ARGB, 굵기(로그 칸, 오차 0.25%), 글로우(반경·두께 0.1 단위, 알파, 색)를 적는다.
- **수**: 수 토큰 8,192개를 공유한다.
  - 좌표는 0.025 단위다(−50~154.8). 0.05 단위는 렌더 차이가 1%라서 줄였다.
  - 범위를 넘는 수(화면 밖으로 뻗은 곡선 조절점, 4,096개 넘는 번호)는 `BIG` + 세 자리로 정확히 적는다.
  - 직선은 상자(−1000~1100) 안으로 정확히 자른다. 보이는 모양은 그대로다.
- **빼는 것**(모두 화면에 영향이 없거나 규칙으로 다시 만든다):
  - 숨긴 레이어
  - 안 보이고(색·글로우 알파 0) 면에도 안 쓰인 오브젝트
  - 화면에서 아주 먼 오브젝트
  - Flags(파란점 — 규칙으로 다시 만든다)
  - ID(파일 전체에서 새로 매겨 앱 규칙 'ID마다 레이어 하나'를 지킨다)
  - ObjectScale(렌더 영향 없음)
- 해독(`decode`)은 토큰열을 바로 앱이 여는 Frame XML로 바꾼다.

### 3.1 정답지가 SFA를 빠짐없이 담는지 — 왕복 검사(`tools/sfa_tokens_check.py`, 서버 측정)
SFA 장 → 토큰 → SFA 장 → 렌더해서 원본 렌더와 비교했다. 대상은 학습 파일 전체 22,371장이다.

| 항목 | 결과 |
|---|---|
| 연결(AC) | 1,576,561 → 1,576,561 (전부 복원) |
| 면(FR) | 10,653 → 10,653 (전부 복원) |
| 오브젝트 | 1,714,168개를 적음. 버림: 안 보임 512, 화면 밖 132,340(7.7%) |
| 렌더 비교(894장, 640폭, 채널 차 > 24 픽셀) | 중앙값 0.036%, 90% 0.20%, 99% 0.47%, 최대 0.64% |
| 차이 모양 | 선 가장자리 안티에일리어싱뿐. 최악 장면도 눈으로는 같다(시트 확인) |

토큰 길이(장당): 중앙값 376, 90% 1,970, 99% 6,033, 최대 120,326.

| 길이 상한 | 들어가는 장 |
|---|---|
| 1,024 | 79.4% |
| 2,048 | 90.5% |
| 4,096 | 97.0% |
| 8,192 | 99.5% |

검사 중 고친 것:
- 먼 곡선 조절점을 잘라 쓰던 것: 렌더가 최대 45% 달라졌다.
- 4,096 넘는 번호가 잘리던 것.
- 직선 자르기에 다른 오브젝트 좌표가 들어가던 버그.

단위 시험: `tests/test_sfa_tokens.py`.

## 4. 모델
- **입력**: 렌더·압축한 영상 한 장(기존 자료 만들기 그대로: 1920/1280/854/640, 압축, 페인트 합성). 2단계에서 앞 장의 정답 문장을 더한다(5절).
- **인코더**: 이미지 특징 지도. 기존 ResNet34 U-Net의 인코더(우리 렌더로 1·2차 학습된 가중치)로 시작할 수 있다. 1/16 크기 특징 + 2D 위치를 넣는다. 640×360 기준 약 900개다.
- **디코더**: 트랜스포머 8–12층, 폭 512, 이미지 특징에 교차 주의를 건다. 크기는 약 6천만–9천만 변수다.
- **출력 머리 3개**
  1. 일반 토큰(종류·스타일·수): 분류. 좌표 칸은 이웃 칸에 정답 무게를 조금 나눈다(가우스 부드러운 정답). 0.025 단위 한 칸 차이를 완전 오답으로 보지 않게 하기 위해서다.
  2. **연결 가리키기**: `LINK` 뒤에는 앞 점들의 은닉 상태와 내적해서 고른다(포인터). 번호를 수 토큰으로 외우게 하지 않는다.
  3. **면의 오브젝트 가리키기**: 같은 방식으로 앞 오브젝트를 고른다.
- **문법 강제 해독**: 생성 때 상태 기계가 다음에 올 수 있는 토큰만 허용한다. 그래서 출력은 항상 앱이 여는 SFA가 된다.

## 5. 단계
1. **한 장 → 한 장의 SFA**(먼저).
   - 길이 2,048 이하 장(90.5%)으로 시작하고, 잘 되면 4,096(97%)으로 늘린다.
   - 출력 파일은 장마다 새 ID다(앱에서 그대로 열린다). 사용자는 24,24로 만들기 때문에 트위닝이 필요 없다.
2. **장 사이 추적(스틱맨 움직임, 사용자 주 목적)**.
   - 앞 장의 문장을 앞에 붙인다. `KEEP j`(앞 장 j번째 오브젝트와 같은 것) 토큰을 추가해서 같은 오브젝트가 같은 ID를 유지하게 한다.
   - 이렇게 하면 관절 궤적을 그대로 뽑을 수 있고 앱에서 편집하기도 쉽다.
   - 정답은 SFA의 AO ID가 장 사이에 공통인 데서 바로 나온다.
3. **정답 없는 영상으로 깎아내기(최종 목표, 사용자 10-30)**: 채점은 **오브젝트 단위 대입**이다(사용자 10-30: "스파는 픽셀로 보는 게 아니라 오브젝트로 보는 거야, 대입하는 거야"). 화면 전체 픽셀 비율로 채점하지 않는다. AI가 놓은 오브젝트마다 영상 속 획에 값(점·굵기·색)을 대입해 그 오브젝트가 자기 획 위에 놓였는지, 획 중 어느 오브젝트도 덮지 않은 부분(놓친 획)이 있는지를 오브젝트별로 센다. 1·2단계에서 원본 파일과 오브젝트 짝짓기 채점으로 SFA 짜는 법(연결·레이어·순서)을 먼저 배운 뒤 한다. 구조 점수(사람 파일 통계: 연결된 끝 비율 등)도 같이 본다. 세부 방식은 1단계 결과를 본 뒤 정한다.
4. **긴 장(> 4,096)**: 레이어·영역별로 나눠 이어 쓰기. 나중에 한다.

## 6. 늘리기(정답과 그림이 정확히 같이 변한다)
SFA를 먼저 바꾸고 렌더하므로 정답이 늘 정확하다.
- 이동·확대·좌우 뒤집기(좌표 변환)
- 색 바꾸기
- 배경색
- 페인트 합성(`sfa_paint_synth.py`)
- 굵기 배율
- 압축 세기

같은 장도 매번 다른 그림이 되므로 22,371장 × 무한 변형이다.

## 7. 평가(시험용 38개 파일, `holdout_vec.txt`) — 오브젝트 단위(`tools/sfa_objscore.py`)
AI가 만든 장과 원본 장의 오브젝트를 하나씩 짝지어(헝가리안, 종류 + 점 평균 거리) **오브젝트마다 대입한 값**을 비교한다. 픽셀은 주 지표가 아니다(사용자 10-30).
**구조 채점이 주 지표**(사용자 10-30 영상: 선 세 개를 작게 따라 그려도 관계가 맞으면 O, 같은 크기라도 기울고 배치가 틀리면 X): AI 그림 전체를 이동 + 같은 비율 확대로 원본에 맞춘 뒤 비교한다. 회전은 맞추지 않는다. 제자리 비교는 보조. 시험: 영상 상황 재현 — 작게 그린 것 3/3(배율 2.99), 기울게 그린 것 1/3.
1. **오브젝트**: 맞음 = 같은 종류 + 점 평균 거리 1.0 단위 이하. 원본 중 맞힌 비율(놓친 것), AI 것 중 맞은 비율(지어낸 것).
2. **값**: 맞은 오브젝트의 점 오차, 색 일치, 굵기 일치.
3. **연결**: 짝지은 점끼리 연결 F1. 이전 방식이 가장 못한 항목.
4. **가림 순서**: 짝지은 오브젝트 쌍의 앞뒤 일치 비율.
5. **문법**: 앱이 여는 파일 100%(문법 강제로 보장, 시험으로 확인).
6. **사용자 앱 확인**: 오버드라이브·S2aqoie 등 시험 장면.

결과는 그림(입력 | AI SFA | 원본 SFA)으로 먼저 보여 드리고 위 숫자를 붙인다.

## 8. 계산·시간(추정 — 짧은 시험으로 잴 것)
- 2,048 토큰 × 묶음 8 수준이면 5060 8GB(bf16, 주의 메모리 절약 SDPA)에 들어갈 것으로 **추정**한다. 실측 전이다.
- 순서:
  1. 서버 CPU 수십 걸음(손실 감소·문법·저장 확인)
  2. 1050 Ti 빠른 시험(속도·메모리 실측)
  3. 5060/4060 본 학습(시간은 2의 실측으로 계산)
- 생성 속도: 장당 수백–수천 토큰을 차례로 낸다(KV 캐시). GPU에서 장당 수 초–수십 초로 추정한다. 서버 생성(10-26 임시 결정 B)이라 수용 가능하다.

## 9. 위험과 대책
| 위험 | 대책 |
|---|---|
| 긴 문장에서 뒤로 갈수록 틀림이 쌓임 | 짧은 장부터(커리큘럼), 문법 강제, 2단계에서 앞 장 문장으로 안정화 |
| 좌표 정밀도(0.025 단위 = 1920폭에서 약 0.5픽셀) | 부드러운 정답, 필요하면 대강 칸 + 세밀 칸 두 토큰 |
| 자료 22,371장, 비슷한 장이 많음 | 6절 늘리기, 합성, 이전 인코더 가중치 |
| 화면 밖 오브젝트(7.7%)를 버림 → 2단계에서 화면 안으로 들어오는 오브젝트 | 2단계에서 앞 장 문장에 남긴다(장 사이 정보) |
| 같은 그림을 다른 오브젝트 조합으로 그릴 수 있음(정답이 하나가 아님) | 사람 파일 순서를 그대로 정답으로(지도 학습). 평가는 그림 + 구조 둘 다 |
